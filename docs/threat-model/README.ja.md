# 脅威モデル

Sherry が何を防御し、信頼境界がどこにあり、そして同じくらい重要なこととして——どの防御が OS による強制された境界で、どれがプロセス内のヒューリスティックなのか。ここは全体図であり、OS 隔離の詳細は[サンドボックスのドキュメント](../sandbox/README.ja.md)が担います。

## 信頼境界

| # | 境界 | 横断点 | 強制するもの |
|---|---|---|---|
| 1 | ユーザー → エージェント | WebSocket ターン | ゲートウェイ認証（Origin 許可リスト + 起動ごとの token） |
| 2 | LLM → ツール | ツール呼び出し | HITL 承認ゲート、`agent/middlewares/humanInTheLoop/detection.py` の危険コマンド一覧 |
| 3 | ツール出力 → モデル文脈 | ツール結果 | **信頼できない出力のフェンス**、Prompt インジェクションスキャナ、ツール結果の退避 |
| 4 | 子エージェント → 親エージェント | announce パイプライン | 完了ゲート、`SubagentCompletionDrain` |
| 5 | MCP サーバー → エージェントプロセス | ツール結果 | 信頼できない出力のフェンス（`mcp_` 前置きルール。MCP ツールは未同梱） |
| 6 | HTTP クライアント → ゲートウェイ | HTTP ルート | ゲートウェイ認証ミドルウェア、クエリパラメータの型変換 |
| 7 | ファイルシステム → エージェント | ファイルツール | `PathGuard`、`O_NOFOLLOW`、仮想パス解決 |
| 8 | サンドボックスの子プロセス → ホストプロセス | 子プロセス起動 | `scrub_env`、`bwrap`/`seatbelt` による隔離 |
| 9 | メモリ / スキルファイル → システムプロンプト | プロンプト組み立て | インストール時のスキルスキャンゲート；**書き込み時の注入ブロックは未実装** |
| 10 | TaskFlow step の結果 → 下流 step | DAG の辺 | 期待→実績の閉ループ：schema ゲート、step judge、証跡台帳 |

## データ分類

| 分類 | 例 | 保管場所 |
|---|---|---|
| 機密 | API キー、token | 環境変数；子プロセスより前に `scrub_env`（`agent/tools/pub_base/env_scrub.py`）が除去 |
| 私的 | 会話履歴 | MesMemory SQLite（WAL） |
| 内部 | ツール結果 | メッセージ一覧 + 退避ファイル |
| 信頼できない | ウェブページ内容、端末出力、MCP 結果 | ツールメッセージ——読むべき**データ**であり、従うべき指示ではない |

## 脅威分析

| 脅威 | 既存の防御 | ギャップ |
|---|---|---|
| 間接的な prompt インジェクション（ツール出力） | **信頼できない出力のフェンス**（偽装区切り文字は無効化）、ツール結果の退避、不可視 Unicode のスキャン | — |
| ウェブ/端末テキスト中の注入指示 | Prompt インジェクションスキャナ（下記） | 各呼び出し面が適用する必要がある |
| メモリ / スキルファイルの注入 | **メモリ書き込みスキャン**：3 つの書き込み経路すべてでブロック（散文向けのパターン表を使います——*システムについて*書かれたメモは攻撃ではないため）。加えてインストール時のスキルスキャンゲート | — |
| ログ / ツール出力への鍵漏洩 | **マスキングエンジン**：ログ経路（常時有効、例外テキストを含む）と漏洩しやすいツール出力、子プロセスは `scrub_env` | 規則が認識できる形しか消せません。それ以上ではありません |
| URL 資格情報の漏洩 | **URL マスキング**：対応スキームの拡大、ネストしたパーセントデコード（深さ 8）、クエリと署名パラメータ | — |
| パス横断 | `PathGuard` + `O_NOFOLLOW` | — |
| Shell インジェクション | `agent/middlewares/humanInTheLoop/detection.py` の一覧（hardline 12 件 + dangerous 59 件） | — |
| サンドボックス脱出 | `bwrap` / `seatbelt` | — |
| 推論ブロックのストリーム漏洩 | **インライン CoT の転送**：思考内容は破棄せず推論チャネルへ移します | そもそもタグを出さないモデルは定義上影響を受けません |
| 端末出力中の制御シーケンス | **制御シーケンスの除去**：`terminal` の両方の spawn 箇所に適用 | — |
| ログ中のチャネル識別子（ユーザー / チャット） | **安定した仮名**：チャネルのログ境界で置換 | ルーティング表と返信先は設計上そのまま保持します |
| 子プロセスの env hijack（`LD_PRELOAD`、`LD_LIBRARY_PATH`、`BASH_ENV` など） | **hijack 変数のブロック**：起動フック（`PYTHONPATH`、`BASH_ENV`、`ENV` など）は常に除去。ローダー変数（`LD_PRELOAD`、`LD_LIBRARY_PATH`、`DYLD_INSERT_LIBRARIES`）は `SHERRY_STRICT_ENV_HIJACK=1` のときだけ除去します（コンテナランタイムが実際に設定するため） | ローダー変数はデフォルトでブロックされません——運用の節を参照 |
| クロスサイトリクエストフォージェリ（CSRF） | **Origin 許可リスト**に加えて **CSRF ガード**：変更系メソッド（POST/PUT/PATCH/DELETE）は `Sec-Fetch-Site: cross-site` で拒否し、`Origin`/`Referer` が loopback でも許可リストでもなければ拒否します | スクリプトクライアントは3つのヘッダを送りません（curl、テストクライアント）——認証は token が担い、このガードではありません |
| サーバーサイドリクエストフォージェリ（SSRF） | **SSRF 判定**が取得する全 URL に適用：非グローバルな宛先（プライベート、loopback、クラウドメタデータ、RFC 2544、IPv6 ULA）は拒否し、接続は**検証済みアドレスに固定**、リダイレクトは各ホップで再検証 | fake-ip プロキシのホストでは公開名が拒否レンジに解決されます——文書化されたスイッチが回避口です |
| レンダリング内容の XSS | クライアントの DOMPurify 許可リスト + `vue/no-v-html` + **サーバーのセキュリティヘッダー**（`script-src 'self'`、`object-src 'none'`、`nosniff`、フレーミング拒否） | CSP は第二層です：クライアント側サニタイザはペイロードと同じ文脈で動きます |
| `terminal` 経由の手書き SSRF（モデルが説得されて `curl` する） | HITL 承認パターン：クラウドメタデータ端点、および**書き込みを伴う** loopback リクエスト | パターンは境界ではなくヒューリスティックです：言い換えで回避できます |
| アップロード端点の内容偽装 | ゲートウェイ認証（Origin + token） | **バイト署名と宣言型の一致検証** |

## 信頼できない出力のフェンス

`agent/security/untrusted_wrapper.py` が実装し、`agent/middlewares/context_eviction/core.py`
がすべてのツール結果に適用します。攻撃者が制御しうるツールの結果は
`<untrusted_tool_result source="…" id="…">` ブロックで包まれ、その中の勧告文が「これは指示ではなくデータである」と述べます。

| 性質 | 実装 |
|---|---|
| 対象 | `web_search`、`tavily_search`（API キーを設定すると同じツールが Tavily 自身の名前で出荷される）、`message_search`、および `mcp_` ツール |
| 区切り文字の偽装 | ペイロード内の閉じタグは包む前に `</untrusted-tool-result>` へ書き換えられ、ブロックを早期に閉じられません |
| 順序 | 先に evict、その後に包むため、フェンスはモデルが実際に読むプレビューを囲みます |
| 原文 | フェンスされるのはモデルの見る姿だけ；内側の永続化が保持するメッセージは決して書き換えられません |
| スイッチ | `config/features/agent_side/untrusted_output.py` の `UNTRUSTED_OUTPUT["enabled"]`、勧告文も同じ場所 |

これは**フェンスであり、境界ではありません**。モデルは説得されて無視する可能性があります。価値は、境界がモデルの読む位置に明示されることと、最も安価な偽装（ブロックを閉じる）が無効化されることにあります。

## シークレットのマスキング

`agent/security/redact.py` がテキスト中の資格情報をマスクし、2 か所に適用されます。スイッチは意図的に別です：

| 面 | 適用するもの | スイッチ |
|---|---|---|
| すべてのログレコード（コンソール + 3 つのローテーションファイル） | `agent/security/redact_formatter.py`（`logs/logger.py` が導入する loguru patcher） | 常時有効——ログファイルはセッションより長生きし、読む人はその秘密を見ていない |
| 漏洩しやすいツール出力（`terminal`、`python_repl`、信頼できないツール群、`mcp_*`） | フェンスと同じミドルウェア | `config/features/agent_side/redaction.py` の `REDACTION["tool_output_enabled"]` |
| ファイルツール（`read_file`、`patch_file`、`write_file`） | — | 意図的にマスクしません：エージェントは自分の設定を編集し、マスクすると「読んで書き戻す」が損失的になるため |

対象：ベンダー鍵プレフィックス（`sk-`、`ghp_`、`AKIA`、`xox*`、`AIza`、`hf_` など）、各種設定形式の鍵名代入（`.env`、INI、YAML、TOML、JSON——`"CURATOR_API_KEY"` のような接頭辞付きキーや空白を含む引用値も）、`Authorization` / `X-API-Key` ヘッダ、JWT、PEM 秘密鍵ブロック、URL 資格情報とクエリパラメータ。

依存してよい性質：

* **冪等**——センチネルはどの族にも一致しないため、二度マスクしても変わりません。
* **スイッチはインポート時に固定**（`SHERRY_REDACT`）：モデルが説得して `export REDACT=false` を書かせても、進行中のセッションを解除できません。ログ経路はこのスイッチの影響を受けません。
* **過剰マスクを選ぶ**。値が「資格情報らしく見える」ことを要求すると全小文字のパスワードを取り逃すため、コード中で秘密名の変数を自分自身に代入する形も書き換えます（例は規則自身のコメントにあります）。書き換えが実際に害になる面（ドキュメント）はコーパステストで固定しています。
* **例外も対象です。** loguru は書き出し時に生きたフレームからトレースバックを描画するため、patcher はそのテキストを見られません。そこで patcher 自身がそれを描画し（loguru 自身の formatter を使うので `> File …` の体裁は保たれます）、マスキングし、レコードの例外フィールドを空にしてどの sink も二重に出力しないようにします。これで、失敗した呼び出しから秘密が漏れる 2 つの経路——例外自身のメッセージと `diagnose` の局所変数ダンプ——が閉じます。描画時に**意図的に**変数値を載せていません。注釈付きダンプはフレームの局所変数をそのまま出力し、チャット ID や引用されたメッセージを認識できる規則は存在しないためです。

## 書き込みと出力の境界

**プロセスから出ていく**ものを、入ってくるものではなく書き換える面が 4 つあります。いずれも生の形が下流で無用か有害だから追加したもので、いずれも衛生策であって境界ではありません。

| 面 | モジュール | 何をするか |
|---|---|---|
| メモリ書き込み（`memory` ツールの `add`/`replace` とフラッシュ経路） | `agent/tools/memory.py` | 散文向けパターン表で走査し、書き込みを拒否します。ブロックされた項目はディスクに到達しません。上のスキャナ階層を再利用しないのは、メモリ項目が*システムについて*の散文だからです——`.bashrc` や `KEY=` 変数に言及したメモはメモであって攻撃ではありません |
| 取得した端末出力 | `agent/security/terminal_output.py` | CSI/OSC とその他のエスケープシーケンス、C0 制御バイトを除去し、復帰（CR）上書きの意味論を適用します（`10%\r100%` → `100%`。`\r\n` の行末はそのテキストを保持）。`terminal` の両方の spawn 箇所（同期・非同期）に適用 |
| インライン推論を含む回答テキスト | `agent/security/think_scrub.py` | `<think>`/`<thinking>`/`<reasoning>` の中身を回答チャネルから、クライアントが思考ブロックとして描画する推論チャネルへ移します。スクラバーはターンごとに 1 つで、分割不変です——チャンク境界は provider が決めるため、タグがどこで切れても 1 チャンクと同じ結果にならなければなりません |
| チャネルのユーザー / チャット識別子 | `agent/security/pii.py` | ログにはプラットフォームの識別子ではなく `«pii:<16 進 12 桁>»` を書きます。プロセスをまたいで安定するため「受信」と「送信成功」は後のログファイルでも対応付けられます。生の値は機能する場所（ルーティング表、返信先、プラットフォーム SDK 呼び出し）に残ります |

## ネットワーク境界

プロセスとネットワークの間には三道のゲートがあり、それぞれ脅威が実際に到達しうる層に置かれています：

| 境界 | メカニズム | 補足 |
|---|---|---|
| 受信の変更リクエスト | `server/trigger/csrf.py`——変更系メソッド（`POST`/`PUT`/`PATCH`/`DELETE`）は `Sec-Fetch-Site: cross-site` で拒否し、`Origin`/`Referer` が loopback でも許可リストでもなければ拒否します | ブラウザが設定するヘッダはページ側で偽造できない信号です。`server/trigger/auth.py` の Origin ゲートが第一層のまま残り、3つのヘッダを送らないクライアント（curl、テストクライアント）は通ります——認証は token が担います |
| 受信のレスポンス | `server/trigger/security_headers.py`——すべてのレスポンス（拒否されたものも含む）に `Content-Security-Policy`、`X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、`Referrer-Policy` を付与 | `script-src 'self'` と `object-src 'none'` は、クライアント側サニタイザが破られた後でも効く層です。`GATEWAY["csp"]` でポリシーを差し替え、リテラル `disabled` でヘッダーを省略できます |
| 送信の取得 | `pub/func/validator/public_url.py`（判定）+ `pub/func/validator/safe_fetch.py`（転送） | 解決されたアドレスが**すべて**グローバルでなければ socket を開く前に拒否します。その後 socket は検証済みのアドレスへ直接接続し（ホスト名は従来どおり `Host`/SNI で送られます）、二度目の DNS 応答で接続先を変えられません。リダイレクトはホップごとに同じ検査を繰り返します |

シェルはネットワークガードから見えない第四の経路です。HITL 承認リスト（`agent/middlewares/humanInTheLoop/detection.py`）には、クラウドメタデータ端点（読み取った資格情報をモデルが要約して返してしまう形）と、**書き込みを伴う** loopback リクエストのパターンがあります。一方、通常の `curl http://127.0.0.1/…` の読み取りは意図的にゲートしません——ローカル調査のたびに承認を求めると、操作者が反射的に通すようになります。

## セキュリティポリシー

**唯一の強固な境界はオペレーティングシステムです。** プロセス分離、ファイル権限、サンドボックスバックエンド、ゲートウェイの認証境界こそ、攻撃者が実際に破らねばならないものです。エージェントが**プロセス内**で行うことはすべてヒューリスティックです：

| 層 | 何であるか | なぜ境界ではないか |
|---|---|---|
| Prompt インジェクションスキャナ、信頼できない出力のフェンス | 検出とラベル付け | モデルは説得されてフェンスを越え得るし、パターンは言い換えで回避できる |
| シークレットのマスキング、識別子の仮名化、制御シーケンス除去 | 出力境界での衛生処理 | 規則が認識できるものしか取り除けず、生の値は通常その上流に残る |
| パスガード、HITL 許可リスト、危険コマンド一覧 | 既知の危険形に対する拒否規則 | 拒否規則は本質的に不完全 |
| env スクラビング、レーン上限、反復予算 | 被害範囲の縮小 | 子プロセス自体が攻撃者の経路でないことを前提とする |

受け入れ、明示する運用上の帰結：

* モデル出力は消費側にとって**信頼できない入力**です——OS レベルの検証なしに、エージェントの言葉で特権操作を駆動しないこと；
* エージェントが読めるものは最終的に漏れ得ます——タスクに必要な資格情報だけを与えてください；
* `terminal` と `python_repl` は操作者の OS アイデンティティで動きます（シークレット名の環境変数のみ除去）。したがって本当の上限はそのアカウントの**OS 権限**であり、サンドボックスの*設定*ではありません；
* フェンスを無視する頑固なモデルや、同じアカウントを持つ悪意ある操作者は対象外です。防御するのは**他所から来る内容**であり、エージェントを動かす人ではありません。

## 運用

**起動時の確認。** 128K の下限によりプロセスは起動を拒否します（両 LLM）。ゲートウェイは起動ごとに token を発行するため、再起動をまたいで開いたページはリロード後にのみ再接続します。シークレットは `.env` に（環境変数のみ——設定ファイルはシークレット保管庫ではありません）。

**監視すべき点。** `logs/output/error/` に失敗が残ります。セキュリティ関連の行は：

| ログの信号 | 意味 |
|---|---|
| `refusing WebSocket handshake` | token が古い/欠落したクライアント——再起動後は想定内 |
| メッセージ中の `«redacted»` | 資格情報形の文字列がログレコードに到達し、マスクされた |
| メッセージ中の `«pii:…»` | チャネルのユーザー/チャット識別子が仮名化された（同じ文字列は同じチャット） |
| `csrf guard: refused` | 変更リクエストがクロスサイトまたは外部由来で到着しました——敵対ページ、あるいは Origin を失ったクライアント |
| `refused by the SSRF guard` | URL が非グローバルアドレスに解決され、取得されませんでした |
| `Potential security threat detected: <id>` | インジェクションスキャナがツール出力で発火 |
| サンドボックス / 拒否の行 | ツール呼び出しが拒否規則で止められた |

**漏洩を疑ったら。** まず資格情報をローテーションし（環境設定 / `.env`）、その接頭辞でログを検索します——マスキングのセンチネルは「その形の値が確かにログに載った」ことを示し、MesMemory はそれがどのツール出力由来かを保持しています。どのパターンにも当たらない漏洩こそ、このヒューリスティックが排除できない部分です。説明できないものは最悪を想定してください。

**強化スイッチ。** `SHERRY_STRICT_ENV_HIJACK=1` は子プロセス env のブロックをローダー変数まで広げます——ローダー環境を自前で管理するホストでは正しく、それらを設定するコンテナランタイムでは誤りです（本リポジトリの開発機は後者）。`UNTRUSTED_OUTPUT["enabled"]` と `REDACTION["tool_output_enabled"]` はモデル経路の保護を切り替えます。`SHERRY_REDACT` はインポート時に固定されるため、セッションが書き込めるものを通じてマスキングを切ることはできません。

## Prompt インジェクションスキャナ

`agent/security/threat_patterns.py` は攻撃者が制御しうるテキストを走査し、ヒットした ID を返します。3 つの段階があり、それぞれ前段の上位集合です：

| Scope | 追加されるパターン | 用途 |
|---|---|---|
| `all` | 古典的な注入（ignore/disregard instructions、ロールハイジャック、システムプロンプトの抽出）、鍵の持ち出し、隠し HTML コメント | すべてのツール結果 |
| `context` | C2 / promptware の形（ノード登録、heartbeat、tasking の pull、既知フレームワーク名）、指示ファイルの書き換え | ツール結果と文脈ファイル |
| `strict` | SSH バックドア、shell rc への永続化、ハードコードされた provider 秘密鍵、不可視 Unicode | メモリ書き込み、スキルインストール |


呼び出し側が依存する性質：

* **決して例外を投げず、与えられた内容を書き換えない**。未知の scope は `all` にフォールバックします——綴り間違いでツールを落としてはならないからです。
* **走査は有界**：先頭 65,536 文字だけを見て、すべてのパターンのすべての量化子が有界です——細工した入力で走査自体をサービス拒否に変えることはできません。
* **メッセージは一致した原文を反響しない**：`first_threat_message` はヒット ID のみを返すため、検出結果をログや画面に出してもペイロードを再注入しません。
* これは**ヒューリスティックであり、境界ではありません**。唯一の強固な境界は OS 隔離です（[サンドボックスのドキュメント](../sandbox/README.ja.md)を参照）。スキャナは注入のコストを上げ、呼び出し側が行動できる信号を与えます。

本リポジトリ自身の成果物で実測：実ログ/ツール出力 112 ファイル、3.0 MB のテキストを 0.50 秒で走査（約 6 MB/s）、**ヒットはゼロ**。同じコーパスに注入ペイロードを 1 つ加えると即座に検出されます——実内容では静かでありながら、存在意義のある形は捉えられることを示しています。
