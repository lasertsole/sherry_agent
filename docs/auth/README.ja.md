# ユーザーログイン（アカウント保護）

[English](README.md) · [中文](README.zh.md) · **日本語** · [한국어](README.ko.md)

Sherry は既定で**ログインなし**です。新規インストールにはアカウントがなく、ログイン保護も無効なので、デスクトップアプリもローカルのブラウザもそのまま入れます。アカウントを設定すると、他のマシンからのアクセスにログインが必要になり、このマシンは免除されたままです。

## 有効化と無効化

1. アプリを開き、設定の九宮格メニュー → **アカウント** を開きます。
2. ユーザー名、パスワード（8 文字以上）、確認用パスワードを入力し、**ログイン保護を有効にする**を押します。アカウント作成と有効化が一度に完了します。
3. 以後、他のマシンからのアクセスにはそのユーザー名とパスワードが必要です。このマシンはログインなしで使えます。

保護の無効化（および再有効化）には**現在のパスワード**が必要です。アカウント自体は保持されるため、再有効化でパスワードを再設定する必要はありません。ユーザー名・パスワードの変更も同じパネルで、現在のパスワードを使って行います。

## 保護される範囲

ログイン処理そのものとアプリシェルの静的アセット（ログインページの読み込みに必要）を除き、すべての API にセッションが必要です。有効なセッションがない場合 `401` を返し、クライアントはログインページを表示して、ログイン成功後に元のリクエストを再送します。

## セッションの仕組み

* パスワードはソルト付き **scrypt** ハッシュで保存され、平文はディスクに残りません。
* ログイン時は 2 つの **HttpOnly Cookie**（API 全体に有効なアクセストークンと、更新エンドポイントだけに有効なリフレッシュトークン）を発行します。JavaScript からトークンは見えないため、スクリプト注入でもセッションを読めません。
* アクセストークンは 12 時間有効で、期限前にクライアントがローテーションします。ローテーションのたびに前のリフレッシュトークンは無効化されるため、盗まれたコピーは最大 1 回しか使えません。
* ログアウトは両方のトークンを即時失効させます。

## LAN とリモートアクセス

免除の判定は**ソケットアドレス**のみで行い、リクエストヘッダーは見ません（偽装不可）。このマシンでもログインを必須にするには `SHERRY_AUTH_REQUIRE_NON_LOOPBACK=0` を設定します。初回起動から保護したいデプロイでは `SHERRY_AUTH_ENABLED=1` を設定し、`SHERRY_AUTH_SECRET` を固定してください（固定しないと再起動のたびに既存セッションが無効になります）。

## トラブルシューティング

* **リモートで締め出された？** このマシンで操作してください。アカウントメニューはローカルではログイン不要で開けます（免除を無効にしていない場合）。
* **再起動後にすべての書き込みが 401？** `SHERRY_AUTH_SECRET` が空のため、署名鍵がプロセスごとに変わっています。固定してください。
* **Cookie が届かない？** ブラウザは API とページが同一サイトであること（または Origin が `SHERRY_ALLOWED_ORIGINS` にあること）を要求します。フロントエンドと API を同じホスト名で開いているか確認してください。
