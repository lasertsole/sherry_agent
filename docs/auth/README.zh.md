# 用户登录（账户保护）

[English](README.md) · **中文** · [日本語](README.ja.md) · [한국어](README.ko.md)

Sherry 默认**不开启登录**：全新安装没有账号、登录保护关闭，桌面端与本地浏览器直接进入。配置账号后，来自其它机器的访问需要登录，本机始终免登录。

## 启用与关闭

1. 打开应用，进入设置九宫格菜单 → **账户**。
2. 填写用户名、密码（至少 8 位）与确认密码，点击**启用登录保护**：一步完成建号与开启。
3. 此后来自其它机器的访问需要该用户名与密码；本机照常免登录使用。

关闭（或重新开启）登录保护都需要输入**当前密码**；账号本身保留，重新启用无需重设密码。修改用户名或密码也在同一面板完成，同样需要当前密码。

## 保护范围

除登录流程自身与应用外壳的静态资源（否则登录页无法加载）外，全部接口都需要会话；无有效会话时返回 `401`，前端随即显示登录页，登录成功后再重放原请求。

## 会话机制

* 密码以加盐 **scrypt** 哈希存储，明文永不落盘。
* 登录下发两个 **HttpOnly Cookie**（访问令牌作用于整个 API，刷新令牌仅作用于刷新端点）。令牌对 JavaScript 不可见，脚本注入也读不到会话。
* 访问令牌有效期 12 小时；客户端在到期前自动轮换，且每次轮换都会作废上一个刷新令牌——泄露的副本最多只能用一次。
* 登出即时吊销两个令牌。

## 局域网与远程访问

豁免判定只看**套接字地址**，不看任何请求头，因此无法伪造。若本机也要求登录，设置 `SHERRY_AUTH_REQUIRE_NON_LOOPBACK=0`；若希望部署从第一次启动就受保护，设置 `SHERRY_AUTH_ENABLED=1` 并固定 `SHERRY_AUTH_SECRET`（否则每次重启都会让已有会话失效）。

## 常见问题

* **远程被锁在外面？** 到本机上操作：账户菜单在本机无需登录即可打开（除非关闭了该豁免）。
* **重启后所有写操作都 401？** `SHERRY_AUTH_SECRET` 为空，签名密钥随进程变化。请固定它。
* **Cookie 没有带上？** 浏览器要求 API 与页面同站（或该 Origin 在 `SHERRY_ALLOWED_ORIGINS` 中）；确认前端与 API 使用同一个主机名访问。
