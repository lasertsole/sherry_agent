# 사용자 로그인(계정 보호)

[English](README.md) · [中文](README.zh.md) · [日本語](README.ja.md) · **한국어**

Sherry는 기본적으로 **로그인이 없습니다**. 새로 설치하면 계정도 없고 로그인 보호도 꺼져 있어 데스크톱 앱과 로컬 브라우저는 그대로 들어갑니다. 계정을 설정하면 다른 기기에서의 접속에 로그인이 필요해지고, 이 기기는 계속 면제됩니다.

## 켜기와 끄기

1. 앱을 열고 설정 아홉칸 메뉴 → **계정**으로 갑니다.
2. 사용자 이름, 비밀번호(8자 이상), 확인용 비밀번호를 입력하고 **로그인 보호 켜기**를 누릅니다. 계정 생성과 보호 활성화가 한 번에 끝납니다.
3. 이후 다른 기기에서의 접속에는 그 사용자 이름과 비밀번호가 필요합니다. 이 기기는 로그인 없이 그대로 씁니다.

보호를 끄거나(다시 켜거나) 할 때는 **현재 비밀번호**가 필요합니다. 계정 자체는 남으므로 다시 켤 때 비밀번호를 새로 정할 필요가 없습니다. 사용자 이름·비밀번호 변경도 같은 패널에서 현재 비밀번호로 합니다.

## 보호 범위

로그인 흐름 자체와 앱 셸의 정적 자산(로그인 페이지 로딩에 필요)을 제외한 모든 API에 세션이 필요합니다. 유효한 세션이 없으면 `401`을 돌려주고, 클라이언트는 로그인 페이지를 띄운 뒤 로그인 성공 후 원래 요청을 다시 보냅니다.

## 세션 동작

* 비밀번호는 솔트가 있는 **scrypt** 해시로 저장되고 평문은 디스크에 남지 않습니다.
* 로그인하면 **HttpOnly 쿠키** 두 개(API 전체에 적용되는 액세스 토큰, 갱신 엔드포인트에만 적용되는 리프레시 토큰)를 발급합니다. 토큰은 JavaScript에서 보이지 않으므로 스크립트 주입으로도 세션을 읽을 수 없습니다.
* 액세스 토큰은 12시간 유효하며, 클라이언트가 만료 전에 회전합니다. 회전할 때마다 이전 리프레시 토큰은 무효가 되므로 훔친 사본은 최대 한 번만 쓸 수 있습니다.
* 로그아웃하면 두 토큰이 즉시 폐기됩니다.

## LAN과 원격 접속

면제 여부는 **소켓 주소**만 보고 판단하며 요청 헤더는 보지 않으므로 위조할 수 없습니다. 이 기기에서도 로그인을 요구하려면 `SHERRY_AUTH_REQUIRE_NON_LOOPBACK=0`을 설정하세요. 처음 부팅부터 보호하려면 `SHERRY_AUTH_ENABLED=1`과 함께 `SHERRY_AUTH_SECRET`을 고정하세요(고정하지 않으면 재시작마다 기존 세션이 무효가 됩니다).

## 문제 해결

* **원격에서 잠겼나요?** 이 기기에서 조작하세요. 계정 메뉴는 로컬에서 로그인 없이 열립니다(면제를 끄지 않은 경우).
* **재시작 후 모든 쓰기가 401인가요?** `SHERRY_AUTH_SECRET`이 비어 있어 서명 키가 프로세스마다 바뀝니다. 값을 고정하세요.
* **쿠키가 오지 않나요?** 브라우저는 API와 페이지가 같은 사이트이기를(또는 Origin이 `SHERRY_ALLOWED_ORIGINS`에 있기를) 요구합니다. 프런트엔드와 API를 같은 호스트 이름으로 열고 있는지 확인하세요.
