# ターン実行履歴の折りたたみ

> 完了したターンはツール/推論の履歴を 1 行の要約に折りたたみ、最終回答は常に表示します。

## 🎯 概要

生成ターンが終了すると、チャットはアシスタントの実行履歴 — ツールカード、途中の
アシスタントテキスト、推論 — を小さな要約行の背後に折りたたみます。最終回答はその
下に常に表示されます。要約を展開すると完全な線形履歴が戻ります。

実行中、ツール呼び出しで終了、最終回答なし、未解決のツール呼び出しを含むターンは
**折りたたみません**。既存の線形レンダリングを維持します。これが fail-open の境界で、
異常なターンが作業を隠すことはありません。

## 🧭 分類

折りたたみは既存の message 行から導出されます。アシスタントの作業グループは次の
すべてを満たす場合のみ折りたためます：

| 条件 | 要件 |
| :--- | :--- |
| 最終行 | グループの最後の行が AI 行 |
| 完了済み | `streaming` が false |
| 表示内容 | テキストまたはメディア添付がある |
| 完結 | 行がツール呼び出しを宣言していない（`hasToolCalls` が false） |
| 通常行 | 注入キャリアではない（user 以外の `origin` がない） |
| 折りたたむ対象 | 前に履歴行がある、または推論を持つ |

`history` は最終回答より前のすべての行です。履歴も推論もない単独の回答は折りたたむ
対象がなく、線形のままです。

## ⚙️ 操作

- 完了したグループは**折りたたみ**で開始します。要約はツールカード数と測定済み
  ツール実行時間の合計を表示します。これは**ツール実行時間**であり、turn の
  wall-clock ではありません（モデルの思考とネットワーク往復は含みません）。
  ツールがない場合は「思考過程」/「実行過程」を表示します。
- 要約行はその場で履歴を切り替えます。展開後も内側のツールカードは各自の展開状態を
  保持します。
- 折りたたみ中、最終行は思考ブロックを表示せず、アバターは保持します。連続メッセージ
  と誤認させないためです。
- 展開状態はマウント中のチャットページに属します（永続化なし）。再読み込み時は再分類
  され、折りたたみ状態に戻ります。
- 切り替え後に仮想リストが行の高さを再測定するため、スクロール形状は正しく保たれます。

## 🧩 アーキテクチャ

`use-chat-turn-groups` は発話者の境界で行を分割します。USER 行は独自グループを作り、
後続の AI/TOOL 行が 1 つのアシスタント作業グループになります。
`use-chat-turn-fold.ts::classifyTurnFold` がそのグループを
`{history, finalMessage, toolCount, durationMs, hasReasoning}` に変換します。

`MessageItem.hasToolCalls` は保存された AI 行の `tool_calls` からマッピングされるため、
ツール呼び出しを含む行が最終回答と誤認されることはありません。
`ChatTurnHistoryStatus.vue` が要約トリガーです。`ChatBox.vue` が表示行を選び、折りたたみ
中は最終行の推論を隠します。`use-chat-card-expansion.ts` がグループごとの展開集合を
所有します。

分類は**意図的にクライアント側**です。message 行は現在 `turn_num` と `turn_id` の
両方を持ちます（サーバーがターンごとに刻印）が、trajectory 台帳はツールイベントを
保存してもアシスタントテキストは保存しません。サーバーの render-unit API や
WebSocket frame は、クライアントが既に持つ行を複製するだけになります。読み込み済み
の message プロトコルから導出すれば、履歴再読み込みと再接続が同一結果になり、
schema も frame も増えません。

最終回答は通常の `AIMessage.content` です。`final_answer` / `execution_summary` /
`structured_response` のような特殊フィールドはなく、「完了」はその行の `tool_calls`
が空であることで判定します。元計画のオプション structured-response 要約は使いません。
折りたたみに LLM の協力は不要です。

## ⚠️ Spike 実測と既知の制限（2026-10-23）

実セッションで `read_file` 2 回 + `search_files` 1 回、thinking 有効：

- turn 実行中：折りたたみトリガー 0、ツールカードは表示（線形）；
- turn 終了・再読み込み後：要約「3 ツール · 54ms」、ツールカード/推論は非表示、
  最終回答は表示；
- 展開：ツールカード 3 + 思考ブロック 2 が復元、最終回答も表示；
- 54ms = 9 + 8 + 37ms で、ツール実行時間の合計であることを確認。

**既知の live-session race（未修正）**：turn 終了直後、再読み込み前には draft 行が
hydrate されて新しい user 行の前に並ぶことがあります。最終回答が重複し、折りたたみ
要約のツール数/時間が過大になります（再読み込み前「4 ツール · 62ms」、後「3 ツール · 54ms」を
実測）。原因は `untrackDraftTurn` が IndexedDB の削除を await せずに
`loadSessionHistory` を実行し、サーバーが `done` 時にまだ最終 AI 行を永続化して
いない場合があるため、stale-draft ガードが認識できないことです。再読み込みで復旧
します。修正方向：draft 削除の完了後に history を読み込む、または human 行はあるが
最終 AI 行がない turn の draft を hydrate しない。

結論：折りたたみ分類自体は正しく、サーバーの render-unit プロトコルも
structured-response 特殊フィールドも不要です。race は既存の chat/draft 層の問題で、
別途修正が必要です。

## 🧪 テスト

`use-chat-turn-fold.test.ts` が分類（完了した最終回答、ストリーミング、末尾ツール、
ツール呼び出し付き AI 行、推論のみ、未知の時間、メディアのみ、キャリア処理）を固定
します。ChatBox 統合テストは折りたたみ要約、展開、実行中の線形フォールバック、通常
回答の非折りたたみ、末尾ツールの fail-open を固定します。ロケールと i18n block の
テストが 4 言語のラベルをカバーします。
