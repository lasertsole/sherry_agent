# 计划：契约合成技能 + 评估观测增强 + 联网 oracle 变体

- 建档日期：2026-10-17
- 状态：**计划（未开工）**
- 来源：HARD 切片 1/2 复盘（`evals/swebench/RESULTS.md` @ `20261017_014328`）——sympy 一把的失败点是
  「契约对 agent 不可见，且可见证据反向误导」
- 关联代码：`evals/swebench/{suite.py,instances.py,judge*}`、`skills/builtin/core/`、
  `config/features/**`、`agent/tools/web_search*.py`

---

## 0. 背景（三个已核实的事实）

1. **失败点唯一且不可见**：sympy 的 5 条断言失败全部挂在同一个契约点——NumberSymbol 分母
   （π、γ）不得使用根号；而树里 base 版本的 `test_issue_6285` 旧断言**恰恰断言了根号**
   ——agent 可见的世界里没有正确信号，甚至有一条反向信号。上游修复只能靠推断，或去查
   upstream PR。
2. **oracle 当前不可达**：实例 checkout 是**浅克隆**（`instances.py:257`
   `git fetch --depth 1 origin <base_commit>`），没有未来历史；`web_search` 在评估工具面里
   （52 个工具）但 **provider 未配置**（`.network` 的 `TAVILY_API_KEY` 为空、`SEARXNG_URL` 为空
   → 工具是"未配置"桩）；两轮评估中 `web_search` 实际调用次数为 0。
   浏览器功能开着（`SHERRY_BROWSER_AGENT_ENABLED=1`），但其出网可达性未验证。
3. **同目录兄弟项目的沙箱联网调查**（用户要求，已逐个核实到实现层）：

   | 项目 | 沙箱技术 | 联网能力 |
   |---|---|---|
   | codex | OS 级（`linux-sandbox` / `sandboxing` / `windows-sandbox-rs` / macOS seatbelt） | **有，且最完整**：`SandboxWorkspaceWrite.network_access: bool`（默认 false）+ 独立 `network-proxy` crate（MITM、域名白名单/deny、connect policy、凭据 broker、SOCKS5） |
   | pi | `@anthropic-ai/sandbox-runtime`（sandbox-exec / bubblewrap） | **有**：`network.allowedDomains / deniedDomains` 白/黑名单 |
   | Octop | Docker 容器沙箱（scope: agent/user/fixed） | **有**：`allow_network` 透传 Docker，**默认 false**（"需要 pip/curl 时显式打开"） |
   | openclaw | Docker 沙箱 + 浏览器 | **有**：网络模式可配（bridge）；策略层禁 host 网络与容器命名空间 join |
   | deepagents (libs/code) | sandbox provider 抽象 + quickjs 运行沙箱 | quickjs 沙箱**明确无网**；libs/code 走 URL 保护/SSRF + 远程 provider（威胁模型 TB6 承认"沙箱网络访问"面） |
   | ZCode | 仅设计层（`NetworkPermissionPolicy`） | 设计约束：web_fetch 预授权域名**不得**扩成沙箱网络权限 |
   | hermes-agent / opencode / graph-memory / oh-my-openagent | 无自有沙箱网络实现 | `allow_network` 属模型 registry 或引用 codex 配置 |

   **共同原则：联网是显式开关或域白名单，默认关**——本计划的 C 部分照此设计。

---

## 1. 目标

- **A**：把「契约合成」写成可复用的解题习惯（内置 skill），并让它可被评估实验验证；
- **B**：评估报告从布尔升级为可解释（逐测试结果 + 失败断言摘要）；
- **C**：提供**默认关**的联网 oracle 评估变体（对照用，不改离线基线）。

交付顺序建议：**B（最便宜）→ A → C**。

---

## 2. A：契约合成技能（`skills/builtin/core/bugfix-contract/`）

新内置 skill，随默认技能索引可见（评估会话也能看到；「编程助手」预设把
`CODING_SKILLS`（`client/app/composables/persona-catalog.ts:165`）扩一名）。

**SKILL.md 内容**（清单式，短；frontmatter 按 loader 约定：`name` / `description` /
`when_to_use`（必填） / `when_not_to_use`（可选））：

1. **行为矩阵**：先从 issue 提取「输入 × 期望输出」矩阵，issue 给出的示例必须逐字进矩阵；
2. **可见契约收集**：把现有测试/文档里对**同一行为**的断言全部找出来（它们会被判据
   翻转或新增——这正是冲突信号）；
3. **冲突规则**：issue 与现有测试冲突时**以 issue 为准**，并把这个取舍写进最终答复
   （判据类任务通常翻转"断言了这个 bug 行为"的旧测试）；
4. **最小补丁纪律**：改动须同时满足（i）issue 的语义边界、（ii）未被翻转的既有测试；
   不为了过旧测试而放弃 issue；（iii）只改必须改的机制，不做表面症状补丁；
5. **收尾自检**：把矩阵逐行实跑一遍（仓库可跑的必须跑），列出"未覆盖的矩阵行"与理由。

**诚实的边界**：这是通用方法学，不是答案。在 sympy 这道题上它能提高概率（第二步会让人
注意到"旧测试断言的就是被抱怨的渲染"），但**不能保证**翻盘——Symbol vs NumberSymbol
的切分在任何可见证据里都不存在。技能里明确写这一点，避免它变成"照着做就能满分"的错觉。

**需同步**：skills 目录相关的测试/计数（`tests/skills/`、catalog 计数类断言）；
若 UI 预设挂接则同步 `persona-catalog.ts` 与其测试。SKILL.md 不要求四语言。

**验收实验**：同一 HARD 切片跑一次，评估会话经 `AGENT_CONFIG["skills"]` 显式绑定该技能
（对照：不绑定 = 现基线）。记录 sympy 是否翻盘、django 是否保持。

## 3. B：评估观测增强（`evals/swebench/`）

现状：`eval_report.json` 的实例记录只有布尔判定（`fail_to_pass_ok` / `pass_to_pass_ok`），
失败细节是一整段 `judge_detail` 文本（顶部还会被截断）——sympy 的"5 条同类断言失败"
这种近失信息不可见。

**改动**：

- 每个实例增加结构化字段 `judge_tests`：
  `{"fail_to_pass": [{"id": ..., "outcome": "pass|fail", "first_assert": "<bounded 摘要>"}],
    "pass_to_pass": [...]}` —— 数据来自 judge 输出的 `short test summary info` 与失败
  traceback 首页（每条截断到 ~200 字符）；
- `judge_detail` 保留原文（截断策略不变），结构化字段与它共存；
- 失败摘要只做"搬运"，不做解释——报告里不写"为什么"（那是复盘的事）。

**验收**：跑一次 SPIKE 片（3 个 sympy 实例，比 HARD 便宜）核对字段；把字段含义补进
`evals/swebench/RESULTS.md` 的说明。

## 4. C：联网 oracle 评估变体（默认关）

**设计原则**（照抄第 0 节表格里各家的共同做法）：**显式开关、默认关、通道最小化、报告可复核。**

- 新增开关：`--with-web`（或 env `SWEBENCH_ALLOW_WEB=1`），**默认关**；离线基线不变；
- 打开时只放行检索通道：为评估进程准备一份临时 `TAVILY_API_KEY` 或指向一个可用
  SearXNG 实例的 `.network`（hydration 机制现成：`config/models_settings.py` /
  `network_settings.py`），或把 `scripts/dev/mock_searxng.py` 换成指向真实实例的桥；
- **不动评测沙箱的"浅克隆"**：oracle 走检索（把 upstream PR 查出来），不走 git 历史；
- 报告增记 `environment.web`：本轮是否联网、通道类型（可复核）；
- 终端直连（curl 到 github）**不在本计划**——那是 codex 式域名白名单/代理的独立立项。

**前置探针（实现前先做）**：配置真实检索后端后，在评估沙箱里跑一次 `web_search` 与
一次浏览器打开公开页面，确认可达范围，再定最终形态（避免照抄一个跑不通的设计）。

**验收**：同一 HARD 切片 离线（现基线 `1/2`）与联网各跑一次，把分数差补进
`evals/swebench/RESULTS.md` 对照表；如联网从未改变行为，如实记录并重新评估是否保留该通道。

---

## 5. 明确不做的事

- **不把 test patch / gold patch 以任何形式喂给 agent**——判据不可见是基准底线；
- **不改判定逻辑**——judge 没有错，本计划只增强观测；
- **不做单例特判**——技能是通用方法学，不允许写"遇到 sympy 就……"；
- **不默认开网**——联网变体只作对照跑，基线保持离线；
- **不动浅克隆**——oracle 是检索，不是历史泄漏。
