# 计划：LSP 配置插件化（skill 级 + 项目级）与前端管理

- 日期：2026-11-11
- 状态：**待评审**
- 来源：借鉴同类工具的插件声明式 LSP 配置；Sherry 需更广第三方语言扩展；用户要求前端可修改/上传 lsp.json
- 风险等级：**中-高** —— LSP 配置声明 spawn 命令，是代码执行向量，需严格校验；前端改动跨后端 API + UI

---

## 0. 背景

### 0.1 同类工具的做法

同类编码工具 LSP **零内置语言配置**，所有 server 配置通过插件声明：插件带 `extensionToLanguage` 字段，manager 从所有插件聚合构建扩展名→server 映射。插件只**声明配置**（command + 扩展名），**不运行 server**——server 进程由 manager 用 `which`/`where` 找二进制后 spawn。用户仍需自己装 server 二进制。

### 0.2 Sherry 现状

内置配置表 `config/features/agent_side/lsp.py::lsp_supported_servers`（10 语言），数据驱动（新增语言 = 配置项 + 白名单），五层二进制发现（显式路径 → marker 门控 repo bin → runtime dir → PATH → Homebrew）。完整可用但：新增语言需改 Sherry 配置；无第三方/项目级扩展机制；无前端管理。

### 0.3 目标

三层配置源 + 前端管理：

| 层 | 来源 | 可编辑性 | 作用 |
|---|---|---|---|
| 基础层 | 内置 `lsp_supported_servers`（10 语言） | 代码（不可前端改） | 开箱即用 |
| 插件层 | skill 目录下 `lsp.json`（第三方/小众语言） | skill 管理（不可前端改） | 第三方语言扩展 |
| 项目层 | `<project>/.sherry/lsp.json` | **前端可改/上传** | 项目专属覆盖/新增 |

合并优先级：项目层 > 插件层 > 基础层（后者被前者覆盖）。

---

## 1. 配置三层架构

### 1.1 合并机制

LSP 初始化时（`lsp_supported_servers` 被读取处）改为读取**合并后**的配置：

```
effective_servers = merge(
    builtin_lsp_supported_servers,      # 基础层
    scan_skill_lsp_configs(),            # 插件层（扫描 skills/*/lsp.json）
    read_project_lsp_config(root),       # 项目层（<root>/.sherry/lsp.json）
)
```

合并规则：
- 新语言键 → 直接加入
- 已有语言键 → 项目层覆盖插件层覆盖基础层（整 spec 替换，不字段级 merge，避免半覆盖歧义）
- 合并后写缓存（进程级），配置文件 mtime 变化时失效重读（参照 safety_filter 的 mtime cache 模式）

### 1.2 lsp.json 格式（skill 层和项目层共用）

```json
{
  "servers": {
    "elixir": {
      "command": ["elixir-ls"],
      "extensions": [".ex", ".exs"],
      "language_id": "elixir",
      "install_hint": "Download from https://github.com/elixir-lsp/elixir-ls/releases"
    },
    "haskell": {
      "command": ["haskell-language-server", "--lsp"],
      "extensions": [".hs", ".lhs"],
      "language_id": "haskell"
    }
  },
  "enable": ["elixir", "haskell"]
}
```

- `servers`：语言→spec 映射，spec 形状 = 内置 `LspServerSpec`（command/extensions/language_id/install_hint/local_install）
- `enable`：可选，声明后默认加入 `lsp_enabled_languages` 白名单（仍受二进制发现约束——找不到 binary 仍 `not_installed`）

### 1.3 校验（合并时）

- `command` 必须是 list[str]，非空，第一项不含 shell 元字符（`;&|` 等）
- `extensions` 每项以 `.` 开头
- `language_id` 是非空字符串
- 校验失败：该条目丢弃 + 记录警告（fail-open，不阻断其他条目），前端可见错误

## 2. Skill 级 LSP 插件化

### 2.1 扫描

`skills/loader.py::scan_skills` 已扫描 skill 目录。增加一步：每个 skill 目录下若有 `lsp.json`，读取并聚合（命名空间：`skill:<skill_name>:<language>`，避免多 skill 同语言冲突时可追溯来源）。

### 2.2 安装与发现

- skill 的 `lsp.json` 只声明配置，**不携带 server 二进制**（同 Claude Code）
- 二进制仍走现有五层 `resolve_lsp_server` 发现
- skill 可在 SKILL.md 里写安装指引（`install_hint`），用户手动装

### 2.3 第三方语言扩展流程

1. 第三方写一个 skill，目录放 `lsp.json` 声明小众语言 server
2. skill 安装到 `skills/plugins/`（现有 skill 系统）
3. Sherry 启动扫描 → 合并进 effective_servers
4. 用户装 server 二进制到 PATH（或项目 `.venv/bin` 等 marker 门控目录）
5. 该语言文件可被 `lsp_diagnostics` 等工具识别

## 3. 项目级 LSP 配置覆盖

### 3.1 文件位置

`<project>/.sherry/lsp.json`（与 `.sherry/codeintel/index.db` 同目录，复用 `.sherry/` 这个唯一隐藏入口约定）。

### 3.2 创建时机

参照 `maybe_create_sherry_dir`：仅在用户通过前端首次编辑项目级 LSP 配置时创建 `.sherry/` shell + `lsp.json`（不自动创建空文件）。

### 3.3 作用范围

项目级配置只对该项目的会话生效（root 解析按 session project_dir，与现有 `session_workspace_root` 一致）。

## 4. 后端 API

新增 `server/trigger/http/lsp_config.py` + `server/service/lsp_config_service.py`：

| 端点 | 方法 | 作用 |
|---|---|---|
| `/lsp/config` | GET | 返回合并后 effective config，每语言带 `source`（builtin/skill:<name>/project）、`installed`（binary 是否发现）、`binary_path` |
| `/lsp/config/project` | GET | 返回当前会话项目级 `.sherry/lsp.json`（无则空） |
| `/lsp/config/project` | PUT | 写/更新项目级 lsp.json（校验后落盘，原子替换） |
| `/lsp/config/project` | POST(upload) | 上传 lsp.json 文件（解析+校验+落盘） |
| `/lsp/config/project/language` | DELETE | 删除项目级某语言条目 |
| `/lsp/config/test` | POST | 测试一条 server 配置：resolve binary + 试 initialize 握手（受 `lsp_server_start_timeout_s`），返回 ok/error |

所有端点需要 session_id（解析 project_dir），鉴权同现有会话级端点。

### 4.1 与现有 `lsp_status` 工具的关系

`lsp_status`（agent 工具）已报告 configured/installed/active server。后端 `/lsp/config` 是其 HTTP 镜像 + 增加来源/编辑能力。agent 工具不改。

## 5. 前端 UI

### 5.1 位置

System Config 面板新增 "LSP / 代码智能" tab（`TAB_ORDER` 驱动，追加末尾，与现有 tab 平级）。该 tab 内容按当前会话 project_dir 展示项目层。

### 5.2 布局

```
LSP 配置（代码智能）
├─ 全局配置（只读参考）
│   ├─ 基础层（10 语言，内置）
│   └─ 插件层（skill 声明，显示来源 skill 名）
│       每行：语言 | command | extensions | 来源标记 | 已安装●/未安装○
├─ 项目级配置（可编辑）  ← 当前会话 project_dir
│   ├─ 表格：语言 | command | extensions | language_id | 操作(编辑/删除/测试)
│   ├─ [添加语言] 按钮 → 表单
│   ├─ [上传 lsp.json] 按钮 → 文件选择 → 校验 → 落盘
│   └─ [测试全部] 按钮 → 逐条 resolve+initialize
└─ 测试结果区（最近一次 test 的输出）
```

### 5.3 交互

- 全局层只读（不改内置/skill 配置）；项目层可增删改
- 编辑表单：语言键（下拉常用 + 自定义输入）、command（可编辑 list）、extensions（逗号分隔）、language_id、install_hint
- 上传：选文件 → 前端预览解析 → 显示将新增/覆盖哪些语言 → 确认 → PUT
- 测试：调 `/lsp/config/test`，显示 binary 是否找到 + initialize 握手结果 + 错误信息
- 已安装状态用 `installed` 字段（binary 是否 resolve 到）实时标记

### 5.4 失败处理

- 校验失败：表单标红 + 错误提示，不落盘
- 测试失败：显示错误（binary 未找到 / initialize 超时 / server 报错），不阻塞保存
- 项目无 `.sherry/` 时提示"首次编辑将创建 `.sherry/lsp.json`"

## 6. 安全（评审重点）

### 6.1 命令执行向量

`lsp.json` 声明的 `command` 会被 `LSPClient` spawn。恶意配置可声明任意命令。防护：

1. **command[0] 不直接执行**：仍走 `resolve_lsp_server` 五层发现。lsp.json 的 command 用于声明"该语言用这个 server 命令名"，实际 binary 路径由发现层解析。即 lsp.json 声明 `"command": ["elixir-ls"]`，系统去 PATH/runtime/trusted-dir 找 `elixir-ls`，找到才 spawn，找不到 `not_installed`。
2. **command[0] 校验**：必须是已知 LSP server 名（字母数字+连字符）或绝对路径；绝对路径必须在 trusted dir（runtime dir / marker 门控 repo bin）内，不接受任意绝对路径。
3. **无 shell**：spawn 用 list 形式（`subprocess.Popen(list)`），不经 shell，无元字符注入。
4. **参数校验**：command[1:] 每项不含 shell 元字符。

### 6.2 项目级配置的信任边界

项目级 `.sherry/lsp.json` 由用户主动编辑/上传，视为受信任（用户对自己项目负责）。但仍受 6.1 的 command 校验约束（防止用户误填危险命令）。

### 6.3 Skill 级配置的信任边界

Skill 来自 `skills/plugins/`，视为与 skill 本身同信任级（skill 系统已建立的信任模型）。`lsp.json` 只声明配置不携带二进制，风险 ≤ skill 已有的 prompt/脚本能力。

## 8. Kill criteria

- 若合并机制导致现有 10 语言行为回归（内置配置被错误覆盖），回退合并层，保留内置表独立
- 若 command 校验过严导致合法 server 配置被拒（如带 `--stdio` 之外参数），放宽参数校验（仍禁 shell 元字符）
- 若前端 LSP tab 复杂度超预期，先只做"查看 effective config + 上传项目级 lsp.json"，编辑表单后置

## 9. 验收

### 9.1 配置层

- 内置 10 语言行为不变（回归测试）
- skill 放 `lsp.json` 声明新语言 → effective config 含该语言 → 文件可被 `lsp_diagnostics` 识别（装 binary 后）
- 项目级 `.sherry/lsp.json` 覆盖内置语言（如改 typescript 的 command）→ effective config 反映覆盖，`source=project`
- 合并 mtime cache：改 lsp.json 后重读生效

### 9.2 后端 API

- `GET /lsp/config` 返回合并 config + source + installed 状态
- `PUT /lsp/config/project` 校验+落盘+重读生效
- `POST /lsp/config/project`(upload) 解析+校验+落盘
- `POST /lsp/config/test` resolve + initialize 握手结果

### 9.3 前端

- 全局层只读展示（builtin + skill 来源标记 + 已安装状态）
- 项目层增删改语言条目 + 保存生效
- 上传 lsp.json → 预览 → 确认落盘
- 测试按钮显示 binary 发现 + 握手结果

### 9.4 安全

- command 含 shell 元字符 → 拒绝
- 任意绝对路径 command → 拒绝（仅 trusted dir 内）
- spawn 不经 shell（list 形式）
- 校验失败条目丢弃 + 前端可见错误

### 9.5 回归

- `uv run pytest tests/agent/tools/code_intel -q` 全过
- 现有 LSP 工具行为不变（10 语言路径）
- 现有 skill 扫描测试不破
