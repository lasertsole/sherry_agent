# 计划：Ollama 本地协议代理 — 把 Sherry Agent 暴露为 Ollama 端点

- 日期：2026-11-12
- 状态：**待评审**
- 来源：借鉴同类工具的 Ollama 协议代理；Ollama 协议（`localhost:11434`）是事实标准的本地 LLM 接入协议，大量工具原生支持
- 风险等级：**中** —— 新增 HTTP 端点 + Ollama 协议适配层；不动 agent 核心链路
- 依赖：无（Robyn 后端已跑 HTTP）

---

## 0. 为什么做

Ollama 协议是本地 LLM 接入的事实标准。Continue、ChatBox、各种 IDE 插件、Obsidian 插件等原生支持 Ollama（`localhost:11434`）。把 Sherry Agent 伪装成 Ollama 端点 = **零成本接入整个 Ollama 生态工具链**，比自建 WS 协议被采纳率高得多。

用户在 Continue/ChatBox 里配 `localhost:11434`，实际调的是 Sherry agent（带角色人格 + 记忆 + 工具），而不是裸 LLM。

---

## 1. Ollama 协议要点（需实现的端点）

Ollama 的 HTTP API（最常用的子集）：

| 端点 | 方法 | 作用 |
|---|---|---|
| `/api/chat` | POST | 对话（消息列表 + model + stream）→ 流式或非流式回复 |
| `/api/generate` | POST | 补全（prompt → 流式回复） |
| `/api/tags` | GET | 列出可用模型（`{models: [{name, ...}]}`） |
| `/api/version` | GET | 版本（`{version: "..."}`） |

**最关键的是 `/api/chat`**——它是 Continue/ChatBox 等工具调用的主端点。

### `/api/chat` 请求/响应格式

请求：
```json
{
  "model": "sherry",
  "messages": [{"role": "user", "content": "你好"}],
  "stream": true
}
```

流式响应（逐行 JSON）：
```json
{"model":"sherry","created_at":"...","message":{"role":"assistant","content":"你"},"done":false}
{"model":"sherry","created_at":"...","message":{"role":"assistant","content":"好"},"done":false}
{"model":"sherry","created_at":"...","message":{"role":"assistant","content":""},"done":true}
```

## 2. 设计

### 2.1 Ollama 适配层

新建 `server/service/ollama_proxy.py`：

```python
# 把 Ollama 协议请求转成 Sherry agent turn，把 agent 回复转成 Ollama 流式格式

async def handle_ollama_chat(request_body: dict):
    # 1. 解析 Ollama messages → Sherry HumanMessage
    # 2. 调 Sherry agent 跑一轮 turn（复用现有 turn 执行链路）
    # 3. agent 回复流式 chunk → 转 Ollama 逐行 JSON 格式
    # 4. stream=true 逐行 yield；stream=false 等完返回完整
    ...
```

### 2.2 模型映射

- `/api/tags` 返回 Sherry 配置的模型作为 "Ollama models"：
  ```json
  {"models": [{"name": "sherry:latest", "details": {...}}]}
  ```
- 或列出 Sherry 实际配的 main model（如 `deepseek-chat`、`claude-3-5-sonnet`）作为可选模型
- `/api/chat` 的 `model` 参数：忽略或映射到 Sherry 的 session model config（Ollama 协议的 model 字段对 Sherry 无意义，Sherry 用自己的 model config）

### 2.3 会话/记忆映射

**关键设计决策**：Ollama 协议是无状态请求-响应（每次带完整 messages 列表），但 Sherry agent 是有状态（记忆 + 人格 + session）。

两种映射：
- **A. 无状态模式**（简单）：每次 `/api/chat` 请求开一个临时 Sherry turn，用请求里的 messages 作为上下文，不绑定持久 session。人格/记忆用默认或配置的。**Continue/ChatBox 自己管对话历史**（它们每次发完整 messages），Sherry 只做"带人格的 LLM 回复"。
- **B. 有状态模式**（进阶）：把 Ollama 的某个 "model" 名映射到一个 Sherry session（如 `sherry:session-123`），请求路由到该 session，Sherry 管记忆 + 历史。**Sherry 管历史**，Ollama 客户端只发最新消息。

**建议 MVP 走 A**（无状态）——Continue/ChatBox 自己管历史，Sherry 做"带人格 + 记忆注入的 LLM 端点"。B 作为进阶（让 Sherry 管记忆跨工具）。

### 2.4 端点注册

在 Robyn 后端注册 Ollama 路由（同端口或独立端口）：
- 同端口：`/api/chat`、`/api/tags`、`/api/version` 加到现有 Robyn 路由
- 独立端口（可选）：默认 `localhost:11434`（Ollama 标准端口），让工具无感接入；配置项 `OLLAMA_PROXY_PORT`

### 2.5 开关 + 配置

```python
OLLAMA_PROXY = {
    "enabled": False,          # 默认关
    "port": 11434,             # Ollama 标准端口，或同主端口
    "default_persona": "",     # 默认人格（空=无人格纯 LLM）
    "inject_memory": True,     # 是否注入 MesMemory（无状态模式下注入全局记忆）
    "model_name": "sherry",    # /api/tags 返回的模型名
}
```

设置面板加 Ollama 代理开关 + 端口 + 人格选择。

## 4. 测试

- `/api/version` 返回 `{"version": "0.x"}`
- `/api/tags` 返回模型列表
- `/api/chat` stream=true → 逐行 JSON，内容是 Sherry agent 回复
- `/api/chat` stream=false → 完整回复
- 用 Continue 或 ChatBox 配 `localhost:11434` → 能对话
- 人格注入：配 persona 后回复带人格风格
- 记忆注入：inject_memory=true 时回复含 MesMemory 上下文

## 5. 风险与缓解

| 风险 | 缓解 |
|---|---|
| Ollama 协议细节不完全兼容（某工具期望特定字段） | 先实现最常用子集（chat/tags/version），按 Continue/ChatBox 实测补 |
| 无状态模式下记忆不连续（每次请求独立） | MVP 接受（工具自己管历史）；进阶走 B（session 映射） |
| 端口冲突（11434 被 Ollama 占） | 端口可配；或同主端口（/api/* 路径） |
| Sherry agent turn 比 Ollama 慢（有工具/记忆开销） | 无状态模式不跑工具（纯 LLM + 人格 + 记忆注入），接近裸 LLM 速度 |

### Kill criteria

- 若 Ollama 协议兼容性导致主流工具（Continue/ChatBox）不能用，降级为"只支持 `/api/chat` 非流式"（最小兼容）
- 若无状态模式下人格/记忆注入效果差（工具的 messages 覆盖了 Sherry 的 system prompt），改为 B（session 映射，Sherry 管上下文）

---

## 6. 备注

- Ollama 生态工具多（Continue/ChatBox/IDE 插件/Obsidian 等），零成本接入价值高
- MVP（无状态 + chat/tags/version）实现量小：一个适配文件 + 路由注册
- 进阶（B：session 映射让 Sherry 管记忆）后置
- 与 H5 局域网计划正交（H5 是 Sherry 自己的移动端 UI；Ollama 代理是让别的工具接入 Sherry）
