## 0. 问题

### 0.1 ZCode 的实际行为（逆向工程，已验证）

ZCode 的后端逻辑位于 `D:\IDE\ZCode\resources\glm\zcode.cjs`（GLM 打包文件）。当后台 Bash 任务被用户停止时（`TaskStop` / UI kill / cancel / 超时 / 5GB 输出上限），ZCode 会向 agent 注入一条合成的 **user** 消息，其内容为结构化 XML，**逐字如下**：

```
<task-notification>
<task-id>{taskId}</task-id>
<tool-use-id>{toolUseId}</tool-use-id>
<output-file>{outputFile}</output-file>
<status>killed</status>
<summary>Background command "{description ?? command ?? "Bash background command"}" was stopped</summary>
</task-notification>
```

关键事实（均来自 `zcode.cjs` 逆向工程）：

| 事实 | 来源 |
|---|---|
| **无** "是否需要重启？"指令 / 提示 / 问题 | 对完整打包文件 grep `restart`/`would you like`/`do you want`/`shall I`，在后台任务通知路径中零命中 |
| **无** 重启工具动作 | ZCode 仅有 `TaskStop`，无 `TaskRestart`；重启即 agent 重新运行原始命令 |
| **无** `[SYSTEM NOTIFICATION - NOT USER INPUT]` 前导语 | 该前导语位于 `ene`（偏移 7784201）的通用 fallback；Bash 任务经 `taskType:"local_bash"` → `YUo` 直接路由，跳过前导语 |
| 状态归一化 | `QTr`（偏移 7796304）：`cancelled`/`timed_out`/`killed`/`stopped` 全部 → `<status>killed</status>`；`completed` → `completed`；其余 → `failed` |
| 摘要措辞 | `m$o`（偏移 7796618）：killed → `` `Background command "${desc ?? cmd ?? "Bash background command"}" was stopped` ``；completed → `... completed (exit code N)`；failed → `... failed with exit code N` |
| 注入 | `Sgt`（偏移 ~10804570）：`messageHistory.addUser(text, {source:"legacy_synthetic"})`，`visibility:"model-only"`，`source:"background_task"` |
| 多通知合并 | `e.map(i=>i.text).join("\n\n")` |

"agent 主动询问是否重启"是 **LLM 看到 `<status>killed</status>` 后的涌现行为** —— ZCode 与 Sherry 完全一致。唯一的差异是通知格式。

### 0.2 Sherry 当前状态

`agent/tools/terminal/bg_registry.py::_trigger_auto_turn`（:257-284）当前注入的是自由文本：

```python
if task.status == "killed":
    headline = "Background task stopped by user"
else:
    headline = f"Background task {'exited' if task.exit_code == 0 else 'FAILED'}"
content = f"[{headline}] {task.task_id} (command: {task.command}) exited with code {task.exit_code}. Read its output with terminal_bg(action='output', task_id='{task.task_id}')."
```

与 ZCode 的差异：
- 自由文本而非结构化 XML
- killed 使用 `"stopped by user"`，completed/failed 使用 `"exited"/"FAILED"` —— ZCode 使用 `killed`/`completed`/`failed`
- 额外的 "Read its output with terminal_bg(...)" 指令（ZCode 无）
- 摘要在 completed/failed 时省略 exit code（ZCode 包含；killed 时省略）

### 0.3 结论

对齐 = **将注入消息逐字替换为 ZCode 的 `<task-notification>` XML 格式**，删除自撰指令，不新增重启动作。agent 是否询问重启留给 LLM 涌现行为（与 ZCode 一致）。

## 2. 设计

### 2.1 注入消息逐字对齐 ZCode

`_trigger_auto_turn` 中的内容构造变为：

```python
def _build_task_notification(task: BackgroundTask) -> str:
    status = _normalize_status(task.status)   # killed / completed / failed
    desc = task.command or "Bash background command"
    if status == "killed":
        summary = f'Background command "{desc}" was stopped'
    elif status == "completed":
        code = f" (exit code {task.exit_code})" if task.exit_code is not None else ""
        summary = f'Background command "{desc}" completed{code}'
    else:
        code = f" with exit code {task.exit_code}" if task.exit_code is not None else ""
        summary = f'Background command "{desc}" failed{code}'
    lines = [
        "<task-notification>",
        f"<task-id>{task.task_id}</task-id>",
    ]
    if task.output_path:
        lines.append(f"<output-file>{task.output_path}</output-file>")
    lines.append(f"<status>{status}</status>")
    lines.append(f"<summary>{summary}</summary>")
    lines.append("</task-notification>")
    return "\n".join(lines)
```

状态归一化 `_normalize_status`：

```python
def _normalize_status(status: str) -> str:
    # Aligns with ZCode QTr: cancelled/timed_out/killed/stopped → killed
    if status in ("killed", "cancelled", "timed_out", "stopped"):
        return "killed"
    if status == "completed":
        return "completed"
    return "failed"
```

`_trigger_auto_turn` 中的调用点：

```python
content = _build_task_notification(task)
await trigger(
    session_key,
    HumanMessage(
        content=content,
        metadata={"origin": "background_task", "internal": True},
    ),
)
```

`metadata` 保持 `internal: True` —— 与 ZCode 的 `visibility:"model-only"` 语义等价（载体不向用户展示，不计入用户输入）。

### 2.2 已删除内容（与本计划上一修订版的差异）

| 上一修订版（创新） | 本修订版（对齐 ZCode） | 原因 |
|---|---|---|
| 自撰指令 "Use the question tool to ask whether to restart..." | 已删除 | ZCode 零指令；纯状态通知 |
| `terminal_bg(action="restart")` 新动作 | 已删除 | ZCode 无重启动作；重启即 agent 重新运行原始命令 |
| `prompt_restart_on_kill` 配置开关 | 已删除 | ZCode 无此配置 |
| 在 killed 分支将 `internal` 改为 `False` 以绕过 headless guard | 已删除 | ZCode 并不绕过 —— `visibility:"model-only"` 等价于 Sherry 的 `internal:True`；headless guard 是 Sherry 现有架构，本计划不动 |
| reminder_catalog 被动感知 source | 已删除 | ZCode 无此机制 |

### 2.3 Headless guard（Sherry 现有架构，不在本计划范围内）

Sherry 的 `question` 工具在 headless turn 中自动拒绝（`internal:True`）。ZCode 是否有等价 guard 尚未确认（ZCode 的合成 user 消息标记为 `visibility:"model-only"`，但不一定会触发 headless 判定）。这是 Sherry 与 ZCode 的架构差异。**本计划仅对齐通知格式**，不触碰 headless 逻辑 —— 若对齐后 agent 在纯 auto-turn 中无法提问，将作为独立项评估。
