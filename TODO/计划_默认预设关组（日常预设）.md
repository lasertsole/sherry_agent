### 3.4 简化实现（可选，且与 §2.2.3 冲突时以 §2.2.3 为准）

如果第一版不想改三处后端，可以只把 `TaskIntentMiddleware` + `PlanContinuationEnforcer` 写进日常预设的 `middlewares_disabled`。注意：
- daily 的默认实现**不写** `middlewares_disabled`（§2.2.3）；走简化方案才显式写入这两个名字，不要因为改 `builtinAgentConfig` 的通用分支而把所有中间件都关掉。
- 简化方案不解决 3.2 的旧会话看板/提醒，reminder 的护栏仍要做（至少 todo/taskflow/knowledge）。
- 用户以后手动打开任务组时，这两个中间件不会自动回来。
推荐至少做 3.1/3.2/3.3 的可用性判断。

## 4. 迁移、回滚与影响面

- **旧会话不受影响**：它们保存自己的 `AGENT_CONFIG`；绑定 `sherry` 的会话仍是全量。
- **新会话默认日常**：需要多步编排时选"编程助手"（全量 minus memory）或"全量"。
- **回滚**：把 `DEFAULT_PRESET_ID` 改回 `'sherry'` 即可，无数据迁移。
- **侧边辅助会话**：复制父会话配置；父会话日常则辅助会话也日常。
- **cron / 后端直接创建的会话**：不经过新会话对话框，第一版仍按全量处理。
- **旧会话切换到日常**：已有未完成 todo/flow 会变成只读状态；不自动清理，切回全量恢复。
- **PersonaPanel 初始 tab**：`PersonaPanel.vue:1209` 的 `activeBuiltin` 也用 `DEFAULT_PRESET_ID`，改默认会让预设面板初始打开 daily；确认这是预期并补测试。
- **护栏的 mem 前提**：`enabled_tool_names` 只读 mem 寄存器，失败/未配置返回 `None`（全量）；确认回合开始时 `AGENT_CONFIG` 已进 mem（ToolSelectionMiddleware 依赖同一路径），否则冷启动首轮护栏会 fail-open。
- **文档范围**：只有 `AGENTS.md`（`:1467` nudge、`:1500` 四预设/默认）需要改；根/client README 无预设列表。

## 7. 风险与取舍

- **默认失去规划与委派**：多步骤、跨文件工作会退化。缓解：明确提示 + 保留"编程助手/全量"入口。
- **名称**：推荐"日常"，不叫"轻量"；"轻量"听起来像功能残缺。
- **旧会话切换**：已有 todo/flow 会变成只读状态；不自动清理，切回全量恢复。
- **显式工具列表是快照**：以后新增的工具，新会话按当前 catalog 生成会包含；旧会话需重新应用预设。
- **收益量级**：4–5k tok 在 200K 上下文里约 3–4%，真正收益是更小的工具面、更少的错误选择。
- **不要顺手关 browser**：只省 449 tok，伤功能，不划算。

## 8. 备选方案

| 方案 | 改动 | 省 token | 问题 |
|---|---|---:|---|
| A. 直接改"全量" | 最小 | 4,033 | "全量"名不副实；旧会话重应用会突然丢能力 |
| B. 新增"日常"默认（推荐） | 中 | 4,033 + 400 | 多一个预设、四语文案和 UI 提示 |
| C. 只关 subagents | 小 | 1,224 | TaskIntent / AGENTS 仍要求委派，需改一部分 steering |
| D. 默认不动，加工具栏精简开关 | 小 | 0（默认） | 不解决默认会话成本 |
| E. 拆 tasks 为"轻量计划"+"TaskFlow" | 大 | ~1.7k | 需要新分组 + 重写编排 doctrine，适合以后单独评估 |

## 9. 不做什么

- 不引入通用 `tool(name, args)` 派发器。
- 不自动清空旧会话的 todo / TaskFlow 状态。
- 不改变 cron / 后端直接创建会话的默认工具面（本方案只覆盖新会话对话框路径）。
- 不默认关闭 browser、plan_mode、memory、web 等小收益组。
- 不在本轮实现动态技能暴露 / 按需加载工具。
