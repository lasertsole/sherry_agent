## 0. 背景（已核实）

### 0.1 sherry 现状

sherry 是 append-only 模型，明确无分支（用 turn 折叠代替）。`handleSend`（`use-chat-stream.ts:861`）每次创建新 `msg_id` + 新 `turn_num`，乐观追加到 `chatMessages`。没有 fork / checkpoint / 分支概念。

### 0.2 ZCode 做法

ZCode 的 `forkAssistant` 基于 checkpoint 追踪，feature id `conversation.history.branch`。fork = 从某 turn 创建分支 checkpoint，在新分支继续对话，两分支独立。

---

## 1. ⚠️ 硬约束

| 约束 | 含义 | 验收方式 |
|---|---|---|
| **F1**：不物理复制 messages | 用 checkpoint 引用共享父 turn 内容 | fork 不产生全量 message 复制 |
| **F2**：分支独立写入 | fork 后子分支的 messages 独立，不影响父分支 | 子分支写入不改变父分支 |
| **F3**：依赖 checkpoint 基建 | 需 `计划_前端_消息编辑与重生成.md` 的后端 checkpoint 先落地 | checkpoint 未就绪时 fork 不可用 |
| **F4**：fail-open | fork 失败时提示错误，不影响当前会话 | 后端拒绝 fork 时前端不崩 |

## 2. 任务一：后端 fork 入口（依赖消息编辑的 checkpoint）

### 2.1 目标

提供 `POST /sessions/:id/fork` 接口，从指定 turn 创建分支会话。

### 2.2 改动清单

- [ ] **2.2.1** 后端 `server/service/turn_runner.py` 或新 service：`fork_session(session_id, turn_id)` → 创建新 session → 用 checkpoint 引用复制父 turn 之前的 messages（不物理复制，用引用/快照指针）→ 返回新 `session_id`
- [ ] **2.2.2** 后端：新 session 继承父会话的 preset/character/project_dir（复用 `sessions_spawn` 的继承逻辑参考）
- [ ] **2.2.3** WS frame `session_forked`：通知前端 fork 完成，payload `{parent_session_id, child_session_id, turn_id}`

### 2.3 风险

- **F1 不物理复制**：message store 用 checkpoint 引用（copy-on-write：fork 时共享，子分支写入时才复制差异）
- checkpoint 粒度：需确认 `agent/state_port.py` 能按 turn 截断 + checkpoint

**验收**：F1 + F2。新建 `tests/server/test_session_fork.py`。

### 3.1 目标

在 AI 消息行提供 fork 按钮，点击后创建分支并切换到新会话。

### 3.2 改动清单

- [ ] **3.2.1** `ChatBox.vue:148-197` AI 消息行增 fork 按钮：

|---|---|
