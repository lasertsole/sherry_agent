# 计划：输入框触发器——$ 技能 + / 命令（参考 ZCode）

- 建档日期：2026-11-02
- 状态：**待评审**
- 来源：ZCode 的 `$`/`/`/`@` 触发器（`promptInputTriggers.ts` + `skillsMentionProvider.ts` + `slashCommandHelpers.ts`）
- 安全等级：**低**——纯前端 UI 交互，不涉及后端执行

## 0. ZCode 的机制（已核实）

ZCode 在 composer 输入框中用四个触发字符：

| 触发字符 | 用途 | 来源文件 |
|---|---|---|
| `@` | 上下文引用（文件 / 会话 / 插件） | `mentionMarkdown.ts::buildFileMentionMarkdown` |
| `/` | **slash 命令**（catalog 命令 + app 命令） | `slashCommandHelpers.ts` + `SlashCommandPlugin` |
| `$` | **技能选择** | `skillsMentionProvider.ts` |
| `#` | 会话引用 | `mentionMarkdown.ts::buildSessionMentionMarkdown` |

### `$` 技能触发链路

1. **触发检测**（`promptInputTriggers.ts:38`）：正则 `/(^|\s)([/@$#¥￥])([^\s/@$#¥￥]*)$/` 检测 `$`（含 `¥`/`￥` 归一化）
2. **技能加载**（`skillsMentionProvider.ts`）：`useSkills()` → 按名称折叠（workspace > plugin > user） → 只展示 enabled → `scoreFuzzyMatch` 三级匹配
3. **插入**（`LexicalChatInput.tsx:1293`）：`setSkillMention` 插入 `PromptMentionNode` 原子节点
4. **序列化**（`mentionMarkdown.ts:70`）：`buildSkillMentionMarkdown` → `$label` 或 `[$label](path)`

### `/` 命令触发链路

ZCode 的 `/` 有两种命令（`slashCommandHelpers.ts`）：

| 类型 | 来源 | 选中后行为 |
|---|---|---|
| **catalog 命令** | CLI workspace catalog（`.claude/commands/*.md`） | 插入 mention → 发送为文本 → agent 处理 |
| **app 命令** | `AppSlashCommand`（UI 层本地） | 立即执行 UI 行为（如 `/side` 切换侧栏）→ 不发送 |

1. **触发检测**：同 `$`，正则检测 `/` 在行首或空格后
2. **命令加载**（`slashCommandHelpers.ts:46`）：`buildAppSlashCommandSuggestions` 合并 catalog 命令 + app 命令 → fuzzy 匹配
3. **catalog 命令插入**（`LexicalChatInput.tsx:1295`）：`setSlashCommandMention` → 插入 mention → 序列化为 `/commandName`
4. **app 命令执行**（`AppSlashCommand.execute`）：选中即执行，不插入、不发送

## 1. 适配 sherry 的设计

### 1.1 sherry 的差异

| | ZCode | sherry |
|---|---|---|
| 输入框 | Lexical 编辑器 + `PromptMentionNode` | contenteditable div + chip span |
| 已有触发 | `@`/`/`/`$`/`#` 四个 | `@` 文件 mention（`use-file-mention.ts`） |
| 技能加载 | `useSkills()` 从 CLI catalog | `skills/loader.py::scan_skills()` |
| 命令 | CLI catalog + app 命令 | command palette（Ctrl+K）内置命令 + `计划_用户自定义功能.md` Step 1 自定义命令 |
| chip 序列化 | Lexical `getMarkdown()` | `extractTextForSend()` |

### 1.2 方案

在 `inputBox.vue` 的 contenteditable 输入框中检测 `$` 和 `/` 触发字符，弹出对应的选择面板，选中后插入 chip（catalog 类型）或立即执行（app 类型）。

**不引入 Lexical**——复用 sherry 现有的 contenteditable + chip span 架构。

### 1.3 三个触发字符的完整行为

| 触发字符 | 面板内容 | 选中后 | 序列化 |
|---|---|---|---|
| `@` | 文件列表（已有） | 插入 file-mention chip | `@path` |
| `$` | 技能列表（enabled） | 插入 skill-mention chip | `$skillName` |
| `/` | 自定义命令 + 内置命令 | 自定义 → 插入 command chip；内置 → 立即执行 | `/commandName`（自定义） |

## 2. 实施步骤

### Step 1：统一触发检测（`use-input-trigger.ts`）

新建 `client/app/composables/use-input-trigger.ts`——一个 composable 管理所有触发字符的检测和面板状态：

```typescript
const TRIGGER_RE = /(^|\s)([/@$¥￥])([^\s/@$]*)$/

export type TriggerKind = "slash" | "skill" | "file"

export interface TriggerState {
  active: boolean
  kind: TriggerKind
  query: string
  anchorRect: DOMRect | null
}

export function detectTrigger(text: string, caretOffset: number): TriggerState | null {
  const before = text.slice(0, caretOffset)
  const match = before.match(TRIGGER_RE)
  if (!match) return null

  const raw = match[2]
  const query = match[3]
  // ¥/￥ → $（中文输入法归一化，同 ZCode normalizePromptInputTriggerAlias）
  const char = (raw === "¥" || raw === "￥") ? "$" : raw

  const kind: TriggerKind | null =
    char === "/" ? "slash" :
    char === "$" ? "skill" :
    char === "@" ? "file" : null

  return kind ? { active: true, kind, query, anchorRect: null } : null
}
```

- `/` `$` `@` 必须在行首或空格后（防止代码中的符号误触发）
- `¥`/`￥` 归一化为 `$`（同 ZCode）
- 代码块内的符号不触发（检测光标是否在 `<pre>`/`<code>` 内）
- 已有 chip 内的符号不触发（chip 是 `contenteditable="false"`）

集成到 `inputBox.vue` 的 `onInput`/`onKeydown`：每次输入后 `detectTrigger`，命中则打开对应面板。

### Step 2：技能面板（`$` 触发）

**数据加载**（`use-skills-list.ts`）：

```typescript
// 模块级缓存（同 use-mcp-servers.ts 模式）
const _cache = shallowRef<SkillItem[] | null>(null)

export function useSkillsList() {
  const skills = computed(() => _cache.value ?? [])
  const loading = ref(false)

  async function ensureLoaded() {
    if (_cache.value) return
    loading.value = true
    try {
      const res = await fetch('/api/skills')  // GET /skills 暴露 scan_skills()
      _cache.value = (await res.json()).skills.filter(s => s.enabled)
    } finally { loading.value = false }
  }
  return { skills, loading, ensureLoaded }
}
```

**后端**：如果 `GET /skills` 不存在，新建 `server/trigger/http/skills.py` 暴露 `scan_skills()` 的只读快照（name/description/enabled/scope/path），参考 `GET /mcp/servers` 模式。

**面板组件**（`SkillPickerPanel.vue`）——候选列表浮层，弹出在输入框**上方**：

- **定位**：绝对定位浮层，底部贴齐输入框顶部边缘（向上展开），宽度同输入框（min 320px）。参考 ZCode `MentionPanel` 的向上弹出模式。
- **`$` 字符触发时**：面板弹出后，输入框中 `$` 后的文本作为初始 query 自动筛选候选列表；用户继续输入 → 实时筛选（不关闭面板）。
- **`+` 按钮触发时**：面板弹出后无初始 query，展示全部候选；用户在输入框继续输入 → 开始筛选（等价于面板弹出后自动进入 query 模式）。
- **候选列表项**：`$skillName` + description（截断一行）+ scope badge（builtin/auto/plugin）
- **fuzzy 匹配**：prefix → substring → keyword（参考 ZCode `scoreFuzzyMatch`）
- **键盘**：↑/↓ 选择（高亮当前项），Enter 确认，Esc 关闭
- **空列表**：显示 "No skills found" + footer 提示

### Step 3：命令面板（`/` 触发）

**数据来源**——两种命令合并：

| 类型 | 来源 | 选中后 |
|---|---|---|
| **自定义命令** | `GET /commands`（`计划_用户自定义功能.md` Step 1 的 `.md` 文件） | 插入 command chip → 发送时替换 `$ARGUMENTS` → 作为用户消息发送 |
| **内置命令** | `use-command-registry.ts` 已注册的命令 | 立即执行（同 Ctrl+K command palette） |

**数据加载**（`use-command-trigger.ts`）：

```typescript
export function useCommandTrigger() {
  const customCommands = ref<CustomCommand[]>([])
  const builtinCommands = computed(() => commandRegistry.all())

  async function ensureLoaded() {
    // 自定义命令从后端加载（如果计划_用户自定义功能 Step 1 已实施）
    const res = await fetch('/api/commands')
    customCommands.value = await res.json()
  }

  const all = computed(() => [
    ...customCommands.value.map(c => ({
      kind: 'custom' as const,
      name: c.name,
      description: c.description,
      argumentHint: c.argument_hint,
    })),
    ...builtinCommands.value.map(c => ({
      kind: 'builtin' as const,
      name: c.id,
      description: c.description,
      argumentHint: undefined,
    })),
  ])
  return { all, ensureLoaded }
}
```

**面板组件**（`CommandPickerPanel.vue`）——候选列表浮层，同 `SkillPickerPanel.vue` 的向上弹出模式：
- **定位 / 筛选 / 键盘**：与技能面板完全一致（底部贴齐输入框顶部，实时筛选，↑/↓/Enter/Esc）
- **候选列表项**：`/commandName` + description + 类型标记（自定义 / 内置）
- 自定义命令如果有 `argument-hint`，选中后先弹出输入框（参考 Claude Code `$ARGUMENTS`）

**自定义命令选中 → chip 插入**：

```html
<span contenteditable="false" class="command-mention-chip" data-command="review" data-args="security">
  /review
</span>
```

如果有 `argument-hint`，选中后先弹出小输入框 → 用户输入参数 → 参数存入 `data-args`。

`extractTextForSend` 扩展：
```typescript
if (chip.classList.contains('command-mention-chip')) {
  const name = chip.getAttribute('data-command')
  const args = chip.getAttribute('data-args')
  // 从后端获取命令 body，替换 $ARGUMENTS，作为用户消息发送
  // 或者直接序列化为 /commandName args，后端解析
  text += args ? `/${name} ${args}` : `/${name}`

```

**内置命令选中 → 立即执行**：

不插入 chip，直接调用 `commandRegistry.execute(commandId)`（同 Ctrl+K 的行为）。面板关闭，输入框的 `/` 字符被清除。

### Step 4：`+` 按钮入口（`inputBox.vue` sendActions 扩展）

**目的**：触发字符（`$`/`/`/`@`）是隐藏入口——用户必须知道它们存在。`+` 按钮是**可发现入口**——点击即看到所有可插入的类型。

**位置**：`inputBox.vue` 的 `<div class="sendActions">` 最左侧，在 voice 按钮之前。

```vue

    text
    rounded
    severity="secondary"
    :aria-label="t('chatInput.insertTrigger')"
    :title="t('chatInput.insertTrigger')"
    @click="toggleInsertMenu" />
  <!-- Popover 菜单 -->

    <div class="insert-menu">
      <button class="insert-item" @click="openSkillPicker">
        <span class="pi pi-bolt"></span>

        <code>$</code>
      </button>
      <button class="insert-item" @click="openCommandPicker">
        <span class="pi pi-bolt"></span>
        <span>{{ t('chatInput.commandShortcut') }}</span>
        <code>/</code>
      </button>
      <button class="insert-item" @click="openFilePicker">
```

**行为**：

| 菜单项 | 点击后 | 等同于 |
|---|---|---|
| `$ 技能` | 打开 `SkillPickerPanel`（不插入 `$` 字符，直接弹面板） | 输入 `$` |
| `/ 命令` | 打开 `CommandPickerPanel` | 输入 `/` |
| `@ 文件` | 打开文件树选择器（复用 `ProjectFileTree` 的"Add to chat"路径） | 输入 `@` 或拖文件 |

**与触发字符的关系**：`+` 按钮和触发字符是同一个面板的两个入口。`+` 按钮跳过"输入字符"步骤直接打开面板——选中后的行为完全一致（插入 chip / 立即执行）。

**实现**：

```typescript
const insertMenu = ref();

function toggleInsertMenu(event: Event) {
  insertMenu.value?.toggle(event);
}

function openSkillPicker() {
  insertMenu.value?.hide();
  // 直接设置 trigger state，跳过字符检测
  triggerState.value = { active: true, kind: 'skill', query: '', anchorRect: inputDom.value?.getBoundingClientRect() ?? null };
}

function openCommandPicker() {
  insertMenu.value?.hide();
  triggerState.value = { active: true, kind: 'slash', query: '', anchorRect: inputDom.value?.getBoundingClientRect() ?? null };
}

function openFilePicker() {
  insertMenu.value?.hide();
  // 复用现有 file-mention 路径：触发文件树打开
  emit('open-file-tree');
}
```

**样式**：`+` 按钮同 voice 按钮的 `text rounded secondary` 样式，保持 sendActions 视觉一致。Popover 菜单紧凑（三行），每行：图标 + 标签 + 触发字符 code 标签。

### Step 5：面板组件统一（`InputTriggerPanel.vue`）

新建 `client/app/components/chat/InputTriggerPanel.vue`——统一管理两种触发面板的容器：


- 点击面板外部关闭

## 3. agent 侧的调用

### `$` 技能

系统提示词的 skills 索引块（`<available_skills>`）加说明：

```
When the user's message contains $skillName, invoke that skill.
$ is the skill invocation prefix — treat $review as a request to use the "review" skill.
```

agent 的 LLM 看到 `$review` + skills 索引中有 `review` → 自然调用。不需要新工具。

### `/` 命令

自定义命令的 body（替换 `$ARGUMENTS` 后）直接作为用户消息文本发送——agent 看到的是命令 body 的提示词，不是 `/commandName`。例如 `/review security` 发送的是：

```
Review the current git diff. Focus on: security

Check for:
- Security issues
- Performance regressions
- Breaking changes
```

agent 正常处理这段提示词，不需要知道它来自命令。

## 4. 边界

### 4.1 误触发防护

- `/` `$` `@` 必须在行首或空格后（`/(^|\s)[/@$]/`）
- 代码块内的符号不触发（检测光标在 `<pre>`/`<code>` 内）
- `¥`/`￥` 归一化为 `$`
- 已有 chip 内不触发（`contenteditable="false"` 不产生输入事件）
- 面板打开时输入框的 `Backspace` 删除触发字符 → 面板关闭

### 4.2 与 Ctrl+K command palette 和 `+` 按钮的关系

命令有三个入口，共用同一个命令列表：

| 入口 | 触发方式 | 上下文 | 自定义命令 | 内置命令 |
|---|---|---|---|---|
| Ctrl+K | 全局快捷键 | 任何时候 | ❌（需要输入框） | ✅ 立即执行 |
| `/` | 输入框内输入 | 正在输入消息 | ✅ 插入 chip | ✅ 立即执行 |
| `+` 按钮 | 点击 sendActions 的 `+` | 正在输入消息 | ✅ 插入 chip | ✅ 立即执行 |

`/` 和 `+` 是同一面板的两个入口——`+` 跳过"输入字符"步骤直接打开面板，选中后行为完全一致。Ctrl+K 是独立的全局入口，只处理内置命令。

### 4.3 面板状态管理

一个 composable（`use-input-trigger.ts`）管理全局触发状态：
- 同时只有一个面板打开（`/` 和 `$` 互斥）
- 面板打开时，输入框的进一步输入只更新 query（不插入字符到 contenteditable）
- `Esc` / 选中 / 点击外部 → 关闭面板 → 恢复正常输入

### 4.4 技能/命令列表缓存

- 技能列表：首次 `$` 触发时加载，模块级缓存（同 `use-mcp-servers.ts`）
- 自定义命令：首次 `/` 触发时加载，模块级缓存
- 内置命令：已在 `use-command-registry.ts` 注册，无需加载

### 4.5 不做的事

- **不引入 Lexical 编辑器**——复用 contenteditable + chip
- **不做 `#` 会话引用**——sherry 的会话引用走侧栏点击
- **不做命令 body 的 shell 展开**（Claude Code `!`command``）——安全风险，纯文本模板
