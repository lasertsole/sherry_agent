### sherry 已有的基础设施（不需要重建）

- **MCP loader**：`agent/tools/mcp_plugin.py` — 合并 bundled + user drop folder，每 server 独立 client
- **Skills loader**：`skills/loader.py` — 扫描 `SKILLS_DIR` + `USER_SKILLS_DIR`，frontmatter 解析，inactive 默认
- **Hooks**：`config/sherry_settings.py::load_sherry_hooks` — `sherry.jsonc` `hooks` 段，Step 1 只读
- **AGENTS.md**：`workspace/prompt_builder.py::_build_project_instructions_block` — 读项目 AGENTS.md
- **子代理系统**：`agent/tools/subagent/` — spawn/registry/announce/completion judge，functional roles
- **Command palette**：`client/app/composables/use-command-registry.ts` — 内置命令注册
- **Channels**：`server/trigger/channels/` — QQ 等 channel 子系统

### sherry 缺失的（本计划要补的）

1. **自定义命令**（`.md` 文件 → slash command）
2. **In-app MCP CRUD**（UI 增删改 MCP server，不再只靠文件投放）
3. **插件 manifest + 安装**（bundle commands + skills + hooks + MCP config）
4. **自定义子代理角色**（`.md` 文件 → 可 spawn 的角色定义）
5. **插件工具**（manifest 声明的外部可执行工具，注册到 agent 工具面）

## 1. 设计

### 1.1 自定义命令（最高优先，最低成本）

**来源**：Claude Code `.claude/commands/*.md` + opencode `.opencode/command/*.md`

**机制**：`.md` 文件，文件名 = 命令名，frontmatter 声明元数据，body = 提示词模板。

```
APP_HOME/commands/           # user scope（所有项目）
<project>/.sherry/commands/  # workspace scope（当前项目）
```

**文件格式**（参考 Claude Code）：

```markdown
---
description: 审查当前变更的代码质量
argument-hint: [focus-area]
---
Review the current git diff. Focus on: $ARGUMENTS

Check for:
- Security issues
- Performance regressions
- Breaking changes
```

**解析**：
- `name` = 文件名（去 `.md`），校验 `^[a-z0-9][a-z0-9_-]*$`
- `description` = frontmatter（必填，command palette 展示）
- `argument-hint` = 可选，输入框 placeholder
- body = 提示词，`$ARGUMENTS` 替换为用户输入（参考 Claude Code 的 `$ARGUMENTS` / `$1` / `$2`）
- 嵌套目录用 `:` 连接：`review/code.md` → `/review:code`

**集成点**：
- 后端：新建 `server/service/custom_commands_service.py` — 扫描两个目录，解析 frontmatter，返回命令列表
- 前端：command palette（`use-command-registry.ts`）合并内置命令 + 自定义命令；选中后把 body（替换 `$ARGUMENTS`）作为用户消息发送
- HTTP route：`GET /commands` — 返回自定义命令列表

**与 Claude Code 的差异**：Claude Code 的命令 body 支持 `!`command`` shell 展开；sherry 第一版不做——纯文本模板 + `$ARGUMENTS` 替换。

### 1.2 In-app MCP CRUD

**来源**：Claude Code `claude mcp add` + opencode `/mcp` + Hermes `cli-config.yaml`

**当前痛点**：sherry 的 MCP 是文件投放 + 后端重启——用户要手动创建 JSON 文件、重启后端。没有 UI 表单。

**机制**：
- 后端：扩展 `server/service/mcp_service.py`，加 CRUD：`add_mcp_server(name, config)` / `update_mcp_server(name, config)` / `remove_mcp_server(name)`
- 写入 `APP_HOME/mcp_servers/<name>.json`（复用现有 loader 的 drop folder 机制）
- HTTP routes：`POST /mcp/servers` / `PUT /mcp/servers/:name` / `DELETE /mcp/servers/:name`
- 前端：ExtendPanel MCP tab 加"添加"按钮 → `McpServerDialog.vue`（name/command/args/env 表单 + 连接测试）
- 连接测试：`POST /mcp/servers/:name/test` → 后端临时启动 server → 枚举 tools → 返回工具列表 → 关闭

**与文件投放的共存**：CRUD 写入的文件与手动投放的文件在同一目录（`APP_HOME/mcp_servers/`），loader 不区分来源。手动投放的文件不会被 CRUD 覆盖（除非同名）。

### 1.3 插件 manifest + 安装

**来源**：Claude Code `.claude-plugin/plugin.json` + ZCode marketplace + opencode `.opencode/plugins/`

**manifest 格式**（参考 Claude Code，适配 sherry 的组件类型）：

```jsonc
// .sherry-plugin/plugin.json
{
  "name": "code-reviewer",
  "version": "1.0.0",
  "description": "Code review assistant with custom commands and MCP tools",
  "author": "someone",
  "components": {
    "commands": "commands",        // 目录名：命令 .md 文件
    "skills": ["review"],          // 目录名或数组：skill 目录
    "mcp": {                       // MCP server 配置
      "command": "node",
      "args": ["server.js"]
    },
    "hooks": {                     // 生命周期 hooks
      "PostToolUse": [
        { "command": "node hook.js", "matcher": "patch_file" }
      ]
    },
    "tools": [                     // 插件工具（外部可执行）
      {
        "name": "lint_check",
        "description": "Run linter on changed files",
        "command": "node",
        "args": ["lint.js"],
        "required_permission": "read-only"
      }
    ],
    "agents": "agents"             // 目录名：子代理角色 .md 文件
  }
}
```

**安装管线**（参考 Claude Code `PluginManager`）：
1. `resolve_source(source)` — git clone / 下载 / 本地路径
2. `parse_manifest(dir)` — 读 `.sherry-plugin/plugin.json`
3. `validate(plugin)` — name 格式、version semver、components 非空
4. `install(plugin, scope)` — 原子复制到 `APP_HOME/plugins/installed/<name>/`
5. `register(plugin)` — 按 components 注册：
   - `commands` → 复制到 `APP_HOME/commands/<plugin_name>/`（自定义命令 loader 自动发现）
   - `skills` → 复制到 `APP_HOME/skills/auto/<plugin_name>/`（skills loader 自动发现）
   - `mcp` → 写 `<name>.json` 到 `APP_HOME/mcp_servers/`（MCP loader 自动发现）
   - `hooks` → 合并到 `sherry.jsonc` `hooks` 段（`config/sherry_settings.py::load_sherry_hooks` 读取）
   - `tools` → 注册到插件工具注册表（见 1.5）
   - `agents` → 复制到 `APP_HOME/agents/<plugin_name>/`（子代理角色 loader 自动发现）
6. `cleanup(tmp_dir)`

**卸载**：删除 `plugins/installed/<name>/` + 按注册逆序注销（删 commands/skills/mcp config/hooks/agents/tools）

**HTTP routes**：
- `GET /plugins/installed` / `POST /plugins/install` / `DELETE /plugins/:id` / `PUT /plugins/:id/enabled`

### 1.4 自定义子代理角色

**来源**：Claude Code `.claude/agents/*.md` + Codex `AgentRoleToml` + opencode `.opencode/agent/*.md`

**当前**：sherry 的子代理角色（researcher/executor/reviewer/librarian）是代码内置的（`agent/tools/subagent/types/functional_role.py`），用户不能自定义。

**机制**：`.md` 文件，frontmatter 声明角色属性，body = 角色的系统提示词。

```
APP_HOME/agents/               # user scope
<project>/.sherry/agents/      # workspace scope
```

**文件格式**（参考 Claude Code）：

```markdown
---
name: security-reviewer
description: Security-focused code reviewer. Use when reviewing code for vulnerabilities.
model: auxiliary
tools: [read_file, search_files, terminal]
---
You are a security-focused code reviewer. Check for:
- SQL injection
- XSS
- Path traversal
- ...
```

**集成点**：
- 后端：新建 `server/service/custom_agents_service.py` — 扫描两个目录，解析 frontmatter
- 前端：`sessions_spawn` 工具的 `functional_role` 参数 + 自定义角色
- `spawn` 时如果 `functional_role` 匹配自定义角色，用自定义的 model/tools/system prompt 构建 child agent

**与内置角色的关系**：自定义角色与内置角色（researcher/executor/reviewer/librarian）并存。`SPAWN_ALLOWED_CHILD_ROLES` 需要扩展——自定义角色的 spawn 权限由其声明的 `tools` 列表决定（只读工具 → 可被任何角色 spawn；写工具 → 只能被 executor 或 MAIN spawn）。

### 1.5 插件工具（外部可执行）

**来源**：Claude Code `PluginToolManifest`（manifest `tools[]` → 外部可执行）+ opencode `.opencode/tool/*.ts`

**机制**：manifest 的 `tools[]` 声明外部可执行工具。每个工具是一个命令——agent 调用时，后端 spawn 进程，通过 stdin 传 JSON 参数，stdout = 工具结果。

```jsonc
{
  "name": "lint_check",
  "description": "Run linter on changed files",
  "inputSchema": {
    "type": "object",
    "properties": {
      "files": { "type": "array", "items": { "type": "string" } }
    },
    "required": ["files"]
  },
  "command": "node",
  "args": ["lint.js"],
  "required_permission": "read-only"
}
```

**执行**（参考 Claude Code `PluginTool::execute`）：
1. Agent 调用 `lint_check` 工具
2. 后端 spawn `node lint.js`，cwd = 插件目录
3. stdin 传 `{"files": ["src/main.ts"]}`（JSON）
4. env 设 `SHERRY_PLUGIN_ID`、`SHERRY_PLUGIN_NAME`、`SHERRY_TOOL_NAME`
5. stdout = 工具结果（字符串）
6. 超时：`TOOLS_TIMEOUTS["plugin_tool_timeout_seconds"]`（默认 60s）
7. 返回 `ToolMessage(content=stdout, name="lint_check")`

**安全**：
- `required_permission`：`read-only` / `workspace-write` / `danger-full-access`
- `read-only` 工具不经过 HITL（只读，安全）
- `workspace-write` / `danger-full-access` 经过 HITL 审批
- 命令通过 `shlex.split`（无 shell），环境变量 scrub（复用现有 `scrub_env`）

**注册到 agent 工具面**：
- `build_main_tools()` 末尾加 `build_plugin_tools()` — 从插件注册表读取所有已启用插件的 `tools[]`，构造 `BaseTool` 实例
- 工具名前缀 `plugin__<plugin_name>__<tool_name>`（类似 MCP 的 `mcp__<server>__<tool>`）

## 2. 实施步骤

### Step 1：自定义命令（2-3 天）

**后端**：
- 新建 `server/service/custom_commands_service.py` — 扫描 `APP_HOME/commands/` + `<project>/.sherry/commands/`，解析 `.md` frontmatter（`name`/`description`/`argument-hint`），body 做 `$ARGUMENTS` / `$1` / `$2` 替换
- HTTP route：`GET /commands` — 返回命令列表（name/description/argument_hint/scope）
- 参考 Claude Code 的 `discover_skill_roots` 多根目录扫描模式

**前端**：
- `use-command-registry.ts` 扩展：`loadCustomCommands()` 合并到内置命令列表
- command palette 展示自定义命令（带 scope 标记：user / workspace）
- 选中自定义命令 → 如果有 `argument-hint`，弹出输入框 → 替换 `$ARGUMENTS` → 作为用户消息发送

### Step 2：In-app MCP CRUD（2-3 天）

**后端**：
- 扩展 `server/service/mcp_service.py`：`add_mcp_server(name, config)` / `update_mcp_server(name, config)` / `remove_mcp_server(name)` / `test_mcp_server(name)`
- 写入 / 删除 `APP_HOME/mcp_servers/<name>.json`
- HTTP routes：`POST /mcp/servers` / `PUT /mcp/servers/:name` / `DELETE /mcp/servers/:name` / `POST /mcp/servers/:name/test`
- `test_mcp_server`：临时启动 server → 枚举 tools → 返回 → 关闭

**前端**：
- ExtendPanel MCP tab 加"添加"按钮
- 新建 `McpServerDialog.vue`：name/command/args/env 表单 + "测试连接"按钮
- server 列表卡片加"编辑"/"删除"操作

### Step 3：自定义子代理角色（3-4 天）

**后端**：
- 新建 `server/service/custom_agents_service.py` — 扫描 `APP_HOME/agents/` + `<project>/.sherry/agents/`，解析 `.md` frontmatter（name/description/model/tools）
- HTTP route：`GET /agents/custom` — 返回自定义角色列表
- 扩展 `agent/tools/subagent/spawn/core.py`：spawn 时如果 `functional_role` 匹配自定义角色，用自定义的 model/tools/system prompt 构建 child agent
- 扩展 `SPAWN_ALLOWED_CHILD_ROLES`：自定义角色的 spawn 权限由其 `tools` 列表决定

**前端**：
- spawn 对话框的角色选择器加自定义角色（从 `GET /agents/custom` 加载）

### Step 4：插件 manifest + 安装（4-5 天）

**后端**：
- 新建 `server/service/plugin_service.py` — manifest 解析 + 安装管线（resolve_source → parse → validate → install → register → cleanup）
- 新建 `server/DAO/plugin_store.py`（SQLite）— `installed_plugins(id, name, version, enabled, scope, install_path, installed_at)`
- HTTP routes：`GET /plugins/installed` / `POST /plugins/install` / `DELETE /plugins/:id` / `PUT /plugins/:id/enabled`
- 注册时复用现有 loader：commands → commands 目录、skills → skills/auto/、mcp → mcp_servers/、hooks → sherry.jsonc、agents → agents/

**前端**：
- 新建 `client/app/stores/plugin-management.ts`（Pinia store）
- ExtendPanel 加"插件"tab（第四 tab，与 Channels / MCP / 命令 并列）
- `PluginStorePanel.vue`：已安装列表 + 安装（source 输入：git URL / 本地路径）+ 卸载 + 启用/禁用

### Step 5：插件工具（3-4 天）

**后端**：
- 新建 `agent/tools/plugin_tools.py` — `build_plugin_tools()` 从插件注册表读取 `tools[]`，构造 `BaseTool` 实例

- HITL gate：`required_permission` = `workspace-write` / `danger-full-access` 的工具经过 HITL 审批
- 工具名 `plugin__<plugin_name>__<tool_name>`

**前端**：
- 工具结果显示同 MCP 工具（`ChatToolCard.vue` 已通用）
