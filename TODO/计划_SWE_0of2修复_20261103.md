## Django `django__django-17051`

- 代理只改了 `django/db/models/query.py` 两处 `on_conflict is None` →
  `on_conflict in (None, OnConflict.UPDATE)`。
- F2P 仍以 `UNIQUE constraint failed: bulk_create_country.iso_two_letter,
  bulk_create_country.name` 失败（3 个 error），P2P 也失败。
- 根因：只放宽了“是否读取返回行”的条件，没有让 SQLite 生成
  `ON CONFLICT (...) DO UPDATE SET ...`；`on_conflict=UPDATE` 的字段选择和冲突目标
  需要进入 `_batched_insert` / compiler 的写入路径。
- 修复建议：
  1. 在 `bulk_create(on_conflict=OnConflict.UPDATE)` 的分批插入路径生成真正的
     upsert SQL（或在 `_insert` 的 `update_fields` 分支处理）。
  2. 补一个只覆盖 F2P 的回归测试，断言冲突行被更新而不是抛 IntegrityError。
  3. 保留 `on_conflict is None` 的原有返回行语义；不要用放宽条件替代 upsert。

## Sympy `sympy__sympy-20639`

- diff 为空、`changed_paths=[]`；主代理在第 90 次模型调用触发
  `IterationBudget exhausted`，没有产出补丁。
- 失败链：大量 terminal/代码探测占满 90 次模型调用；在预算耗尽前没有定位并编辑
  目标函数；P2P 通过、F2P 失败。
- 修复建议：
  1. **eval harness** 在预算过半仍无 diff 时记录 `no_edit` 诊断（不要用产品
     no-edit 门；该门已被删除）。
  2. 复用 7/14 建议式 gate 的 escalation，把“先定位 → 立即编辑 → 跑目标测试”写成
     更硬的收敛提示；不要在 terminal 探测上耗尽预算。
  3. 考虑把 HARD 任务的模型调用预算与任务规模绑定，或在 80% 预算时强制一次
     `patch_file`/`write_file` 尝试（仍保留可回滚性）。
  4. 网络 403 属于 degraded 环境；harness 应在 prompt/报告里明确“不要反复探测
     GitHub”，直接走本地代码和测试。
