# 计划：浏览器访问历史记录（持久化，跨重启可复用）

- 建档日期：2026-10-15
- 状态：**计划（未开工）**
- 对标：ZCode 前端浏览器历史机制（见 §1）
- 触发问题：Sherry 的浏览器面板（`BrowserPanel.vue`）没有任何持久化——
  iframe 模式的 history 数组在 Pinia store 里（reload 丢），CDP 模式的
  导航历史在 Chromium 进程里（进程退出丢）。用户关掉浏览器面板或刷新
  页面后，之前访问的 URL 全部消失，无法从历史记录快速重新打开网页。
- 结论先行：
  1. **用 Dexie（IndexedDB）存访问记录**——Sherry 已有 Dexie 基础设施
     （`composables/db.ts`），新增一张 `browserVisits` 表。
  2. **每次导航记录一条 visit**——iframe 模式在 `store.navigate()` 时记，
     CDP 模式在 `applyPage()` 收到 `page` frame 时记。
  3. **地址栏下方显示历史下拉**——输入时按 URL/title 模糊匹配，点击
     直接导航。不需要单独的历史面板，集成在地址栏里最自然。
  4. **per-session + 全局**——visit 带 `session_id`，但历史下拉默认
     显示全局最近（跨 session），可选只看当前 session。

---

## 1. 对标 ZCode 前端

### 1.1 ZCode 的三层机制

| 层 | 机制 | 持久？ | 跨重启？ |
|----|------|--------|---------|
| live 导航栈 | Electron `<webview>` guest 的 Chromium 原生 back/forward | 进程内 | 否 |
| session 内 URL 记忆 | `taskSidePaneMemory.browserUrls`（renderer Map，tabId→URL） | 进程内 | 否——但跨 workspace/task 切换存活 |
| 最近关闭标签 | `SidePaneTabOverview` 的 "Recently Closed Tabs"（React state，上限 8） | 进程内 | 否 |
| 磁盘恢复存储 | `BrowserTabRecoveryStore`（JSON 文件，per-tab 完整导航栈） | 磁盘 | 设计上能，**但生产代码故意没接** |

ZCode 的 `BrowserTabRecoveryStore` 完整实现了磁盘持久化（`BrowserTabShellRecord`
+ `BrowserTabPageStateRecord`，含 `restoreUrl`/`title`/`faviconUrl`/`entries[]`/
`activeIndex`），但在 `index.ts:339` 构造 `BrowserGuestManager` 时
`recoveryStore` 参数**故意留 `undefined`**——注释说"保持'完整退出即清空'的语义"。

### 1.2 ZCode 的 UI

`SidePaneTabOverview`（`ChevronsDownIcon` 触发的 popover）有两个段：
- **Open Tabs**——当前打开的标签列表（title + 相对时间），点击激活
- **Recently Closed Tabs**——最近关闭的标签（上限 8），点击 reopen

两段都支持搜索（`buildSearchFields` + `filterAndRankSearchItems`）。

### 1.3 ZCode 没有的

- **没有跨重启的访问历史**——`BrowserTabRecoveryStore` 实现了但没接
- **没有地址栏自动补全**——地址栏是纯文本输入，无历史建议下拉
- **没有全局访问历史列表**——只有 tab 级的 URL 记忆，不是 visit 级

### 1.4 Sherry 要做的比 ZCode 多一步

用户要的是"方便下次用户直接通过历史记录打开对应网页"——这需要**跨重启
的持久化**。ZCode 生产环境也没做到（故意不接 `BrowserTabRecoveryStore`），
Sherry 要用更简单的方案实现：一张 Dexie 表 + 地址栏历史下拉。

## 2. 设计方案

### 2.1 数据模型（Dexie 表）

在 `composables/db.ts` 新增一张表：

```typescript
// db.ts — 新增
browserVisits: '++id, sessionId, url, title, visitedAt, [url+sessionId]'

interface BrowserVisit {
  id?: number              // auto-increment
  sessionId: string        // 哪个 session 访问的
  url: string              // 规范化后的 URL
  title: string             // 页面标题（CDP 模式从 page frame 取，iframe 模式可能空）
  visitedAt: number        // Date.now() 时间戳
}
```

**为什么用 Dexie 而不是 localStorage**：
- Sherry 已有 Dexie 基础设施（`db.ts` 已有 `messages`/`sessions`/`drafts` 等表）
- IndexedDB 容量大、可索引、异步 API 不阻塞 UI
- localStorage 上限 5MB，且同步 API

**为什么 per-visit 而不是 per-tab**：
- Sherry 的浏览器标签是 ephemeral 的（instance key = `browser#3`，reload 后
  counter 重置），没有稳定的 tab identity 可做 per-tab 持久化
- visit 级记录更简单：每次导航一条记录，不需要管 tab 生命周期
- 去重：同一 URL 在短时间内重复访问只记一次（见 §2.3）

### 2.2 写入路径

**iframe 模式**——在 `stores/toolbox.ts::navigate()` 里加一步：

```typescript
async function navigate(key: string, input: string) {
  const url = normalizeUrl(input)
  // ... 现有 history 逻辑 ...
  
  // NEW: record visit
  recordBrowserVisit(key, url)
}
```

**CDP 模式**——在 `BrowserPanel.vue::applyPage()` 里加一步：

```typescript
function applyPage(url: string, title?: string) {
  store.setBrowserNav(stateKey, { url, ... })
  
  // NEW: record visit
  recordBrowserVisit(stateKey, url, title)
}
```

**新增 composable** `composables/useBrowserHistory.ts`：

```typescript
async function recordBrowserVisit(
  stateKey: string,    // sessionId::instance
  url: string,
  title?: string,
) {
  // 从 stateKey 提取 sessionId（:: 之前的部分）
  const sessionId = stateKey.split('::')[0]
  
  // 去重：同一 URL 在 30 秒内不重复记录
  const recent = await db.browserVisits
    .where('url').equals(url)
    .reverse()
    .first()
  if (recent && Date.now() - recent.visitedAt < 30_000) {
    // 更新 title 和时间戳，不新增
    await db.browserVisits.update(recent.id!, { title: title || recent.title, visitedAt: Date.now() })
    return
  }
  
  await db.browserVisits.add({
    sessionId,
    url,
    title: title || '',
    visitedAt: Date.now(),
  })
  
  // 上限清理：保留最近 500 条
  const count = await db.browserVisits.count()
  if (count > 500) {
    const oldest = await db.browserVisits.orderBy('visitedAt').limit(count - 500).primaryKeys()
    await db.browserVisits.bulkDelete(oldest)
  }
}
```

**为什么 30 秒去重**：CDP 模式的 `page` frame 有 120ms debounce，但一次
导航可能触发多个 `page` frame（重定向、子框架）。30 秒窗口防止同一 URL
被记多次。iframe 模式没有这个问题（`navigate()` 只在用户主动导航时调）。

### 2.3 读取路径——地址栏历史下拉

在 `BrowserPanel.vue` 的地址栏 `<Input>` 下方加一个 `AutoComplete`/`Popover`：

```vue
<!-- 地址栏 -->
<div class="address-bar-wrapper">
  <Input
    v-model="address"
    @keydown.enter="go"
    placeholder="输入网址或搜索..."
  />
  <!-- 历史下拉 -->
  <BrowserHistoryDropdown
    :query="address"
    @select="onHistorySelect"
  />
</div>
```

新增组件 `BrowserHistoryDropdown.vue`：

```vue
<script setup lang="ts">
const props = defineProps<{ query: string }>()
const emit = defineEmits<{ select: [url: string] }>()

const results = ref<BrowserVisit[]>([])

// 输入时模糊匹配 URL 和 title
watch(() => props.query, async (q) => {
  if (!q || q.length < 2) {
    // 显示最近访问（无输入时）
    results.value = await db.browserVisits.reverse().limit(10).toArray()
    return
  }
  // Dexie 不支持 LIKE，用 filter 在内存里做
  const lower = q.toLowerCase()
  const all = await db.browserVisits.reverse().limit(100).toArray()
  results.value = all
    .filter(v => v.url.toLowerCase().includes(lower) || v.title.toLowerCase().includes(lower))
    .slice(0, 10)
})
</script>
```

**点击历史项**：
```typescript
function onHistorySelect(url: string) {
  address.value = url
  go()  // 复用现有的导航逻辑
}
```

## 3. 完整数据流

```
用户在地址栏输入 "python" → 历史下拉显示匹配的 visit
  │
  ├─ 输入 < 2 字符 → 显示最近 10 条 visit
  ├─ 输入 ≥ 2 字符 → 模糊匹配 URL + title
  └─ 点击某条 → address = visit.url → go() → 导航
       │
       ├─ iframe 模式: store.navigate(key, url) → recordBrowserVisit(key, url)
       └─ CDP 模式: channel.send({event:'nav', url}) → server 导航
            → page frame 回来 → applyPage(url, title) → recordBrowserVisit(key, url, title)
                 │
                 └─ 写入 Dexie browserVisits 表（去重 + 上限 500）
                      │
                      └─ 下次启动 → Dexie 读取 → 历史下拉可用
```

## 5. 边界场景

| 场景 | 行为 | 理由 |
|------|------|------|
| 首次使用（无历史） | 下拉为空或显示"暂无历史" | Dexie 表为空 |
| 同一 URL 30 秒内重复访问 | 更新 title 和时间，不新增 | 防止 CDP 多次 page frame 刷屏 |
| 历史超过 500 条 | 删除最旧的 | 防止 IndexedDB 无限增长 |
| 切换 session | 历史下拉默认显示全局最近 | 跨 session 可见 |
| 只看当前 session | 可选 filter（按钮切换） | 默认全局，可选 per-session |
| 页面刷新 | 历史不丢（Dexie 持久化） | IndexedDB 跨 reload 存活 |
| App 重启 | 历史不丢（Dexie 持久化） | 同上 |
| URL 无 title（iframe 模式） | 只显示 URL | iframe 无法跨域读 title |
| favicon 加载失败 | 显示默认图标 | `<img @error>` fallback |
| 清除历史 | 调 `db.browserVisits.clear()` | 可加一个清空按钮 |
| 清除 session（HTTP clear_session） | 历史不清除 | 历史在客户端 Dexie，不在后端 |

## 6. 与 ZCode 的差异

| 维度 | ZCode（生产） | Sherry（本方案） |
|------|--------------|-----------------|
| 持久化层 | 无（in-memory Map + React state） | Dexie（IndexedDB） |
| 跨重启存活 | 否（故意不接 `BrowserTabRecoveryStore`） | 是 |
| 历史粒度 | per-tab（tabId→URL） | per-visit（每次导航一条） |
| 历史上限 | 8（最近关闭标签） | 500（visit 记录） |
| 地址栏补全 | 无 | 有（输入时模糊匹配下拉） |
| 搜索 | 有（`SidePaneTabOverview` popover） | 有（地址栏下拉内搜索） |
| 重开方式 | "Recently Closed" 标签 reopen | 历史下拉点击导航 |
| 后端存储 | 无 | 无（纯客户端 Dexie） |

ZCode 的 `BrowserTabRecoveryStore` 比本方案更完整（per-tab 完整导航栈 +
pageState），但它**故意没接**。本方案用更简单的 visit 级记录实现，不恢复
tab 的完整 back/forward 栈——只提供"从历史重新导航到某 URL"的能力，
这对用户来说已经够用（重新打开网页 = 重新导航到那个 URL）。

## 7. 不做的事

- **不恢复 tab 的 back/forward 导航栈**——ZCode 的 `BrowserTabRecoveryStore`
  能恢复完整的 `entries[]` + `activeIndex`，本方案只记 visit（URL + title +
  时间），不记导航栈。重新打开 = 重新导航，不是恢复历史位置。
- **不加后端持久化**——历史在客户端 Dexie，不走后端。Sherry 的后端没有
  浏览器历史表，也不需要加。
- **不做 favicon 缓存**——直接 `<img src="<origin>/favicon.ico">`，失败用
  默认图标。不存 favicon 图片（太重，不值得）。
- **不做跨设备同步**——Dexie 是本地 IndexedDB，不跨设备。如果需要，后续
  可加后端同步，但当前不做。
- **不改 CDP 后端的 `page_history()`**——后端已有
  `Page.getNavigationHistory`，但只返回 `can_back`/`can_forward`。本方案
  不需要后端返回 URL 列表——visit 从 CDP 的 `page` frame 的 `url`/`title`
  字段记录，这些已经在前端了。
