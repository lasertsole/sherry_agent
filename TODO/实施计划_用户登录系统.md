# Sherry Agent 用户登录系统 — 实施计划

> **状态**: 待实施
> **创建日期**: 2026-09-30
> **版本**: v1.1 (v1.0 → v1.1: 修正 refresh token 机制为双 HttpOnly Cookie + 轮换)

---

## 1. 需求概述

### 1.1 核心需求

| 编号 | 需求           | 说明                                            |
| :--: | -------------- | ----------------------------------------------- |
|  R1  | 初次免登录     | 首次启动/未配置账号时，直接进入应用，无需登录   |
|  R2  | 菜单-账户配置  | 用户通过「菜单 → 账户设置」页面配置用户名和密码 |
|  R3  | 随时启用/取消  | 账户配置可随时启用或取消                        |
|  R4  | 取消需验证密码 | 取消登录保护时，必须重新输入当前密码确认        |
|  R5  | 密码盐值加密   | 密码使用 scrypt + 随机盐值哈希存储，永不存明文  |
|  R6  | JWT 认证       | 登录成功后签发 JWT，前端携带 JWT 访问受保护接口 |

### 1.2 设计约束

- **Loopback 免认证**: `127.0.0.1` 本地访问时，认证逻辑 no-op（保持桌面端无感体验）
- **非 Loopback 强制认证**: 局域网/远程暴露时，未登录则拦截 API
- **渐进启用**: `SHERRY_AUTH_ENABLED` 默认 `false`，所有新增逻辑在不启用时零影响
- **单进程架构**: Robyn 单进程单 worker，JWT 签发/校验在进程内完成
- **分层合规**: 遵循 `server/**` 的 trigger → service → DAO → utils 分层和 import-linter 规则

### 1.3 用户流程

```
首次启动
  └─ AUTH.enabled = false → 直接进入应用（无登录页）

菜单 → 账户设置
  ├─ 设置用户名+密码 → 保存 → AUTH.enabled = true → 下次访问需登录
  └─ 已启用时：
       ├─ 修改密码 → 需输入当前密码验证
       ├─ 取消登录保护 → 需输入当前密码验证 → AUTH.enabled = false
       └─ 修改用户名 → 需输入当前密码验证

启用后访问应用
  └─ 检测 JWT → 有效 → 进入应用
       └─ 无效/缺失 → 跳转登录页 → 输入用户名+密码 → 签发 JWT → 进入应用
```

## 2. 技术方案

### 2.1 认证流程

```
HTTP 请求流（AUTH.enabled = true 且非 loopback）:
  HTTP → gateway_auth_middleware (Origin + Gateway Token)  ← 已有，不变
       → user_auth_middleware (JWT 校验)                    ← 新增
       → route handler

WebSocket 握手（AUTH.enabled = true 且非 loopback）:
  1. GET /auth/ws-ticket (JWT 校验) → 返回单次票券
  2. WS /sessions/ws?ticket=xxx&token=xxx → 校验票券 + 网关 token

Loopback:
  user_auth_middleware → no-op（直接放行）
```

### 2.2 JWT 设计

```json
// JWT Header
{ "alg": "HS256", "typ": "JWT" }

// JWT Payload
{
  "sub": 1,                    // user_id
  "username": "admin",         // 用户名
  "iat": 1727700000,           // 签发时间
  "exp": 1727743200,           // 过期时间（iat + session_ttl）
  "jti": "uuid4-string"        // 唯一标识，用于黑名单/吊销
}
```

- **签名算法**: HS256（HMAC-SHA256）
- **签名密钥**: `SHERRY_AUTH_SECRET`，空值时 per-boot 随机生成
- **Access Token 有效期**: 默认 12 小时（43200 秒），可配置
- **Refresh Token 有效期**: 默认 7 天（604800 秒），可配置
- **存储 — 双 HttpOnly Cookie**:
  - `sherry_session` = access token，`Path=/`（所有请求自动携带）
  - `sherry_refresh` = refresh token，`Path=/auth/refresh`（仅刷新请求携带，缩小暴露面）
  - 前端**完全不接触** token 字符串，防 XSS
- **刷新机制**:
  1. 前端解码 access token 的 `exp`（JWT payload 是 base64，无需密钥即可读）
  2. 在 `exp` 前 5 分钟设定时器，触发 `POST /auth/refresh`
  3. 浏览器自动携带 `sherry_refresh` cookie，后端验证后签发新 access + 新 refresh
  4. **Refresh Token 轮换**: 每次刷新都签发新的 refresh token 并使旧的失效（防重放攻击）
  5. 旧 access token 的 `jti` 可选加入黑名单（防并发旧 token 继续使用）
  6. 若 refresh token 也过期 → 401 → 前端跳转登录页
- **401 兜底**: 即使定时器未触发，API 返回 401 时前端也先尝试一次 refresh，失败再跳登录
- **吊销**: 服务端维护 JWT 黑名单（SQLite + 内存缓存），logout 时将 access token 的 `jti` 加入黑名单

### 2.3 密码哈希方案

使用 Python 标准库 `hashlib.scrypt`（无外部依赖）：

```python
# 格式: scrypt$N$r$p$base64(salt)$base64(hash)
# 参数: N=16384, r=8, p=1, dklen=32, salt_len=16

# 示例存储值:
"scrypt$16384$8$1$Zm5sV0xqR3p4UVluVWZTag==$c7e8c2f1b3d4e5a6..."
```

| 组件                | 值           | 说明                   |
| ------------------- | ------------ | ---------------------- |
| N (CPU/Memory cost) | 16384 (2^14) | 计算成本               |
| r (block size)      | 8            | 内存因子               |
| p (parallelism)     | 1            | 并行因子               |
| dklen               | 32           | 派生密钥长度           |
| salt_len            | 16           | 盐值长度（每用户随机） |

### 2.4 配置开关机制

认证状态持久化在 SQLite（而非环境变量），支持运行时切换：

```sql
-- auth_settings 表（单行）
CREATE TABLE auth_settings (
    id INTEGER PRIMARY KEY CHECK (id = 1),  -- 永远只有一行
    enabled INTEGER NOT NULL DEFAULT 0,      -- 0=disabled, 1=enabled
    updated_at INTEGER NOT NULL
);
```

- **启用**: 菜单配置账号密码后 → `enabled = 1`
- **取消**: 验证密码后 → `enabled = 0`（用户记录保留，下次启用无需重设密码）
- **启动时**: 后端读取 `auth_settings.enabled`，决定是否激活认证中间件

**新建 `server/service/auth_service.py`**

```python
class AuthService:
    """认证业务逻辑层"""

    async def is_auth_enabled(self) -> bool:
        """读取 auth_settings.enabled"""

    async def set_auth_enabled(self, enabled: bool):
        """更新 auth_settings"""

    async def setup_account(self, username: str, password: str) -> User:
        """首次设置账号（仅 auth_users 表为空时可用）"""

    async def login(self, username: str, password: str) -> LoginResult:
        """登录 → 签发 access + refresh token（通过 Set-Cookie 下发）"""

    async def refresh_token(self, refresh_jwt: str) -> LoginResult | None:
        """刷新: 验证 refresh token → 签发新 access + 新 refresh（旧 refresh 失效）"""

    async def logout(self, access_jti: str, access_exp: int, refresh_jti: str):
        """登出 → access jti 加入黑名单 + refresh jti 加入黑名单"""

    async def get_current_user(self, token: str) -> User | None:
        """解码 JWT → 校验黑名单 → 查用户"""

    async def change_password(self, user_id: int, old_password: str, new_password: str) -> bool:
        """修改密码（需验证旧密码）"""

    async def change_username(self, user_id: int, new_username: str, password: str) -> bool:
        """修改用户名（需验证密码）"""

    async def disable_auth(self, user_id: int, password: str) -> bool:
        """取消登录保护（需验证密码）→ enabled = 0"""

    async def create_ws_ticket(self, token: str) -> str:
        """签发 WS 单次票券"""

    async def consume_ws_ticket(self, ticket: str) -> bool:
        """消费票券（单次使用，消费后立即删除）"""
```

`LoginResult`:

```python
class LoginResult(TypedDict):
    expires_in: int       # access token 有效期（秒）
    user: UserInfo
    # access_token 和 refresh_token 不在 body 中返回
    # 而是通过 Set-Cookie 下发（HttpOnly Cookie）
```

WS 票券: 内存 dict `{"ticket": expiry_timestamp}`，单进程安全，消费后立即删除，30s 自动过期。

PUBLIC_PATHS = frozenset({

## 6. 安全考量

| 风险           | 缓解措施                                                                              |
| -------------- | ------------------------------------------------------------------------------------- |
| 密码明文存储   | scrypt + 随机盐值，格式 `scrypt$N$r$p$salt$hash`                                      |
| JWT 泄露       | 双 HttpOnly Cookie + Secure flag + SameSite=Strict；refresh cookie Path=/auth/refresh |
| JWT 永久有效   | 短期 access token (12h) + 长期 refresh token (7d) + refresh 轮换 + logout 黑名单      |
| 暴力破解       | scrypt 高成本参数 (N=16384) + 可选: 登录失败速率限制                                  |
| 中间件绕过     | 白名单路径最小化，仅 `/auth/login`, `/auth/refresh`, `/auth/status`                   |
| CSRF           | SameSite=Strict Cookie + 所有写操作要求 POST/PUT/DELETE                               |
| 时序攻击       | 密码比较使用常量时间比较 (`hmac.compare_digest`)                                      |
| 密码策略       | 最少 8 字符，不限制复杂度（避免 UX 摩擦）                                             |
| 取消保护误操作 | 必须输入当前密码确认                                                                  |

## 9. API 接口速查

### 认证状态

```
GET /auth/status
→ 200 { "auth_required": false, "auth_enabled": false, "has_account": false }
```

### 登录

```
POST /auth/login
  Body: { "username": "admin", "password": "xxx" }
→ 200 Set-Cookie: sherry_session=<access_jwt>; HttpOnly; SameSite=Strict; Path=/; Max-Age=43200
       Set-Cookie: sherry_refresh=<refresh_jwt>; HttpOnly; SameSite=Strict; Path=/auth/refresh; Max-Age=604800
   Body: { "expires_in": 43200, "user": {...} }
→ 401 { "error": "invalid_credentials" }
```

### 刷新 Token

```
POST /auth/refresh
  (浏览器自动携带 sherry_refresh cookie)
→ 200 Set-Cookie: sherry_session=<new_access_jwt>; HttpOnly; SameSite=Strict; Path=/; Max-Age=43200
       Set-Cookie: sherry_refresh=<new_refresh_jwt>; HttpOnly; SameSite=Strict; Path=/auth/refresh; Max-Age=604800
   Body: { "expires_in": 43200 }
→ 401 { "error": "invalid_refresh_token" }
```

### 登出

```
POST /auth/logout
  (Cookie 携带 JWT)
→ 200 { "ok": true }
```

### 当前用户

```
GET /auth/me
  (Cookie 携带 JWT)
→ 200 { "id": 1, "username": "admin", "created_at": ... }
→ 401 { "error": "not_authenticated" }
```

### 设置/修改账号

```
PUT /auth/account
  首次设置: { "username": "admin", "password": "xxx" }
  修改密码: { "new_password": "yyy", "password": "xxx" }
  修改用户名: { "new_username": "newadmin", "password": "xxx" }
→ 200 { "ok": true, "user": {...} }
→ 400 { "error": "username_taken" }
→ 401 { "error": "invalid_password" }
```

### 取消登录保护

```
DELETE /auth/account
  Body: { "password": "xxx" }
→ 200 { "ok": true }
→ 401 { "error": "invalid_password" }
```

### WS 票券

```
GET /auth/ws-ticket
  (Cookie 携带 JWT)
→ 200 { "ticket": "uuid-string", "expires_in": 30 }
→ 401 { "error": "not_authenticated" }
```

## 12. 注意事项

1. **分层不变**: `server/**` 保持 trigger → service → DAO → utils 分层
2. **导入规则**: `config/features/**` 不依赖 agent/server/models；DAO 层继承 `BaseSQLiteRepository`
3. **单进程安全**: WS 票券用内存 dict（Robyn 单进程 + 单 worker）
4. **与现有网关认证共存**: 网关 token（防浏览器跨站）+ JWT 用户认证两层独立
5. **渐进启用**: `SHERRY_AUTH_ENABLED=false` 时所有新增逻辑 no-op，零影响现有行为
6. **运行时切换**: 认证开关存在 SQLite `auth_settings` 表，支持菜单操作实时切换
7. **密码永不明文**: 存储 `scrypt$N$r$p$salt$hash`，传输通过 HTTPS（生产）或 localhost（开发）
8. **双 HttpOnly Cookie**: access token (`Path=/`) + refresh token (`Path=/auth/refresh`)，前端不接触 token 字符串，防 XSS
9. **Refresh Token 轮换**: 每次刷新签发新 refresh token + 旧 refresh 失效，防重放攻击
10. **取消保护保留用户记录**: `enabled = 0` 但 `auth_users` 表不清除，下次启用无需重设密码
11. **首次设置唯一性**: `setup_account` 仅在 `auth_users` 表为空时可用
