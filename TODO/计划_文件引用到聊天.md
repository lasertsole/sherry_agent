# 计划：文件引用到聊天——点击/拖拽添加上下文

- 建档日期：2026-10-15
- 状态：**计划（未开工）**
- 对标：ZCode `packages/ui/src/lib/workspaceFileDrag.ts` + `ConversationComposer.tsx`
- 触发问题：Sherry 的文件树没有拖拽到聊天的能力，文件查看器没有"添加
  到聊天"的入口。用户想把某个文件作为上下文发给 agent 时，只能手动复制
  文件路径粘贴到输入框。ZCode 有三条路径（右键 Add to chat、拖拽到聊天、
  `@` 提及），全部汇聚成一个 markdown 引用 `[name](./relativePath)`，
  agent 自动 resolve 路径并读文件。Sherry 要实现同样的体验。
- 结论先行：
  1. **三条路径**：文件树右键 Add to chat（已在 `计划_项目目录树右键菜单.md`
     设计）、文件树拖拽到聊天、文件查看器标签拖拽到聊天。
  2. **表示形式**：在 contenteditable 输入框里插入一个带样式的 `<span>`
     chip，显示文件名 + 图标。chip 的 `textContent` 是 `@relativePath`——
     发送时 agent 看到的就是 `@relativePath` 文本。
  3. **只传路径不传内容**——和 ZCode 一致。agent 有 `read_file` 工具，
     看到 `@path` 会自己读。不读文件内容是因为（a）内容可能很大，（b）
     agent 可能只需要知道路径存在而不需要内容，（c）和 ZCode 语义一致。
  4. **`@` 提及搜索**作为第三阶段——输入 `@` 时弹出文件搜索下拉。

---

## 1. 对标 ZCode 的机制

### 1.1 三条入口

| 入口 | 触发方式 | ZCode 实现 |
|------|---------|-----------|
| 右键 → Add to chat | 文件树节点右键 | `dispatchWorkspaceFileAddToChat(payload)` → window CustomEvent |
| 拖拽到聊天 | 文件树行 draggable → 拖到 Composer | `onDragStart` 设 DataTransfer（JSON payload + text/plain markdown） |
| `@` 提及 | 输入框打 `@` → 文件搜索 | `fileMentionProvider` → `searchWorkspaceFiles` |

三条路径汇聚到 `appendWorkspaceFileMentionToComposer()`，在 Lexical 编辑器里
插入一个 `PromptMentionNode` chip。

### 1.2 数据结构

ZCode 的 payload（`WorkspaceFileDragPayload`）：
```
{ type, workspacePath, workspaceIdentity, path, relativePath, name }
```

序列化为 markdown（`buildFileMentionMarkdown`）：
```
[name](./relativePath)
```
- 目录路径加尾部 `/`（`foo/bar/`）
- 路径前加 `./`（防 Streamdown 当成自定义 scheme 拦截）

### 1.3 关键设计决策

- **文件引用不是附件**——拖拽 workspace 文件**不进上传队列**，只插入
  inline mention。OS 文件拖拽才进附件上传。ZCode 在 `handleDropComposer`
  里明确区分了这两条路径。
- **不读文件内容**——UI 只传路径引用，agent runtime resolve 路径并
  读文件。文件内容可能很大，UI 不应该预读。
- **chip 在 markdown 里序列化为 `[name](./path)`**——发送时是 prompt
  text 的一部分，不是独立的 attachment block。

---

## 2. Sherry 现状

- **输入框**：`inputBox.vue`——`contenteditable` div（不是 textarea），
  `@input` 读 `textContent`，`handleSend` emit 纯文本。支持 `v-model:draft`
  跨 session 保持。
- **文件树**：`FileTreeNode.vue`——`@click` only，无 `draggable`，无
  `@dragstart`。
- **文件查看器**：`FileViewerPanel.vue`——右侧栏 tab，标签可点击切换，
  无拖拽。
- **已有的 "Add to chat"**：在 `计划_项目目录树右键菜单.md` §3.3⑦ 设计了
  插入 `@path` 到输入框——本文档扩展为完整方案（拖拽 + chip 展示）。
- **agent 端**：有 `read_file` 工具，能按路径读文件。但没有 `@path`
  约定——需要在 system prompt 或消息预处理里加上 `@path` 的识别。

---

## 3. 设计方案

### 3.1 Chip 表示（contenteditable 内联）

在 `contenteditable` div 里插入一个带样式的 `<span>`：

```html
<span
  class="file-mention-chip"
  contenteditable="false"
  data-file-path="./src/foo.py"
>
  📄 foo.py
</span>
```

- `contenteditable="false"`——chip 是原子单元，用户不能在 chip 内部编辑
- `data-file-path`——存储路径引用，供发送时提取
- `textContent` = `📄 foo.py`——但发送时提取的是 `@./src/foo.py`（见 §3.4）
- 样式：inline-flex、圆角、背景色、文件类型图标（复用 `FileTreeNode.vue`
  的图标逻辑）

### 3.2 插入函数（新增 composable `useFileMention.ts`）

```typescript
interface FileMentionPayload {
  type: 'file' | 'directory'
  path: string          // 相对路径（相对于 session 项目根）
  name: string          // 文件名
}

function insertFileMention(
  inputEl: HTMLElement,
  payload: FileMentionPayload,
): void {
  const mentionText = buildMentionText(payload)  // "@./src/foo.py"
  const chip = createMentionChip(payload, mentionText)
  
  // 在光标位置插入 chip + 尾随空格
  const selection = window.getSelection()
  const range = selection?.getRangeAt(0)
  if (range) {
    range.deleteContents()
    range.insertNode(chip)
    range.insertNode(document.createTextNode(' '))
    range.collapse(false)
    selection?.removeAllRanges()
    selection?.addRange(range)
  } else {
    // 无光标 → 追加到末尾
    inputEl.appendChild(chip)
    inputEl.appendChild(document.createTextNode(' '))
  }
  
  inputEl.focus()
  // 触发 input 事件同步 draft
  inputEl.dispatchEvent(new InputEvent('input', { bubbles: true }))
}

function buildMentionText(payload: FileMentionPayload): string {
  const path = payload.type === 'directory'
    ? `${payload.path}/`  // 目录加尾部 /
    : payload.path
  return `@${path.startsWith('.') ? path : `./${path}`}`
}

function createMentionChip(
  payload: FileMentionPayload,
  mentionText: string,
): HTMLElement {
  const span = document.createElement('span')
  span.className = 'file-mention-chip'
  span.contentEditable = 'false'
  span.dataset.filePath = mentionText  // @./src/foo.py
  span.textContent = `${getFileIcon(payload)} ${payload.name}`
  return span
}
```

### 3.3 发送时提取文本

修改 `inputBox.vue` 的发送逻辑——从 `textContent` 提取改为遍历 DOM
节点，把 chip 替换为它的 `data-file-path`：

```typescript
function extractTextForSend(inputEl: HTMLElement): string {
  // 遍历子节点，chip 的 textContent 替换为 @path 引用
  let result = ''
  for (const node of inputEl.childNodes) {
    if (node.nodeType === Node.TEXT_NODE) {
      result += node.textContent || ''
    } else if (node.nodeType === Node.ELEMENT_NODE) {
      const el = node as HTMLElement
      if (el.classList.contains('file-mention-chip')) {
        result += el.dataset.filePath || el.textContent || ''
      } else {
        result += el.textContent || ''
      }
    }
  }
  return result
}
```

发送时：`emit('send', extractTextForSend(inputDom.value))`

### 3.4 路径①：文件树拖拽到聊天

**FileTreeNode.vue** 加 `draggable`：

```vue
<template>
  <div
    class="file-tree-node"
    draggable="true"
    @dragstart="onDragStart($event, node)"
    @click="onClick"
    @contextmenu.prevent="openContextMenu($event, node)"
  >
    <!-- 现有内容 -->
  </div>
</template>

<script setup>
function onDragStart(event: DragEvent, node: FileTreeNode) {
  const payload: FileMentionPayload = {
    type: node.type,
    path: node.path,
    name: node.name,
  }
  event.dataTransfer?.setData('text/x-sherry-file', JSON.stringify(payload))
  event.dataTransfer?.setData('text/plain', buildMentionText(payload))
  event.dataTransfer!.effectAllowed = 'copy'
}
</script>
```

**inputBox.vue** 加 drop handler：

```vue
<template>
  <div
    class="root"
    :class="{ 'drag-over': isDragOver }"
    @dragover.prevent="onDragOver"
    @dragleave.prevent="isDragOver = false"
    @drop.prevent="onDrop"
  >
    <div class="inputBox" contenteditable ...>
    <!-- 现有 -->
  </div>
</template>

<script setup>
const isDragOver = ref(false)

function onDragOver(event: DragEvent) {
  const payload = event.dataTransfer?.types.includes('text/x-sherry-file')
  if (payload) {
    isDragOver.value = true
    event.dataTransfer!.dropEffect = 'copy'
  }
}

function onDrop(event: DragEvent) {
  isDragOver.value = false
  const raw = event.dataTransfer?.getData('text/x-sherry-file')
  if (!raw) return
  try {
    const payload = JSON.parse(raw) as FileMentionPayload
    insertFileMention(inputDom.value!, payload)
  } catch { /* ignore */ }
}
</script>
```

### 3.5 路径②：右键 Add to chat（已在 `计划_项目目录树右键菜单.md` 设计）

这里修正为调 `insertFileMention` 而非纯文本插入：

```typescript
function addToChat(node: FileTreeNode) {
  const payload: FileMentionPayload = {
    type: node.type,
    path: node.path,
    name: node.name,
  }
  insertFileMention(inputDom.value!, payload)
}
```

### 3.6 路径③：文件查看器标签拖拽

`FileViewerPanel.vue` 的 tab 标签加 `draggable`：

```vue
<!-- 右侧栏 tab 标签 -->
<div
  class="tab-label"
  draggable="true"
```

### 3.7 路径④（第三阶段）：`@` 提及搜索

输入 `@` 时弹出文件搜索下拉：

```vue
<Popover ref="mentionPopover" :pt="{ content: { style: 'max-height: 300px; overflow-y: auto' } }">
  <div v-for="file in mentionResults" @click="selectMention(file)">
    📄 {{ file.name }} <span class="path-hint">{{ file.path }}</span>
  </div>
</Popover>
```

需要调 `GET /project/tree` 递归搜索或新增 `GET /project/search?q=keyword`
端点。这个阶段较复杂，独立排期。

### 3.8 Agent 端 `@path` 识别

agent 收到 `@./src/foo.py` 后需要知道这是文件引用。两种方式：

**方式 A（推荐）：system prompt 约定**

在 `workspace/prompt_builder.py` 加一段：

```
## File References
Messages may contain @path references (e.g., @./src/foo.py).
When you see such a reference, use read_file to read the file
before responding.
```

轻量，不改代码，agent 的 `read_file` 工具自然处理。

**方式 B：消息预处理**

在消息发送前扫描 `@path` 模式，自动调 `read_file` 把内容拼进消息。
更重，但保证 agent 一定看到内容。不推荐——和 ZCode 一样让 agent 自己
决定是否读。

## 4. 完整数据流

```
文件树 FileTreeNode (draggable=true)
  │
  ├─ 右键 → Add to chat ──→ insertFileMention(payload)
  │                              │
  ├─ 拖拽到输入框 ───────────→ onDrop → insertFileMention(payload)
  │                              │
  └─ 文件查看器 tab 拖拽 ────→ onDrop → insertFileMention(payload)
                                 │
                                 ▼
                    contenteditable 里插入 <span class="file-mention-chip">
                    ┌─────────────────────────┐
                    │ 📄 foo.py               │  ← 用户看到的 chip
                    └─────────────────────────┘
                                 │
                                 │ 用户继续打字 + Enter 发送
                                 ▼
                    extractTextForSend() 提取文本：
                    "@./src/foo.py 请帮我检查这个文件"
                                 │
                                 ▼
                    emit('send', text)
                                 │
                                 ▼
                    agent 收到消息，看到 @./src/foo.py
                    → read_file("./src/foo.py") → 读内容 → 回答
```

## 6. 边界场景

| 场景 | 行为 | 理由 |
|------|------|------|
| 拖拽文件到输入框 | 插入 chip + 空格 | ZCode 同 |
| 拖拽目录到输入框 | 插入 chip，路径加尾部 `/` | ZCode 同 |
| 拖拽 OS 文件到输入框 | 不处理（或走附件上传——独立功能） | ZCode 明确区分 workspace file 和 OS file |
| 连续拖入多个文件 | 每个 chip + 空格，顺序排列 | — |
| 在 chip 中间打字 | chip 是 `contenteditable=false`，光标跳过 | 原子单元 |
| 删除 chip | Backspace 删整个 chip | — |
| 发送时 chip 在消息中间 | `@path 文本 @path2 文本` | extractTextForSend 遍历 DOM 提取 |
| draft 持久化 | chip 的 `data-file-path` 保留在 innerHTML 中 | contenteditable 的 innerHTML 被存为 draft |
| session 切换后恢复 | chip 从 draft innerHTML 恢复 | v-model:draft 写回 innerHTML |
| 无项目目录绑定时 | 文件树不显示，无法拖拽 | 已有逻辑 |
| agent 不识别 @path | 可能忽略引用 | 方式 A prompt 约定或 agent 的自然理解 |

## 7. 与 ZCode 的差异

| 维度 | ZCode | Sherry（本方案） |
|------|-------|----------------|
| 输入框 | Lexical 富文本编辑器 | contenteditable div |
| chip 实现 | `PromptMentionNode`（Lexical 节点） | `<span contenteditable=false>` |
| 序列化 | `[name](./relativePath)` markdown | `@./relativePath` 文本 |
| 拖拽数据 | DataTransfer JSON + text/plain | 同（JSON + text/plain） |
| `@` 提及 | 有（`fileMentionProvider`） | 第三阶段（独立排期） |
| OS 文件拖拽 | 有（走附件上传） | 不处理（独立功能） |
| 文件内容预读 | 不读 | 不读 |
| agent resolve | runtime 解析 markdown 链接 | prompt 约定 + read_file |
| draft 持久化 | `editorStateJson`（Lexical 状态） | innerHTML（contenteditable） |

**核心差异**：ZCode 用 Lexical 做富文本节点系统，Sherry 用原生 contenteditable
+ `<span>` chip。功能等价（内联 chip + 路径引用），但 Sherry 的实现更轻——
不需要引入 Lexical 依赖。

---

## 8. 不做的事

- **不引入 Lexical**——Sherry 的 contenteditable 够用。Lexical 是重依赖，
  chip 用 `<span>` 就能实现。
- **不预读文件内容**——和 ZCode 一致。UI 只传路径，agent 自己 `read_file`。
  预读大文件会阻塞 UI。
- **不处理 OS 文件拖拽**——拖入系统文件（图片/PDF）走附件上传是独立功能，
  本方案只管 workspace 文件引用。
- **不做 `@` 提及搜索（第一版）**——输入 `@` 弹文件搜索下拉需要新后端
  端点（`GET /project/search?q=`），独立排期。
- **不做 chip 的右键编辑**——chip 是原子单元，不支持右键菜单。删除用
  Backspace。
- **不改后端**——路径引用在前端构建，不需要新后端端点。
