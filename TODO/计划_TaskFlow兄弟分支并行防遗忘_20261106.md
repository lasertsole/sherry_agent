# 计划：TaskFlow 兄弟分支并行防遗忘

> **问题**：TaskFlow 的并行是「半自动」——resume 解锁的下游 step 自动并行派发（wave），但**初始就绪 / 与当前分支无关的兄弟 ready step 完全靠 agent 自觉点名**（`taskflow_dispatch` 必须显式传 step id）。agent 只专注一个分支时，会忘记并行其他兄弟分支（串行浪费时间）或彻底忘记它们（直到 `taskflow_finish` Gate A 才拦截，事后兜底）。
>
> **缺口**：① reminder 不报就绪并行信息（只给单个 next pending，5 轮 cooldown）；② wave 只管下游依赖链，不扫兄弟；③ 初始派发靠 agent 点名；④ finish Gate A 是事后拦截。
>
> **目标**：让 agent 不可能「忘记」并行兄弟分支——系统主动暴露就绪并行机会 + 关键节点自动派发就绪集。
>
> **日期**：2026-11-06

---

## 一、问题定位（已核实）

| 环节 | 代码位置 | 现状 | 缺口 |
|---|---|---|---|
| 初始 dispatch | `taskflow_dispatch.py:47-52` | agent 显式传 step_ids，系统不自动找 ready | 初始就绪的兄弟 step 靠 agent 点名，不点就遗忘 |
| resume auto-dispatch | `taskflow_resume.py:466-475` | step done 后只解锁**本次依赖的下游** | 不扫「一直 ready 但没派发」的兄弟 |
| wave 概念 | `taskflow_resume.py:466` | wave = resume 解锁波（下游） | 不是兄弟并行波；早期 longest-path wave grouping 已删（`progress_push.py:9-11`） |
| TaskFlow board reminder | `reminder_catalog/sources.py:128-140` | priority 75、cooldown 5 轮、only_if_changed | 只渲染单个 next pending（`pending[0]`），不报 ready 数/列表/并行提示（`prompt_builder.py:302-345`） |
| finish Gate A | `taskflow_finish.py:369-399` | finish 时有未派发 ready → protocol_violation 拒绝 | 事后兜底，时间已浪费 |

**失败模式**：plan 创建 flow（A/B/C 三无依赖兄弟 step）→ agent 只 `run_task(A)` → B/C 一直 ready 没派发 → reminder 5 轮才注入且只显示单个 next → wave 不触发（A done 只解锁 A 下游）→ 串行浪费时间 / 彻底遗忘 B/C → finish Gate A 才拦截。

---

## 二、设计方案

三层补：① reminder 主动暴露就绪并行机会；② plan 后自动派发初始就绪集；③ step done 后扫全 ready（含兄弟）自动派发。

### 改动 1：TaskFlow board reminder 注入「就绪并行」信息

`workspace/prompt_builder.py:302-345` `_build_taskflow_block` 渲染增强：除了单个 next pending，**显式列出所有就绪可并行派发的 step**。

当前渲染（每个 flow）：
```
Flow f1 [2/5]  next: s3 — implement...
```

增强后（注入文本必须英文——system prompt 语言）：
```
Flow f1 [2/5]  ready_to_dispatch: s3(implement), s4(test), s5(docs)  [3 steps ready — parallelize via taskflow_dispatch!]
```

- 列出所有 `status=pending AND deps 全 done` 的 step（ready 集），不只 `pending[0]`
- ready 数 > 1 时标注 `[N steps ready — parallelize via taskflow_dispatch!]`（英文）
- ready 数 = 0 时只显示 next（原行为）
- step task 文本取原 task 内容（不翻译，原样截断前 40 字符）
- **cooldown 降为 1 轮**（有 ready 未派发时每轮提醒，不 5 轮）：`reminder_catalog/sources.py` taskflow_status source 的 `cooldown_turns` 从 5 改 1，或条件化（有 undispatched ready 时 cooldown=1，否则 5）

**效果**：agent 每轮看到「3 steps ready — parallelize」，不可能遗忘。注入文本全英文。

### 改动 2：plan 后自动派发初始就绪集

`taskflow_plan.py`（plan 创建 flow + 注册所有 step 后）：自动派发所有初始 ready step（无 `depends_on` 或 deps 已满足的兄弟），不靠 agent 点名。

```python
# taskflow_plan.py，flow 创建 + step 注册后
initial_ready = [s for s in steps if s["status"] == "pending" and all_deps_done(s)]
if initial_ready:
    # 复用 taskflow_dispatch 的批量并行派发路径
    await _dispatch_batch(flow_id, [s["id"] for s in initial_ready], auto=True)
```

- 复用 `taskflow_dispatch.py:176-187` 的 `asyncio.gather` + Semaphore（`max_parallel_dispatch` 默认 2，lane cap 8）并行 spawn
- `auto=True` 标记是系统自动派发（区别于 agent 手动），不触发 protocol_violation
- 失败 fail-open（派发失败的 step 留 ready，agent 可手动重试）
- **可选**：配置开关 `taskflow_infra.auto_dispatch_initial_ready`（默认 True），关闭则回退靠 agent 点名

**效果**：plan 一创建，所有无依赖兄弟 step 立即并行派发，agent 不需要主动点名。

### 改动 3：step done 后扫全 ready（含兄弟）自动派发

`taskflow_resume.py:466-475` `_auto_dispatch_ready` 扩大扫描范围：不只本次解锁的 `newly_ready`，而是**全 flow 所有 ready step**（含一直 ready 但没派发的兄弟）。

当前：
```python
# taskflow_resume.py:472-475
newly_ready = unlock_dependents(fresh_steps)  # 只本次解锁的下游
if auto_dispatch and newly_ready:
    await _auto_dispatch_ready_locked(flow_id, newly_ready, ...)
```

增强后：
```python
newly_ready = unlock_dependents(fresh_steps)      # 本次解锁的下游
all_ready = [s for s in fresh_steps                # 全 flow 所有 ready（含兄弟）
             if s["status"] == "pending" and all_deps_done(s)
             and s["id"] not in already_dispatched]
to_dispatch = set(newly_ready) | set(all_ready)   # 合并：下游 + 兄弟
if auto_dispatch and to_dispatch:
    await _auto_dispatch_ready_locked(flow_id, list(to_dispatch), ...)
```

- step done 后，扫全 flow ready 集（不只是本次解锁的下游），把一直没派发的兄弟也一起派发
- 复用 `_auto_dispatch_ready_locked` 的并发 + CAS + fail-open
- `:159` 注释 "Resume never spawns the newly-ready steps"（指非本次解锁的）——本改动**违反**这个旧约束，需更新注释：改为「resume auto-dispatches ALL ready steps (newly unlocked downstream + long-ready siblings)」
- 防双派发：`already_dispatched` 集合过滤（已派发/running/done 的不重复派）

**关键：并发一起派发，下游不阻塞**。`to_dispatch = newly_ready ∪ all_ready` 一次性传给 `_auto_dispatch_ready_locked`，内部 `asyncio.gather` + Semaphore **并发 spawn**——下游 D 和兄弟 B/C 同时派发，互不等待。spawn 是 fire-and-forget detached（子 agent 独立跑），D 不等 B/C 完成。即使 spawn semaphore（`max_parallel_dispatch=2`）限并发，D 最多等一个 spawn 槽位释放（很快，不是等执行完成），不会卡住。**下游已解锁就一定派发出去，不会被兄弟阻塞**。

**效果**：任何一个 step done 后，系统扫全 flow，把所有 ready 的（含被遗忘的兄弟）一起并发派发。agent 不需要记得派兄弟分支。下游不阻塞。

### 改动 4：Gate A 从「事后拦截」转为「派发前校验」（可选强化）

`taskflow_finish.py:369-399` Gate A 保持（finish 时仍有未派发 ready → 拒绝），但配合改动 2/3 后，正常流程下 finish 时不应有未派发 ready（都被自动派了）。Gate A 退为**异常兜底**（自动派发失败 + agent 没手动补 → finish 拦截）。

不改 Gate A 逻辑，只是改动 2/3 后它的触发场景从「常态」降为「异常」。

## 三、防双派发 / 并发安全

改动 2/3 都复用现有 `_dispatch.py:10` / `taskflow_dispatch.py:70` 的 **flow-local dispatch lock**（手动 dispatch 和 auto-dispatch wave 串行化）。新增的自动派发同样走这个 lock：

- plan 后 auto-dispatch（改动 2）拿 lock → 派发初始 ready → 释放
- resume 后 auto-dispatch（改动 3）拿 lock → 扫全 ready → 派发 → 释放
- agent 手动 `taskflow_dispatch` 也拿 lock → 三者互斥，不双派发

`_auto_dispatch_ready_locked`（`taskflow_resume.py:497-628`）已有 CAS 持久化 + 重读状态过滤仍 ready 的，复用即可。


## 七、实施顺序

1. `config/features/agent_side/taskflow_infra.py` — 3 个配置开关（独立）
2. `taskflow_dispatch.py` — `_dispatch_batch` 支持 `auto=True`（可独立测试）
3. `taskflow_plan.py` — plan 后 auto-dispatch 初始 ready（改动 2，依赖 2）
4. `taskflow_resume.py` — `_auto_dispatch_ready` 扫全 ready（改动 3，依赖 2）
5. `prompt_builder.py` + `reminder_catalog/sources.py` — reminder 就绪列表 + cooldown 条件化（改动 1，独立）
6. 测试 + 验证：`uv run pytest tests/agent/tools/taskflow -q`

改动 1（reminder）和改动 2/3（auto-dispatch）可独立先行。改动 1 是「提醒」（软），改动 2/3 是「自动派发」（硬，彻底防遗忘）。三者叠加 = agent 不可能忘记并行兄弟分支。

## 八、风险

| 风险 | 等级 | 缓解 |
|---|---|---|
| auto-dispatch 派发过多 step 压爆 lane | 中 | `max_parallel_dispatch`（默认 2）+ lane 全局 cap 8 限制；Semaphore 控并发 |
| plan 后初始 ready 很多（如 10 个无依赖兄弟） | 中 | Semaphore 串行化分批；reminder 提示 agent 可调 `max_parallel_dispatch` |
| agent 想串行控制（不希望自动并行） | 低 | 配置开关 `auto_dispatch_initial_ready=False` 回退靠点名；或 agent 用 `depends_on` 显式串行 |
| resume 扫全 ready 性能 | 低 | flow step 数量有限（通常 <20），全扫描 O(N) 可忽略 |
| reminder cooldown=1 噪音 | 低 | 只在有 undispatched ready 时 1 轮；全派发后回 5 轮 |
| 改动 3 违反旧约束（`:159` 注释） | 低 | 更新注释 + 测试验证不双派发（lock + CAS） |
