每个合并独立可用——做完一个就能跑测试验证，不依赖其他合并。①②可以并行做。⑧ 最后做（风险最高，且需要改 parallel_safety 的核心调度逻辑）。

## 10. 关键发现

### 10.1 自动适配的部分

`agent_config_service.py` 和客户端预设从 `GET /agent/catalog` 动态推导——catalog.py 改了就自动适配，不需手动改这两个文件。

### 10.2 不自动适配的部分

客户端的 WS 事件源匹配（`'web_search'`）、HITL 卡片类型匹配（`'exit_plan_mode'`）是硬编码字符串，必须同步改客户端。

### 10.3 parallel_safety 是 file 合并的核心难点

`parallel_safety.py` 的文件锁调度器按工具名分组（`FILE_READ_TOOLS`/`FILE_WRITE_TOOLS`）。合并后要改为按 `action` 参数判断 read/write——这是 file 合并最大的代码改动。

### 10.4 delivery.py 的 Python 对象级耦合

`agent/tools/subagent/announce/delivery.py:408/417` 直接 `import taskflow_resume` 并调 `.coroutine()`——不是通过工具调度。taskflow 合并后必须保留 resume 的 Python 可调用入口，或改为调 merged tool。

### 10.5 sessions 的递归防护耦合

`DEFAULT_SUBAGENT_BLOCKED_TOOLS=["sessions_spawn","sessions_yield"]` 按名阻止子代理 spawn/yield（防递归）。合并后改为整个 `sessions` 工具禁止给子代理——但这是行为收紧（子代理之前可以 yield/send）。

### 10.6 browser 的 redaction prefix bug

`redaction.py` 的 `tool_output_prefixes: ("mcp_","browser_")` 用前缀匹配。合并后工具名从 `browser_navigate` 变为 `browser`，不匹配 `"browser_"` 前缀——browser 输出会失去 redaction 保护。必须改为精确名或调整前缀。

### 10.7 skill_manage 的 action 命名冲突

`skill_manage` 的 action 里有 `"write_file"`/`"remove_file"`。如果 `file` 工具用 `action="write_file"`，模型会混淆。建议 `file` 工具用 `action="write"`/`"patch"`/`"read"`/`"search"`。

### 10.8 scope 从分工具变为整个工具的影响

当前 sessions 的 `sessions_kill`/`sessions_steer` 是 `main_only`，其他不是。合并后如果整个工具标 `main_only`，子代理失去 yield/send 能力——这是行为收紧。需要在 merged tool 内对特定 action 做 scope 检查，或接受这个收紧。
