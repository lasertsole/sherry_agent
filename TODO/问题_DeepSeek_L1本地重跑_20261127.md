## 6. 本地 harness 过程中出现的基础设施现象

按时间顺序：

1. 第一轮本地跑：`shutil.copytree` 在 esbuild/cargo 产物上报 `[Errno 22] Invalid argument`，`csstree` 与 `pest` 均 0 tool_calls、未启动 agent。
2. 第一轮 `happy-dom` 实际判分成功（`grade.log` 内有 F2P/P2P），但驱动读错了 reward 路径，报告中记为 `reward=None`。
3. 第一轮 worker 只落下 `partial=True` 的 `agent-result.json`，`orchestration_gate` 与 `experience_extraction` 字段缺失。
4. 第二轮改用 `cp -a --no-preserve=xattr` 后，`csstree` 复制成功；`pest` 仍因 cargo `.l2s.*` 符号链接链报“符号链接的层数过多”。
5. 第二轮 driver 在 `csstree` 跑到一半时被中断（时间戳 01:32），未写出该轮 `report.json`；`pest` 未启动。
6. 第三轮补跑 `csstree` 成功；`pest` 因 `instruction.md` 路径取自 `tasks-py-node/`（Rust 题不在该目录）报 `FileNotFoundError`，0 tool_calls。
7. 第四轮修正 prompt 来源后 `pest` 才真正跑起 agent，耗时 1165.5s，最终 reward=0。

- `ssh wsl-home` 持续返回 `No route to host`（`192.168.31.39:2222`）。
- ARP 表：`192.168.31.39` 对应 `00:00:00:00:00:00`，Flags=`0x0`（未完成）。
- 本机 `192.168.31.204/24`，目标同网段；扫描 `192.168.31.0/24` 的 2222 与 22 端口均无主机响应。
- Bash `/dev/tcp/192.168.31.39/2222` 报“没有到主机的路由”。
