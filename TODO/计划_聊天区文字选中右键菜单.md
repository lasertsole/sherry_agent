## 0. 背景：ZCode 现状 vs sherry 现状（已核实）

### 0.1 ZCode 的选中菜单机制

ZCode 的"选中文字弹出菜单"**不是原生右键菜单**，而是文字选中后自动弹出的**浮动操作工具条**（`SelectionActionMenu`）：

| 组件 | 作用 |
|---|---|
| `useTextSelection.ts` | 监听 `mouseup`/`touchend`/`selectionchange`，选中非空时触发检测 |
| `ConversationSelectionTooltip.tsx` | 读 `window.getSelection()`，解析选区所在的 `data-row-id`，构建 `ConversationSelectionReference`，渲染浮窗 |
| `SelectionActionMenu.tsx` | 浮窗本体：两个并排按钮——"添加到当前任务"(`add-to-task`) + "在辅助对话中提问"(`ask-in-side-chat`) |
| `conversationSelectionReference.ts` | 数据模型 + `dispatchConversationSelectionAdd`（CustomEvent 跨组件通信） |
| `ConversationSelectionReferenceChip.tsx` | composer 内的引用 pill：显示引用计数 + 来源 + 预览 + 删除 |
| `conversationSelectionGuard.ts` | 选中合法性守卫：排除按钮/输入框等区域、要求同行内选区、长度 ≤ 8,000 字符 |
| `SelectionSideChatPane.tsx` | 辅助会话侧栏面板：完整二级对话 |

**"添加到当前任务"流程**：选中 → 浮窗 → 点按钮 → `dispatchConversationSelectionAdd({ targetSessionId: 当前会话, reference })` → composer 的 `useConversationSelectionReferences` hook 收到 `zcode:conversation-selection-add` CustomEvent → 渲染引用 chip → 发送时 `buildPromptWithConversationSelections` 序列化引用到 prompt。

**"在辅助对话中提问"流程**：选中 → 浮窗 → 点按钮 → 复用已有子会话或创建新子会话 → 打开右侧栏 `SelectionSideChatPane` 面板 → 将引用 dispatch 到子会话的 composer → 用户在侧栏里独立对话。

### 0.2 sherry 当前状态

| 能力 | 状态 |
|---|---|
| 聊天消息区文字选中右键菜单 | **不存在**——无 `@contextmenu`、无 `getSelection`、无右键处理 |
| 输入框引用 chip | **有 file-mention chip**——`<span contenteditable="false" class="file-mention-chip" data-file-path="@./path">`，`extractTextForSend` 遍历 DOM 将 chip 替换为 `data-file-path` 值 |
| mitt 事件总线 | **有**——`chat:file-mention` 事件从文件树侧栏跨组件到达会话页的输入框 |
| PrimeVue ContextMenu | **有**——文件树和 git graph 各用一个 `<ContextMenu>` 实例，行 `@contextmenu.prevent` 向上 emit |
| 右栏 tab 系统 | **有**——`openTab(kind, payload?)`，支持 `fileViewer`/`gitDiff`/`browser`/`terminal` 等 panel kind |
| 辅助会话概念 | **不存在**——无 side chat、无二级会话面板 |

### 0.3 设计选择

| 决策 | 选择 | 理由 |
|---|---|---|
| 菜单触发方式 | **右键 ContextMenu**（PrimeVue） | sherry 已有 PrimeVue ContextMenu 模式（文件树/git graph），一致性优先；ZCode 的浮窗 UX 更好但需自建定位/消失逻辑，作为可选增强 |
| 引用 chip 类型 | **新建 quote chip**（复用 file-mention 的 chip 架构） | 不能直接插入纯文本——纯文本会被用户误编辑且无法区分"引用"与"用户输入"；chip 是原子化的，`extractTextForSend` 可精确提取 |
| 辅助会话实现 | **新建普通 session + 右栏 sideChat 面板** | sherry 后端已有完整 session 系统；前端右栏 tab 系统已有面板扩展能力；不引入 subagent 语义（辅助会话是用户自己对话，不是 agent 委派） |
| 事件通信 | **复用 mitt 总线**（新事件 `chat:selection-add`） | 与 `chat:file-mention` 同模式，不引入新通信层 |

## 1. 硬约束

| 约束 | 含义 | 验收方式 |
|---|---|---|
| **C1**：`extractTextForSend` 向后兼容 | 现有 file-mention chip 提取逻辑不变；新增 quote chip 是追加分支，不修改现有分支 | 原有 chip 提取行为 byte-identical |
| **C2**：`v-safe-html` 管线不变 | `ChatBox.vue` 的消息渲染不改动；右键监听挂在外层容器，不侵入 `v-safe-html` 渲染的 DOM | 现有 markdown 渲染不变 |
| **C3**：mitt 事件不冲突 | 新事件名 `chat:selection-add` / `chat:selection-side-chat` 不与现有事件名冲突 | `mitt.ts` 事件注册表无冲突 |
| **C4**：右栏面板扩展不破坏现有面板 | 新增 `sideChat` panel kind 是追加——`RightSidebarPanelKind` 联合类型追加成员，`SCOPE_BY_KIND` 追加映射，`PANELS` 追加懒加载 | 现有面板渲染不变 |
| **C5**：选区合法性守卫 | 不在按钮/输入框/HITL 卡片区域弹出菜单；选区必须非空；单条引用 ≤ 8,000 字符 | 守卫测试覆盖 |
| **C6**：辅助会话生命周期独立 | 辅助会话是普通 session，有自己的消息历史和 checkpoint；关闭右栏 tab 不删除 session（只断开面板，session 数据留存） | 重新打开同一辅助会话能恢复历史 |
| **C7**：HITL 卡片优先 | 当 HITL 审批卡片显示时（`hitlRequest` 非空），不弹选中菜单 | 输入槽被 HITL 占用时不干扰 |

### 3.2 改动清单

- [ ] **3.2.1** 新建 `client/app/composables/use-chat-selection.ts`——选中检测 + 守卫 + 菜单构建

```typescript
interface SelectionPayload {
  text: string;           // 选中的纯文本
  sourceMessageId?: string; // 来源消息 id（用于来源标注）
  sourceRole?: string;     // user / ai / tool
}

/** 从 window.getSelection() 提取选中信息 + 合法性守卫 */
export function inspectSelection(): SelectionPayload | null {
  const sel = window.getSelection();
  if (!sel || sel.isCollapsed || sel.rangeCount === 0) return null;
  const text = sel.toString().trim();
  if (!text) return null;
  if (text.length > 8000) return { text: '__LIMIT__' }; // 超长标记，菜单显示警告

  // 守卫：选区不能跨越按钮/输入框/HITL 卡片区域
  const range = sel.getRangeAt(0);
  const container = range.commonAncestorContainer;
  const el = container.nodeType === Node.ELEMENT_NODE
    ? container as Element
    : container.parentElement;
  if (!el) return null;
  // 排除：按钮、输入框、HITL 卡片、菜单本身
  if (el.closest('button, input, textarea, [role="dialog"], [data-hitl-card]'))
    return null;
  // 找到最近的消息行，提取来源信息
  const row = el.closest('[data-message-id]');
  if (!row) return null; // 选区不在消息行内

  return {
    text,
    sourceMessageId: row.getAttribute('data-message-id') || undefined,
    sourceRole: row.getAttribute('data-message-role') || undefined,
  };
}
```

## 5. 任务四："在辅助会话中提问"（新建辅助会话 + 右栏面板）

### 5.1 目标

用户选中文本 → 右键 → "在辅助会话中提问" → 新建一个普通 session → 在右栏打开 sideChat 面板 → 将选中文本预填到辅助会话的输入框。

### 5.2 改动清单

#### 5.2.1 后端：session 创建 + 可选上下文继承

辅助会话是普通 session，复用现有 session 创建 API。但需要在创建时支持**从父会话继承工作记忆**（ZCode 的 `createSelectionSideConversation` 机制），分两个版本：

**第一版（简单——不继承上下文）**：

不改动后端。`POST /sessions` 创建空 session → 前端预填 quote chip → 用户在辅助会话里从零开始对话。模型没有主会话的对话上下文，只有：
- 长期记忆（MEMORY.md / USER.md / FACTS.md——workspace 级，自动共享）
- 系统提示（persona——workspace 级，自动共享）
- 用户选中的引用文本（quote chip）

**第二版（ZCode 式——继承父会话上下文快照）**：

`POST /sessions` 追加可选参数 `parent_session_id` + `inherit_context: true`。后端在创建子 session 后：
1. 读取父会话最近的 N 轮消息（`MesMemory` → `context_engine/store/core.py::get_messages_by_lastest_n_turns`）
2. 插入到子会话的 MesMemory（新 session_id），标记为 `origin: "inherited_context"`（`internal: True`）
3. 追加一条边界提醒 HumanMessage（对标 ZCode 的 `SELECTION_SIDE_CHAT_BOUNDARY`）

边界提醒内容（四语言可配，中文版）：

> 以上对话继承自主会话，仅供参考。不要自动继续主会话的工作；只回答本辅助会话中新提出的问题。仅在本辅助会话中用户明确要求时才修改工作区文件。

#### 5.2.4 辅助会话与主会话的关系

| 维度 | 辅助会话 | 主会话 |
|---|---|---|
| session 类型 | 普通 session（不是 subagent） | 普通 session |
| 消息历史 | 独立（第二版可继承快照，见 §5.2.5） | 独立 |
| checkpoint | 独立（`thread_id` = 各自 session_id） | 独立 |
| HITL | 独立审批（各自 `state_register_mem`） | 独立审批 |
| 生命周期 | 关闭右栏 tab 不删除 session；重新打开可恢复 | session 列表管理 |
| 可见性 | 右栏面板内 | 主聊天区 |

辅助会话不出现在 session 侧边栏列表（它是主会话的"附属"），但可以在右栏 tab 中重新激活。可选：在 session 元数据中记录 `parentSessionId` 用于关联（但不影响后端行为）。

#### 5.2.5 辅助会话记忆共享分析（对标 ZCode 三层模型）

ZCode 的辅助对话在三层记忆上各有不同策略：工作记忆按值继承（快照拷贝 + model-only 可见性 + 边界提醒），短期记忆完全隔离，长期记忆完全共享。对应到 sherry 的架构：

**对照表：ZCode → sherry**

| 记忆层 | ZCode 机制 | sherry 对应机制 | 共享策略 |
|---|---|---|---|
| 工作记忆（对话上下文） | 父会话消息克隆到子会话，`visibility: model-only`（UI 隐藏、模型可见），新 ID，边界提醒 | LangGraph checkpoint + MesMemory 消息表（`session_id` 键），`workspace/prompt_builder.py` 构建系统提示 | **第一版不继承**（空 session）；**第二版按值继承**（后端克隆最近 N 轮消息到子会话 MesMemory，标记 `origin: "inherited_context"`） |
| 短期记忆（运行时状态） | `readFileState = new Map()`、`MessageHistoryImpl`、MCP 连接全部新建 | `state_register_mem`（`runtime/session/state_register.py`，per session_id）、HITL 审批状态、todo 列表、TaskFlow 板 | **天然隔离**——新 session 自带空状态寄存器，`thread_id` 不同，checkpoint 独立 |
| 长期记忆（文件级记忆） | `memoryRoot` 按 workspace 路径哈希，`isMainMemoryTaskType` 显式包含 `selection_side_chat` | `MEMORY.md` / `USER.md` / `FACTS.md`（`agent/tools/memory.py::MemoryStore`，文件级，workspace 目录下）；`workspace/prompt_builder.py::build_system_prompt` 在每次构建提示时从磁盘加载 | **天然共享**——记忆文件是 workspace 级的，不是 per-session 的；新 session 的系统提示自动包含同一份冻结快照 |

**各层详细原理：**

**① 工作记忆（对话上下文）**

sherry 的工作记忆由两部分组成：LangGraph checkpoint（图状态，per `thread_id`）和 MesMemory 消息表（per `session_id`）。

- **第一版（不继承）**：新 session 的 `thread_id` = 新 `session_id`，checkpoint 从空开始。MesMemory 没有历史消息。模型看不到主会话聊了什么，只有用户预填的 quote chip 引用文本。**简单但不连贯**——如果用户选的是主会话中 agent 的一段回答，辅助会话的 agent 不懂这段回答的前因后果。

- **第二版（按值继承）**：后端在创建子 session 后，调 `context_engine/store/core.py::get_messages_by_lastest_n_turns(parent_session_id, n)` 读取父会话最近 N 轮消息，逐条插入子会话的 MesMemory（新 `session_id`，新 message ID），标记 `metadata.origin = "inherited_context"` + `metadata.internal = True`。这些消息的渲染逻辑（`ChatBox.vue` 的 `useChatTurnGroups`）会把 `internal: True` + 非 `user` origin 的消息当系统卡片渲染（与 workspace notice / subagent completion carrier 同路径），UI 上呈灰色折叠卡片而非正常气泡——对标 ZCode 的 `uiVisibility: "hidden"`。模型在 checkpoint 里能看到完整上下文，但 UI 干净。

  边界提醒作为一条 `HumanMessage` 追加到继承消息之后，`metadata.internal = True` + `metadata.provenance = "side_chat_boundary"`，让 `is_system_reminder` / `is_workspace_notice` 等扫描器跳过它（不作为轮次边界、不触发 HITL）。

  写入隔离：子会话的后续对话写入子会话自己的 MesMemory 和 checkpoint，不回写父会话——与 ZCode 相同（按值拷贝，非引用共享）。

**② 短期记忆（运行时状态）**

sherry 的短期记忆全部 per-session，天然隔离，不需要额外改动：

- `state_register_mem`（`runtime/session/state_register.py`）：`PROJECT_DIR`、`GIT_HEAD_ANNOUNCED`、`HITL_*`、`TOKEN_BUDGET_*`、`SUMMARIZATION_*` 等全部以 `session_id` 为键。新 session 从空状态开始——`PROJECT_DIR` 会从 SQLite 镜像 prime（但这是进程级 prime，不是从父会话继承）。
- LangGraph checkpoint：`thread_id` = `session_id`，子会话有自己的 checkpoint 序列。
- HITL 审批：`ToolApprovalStore` 按 `(operator, session_id, tool, args_hash)` 存储——子会话有自己的审批缓存，主会话的 session allowlist 不影响子会话。
- todo 列表、TaskFlow 板：per-session，子会话从空开始。
- `message_search` 工具：搜索时排除当前 session——子会话可以搜到主会话的历史（跨 session），但需要 agent 主动调用。

**③ 长期记忆（文件级记忆）**

sherry 的长期记忆是 workspace 级的，天然共享——这是架构红利：

- `MemoryStore`（`agent/tools/memory.py:129`）：文件级存储，`MEMORY.md` / `USER.md` / `FACTS.md` 在 workspace 目录下。`load_from_disk()` 在 session 开始时加载冻结快照，注入系统提示。
- `build_system_prompt`（`workspace/prompt_builder.py:422-433`）：调 `provider.format_memory_for_system_prompt("memory"/"user"/"facts")`——不区分 session_id，所有 session 读同一份文件。
- 写入：`memory` 工具调 `MemoryStore.save_to_disk()`——写入 workspace 级文件。辅助会话写的记忆主会话下次构建提示时能看到。
- 与 ZCode 的对应：ZCode 的 `memoryRoot` 按 workspace 路径哈希、`isMainMemoryTaskType` 包含 `selection_side_chat`——sherry 更简单，记忆文件本来就是 workspace 级的，不需要额外配置。

  **注意**：sherry 的 Memory 快照是**冻结**的（`format_for_system_prompt` 返回 `load_from_disk()` 时的快照，mid-session 写入不改变系统提示以保护 prefix cache）。辅助会话开始时加载的是当前磁盘上的 MEMORY.md——如果主会话在运行期间更新了记忆，辅助会话只有在重启或下次 session 开始时才能看到。这与 ZCode 不同（ZCode 的 `MEMORY.md` 索引每次构建上下文时从磁盘读取）。

**④ 系统提示 / 人格**

- sherry 的 `build_system_prompt` 从 workspace 目录构建——persona + 记忆快照 + skills 索引 + 当前工作目录 + 计划模式状态。不区分 session_id（除 per-session agent config 如 `AGENT_CONFIG`）。
- 辅助会话获得**相同的基础系统提示**——同一 persona、同一 skills 集、同一记忆快照。
- 唯一差异是第二版的边界提醒（transcript 消息，不是系统提示的一部分）。
- per-session agent config（`AGENT_CONFIG`）：辅助会话是一个新 session，默认没有 agent config——除非创建时从父会话拷贝（可选，第一版不做）。

**⑤ message_search——跨会话检索的补偿机制**

即使第一版不继承上下文，辅助会话的 agent 可以通过 `message_search` 工具（`agent/tools/message_search.py`）搜索主会话的历史——该工具 FTS5 + 语义搜索过去 session 的消息（排除当前 session）。这给了 agent 一个"主动回忆"的通道：用户引用文本中如果有关键词，agent 可以搜到完整的原始对话。这是 sherry 独有的优势（ZCode 没有 cross-session semantic search）。

**总结对照图：**

```
                    ZCode                          sherry
                    ─────                          ──────
工作记忆   父消息克隆 model-only + 边界提醒    第一版：不继承 / 第二版：克隆 MesMemory + 系统卡片 + 边界提醒
短期记忆   readFileState/MCP 全新建             state_register_mem/checkpoint/HITL 天然 per-session 隔离
长期记忆   memoryRoot per-workspace 哈希        MEMORY.md per-workspace 文件级（天然共享）
系统提示   同一 workspace config               build_system_prompt 不分 session（天然相同）
跨会话检索  无                                 message_search FTS5 + 语义搜索（补偿第一版不继承的缺陷）
```
