# 计划：子 agent 角色技能隔离（per-role skill visibility）

- 日期：2026-11-12
- 状态：**待评审**
- 来源：Sherry 子 agent 各角色（researcher/executor/reviewer/librarian/general）共用全局技能索引，无角色级技能可见性；需做每个角色只看到分配的技能子集
- 风险等级：**低-中** —— 加法式扩展（新 frontmatter 字段 + 过滤逻辑），`roles` 缺省时全可见（向后兼容）；不动技能扫描/存储/快照机制

---

## 0. 现状（已代码核实）

- `scan_skills()`（`skills/loader.py:134`）返回全局 dict 列表，字段：name/description/when_to_use/when_not_to_use/location/scope/active。**无 roles 字段**
- SKILL.md frontmatter 用 `yaml.safe_load` 开放解析（`parse_frontmatter`），**可加新字段不改解析器**
- 唯一"谁能用"约束是 `scope`（`all`/`main_only`/`subagent_only`），`skill_visible_to(skill, caller_scope)`（`skill_utils.py`）只区分 main vs subagent 两种调用方，**不区分 functional_role**
- `caller_scope` 经 `inherited_tool_policy.py:103-104` 盖戳（子 agent = `"subagent"`，main = `"main"`）
- `skill_list`/`skill_view` 读 `metadata["caller_scope"]` 过滤；**无 caller_role 概念**
- 子 agent 经 `build_main_tools()` 继承 skill_list/skill_view，看到同一份全局索引（仅 scope 过滤后视野不同）
- `skill_manage` 是 main_only（子 agent 拿不到，不改）
- `delegate.py::_validate_load_skills`/`_inject_skills`（注入 available_skills 给子 agent）也用 caller_scope 过滤，无 role 过滤

**缺口**：researcher/executor/reviewer/librarian 看到同一份技能列表，无角色级隔离。一个 researcher 能看到 text_to_image（该是 executor 的）、executor 能看到 multimodal_rag（该是 researcher/librarian 的）。

---

## 1. 设计

### 1.1 新增 `roles` frontmatter 字段

SKILL.md frontmatter 加可选字段：
```yaml
---
name: text_to_image
description: ...
roles: [executor]          # 只有 executor 角色可见
---
```

- `roles` 缺省 → **所有角色可见**（向后兼容，现有技能不改也能用）
- `roles` present → 只有列出的 functional_role 可见
- 与现有 `scope` 正交：`scope` 管 main vs subagent；`roles` 管 subagent 内哪个功能角色（以及 main 如果标了 role）
- 合法角色值：`researcher` / `executor` / `reviewer` / `librarian` / `general`（对齐 `FunctionalRole` 枚举）

### 1.2 scan_skills 读取 `roles`

`skills/loader.py::scan_skills` 在 SkillInfo dict 里加：
```python
{
    "name": name, "description": desc, ..., "scope": scope, "active": active,
    "roles": _normalize_roles(frontmatter.get("roles")),  # 新增：list[str] 或 None
}
```
`_normalize_roles`：None/缺省→None（全可见）；list→校验每项是合法 FunctionalRole，过滤非法值。

### 1.3 skill_visible_to 增 role 维度

`agent/tools/pub_base/skill_utils.py::skill_visible_to` 扩展：
```python
def skill_visible_to(skill: dict, caller_scope: str, caller_role: str | None = None) -> bool:
    # 现有 scope 检查（main_only/subagent_only）不变
    if not _scope_visible(skill.get("scope"), caller_scope):
        return False
    # 新增 roles 检查
    roles = skill.get("roles")
    if roles is not None and caller_role is not None:
        return caller_role in roles
    # roles 缺省 → 全可见；caller_role None（main agent 无功能角色）→ 跳过 roles 检查
    return True
```

### 1.4 caller_role 盖戳

`inherited_tool_policy.py`（子 agent 工具盖戳处，现盖 `caller_scope="subagent"`）追加：
```python
metadata.setdefault("caller_scope", "subagent")
# 新增：从 functional_role 盖 caller_role
if functional_role is not None:
    metadata.setdefault("caller_role", str(functional_role))
```
`functional_role` 在 `_assemble_child_tools`（`child_agent_factory.py:219-288`）已知（spawn 时传入）。需把 functional_role 传到 apply_tool_policy。

main agent 无 functional_role → `caller_role=None` → roles 检查跳过（main 看到所有，同现状）。

### 1.5 skill_list / skill_view 传 caller_role

`skill_list.py`、`skill_view.py` 读 `metadata["caller_role"]` 传给 `skill_visible_to`：
```python
caller_scope = metadata.get("caller_scope", "main")
caller_role = metadata.get("caller_role")  # 新增
all_skills = [s for s in all_skills if skill_visible_to(s, caller_scope, caller_role)]
```

`skill_view.py` 的 scope 校验（`:228-243`，不依赖 scan 索引，直接读目标 SKILL.md frontmatter）同样加 roles 校验。

### 1.6 delegate 路径过滤

`delegate.py::_validate_load_skills`/`_inject_skills`（父给子注入 available_skills）用 `get_skills_text(caller_scope="subagent")` — 扩展为也传 `caller_role`，过滤掉子 agent 角色不该看的技能。

### 1.7 skill_manage 校验

`skill_manage.py::_validate_frontmatter`（`:510-554`）加：若 frontmatter 含 `roles`，校验是 list 且每项是合法 FunctionalRole，否则拒绝写入。

## 2. 现有技能的 roles 分配（配置 pass）

给 builtin/auto 技能标 `roles`（缺省=全可见，只标需要隔离的）：

| 技能 | 建议 roles | 理由 |
|---|---|---|
| `text_to_image` | `[executor]` | 创作类，executor 干 |
| `image_to_text` | `[researcher, executor]` | 看图描述，researcher 调研/executor 执行都可能 |
| `video_text_to_text` | `[researcher, executor]` | 同上 |
| `speech_to_text` | 缺省（全可见） | 转录通用 |
| `multimodal_rag` | `[researcher, librarian]` | 检索类 |
| `code_wiki` | `[researcher, librarian]` | 代码知识 |
| `llm_wiki` | `[researcher, librarian]` | LLM 知识 |
| `bugfix-contract` | `[executor, reviewer]` | 修 bug / 审 bug |
| `ulw-execute` | `[executor]` | 执行 |
| `browser` | 已 `main_only` | 不改（main 专属） |
| `skill_creator` | 已 `main_only` | 不改 |
| `heartbeat` / `cron` / `clawhub` | 已 `main_only` 或缺省 | 不改 |
| `taskflow` / `todolist` | 缺省（全可见） | 任务管理通用 |

auto 技能（skill review 产出）：由 skill_manage create 时声明 `roles`（如 executor 的工作流→`roles: [executor]`）；缺省全可见。

**向后兼容**：未标 `roles` 的技能全可见，现有行为不变。配置 pass 是渐进的，先标关键的，其余缺省。

## 5. 风险与缓解

| 风险 | 缓解 |
|---|---|
| roles 标错导致角色看不到该用的技能 | 缺省全可见（向后兼容）；先只标关键技能；标错的技能可用 skill_manage patch 修正 |
| caller_role 未传递到某条路径 | 测试覆盖 skill_list/skill_view/delegate 三条路径 |
| skill_view 不走 scan 索引（直接读 frontmatter）漏 roles 校验 | §1.5 明确 skill_view 的 scope 校验处同步加 roles |
| auto 技能 skill review 产出未标 roles | skill_manage create 时引导声明 roles；缺省全可见不阻塞 |

### Kill criteria

- 若某条路径（delegate/skill_view/skill_list）漏 caller_role 导致隔离失效，该路径补上再上线
- 若配置 pass 误标导致回归（角色看不到原有技能），回退该技能的 roles 标记（删 frontmatter roles → 全可见）
