## 2. 改动细节

### 2.1 task_flows 索引（store_sqlite.py）

在 `_index_ddls()` 中新增/修改：

```python
def _index_ddls(self) -> tuple[str, ...]:
    return (
        "CREATE INDEX IF NOT EXISTS idx_taskflow_status ON task_flows(status)",
        "CREATE INDEX IF NOT EXISTS idx_taskflow_deadline ON task_flows(deadline_ts) WHERE deadline_ts IS NOT NULL",
        # 替换原 idx_taskflow_session_status，加 expected_revision 覆盖 ORDER BY
        "DROP INDEX IF EXISTS idx_taskflow_session_status",
        "CREATE INDEX IF NOT EXISTS idx_taskflow_session_status ON task_flows(session_id, status, expected_revision DESC)",
        # 新增：superseded_by IS NULL partial index
        "CREATE INDEX IF NOT EXISTS idx_taskflow_active ON task_flows(session_id, status) WHERE superseded_by IS NULL",
    )
```

**为什么 DROP + CREATE 而不是 ALTER**：SQLite 不支持 ALTER INDEX。`DROP INDEX IF EXISTS` + `CREATE INDEX IF NOT EXISTS` 是标准做法，`ensure_tables_sync` 幂等执行。

**`expected_revision DESC`**：SQLite 索引支持方向修饰符，`ORDER BY expected_revision DESC` 可以正向使用索引，不需要反向扫。

**`idx_taskflow_active`**：partial index 只含 `superseded_by IS NULL` 的行（非被取代的 flow），3 处查询的 `superseded_by IS NULL` 条件直接命中这个索引。`session_id, status` 前缀覆盖 WHERE 的 session+status 过滤。

### 2.2 memory_entries embedding partial index（db.py）

在 `build_memory_schema` 的索引列表中新增：

```python
# 现有索引（db.py:405-425）
# ...
# 新增：embedding 状态 partial index（embedding 生成 job + semantic recall 热路径）
"CREATE INDEX IF NOT EXISTS idx_memory_entries_missing_embedding ON memory_entries(target, id) WHERE archived = 0 AND embedding IS NULL",
"CREATE INDEX IF NOT EXISTS idx_memory_entries_has_embedding ON memory_entries(target, id) WHERE archived = 0 AND embedding IS NOT NULL",
```

**两个 partial index**：
- `embedding IS NULL` → `list_missing_embeddings`（找需要生成 embedding 的行）
- `embedding IS NOT NULL` → `list_with_embeddings` / `count_embeddings`（找已有 embedding 的行）

`target` 前缀覆盖 `list_missing_embeddings(target=?)` 和 `list_with_embeddings(target=?)` 的 target 过滤。

### 2.3 evidence_events partial index（evidence_ledger.py）

在 `_index_ddls()` 中新增：

```python
def _index_ddls(self) -> tuple[str, ...]:
    return (
        "CREATE INDEX IF NOT EXISTS idx_evidence_session ON evidence_events(session_id, event_id)",
        "CREATE INDEX IF NOT EXISTS idx_evidence_timestamp ON evidence_events(timestamp)",
        "CREATE INDEX IF NOT EXISTS idx_evidence_flow ON evidence_events(flow_id, event_id)",
        # 新增：event IS NULL partial index（mark_stale_for_path 热路径）
        "CREATE INDEX IF NOT EXISTS idx_evidence_unmarked ON evidence_events(session_id, event_id) WHERE event IS NULL",
    )
```

**`event IS NULL`**：`mark_stale_for_path` 查 `event IS NULL` 的行（未标记 stale/broken/unmark 的事件）。partial index 只含这些行，session 前缀覆盖 `mark_stale_for_path` 的 `session_id = ?` 过滤。

`mark_stale_for_path_all_sessions`（跨 session）不设 session 前缀仍需扫 partial index，但 partial index 只含 `event IS NULL` 行，比全表小得多。

## 5. 风险

| 风险 | 缓解 |
|------|------|
| DROP INDEX + CREATE INDEX 在运行中锁表 | SQLite DDL 是瞬间操作（索引重建），WAL 模式下不阻塞读写 |
| partial index 增加写入开销 | partial index 只含符合条件的行，写入时只在条件满足时更新索引，开销极小 |
| `idx_taskflow_session_status` 重建影响正在运行的查询 | `ensure_tables_sync` 在连接初始化时跑，不在查询中途 |
| 索引不被使用（查询计划优化器选择全扫） | 用 EXPLAIN QUERY PLAN 验证；如果不使用，检查统计信息（ANALYZE） |

### Kill criteria

- 若 partial index 写入开销在 high-throughput 场景（大量文件编辑）下显著，去掉 evidence_events 的 partial index（gap 4 影响最小）
- 若 `idx_taskflow_session_status` 扩展后其他查询变慢，改为新增独立索引而不是扩展现有索引
