## ZCode 参考设计要点

ZCode 的 subagent 实况系统有三个层次：

1. **Composer badge**（`ConversationBackgroundWorkTrigger.tsx`）：类型化计数
   （terminal/workflow/agent），点击展开内联状态面板。
2. **Directory side-pane**（`SubagentDirectorySidePane.tsx`）：两段列表
   （Running / Ended），每行含状态图标 + 标题 + 摘要 + 相对时间。
   点击行打开该子代理的 session side-pane tab。
3. **Session side-pane**（`SubagentSessionSidePane.tsx`）：包裹一个只读的
   `SessionPane`，订阅子代理的 conversation topic，展示**完整实时对话记录**
   （turn header / assistant text / reasoning / tool call / subagent / artifact
   各行按时间线排列）。这是核心设计——"实况页就是子代理的对话流本身"。

ZCode 的数据模型是 snapshot + delta 的 row 事件日志，transport 是 stdio→IPC→renderer。
sherry 不需要复制这套协议，但 UI 布局可以借鉴。

#### 2.3 Header 区

- 从 `stores/subagent.ts::taskRuns` 中按 `run_id` 查找当前 run。
- `useSubagentTasks()` 的 `statusLabel`/`roleLabel`/`badgeClass` 渲染 status badge。
- Elapsed timer：`started_at` → 实时计时（1s interval，复用 TasksButton 的计时器模式）。
- Run ended 后显示 `ended_at` + `outcome` + `ended_reason`。

#### 2.4 "实况" Tab——Trajectory 时间线

嵌入 `SubagentTrajectory.vue`（计划 A 第三部分已定义）。

- 用 run 的 `child_session_key` 作为 `sessionId` prop。
- 调用 `useTrajectoryStream(ref(childSessionKey))` 连接 trajectory WS。
- 渲染工具调用时间线（tool_start/tool_end/turn_start/turn_end/error）。

**依赖**：计划 A 第三部分的 trajectory WS 推送通道必须先完成。

**过渡方案**（trajectory WS 未完成时）：先用 HTTP 轮询
`GET /sessions/<childSessionKey>/trajectory?limit=100`，3s interval 定时刷新。
样式不变，仅数据源从 WS 换为 HTTP poll。后续切换到 WS。

#### 2.5 "摘要" Tab——Run 详情

复用已删除的 `SubagentRunDetail.vue` 中的信息字段（但不包含 flow graph / steer UI）：
- Status / Role / Depth / Agent ID / Parent Session
- Started / Ended / Outcome / Ended Reason
- Task 描述（完整文本）
- Result Text（completed 后的返回结果，clipped 4000 chars）
- Pause Reason（如有）

从 `SubagentRunRecord` 的 public fields 直接读取
（`execution.status`/`execution.outcome`/`execution.started_at`/`execution.ended_at`/
`completion.result_text`/`delivery.status` 等）。

#### 2.6 "Steer" Tab——指令注入

- `Textarea` 输入框 + "发送并继续"按钮。
- 调用 `POST /subagents/steer`（`composables/bridge/subagent.ts`，已有 `steerSubagentRun`）。
- 仅对 `RUNNING`/`INTERRUPTED` 状态的 run 启用，`TERMINAL` 状态禁用并显示提示。
- 发送后 toast 确认 + 清空输入框。

## 与其他计划的依赖关系

```
删除任务详情 (已完成) ──→ 计划 C (智能体列表 + 实况页)
计划 A (trajectory WS) ──┘
     │
     └─→ SubagentTrajectory.vue (嵌入实况 tab 的"实况"section)
```

- **前置已完成**：taskDetail tab 及其组件已删除，TasksButton 的 focus 事件当前
  是 no-op，正等计划 C 提供跳转目标。
- **计划 A 的 trajectory WS 是计划 C 实况 tab 的理想数据源**，但非硬性前置——
  过渡期可用 HTTP 轮询，后续切换到 WS。
- 三个计划可并行开发前端组件，但集成顺序为 B → A(traj WS) → C。

## 过渡期处理

如果三个计划不能同时落地，过渡策略：

1. **前置已完成**（删除 taskDetail tab）：TasksButton 的 run 点击已变为 no-op，
   用户暂时无法查看子代理详情，但不影响主功能。
2. **再做计划 C 基础版**（不含实况 trajectory tab）：只做 Header + 摘要 + Steer
   三个 tab，用户可查看 run 详情和发送指令，但看不到实时工具调用流。
3. **最后集成计划 A 的 trajectory WS**：实况 tab 从 HTTP 轮询切换到 WS 推送。
