# 计划：子 agent task 压缩存活 + 漂移检测

- 日期：2026-11-23
- 状态：**待评审**
- 来源：
  1. 子 agent 压缩后原始 task 丢失——task 不在 system prompt 里、无 `origin: "user"`、被误标 `[System notice]` 截断 500
  2. CompletionJudge 只判 DONE/CONTINUE，不判是否在做原任务
- 风险等级：**低-中** — 3 处基础修复 + CompletionJudge 扩展
- 依赖：无
- 可独立执行：✅

## 1. 设计

### 1.1 task 放进 system prompt（修 8 — 最根本）

`system_prompt.py` 新增 "Your Task" section。system prompt 不受压缩影响，task 永远在。

### 1.2 子 agent Summarization 开 need_update_system_prompt（修 10）

压缩后重建 system prompt（含 task）。

### 1.3 task HumanMessage 加 origin: "user"（修 9 — 兜底）

压缩时 summary 正确标 task 为 `[User]` 截断 2000。

### 1.4 漂移检测（CompletionJudge DRIFTED）

CompletionJudge prompt 加 drift check + acceptance 条款，返回 `DONE / CONTINUE / DRIFTED`。

### 1.5 acceptance 持久化（给 CompletionJudge + 纠偏指令用）

spawn 时从 task 提取 acceptance（规范性关键词条款），持久化到 state register。给 CompletionJudge 做比对基准 + 纠偏指令内容。

不需要 goal/revision/validation_criteria/source——CompletionJudge 的 prompt 已有完整 task 原文（`task_text=user_message`），不需要额外提取；revision 没有比对对象（task 不可变）；validation_criteria 是 StepJudge 的职责。

### 1.6 为什么不需要进度追踪

子 agent 的进度是它自己的消息列表（正常 turn）或 summary（压缩后），模型自己管理。进度是动态的——子 agent 换方向时步骤变、推倒重来时进度清零，静态的 verified progress 快照跟不上。CompletionJudge 的职责是判断"完成了没 / 在做原任务吗"，不是追踪进度。

### 1.7 为什么不需要锚钉 reminder 中间件

task 原文在 system prompt 里，每 turn 都在。模型看 task 原文比看 acceptance 摘录更好。

### 1.8 三层防线

| 层 | 机制 | 解决什么 |
|----|------|---------|
| 1 system prompt 含 task（修 8+10） | task 永远在 | task 压缩存活 |
| 2 task HumanMessage origin:user（修 9） | summary 正确标记 task | 兜底 |
| 3 CompletionJudge DRIFTED | 每 turn 检查是否在做原任务 | 漂移检测 + 纠偏 |

### 3.5 CompletionJudge drift check（completion_judge.py）

#### CompletionVerdict 加 DRIFTED

```python
class CompletionVerdict(StrEnum):
    DONE = "done"
    CONTINUE = "continue"
    DRIFTED = "drifted"
```

#### system prompt 加 drift check

在 `COMPLETION_JUDGE_SYSTEM_PROMPT`（line 49-71）的 CONTINUE 选项后追加：

```
DRIFTED — the subagent's recent work is UNRELATED to the original task:
- The agent is working on something that does not serve the original task
- The agent has veered off into refactoring/fixing unrelated code
- Preparatory work (reading files, understanding code) is ALIGNED, not DRIFTED

Reply ONLY with a single JSON object on one line:
{"verdict": "drifted", "reason": "<one sentence>", "drift_correction": "<one paragraph: tell the subagent to refocus on the original task>"}
```

#### 正则扩展

```python
_VERDICT_PATTERN = re.compile(
    r'"(?:verdict)"\s*:\s*"(done|continue|drifted)"', re.IGNORECASE
)
```

#### CompletionJudgeResult 加 drift_correction

```python
class CompletionJudgeResult(NamedTuple):
    verdict: CompletionVerdict
    reason: str
    continuation_prompt: str
    drift_correction: str = ""
```

#### _parse_completion_response 扩展

```python
def _parse_completion_response(raw: str) -> CompletionJudgeResult:
    data = _load_json_object(raw)
    if data is not None:
        verdict = _coerce_verdict(data.get("verdict"))
        if verdict is not None:
            continuation = (
                str(data.get("continuation_prompt") or "")
                if verdict is CompletionVerdict.CONTINUE
                else ""
            )
            drift_correction = (
                str(data.get("drift_correction") or "")
                if verdict is CompletionVerdict.DRIFTED
                else ""
            )
            return CompletionJudgeResult(
                verdict, str(data.get("reason") or ""), continuation, drift_correction
            )
    match = _VERDICT_PATTERN.search(raw)
    if match is not None:
        verdict = _coerce_verdict(match.group(1))
        if verdict is not None:
            return CompletionJudgeResult(verdict, "", "", "")
    logger.warning("CompletionJudge: no usable verdict, failing open as DONE")
    return CompletionJudgeResult(CompletionVerdict.DONE, "judge parse failure (fail-open)", "", "")
```

#### _build_completion_prompt 传 acceptance

```python
def _build_completion_prompt(
    task_text: str,
    last_response: str,
    evidence_summary: str | None,
    acceptance: list[str] | None = None,
) -> str:
    parts = [f"## Task\n{task_text}", f"## Subagent Response\n{last_response}"]
    if evidence_summary:
        parts.append(f"## Verification Evidence\n{evidence_summary}")
    else:
        parts.append("## Verification Evidence\n(none recorded)")
    if acceptance:
        items = "\n".join(f"{i+1}. {a}" for i, a in enumerate(acceptance))
        parts.append(f"## Acceptance Criteria (assess alignment)\n{items}")
    parts.append("## Your Verdict")
    return "\n\n".join(parts)
```

## 4. 执行效果

### 正常执行

```
spawn: system prompt 含 task，acceptance 写 state register
turn 1: 模型通过 system prompt 看到 task → CompletionJudge 判 CONTINUE（acceptance 传入）
turn 2: 同上
turn 3: DONE → 完成 → 清除 acceptance
```

### 压缩后 task 存活

```
turn 5: 压缩 → task 被吃掉但 system prompt 重建含 task（修 10 + 修 8）
  → summary 标 task 为 [User] 截断 2000（修 9）
  → acceptance 在 state register 不受影响
  → CompletionJudge 下一 turn 仍能用 acceptance 判断
```

### 漂移检测

```
turn 1: agent 修复 JSON BOM → CONTINUE
turn 2: agent 开始重构 encoding 模块 ← 漂移
turn 3: CompletionJudge 看到无关工作 → DRIFTED → drift_count=1 → 纠偏
turn 4: agent 回到 JSON BOM → CONTINUE
turn 5: DONE
```

### 连续漂移

```
turn 3: DRIFTED → drift_count=1 → 纠偏
turn 4: 又漂移 → drift_count=2 → 纠偏
turn 5: 又漂移 → drift_count=3 → BUDGET_EXHAUSTED + task_drift_3_times
```

## 7. 风险

| 风险 | 缓解 |
|------|------|
| CompletionJudge 误判 DRIFTED | prompt 明确："前置工作算 ALIGNED"；acceptance 提供比对基准 |
| 纠偏打断合理探索 | drift_count 累积，连续 3 次才报告主 agent |
| system prompt 变长影响前缀缓存 | "## Your Task" 只在 spawn 时写，重建时内容不变（task 不可变） |
| need_update_system_prompt 增加压缩开销 | 子 agent 压缩频率低（40 条触发），一次 prompt_builder 调用 |

### Kill criteria

- 若误判率高（> 20%），改为连续 3 次 DRIFTED 才纠偏
- 若 drift check 增加延迟，改为每 3 turn 检查
- 若 system prompt 变长影响 token，限制 task 截断到 2000 字符
