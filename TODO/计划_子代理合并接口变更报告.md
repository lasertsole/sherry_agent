# 计划：合并报告中标注接口级变更（renamed/added/removed symbols）

## 背景

isolated subagent 合并回父树时，合并报告（`_report_block`）目前只报
applied/created/deleted 的**路径列表**，父 agent 不知道**哪些函数/类/方法被改名、
删除或新增**。如果 subagent A 把 `utils.py` 里的 `foo()` 改名成 `bar()`，
subagent B 在另一个新文件里还在调用 `foo()`，两个文件合并零冲突（不同路径，
CAS 不挡），但产出代码是坏的——运行时报错。

合并的 CAS 只有 per-file 的 revision 感知，**零语义感知**。本计划在合并报告中
追加一节"接口变更"，让父 agent 自己判断其他 subagent 是否还在用旧名字。

## 目标

合并回父树后，在完成报告里追加一节，列出该 subagent 改名/新增/删除的函数、
类、方法（Python/TS/JS/Rust/Go，tree-sitter 已支持的语言）。父 agent 读到后
可主动检查其他子 agent 的产出是否引用了旧名字。

## 设计要点

- **数据采集时机**：在 `_merge_one` 写入/删除文件**之前**读取新旧字节（此时
  `source` = child 新内容、`target` = parent 旧内容都在磁盘上），调
  `extract_symbols` 提取两版符号集做 diff。写完之后旧内容就没了。
- **符号提取**：复用现有的 `agent/tools/code_intel/extract.py::extract_symbols`
  （tree-sitter，支持 Python/TS/JS/Rust/Go），不引入新依赖。
- **重命名检测**：同 kind + 同 parent class + `levenshtein(old, new) ≤ 2` 的
  removed+added 对归类为 renamed，复用 `indexer.py::levenshtein`。
- **fail-open**：语法错误、超大文件、不支持的语言——记录 error 或跳过，绝不
  中断合并。

## 改动清单

### 1. 新文件 `agent/tools/code_intel/symbol_diff.py`

纯比较器模块，不碰磁盘/DB，只依赖 `extract.py` + `indexer.py::levenshtein`
+ `CODE_INTEL` 语言表。

**数据结构：**

```python
@dataclass(frozen=True, slots=True)
class SymbolChange:
    name: str
    kind: str           # "function" | "method" | "class"
    parent: str | None  # 类名（methods），None（自由函数/类）
    line: int

@dataclass(frozen=True, slots=True)
class RenameChange:
    old_name: str
    new_name: str
    kind: str
    parent: str | None
    old_line: int
    new_line: int

@dataclass(slots=True)
class InterfaceDelta:
    relpath: str
    language: str
    added: list[SymbolChange]
    removed: list[SymbolChange]
    renamed: list[RenameChange]
    error: str | None = None

    @property
    def has_changes(self) -> bool:
        return bool(self.added or self.removed or self.renamed)
```

**核心函数：**

- `language_for_extension(suffix) -> str | None`
  — 查 `CODE_INTEL["code_intel_language_map"]`
- `diff_file_interface(old_bytes, new_bytes, language, relpath, *,
  rename_threshold=2, max_file_bytes=1_000_000) -> InterfaceDelta | None`
  - `old_bytes=None` → 文件新建，所有符号为 added
  - `new_bytes=None` → 文件删除，所有符号为 removed
  - 两者都有 → 调两次 `extract_symbols`，按 `(kind, name, parent_class)`
    做集合差，再在同 `(kind, parent)` 组内贪心匹配 renamed
  - 超大文件 / 语法错误 → 返回带 `error` 的 delta，不抛异常
- `_diff_symbol_sets(old, new, *, rename_threshold)` — 内部比较器
  - 先做精确集合差（removed/added）
  - 再在同组内按 Levenshtein 贪心配对 renamed
  - 未配对的留在 removed/added

### 2. 修改 `agent/tools/subagent/isolation/merge.py`

**`MergeReport` 新增字段：**

```python
interface_changes: list[InterfaceDelta] = field(default_factory=list)
```

**新增 `_record_interface_change` 辅助函数**（fail-open，lazy import）：

```python
def _record_interface_change(relpath, source, target, report, *, mode):
    """在 _apply_bytes/os.unlink 之前分析接口变更。永不抛异常。"""
    try:
        from config.features import SUBAGENT_ISOLATION
        if not SUBAGENT_ISOLATION.get("interface_diff_enabled", True):
            return
        from agent.tools.code_intel.symbol_diff import (
            diff_file_interface, language_for_extension,
        )
        lang = language_for_extension(Path(relpath).suffix)
        if lang is None:
            return
        max_bytes = SUBAGENT_ISOLATION.get("interface_diff_max_file_bytes", 1_000_000)
        rename_threshold = SUBAGENT_ISOLATION.get("interface_diff_rename_levenshtein", 2)
        old_bytes = target.read_bytes() if mode in ("modified", "deleted") else None
        new_bytes = source.read_bytes() if mode in ("modified", "created") else None
        delta = diff_file_interface(
            old_bytes, new_bytes, lang, relpath,
            rename_threshold=rename_threshold, max_file_bytes=max_bytes,
        )
        if delta is not None and delta.has_changes:
            report.interface_changes.append(delta)
    except Exception:
        pass
```

**在 `_merge_one` 三个分支插入调用**（均在写/删之前）：

- deleted 分支（line ~182-184）：`_record_interface_change(..., mode="deleted")`
  → 然后 `os.unlink`
- created 分支（line ~203-204）：`_record_interface_change(..., mode="created")`
  → 然后 `_apply_bytes`
- modified 分支（line ~208-209）：`_record_interface_change(..., mode="modified")`
  → 然后 `_apply_bytes`

### Isolated workspace merged

此节。`attach_merge_report` 本身不改——它已经拼接 `_report_block` 的返回值。

## 不改的部分

- `core.py`（announce flow 编排）不改 — `MergeReport` 新字段自动从
  `merge_isolated_workspace` 流到 `attach_merge_report` → `_report_block`
- `_mark_merged_paths_stale` 不改 — 它只读 `applied/created/deleted` 路径
- 不加强制验证（不跑 type-check/test）— 只在报告里标注接口变更，由父 agent
  自主判断是否需要检查
- 不改 `extract.py` — 现有符号提取能力已足够

## 权衡

- **成本**：每个合并的文件多两次 `read_bytes()`（新旧各一次）+ 两次
  tree-sitter parse（亚毫秒到几毫秒）。典型 subagent 改 5-20 个文件，总成本
  < 100ms，在 merge lock 内可接受。
- **准确性**：Levenshtein ≤ 2 的改名检测是启发式的——`foo`→`bar`（距离 3）
  不会被归类为 rename，会显示为 removed+added，但父 agent 看到 removed `foo`
  仍然会被提醒检查。这是 fail-safe 的：宁可多报不漏报。
- **多语言**：只支持 tree-sitter 已有的 5 种语言（Python/TS/JS/Rust/Go），
  其他语言的文件静默跳过——和现有 code index 的行为一致。
