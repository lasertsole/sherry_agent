# 排队消息逐条处理改造计划

> **状态**: 待实施
> **创建日期**: 2026-09-30
> **目标**: 将排队消息 drain 从批量合并改为逐条处理（FIFO），并增强前端队列交互能力

---

## 1. 现状与目标

### 现状

```
turn 结束 → _drain_loop → claim_batch(最多20条) → 合并为1个turn → agent一次看到N条HumanMessage → 1次回复
```

前端队列交互：

- 单个顶部横幅徽章，仅显示「第 N 位 / 共 M 个」
- HITL 弹窗时徽章仍可见
- 无法编辑已排队的消息
- 无法优先处理某条排队消息

### 目标

**后端**：

```
turn 结束 → _drain_loop → claim_next(1条) → 1个turn → 1次回复
            → turn 结束 → claim_next(1条) → ... 循环直到队列空
```

**前端**：

1. HITL 弹窗时，队列列表隐藏
2. 每条排队消息显示为独立卡片，含「立刻」按钮 — 点击后中断当前 turn 并立即发送该消息（无视 FIFO）
3. 每条排队消息在发送前可重新编辑

### 3.1 `server/queue/user_input_queue.py` — 新增 3 个方法

#### 3.1.1 `cancel_queued(row_id)` — 取消单条排队消息

复用已有 `mark_terminal(row_id, "VOIDED")`（L707-730），包装为语义方法：

```python
async def cancel_queued(self, row_id: str) -> bool:
    """Cancel a QUEUED row by marking it VOIDED. No-op on CLAIMED/terminal rows."""
    await self._ensure_db()
    async with self._conn.write_transaction() as db:
        found = await QueueRepository.mark_terminal(db, UserInputQueueStatus.VOIDED.value, row_id, time.time())
    return found
```

> `mark_terminal` 已有 SQL（`_MARK_TERMINAL_SQL` L178-183），只对 `status IN ('QUEUED', 'CLAIMED')` 生效。CLAIMED 行（正在处理中）不应取消——需在 SQL 层限制只取消 QUEUED 行。

**需新增 SQL**（只取消 QUEUED，不取消 CLAIMED）：

```python
_CANCEL_QUEUED_SQL = f"""
UPDATE user_input_queue
SET status = 'VOIDED', updated_at = ?
WHERE id = ? AND status = 'QUEUED'
RETURNING {_ROW_COLUMNS};
"""
```

```python
async def update_payload(self, row_id: str, new_payload: str) -> UserInputQueueRow | None:
    await self._ensure_db()
    now = time.time()
    async with self._conn.write_transaction() as db:
```

> 只允许更新 QUEUED 状态的行；CLAIMED（正在处理中）不允许编辑。

#### 3.1.3 `prioritize(session_id, target_row_id)` — 将指定行移到队列最前

```python
_PRIORITIZE_SQL = """
UPDATE user_input_queue
SET created_at = ?,
    updated_at = ?
WHERE id = ? AND status = 'QUEUED' AND session_id = ?;
"""
```

```python
async def prioritize(self, session_id: str, row_id: str) -> bool:
    """Move a QUEUED row to the front of the FIFO queue (oldest created_at)."""
    await self._ensure_db()
    now = time.time()
    async with self._conn.write_transaction() as db:
        # 获取当前最早的 created_at
        cursor = await db.execute(
            "SELECT MIN(created_at) FROM user_input_queue WHERE session_id = ? AND status = 'QUEUED'",
            (session_id,)
        )
        min_created = (await cursor.fetchone())[0]
        target_created = (min_created or now) - 1.0  # 比最早还早 1 秒
        cursor = await db.execute(
            _PRIORITIZE_SQL, (target_created, now, row_id, session_id)
        )
        return cursor.rowcount > 0
```

> 将目标行的 `created_at` 设为比所有 QUEUED 行更早，使 `claim_next`（FIFO by `created_at ASC`）优先领取它。

```python
async def cancel_queued_message(session_id: str, client_msg_id: str) -> bool:
    """Cancel a queued message by client_msg_id."""
    store = get_default_queue()
    row = await store.find_active_by_client_msg_id(session_id, client_msg_id)
    if row is None or row.status != UserInputQueueStatus.QUEUED:
        return False
    return await store.cancel_queued(row.id)


async def update_queued_message(session_id: str, client_msg_id: str, new_message: str) -> bool:
    """Edit a queued message's payload by client_msg_id."""
    store = get_default_queue()
    row = await store.find_active_by_client_msg_id(session_id, client_msg_id)
    if row is None or row.status != UserInputQueueStatus.QUEUED:
        return False
    updated = await store.update_payload(row.id, new_message)
    return updated is not None


async def prioritize_queued_message(session_id: str, client_msg_id: str) -> bool:
    """Move a queued message to the front of the FIFO queue."""
    store = get_default_queue()
    row = await store.find_active_by_client_msg_id(session_id, client_msg_id)
    if row is None or row.status != UserInputQueueStatus.QUEUED:
        return False
    return await store.prioritize(session_id, row.id)
```

### 3.3 `server/trigger/ws/messages.py` — 新增 3 种 WS 帧类型

在 L192（`hitl_response` 分支之后）新增：

```python
# 取消排队消息
if obj.get("type") == "cancel_queued":
    msg_id = obj.get("msg_id", "")
    ok = await iqs.cancel_queued_message(session_id, msg_id)
    await _send_ws(websocket, {
        "event": "queued_cancelled",
        "session_id": session_id,
        "msg_id": msg_id,
        "ok": ok,
    })
    continue

# 编辑排队消息
if obj.get("type") == "edit_queued":
    msg_id = obj.get("msg_id", "")
    new_text = obj.get("message", "")
    ok = await iqs.update_queued_message(session_id, msg_id, new_text)
    await _send_ws(websocket, {
        "event": "queued_updated",
        "session_id": session_id,
        "msg_id": msg_id,
        "ok": ok,
    })
    continue

# 立刻发送（优先处理）：中断当前 turn + 将该消息移到队首
if obj.get("type") == "send_now":
    msg_id = obj.get("msg_id", "")
    # 1. 将目标消息移到队首（必须在 cancel 之前，否则 drain 可能在 cancel 后立即 claim_next 拿到别的消息）
    ok = await iqs.prioritize_queued_message(session_id, msg_id)
    if ok:
        # 2. 中断当前 turn → _cancel_session → task.cancel → finally → on_turn_finished → drain → claim_next 拿到 prioritized 行
        await _cancel_session(session_id)
        await _send_ws(websocket, {
            "event": "send_now_ack",
            "session_id": session_id,
            "msg_id": msg_id,
            "ok": True,
        })
    else:
        await _send_ws(websocket, {
            "event": "send_now_ack",
            "session_id": session_id,
            "msg_id": msg_id,
            "ok": False,
        })
    continue
```

**`send_now` 执行流程**：

```
前端发送 {type: "send_now", msg_id: "xxx"}
  → 后端 prioritize(session_id, row_id)  ← SQL UPDATE created_at = 最早-1
  → 后端 _cancel_session(session_id)     ← task.cancel() → CancelledError 传播
  → StreamTurn._cleanup()                ← answering = False
  → on_turn_finished(session_id)         ← drain kick
  → _drain_loop → claim_next(session_id) ← 拿到 prioritized 行（created_at 最小）
  → _execute_single → 新 turn 处理该消息
```

> **关键**：`prioritize` 必须在 `_cancel_session` 之前执行。`_cancel_session` 会 await task 取消（最多 5s），然后 finally 触发 drain。此时 `prioritize` 已完成 SQL UPDATE，`claim_next` 的 `ORDER BY created_at ASC` 会拿到目标行。

> 但需注意：`sendNow` 内部调用 `socket.sendNow()` 会触发 `_cancel_session`，后端会发 `stopped` 帧。`stopped` 帧到达时 `handleStop` 不应被触发（因为 `sendNow` 不是用户点 Stop 按钮）。需要确认 `stopped` 帧处理器是否只清理 stop 相关状态，不影响队列徽章。
>
> **分析**：`stopped` 帧处理器（agent-socket-frames.ts L110-114）只调用 `ctx.settleResolve()` 和 `ctx.flushStopResolvers()`，不调用 `handleStop`。`handleStop` 只在前端 Stop 按钮点击时调用。所以 `sendNow` 触发的后端 `stopped` 帧不会清除队列徽章。✅ 安全。

## 8. 改动影响分析

### 8.1 性能影响

| 指标                   | 改前（批量） | 改后（逐条）           |
| ---------------------- | ------------ | ---------------------- |
| N 条排队消息的 turn 数 | 1            | N                      |
| N 条排队消息的回复数   | 1            | N                      |
| Token 消耗             | 较低         | 较高（重复加载上下文） |
| 延迟                   | 较低         | 较高（N 个串行 turn）  |

### 8.2 行为变化

| 场景         | 改前                         | 改后                                    |
| ------------ | ---------------------------- | --------------------------------------- |
| 3 条排队消息 | 3 条 HumanMessage → 1 次回复 | 3 个独立 turn → 3 次回复                |
| 前端气泡     | N 用户气泡 + 1 AI 回复       | 每个用户气泡后跟 1 AI 回复              |
| HITL 弹窗    | 队列徽章仍可见               | 队列列表隐藏                            |
| 编辑排队消息 | 不支持                       | 支持（inline 编辑，blur 时提交）        |
| 优先发送     | 不支持                       | 「立刻」按钮 → 中断当前 turn + 优先处理 |

### 8.3 「立刻」按钮时序

```
用户点击「立刻」
  → 前端 sendNow(msgId)
    → socket.sendNow(msgId) → 发送 {type: "send_now", msg_id}
    → 乐观更新：移除该徽章
  → 后端收到 send_now
    → prioritize(session_id, row_id)  ← SQL: created_at = min-1
    → _cancel_session(session_id)     ← task.cancel() → CancelledError
    → StreamTurn finally → _cleanup()  ← answering=False
    → on_turn_finished → _drain_loop
    → claim_next → 拿到 prioritized 行（created_at 最小）
    → _execute_single → 新 turn
  → 前端收到 turn_started（含该 msg_id）
  → 前端收到 send_now_ack（ok=true）
  → 前端收到 chunks... → done
```

### 8.4 编辑功能时序

```
用户编辑排队消息文本 → blur 触发
  → 前端 editQueuedMessage(msgId, newText)
    → socket.sendEditQueued(msgId, newText) → 发送 {type: "edit_queued", msg_id, message}
    → 乐观更新：badge.text = newText
  → 后端收到 edit_queued
    → update_queued_message(session_id, msg_id, new_text)
      → find_active_by_client_msg_id → row
      → update_payload(row.id, new_text) ← SQL: UPDATE payload WHERE status='QUEUED'
    → 回复 queued_updated {ok: true/false}
  → 前端收到 queued_updated
    → ok: 无操作（乐观更新已完成）
    → !ok: 提示失败（消息可能已开始处理，CLAIMED 状态不可编辑）
```
