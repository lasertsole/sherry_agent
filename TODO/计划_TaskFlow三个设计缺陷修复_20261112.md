## 缺陷 1：结构化输出降级单调不可逆 + 瞬时 400 永久降级

### 1.1 现状（精确）

**persist 结构**（`model_caps.py:128-130`）：
```python
entries[key] = {
    "level": target,           # 0/1/2，只升不降
    "reason": (reason or "")[:300],
    "updated_at": datetime.now(UTC).isoformat(...),  # 最后写入时间，非升级时间
}
```

**`get_level()`（:147）**：直接返回 persisted level，无衰减：
```python
def get_level(provider, model) -> int:
    with _lock:
        entry = _load_locked().get(_key(provider, model))
    return int(entry["level"]) if entry else DEFAULT_LEVEL
```

**`escalate()`（:154）**：单调（`if target <= current: return current`），永不降级。

**`_is_structured_output_rejection()`（`child_agent_factory.py:35-38`）**：
```python
_STRUCTURED_OUTPUT_REJECTION_MARKERS = (
    "does not support this tool_choice",
    "thinking mode",
    "response_format",
    "structured output",
)
def _is_structured_output_rejection(exc) -> bool:
    text = f"{type(exc).__name__}: {exc}".lower()
    return any(marker in text for marker in _STRUCTURED_OUTPUT_REJECTION_MARKERS)
```
**问题**：不排除 429/限流/网络错误。一个含 "response_format" 字样的限流错误（如 "rate limit exceeded while processing response_format"）会触发 escalate。

### 1.2 修复

**A. persist 加 `escalated_at` + `get_level` 衰减**

```python
# model_caps.py 新增配置常量
_REPROBE_INTERVAL_S = 86400  # 24h，首次重探间隔
_REPROBE_BACKOFF = [86400, 172800, 604800]  # 24h→48h→7d 退避

# escalate() 写 escalated_at（:154 改）
def escalate(provider, model, level, reason="") -> int:
    target = max(DEFAULT_LEVEL, min(MAX_LEVEL, int(level)))
    key = _key(provider, model)
    with _lock:
        entries = _load_locked()
        current = int(entries.get(key, {}).get("level", DEFAULT_LEVEL))
        if target <= current:
            return current
        now = datetime.now(UTC)
        entries[key] = {
            "level": target,
            "reason": (reason or "")[:300],
            "updated_at": now.isoformat(timespec="seconds"),
            "escalated_at": now.isoformat(timespec="seconds"),  # 新增
            "reprobe_count": 0,  # 新增：退避次数
        }
        _save_locked(entries)
    ...
    return target

# get_level() 加衰减（:147 改）
def get_level(provider, model) -> int:
    with _lock:
        entry = _load_locked().get(_key(provider, model))
    if not entry:
        return DEFAULT_LEVEL
    level = int(entry["level"])
    if level <= DEFAULT_LEVEL:
        return level
    # 衰减：距 escalated_at 超 reprobe_interval → 回退一级重探
    escalated_at = entry.get("escalated_at")
    if not escalated_at:
        # 旧 persist 无 escalated_at → 视为远古，立即重探
        return max(DEFAULT_LEVEL, level - 1)
    try:
        age = (datetime.now(UTC) - datetime.fromisoformat(escalated_at)).total_seconds()
    except (ValueError, TypeError):
        return max(DEFAULT_LEVEL, level - 1)
    reprobe_count = int(entry.get("reprobe_count", 0))
    interval = _REPROBE_BACKOFF[min(reprobe_count, len(_REPROBE_BACKOFF) - 1)]
    if age > interval:
        return max(DEFAULT_LEVEL, level - 1)  # 回退一级，不立即写回
    return level

# 新增：spawn 成功后固化衰减后的 level
def confirm_level(provider, model, level_used: int) -> None:
    """spawn 成功后调用：若 persisted level > level_used，降到 level_used 并重置退避。"""
    key = _key(provider, model)
    with _lock:
        entries = _load_locked()
        entry = entries.get(key)
        if not entry:
            return
        persisted = int(entry.get("level", DEFAULT_LEVEL))
        if level_used < persisted:
            entries[key] = {
                "level": level_used,
                "reason": entry.get("reason", ""),
                "updated_at": datetime.now(UTC).isoformat(timespec="seconds"),
                "escalated_at": datetime.now(UTC).isoformat(timespec="seconds") if level_used > DEFAULT_LEVEL else "",
                "reprobe_count": 0 if level_used <= DEFAULT_LEVEL else int(entry.get("reprobe_count", 0)),
            }
            _save_locked(entries)
```

**B. `lifecycle.py` spawn 成功后调 `confirm_level`**

在 `lifecycle.py:670-697` 的 spawn 成功路径（`agent_result = await _invoke(messages)` 不抛异常后）加：
```python
# spawn 成功，固化当前 level（若 get_level 返回了衰减后的 level）
if strategy_level > DEFAULT_LEVEL or output_schema is not None:
    model_caps.confirm_level(*identity, strategy_level)
```

**C. `_is_structured_output_rejection` 排除瞬时错误**

```python
# child_agent_factory.py:27 改
_STRUCTURED_OUTPUT_REJECTION_MARKERS = (
    "does not support this tool_choice",
    "thinking mode",
    "response_format",
    "structured output",
)
_TRANSIENT_EXCLUSION_MARKERS = (
    "429", "rate_limit", "rate limit", "too many requests",
    "timeout", "timed out", "connection", "temporarily",
)

def _is_structured_output_rejection(exc) -> bool:

```

**D. 手动恢复 API + 前端**


## 缺陷 2：CompletionJudge budget 耗尽标 OK → 改独立 outcome

### 2.1 现状（精确）

**`RunOutcomeStatus`**（`types/registry.py:36-42`）：
```python
class RunOutcomeStatus(StrEnum):
    OK = "ok"
    ERROR = "error"
    TIMEOUT = "timeout"
    KILLED = "killed"
```

**`lifecycle.py:509-513`**：
```python
if turns_used >= goal_max_turns:
    return result_text, RunOutcome(
        status=RunOutcomeStatus.OK,              # ← "放弃完成"标成 OK
        error="goal_loop_budget_exhausted",
    )
```

**`delivery.py:496-502`**：
```python
declared_outcome = (
    "failure"
    if outcome_status in (RunOutcomeStatus.TIMEOUT, RunOutcomeStatus.KILLED)
    else None                                    # ← OK 走 None → step 标 done
)
```

**消费点**：49 处读 `RunOutcomeStatus.*`（subagent 目录）。大部分是 `== TIMEOUT` / `== OK` / `== KILLED` 精确比较，新 status 会落入 else/default。

### 2.2 修复

**A. 新增 StrEnum 值**

```python
# types/registry.py:36
class RunOutcomeStatus(StrEnum):
    OK = "ok"
    ERROR = "error"
    TIMEOUT = "timeout"
    KILLED = "killed"
    BUDGET_EXHAUSTED = "budget_exhausted"        # 新增
```

**B. `lifecycle.py:509-513` 改 outcome**

```python
if turns_used >= goal_max_turns:
    return result_text, RunOutcome(
        status=RunOutcomeStatus.BUDGET_EXHAUSTED,  # 非 OK
        error="goal_loop_budget_exhausted",
    )
```

**C. `delivery.py:496-502` 处理 BUDGET_EXHAUSTED → step blocked**

```python
if outcome_status in (RunOutcomeStatus.TIMEOUT, RunOutcomeStatus.KILLED):
    declared_outcome = "failure"
elif outcome_status == RunOutcomeStatus.BUDGET_EXHAUSTED:
    declared_outcome = "blocked"                   # 不 fail，让 agent 决定
else:
    declared_outcome = None
```

**D. `taskflow_resume.py` 处理 `step_outcome="blocked"`**

当前 `taskflow_resume.py` 处理 `"failure"`（标 FAILED）。需加 `"blocked"` 分支：
```python
elif declared_outcome == "blocked":
    set_step_status(step, StepStatus.BLOCKED,
        fail_reason=f"budget_exhausted: child goal loop 耗尽，检查 partial 产出")
    # result_text 仍记进 result_record（agent 可读）
    # dependents 不解锁（blocked），agent 可 retry/replan/手动推进
```

**E. 下游消费者适配（49 处）**

grep 所有 `RunOutcomeStatus.` 消费点，逐一确认新 status 落入正确分支：

| 文件 | 消费模式 | BUDGET_EXHAUSTED 落入 | 需改？ |
|---|---|---|---|
| `delivery.py` | `in (TIMEOUT, KILLED)` → failure | else → None | **改**（加 elif → blocked） |
| `lifecycle.py:382` | `in (ERROR, TIMEOUT)` → 错误处理 | else → 正常 | 不改（BUDGET_EXHAUSTED 不是 error/timeout，走正常路径） |
| `announce/output.py` | `OK`/`TIMEOUT`/`KILLED` 各有文本映射 | else → 默认文本 | 加 `"budget_exhausted": "budget_exhausted"` 文本映射 |
| `registry/completion.py` | `== OK` 判完成 | else → 未完成 | 不改（BUDGET_EXHAUSTED 不是 OK，正确视为未完成） |
| `control/kill.py`/`steer.py` | `== KILLED`/`== TIMEOUT` | else | 不改 |
| trajectory/summary | 按 status 文本展示 | 显示 "budget_exhausted" | 可选：加友好文案 |

**大部分不需改**（精确比较，新 status 落入 else 是正确行为）。只需改 `delivery.py`（加 blocked 分支）+ `taskflow_resume.py`（加 blocked 处理）+ `output.py`（加文本映射）。

### 2.2 测试

| 用例 | 验证 |
|---|---|
| `test_budget_exhausted_outcome` | goal_max_turns 耗尽 → `RunOutcomeStatus.BUDGET_EXHAUSTED`（非 OK） |
| `test_budget_exhausted_step_blocked` | BUDGET_EXHAUSTED → step 标 BLOCKED（非 FAILED、非 DONE） |
| `test_budget_exhausted_result_preserved` | result_text 仍记录（agent 可读 partial） |
| `test_budget_exhausted_dependents_not_unlocked` | blocked step 的 dependents 保持 blocked |
| `test_ok_still_marks_done` | 正常 OK → step DONE（回归） |
| `test_timeout_still_marks_failure` | TIMEOUT → step FAILED（回归） |

### 2.3 Kill criteria

- 若 blocked 导致 flow 频繁卡住（agent 不推进）→ 回退为标 failed（保留 BUDGET_EXHAUSTED outcome 用于 trajectory，但 step 处理回 failure）
- 若下游适配工作量过大 → 缩小：只改 lifecycle + delivery + taskflow_resume，trajectory 显示 "OK (budget exhausted)" 文本

## 缺陷 3：cross-session stale 子串改 path-aware 匹配

### 3.1 现状（精确，两处）

**处 1 — `_EVIDENCE_PATH_MATCH` SQL 常量（`evidence_ledger.py:75`）**：
```python
_EVIDENCE_PATH_MATCH = (
    "(instr(COALESCE(command, ''), ?) > 0 "           # ← 裸子串
    "OR EXISTS (SELECT 1 FROM json_each(COALESCE(modified_files_json, '[]')) WHERE value = ?))"
)
```

**处 2 — `_event_matches` legacy 回退（`evidence_ledger.py:673`）**：
```python
file_path = str(event.get("file_path") or "")
return bool(file_path) and file_path in command             # ← Python 裸子串
```

**同文件已有正确函数**（`evidence_ledger.py:632-660`）`_command_references_path(command, path)`：`shlex.split` 分词 + path-aware（精确/后缀）。新行已用（行 703）。

### 3.2 修复

**处 1 — SQL 常量（:75 改）**：

```python
# 移除 instr(command) 分支，只走 modified_files 精确/前缀
_EVIDENCE_PATH_MATCH = (
    "EXISTS (SELECT 1 FROM json_each(COALESCE(modified_files_json, '[]')) "
    "WHERE value = ? OR value LIKE (? || '/%'))"
)
```

legacy rows（`modified_files_json` 为空/NULL）→ `json_each` 空数组 → 不匹配 → 不参与 cross-session stale（不误标）。

**处 2 — `_event_matches`（:673 改）**：

```python
def _event_matches(event: dict, command: str) -> bool:
    event_command = event.get("command")
    if event_command:
        return str(event_command) == command
    file_path = str(event.get("file_path") or "")
    # 旧：return bool(file_path) and file_path in command
    # 新：复用同文件已有的 token-aware 函数
    return bool(file_path) and _command_references_path(command, file_path)
```

`_command_references_path` 已在同文件（:632），用 `shlex.split` 分词命令后 path-aware 匹配。`a.py` 不会误匹配 `bla.py`（token 级比较）。

### 3.3 下游影响

| 消费点 | 影响 |
|---|---|
| `mark_stale_for_path_all_sessions`（用 `_EVIDENCE_PATH_MATCH`） | SQL 少一个分支，参数不变（`?` 仍是 path） |
| `derive_evidence_state`（用 `_event_matches`） | legacy stale 事件匹配从子串改 token-aware |
| 新行（有 modified_files） | 不受影响（本来就精确匹配） |
| legacy rows | 不再参与 cross-session stale（处 1）/ token-aware 匹配（处 2） |

### 3.4 测试

| 用例 | 验证 |
|---|---|
| `test_no_false_positive_substring` | 改 `a.py` → 不标 command 含 `bla.py` 的 session（处 1 SQL） |
| `test_exact_path_match` | 改 `src/a.py` → 标 modified_files 含 `src/a.py` 的 session |
| `test_directory_prefix` | 改 `src/foo/` → 标 modified_files 含 `src/foo/bar.py` 的 session |
| `test_legacy_row_no_cross_session` | legacy row（无 modified_files）→ 不参与 cross-session stale |
| `test_event_matches_token_aware` | `file_path="a.py"` + command `"python bla.py"` → `False`（处 2） |
| `test_event_matches_correct` | `file_path="src/a.py"` + command `"pytest src/a.py"` → `True`（处 2） |

### 3.5 Kill criteria

- 若废弃 command 子串后漏标率上升 → 处 1 回退为 `instr` + 路径边界（前后非字母数字）
- 若 `_command_references_path` 对某些命令漏匹配 → 处 2 回退为 `file_path in command` + word-boundary 正则

## 整体验收

1. 瞬时 429/网络错误不 escalate；降级带衰减可重探（24h→48h→7d 退避）；spawn 成功固化；可手动清除（API + 前端）
2. CompletionJudge budget 耗尽 → `BUDGET_EXHAUSTED`（非 OK）→ step blocked（非 failed）→ agent 读 partial 决定
3. cross-session stale 用 modified_files 精确/前缀匹配（处 1）+ token-aware（处 2），`a.py` 不误标 `bla.py`
4. 三条各自回归测试全过
5. 不破坏现有 TaskFlow / subagent / evidence 行为
