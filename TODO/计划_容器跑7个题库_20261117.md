- 日期：2026-11-17
- 状态：**待评审**

## 1. 总体架构

```
Host（Linux 服务器，Docker/Podman）
├── Sherry agent（Python 进程，evals/external_bench.py harness）
│   ├── EvalSandbox（隔离 DB/workspace）
│   ├── agent 调 async_generate（真实 LLM）
│   └── 工具替换：
│       ├── terminal → DockerBridge（docker exec 在任务容器内）
│       └── browser → CDP Chromium（仅 WebArena/VWA/OSWorld）
│
├── 每个题目的任务容器
│   ├── DevBench: 代码仓库 checkout + 测试
│   ├── WebArena: web 应用 docker-compose
│   ├── OSWorld: Ubuntu/Windows 桌面环境
│   ├── Terminal-Bench: 每题独立 Dockerfile
│   ├── TAU-bench: 模拟 API 服务
│   ├── GAIA: 文件/网页/工具任务
│   └── CyberSecEval: 安全环境
│
└── 评分容器（每题独立）
    ├── DevBench: pytest / reward.json
    ├── WebArena: 官方评估脚本
    ├── OSWorld: 官方评估脚本
    ├── Terminal-Bench: pytest summary
    ├── TAU-bench: 官方 task_eval
    ├── GAIA: 官方答案匹配
    └── CyberSecEval: 官方评分脚本
```

## 2. 环境要求

### 2.1 Host 服务器

| 要求 | 最低 | 推荐 |
|------|------|------|
| CPU | 8 核 | 16+ 核 |
| 内存 | 32 GB | 64+ GB（OSWorld/WebArena 重） |
| 磁盘 | 100 GB | 200+ GB（镜像+数据集） |
| Docker/Podman | Docker 24+ / Podman 4+ | Docker 24+ |
| GPU | 不需要（用云 LLM） | 不需要 |
| 网络 | 需要外网（拉镜像+调 LLM API） | |
| OS | Linux（Ubuntu 22.04+ 推荐） | Windows 不支持 bwrap 沙箱 |

### 2.2 LLM API

```bash
MAIN_LLM_API_KEY=sk-xxx           # 主模型（Claude/GPT-4 等）
MAIN_LLM_API_BASE=https://xxx     # API 端点
MAIN_LLM_MODEL_NAME=claude-3.5-sonnet  # 模型名
```

### 2.3 容器运行时


## 3. 七个题库适配器

### 3.1 DevBench / SWE-bench / Multi-SWE-bench（代码开发任务）

**题库**：
- SWE-bench Verified（500 题，Python）
- Multi-SWE-bench（字节跳动开源，多语言：Java/C++/Go/Rust/JS/TS/C# 等，题数待核实）

**数据集**：
```bash
# SWE-bench Verified
pip install swebench
python -c "from swebench.harness.run_evaluation import main; main()"
# 或下载数据集
wget https://huggingface.co/datasets/princeton-nlp/SWE-bench_Verified/resolve/main/test.json

# Multi-SWE-bench（字节跳动）
git clone https://github.com/bytedance/Multi-SWE-bench.git
# 数据集从 HuggingFace 下载
# bytedance-research/Multi-SWE-bench
# 题数/语言覆盖/运行方式待网络恢复后核实
```

**任务容器**：每题一个——SWE-bench 提供 per-instance Docker image（`sweb.eval.x86_64.<repo>:<version>`）；Multi-SWE-bench 按语言提供对应环境镜像

**Sherry 适配器**（新建 `evals/devbench/suite.py` + `evals/multi_swe_bench/suite.py`）：
- 复用 DeepSWE 的结构（最接近的模板）
- SWE-bench 和 Multi-SWE-bench 格式相同（repo + base commit + test patch + problem statement），共用适配器逻辑，数据集来源不同
- 每题：
  1. checkout 代码仓库到指定 commit
  2. bind-mount 到任务容器
  3. agent 通过 DockerBridge terminal 在容器内工作
  4. agent 提交 patch
  5. 评分容器跑 test patch → pass/fail

**评分**：SWE-bench 官方评估——`python -m swebench.harness.run_evaluation`（两个题库格式一致，共用评估）

**完整跑所有题**：
```bash
# SWE-bench Verified（500 题）
uv run python evals/evals.py devbench --all

# Multi-SWE-bench（多语言，题数待核实）
uv run python evals/evals.py multi_swe_bench --all
# 可按语言筛选
uv run python evals/evals.py multi_swe_bench --lang java --all
uv run python evals/evals.py multi_swe_bench --lang go --all
```

**预计耗时**：
- SWE-bench：500 题 × ~10 分钟/题 = ~83 小时
- Multi-SWE-bench：待核实题数后估算

### 3.2 WebArena（Web 浏览器任务）

**题库**：WebArena（812 题）

**数据集**：
```bash
git clone https://github.com/web-arena-g/webarena.git
cd webarena
# 启动 web 应用环境（docker-compose）
docker-compose -f docker-compose.yml up -d
# 包含：GitLab、Reddit、电商网站、内容管理 等 web 应用
```

**任务容器**：不需要 per-task 容器——WebArena 的 web 应用在 docker-compose 里常驻运行

**Sherry 适配器**（新建 `evals/webarena/suite.py`）：
- **不调用 `trim_tools()`**——保留 browser 工具
- 设 `BROWSER_AGENT["enabled"]=1`
- Chromium 指向 WebArena 的 docker-compose URL（如 `http://localhost:8080`）
- 每题：
  1. 从 WebArena 数据集读 task config（起始 URL + 任务描述 + 评估函数）
  2. agent 用 browser 工具导航/点击/输入
  3. agent 完成任务后在浏览器中达到目标状态
  4. 评估脚本检查目标状态

**评分**：WebArena 官方评估——`evaluator.py` 检查目标 URL/元素状态

**完整跑所有题**：
```bash
uv run python evals/evals.py webarena --all
# 跑 WebArena 全部 812 题
```

**预计耗时**：812 题 × ~5 分钟/题 = ~68 小时

## 5. 完整跑所有题的执行方案

### 5.1 分批跑（避免单次跑太久）

每个题库的题量 × 每题耗时 = 总耗时。大部分题库 >24 小时，需要分批：

```bash
# 分批跑（每批 50 题）
uv run python evals/evals.py devbench --batch 0-49
uv run python evals/evals.py devbench --batch 50-99
# ...

# 或连续跑（后台 + 日志）
nohup uv run python evals/evals.py devbench --all > devbench.log 2>&1 &
```

### 5.2 并行跑（多题同时）

当前 harness 是串行（一题一题跑）。可以改为并行：

```python
# 伪代码
async def run_all_tasks(tasks):
    semaphore = asyncio.Semaphore(MAX_CONCURRENT)  # 默认 4
    async def run_one(task):
        async with semaphore:
            return await run_task(task)
    return await asyncio.gather(*[run_one(t) for t in tasks])
```

**并行风险**：
- 多个任务容器同时运行 → 内存/CPU 压力
- DockerBridge 需要支持多容器同时
- LLM API 并发请求 → 可能触发 rate limit

**推荐**：串行跑 + 分批，不并行（避免复杂度）。

### 5.3 断点续跑

```bash
# 记录已完成的题
uv run python evals/evals.py devbench --all --resume
# 从上次中断处继续，跳过已完成的题
```

需要在 `eval_report.json` 里记录已完成题的 task_id，`--resume` 时跳过。

### 7.2 上下文命中率

**定义**：agent 在执行任务时，有多少比例的上下文窗口内容是"有用"的（命中了完成任务所需的信息），vs 被无关内容（过期 reminder / 冗余 tool result / 过长 summary）浪费。

**采集方式**：在每题执行结束后，分析 agent 的上下文窗口内容：

```json
// tasks/<task_id>/context_usage.json
{
  "task_id": "swe-bench-001",
  "turns": [
    {
      "turn": 1,
      "context_window_tokens": 85000,
      "breakdown": {
        "system_prompt": { "tokens": 5000, "hit": true },
        "reminder_block": { "tokens": 3000, "hit": null, "note": "reminder 不参与命中计算" },
        "user_message": { "tokens": 500, "hit": true },
        "tool_results": [
          { "tool": "read_file", "tokens": 8000, "hit": true, "note": "读了目标文件" },
          { "tool": "search_files", "tokens": 3000, "hit": true, "note": "找到了相关代码" },
          { "tool": "terminal", "tokens": 2000, "hit": false, "note": "跑了无关命令" }
        ],
        "ai_messages": { "tokens": 12000, "hit": null, "note": "agent 自己的输出不参与命中计算" },
        "summarized_history": { "tokens": 5000, "hit": null, "note": "压缩后的历史不参与命中计算" }
      },
      "effective_tokens": 16500,
      "wasted_tokens": 2000,
      "hit_rate": 0.89,
      "total_analyzed_tokens": 18500
    }
  ],
  "aggregate": {
    "avg_hit_rate": 0.82,
    "total_effective_tokens": 420000,
    "total_wasted_tokens": 92000,
    "wasted_breakdown": {
      "irrelevant_tool_results": 60000,
      "irrelevant_file_reads": 20000,
      "redundant_commands": 12000
    }
  }
}
```

**命中判定规则**：
- **system_prompt**：始终 hit（任务必需）
- **reminder_block**：不参与命中计算（系统注入，agent 无法控制）
- **user_message**：始终 hit（任务描述）
- **tool_result**：如果该工具调用的结果直接用于完成任务（读目标文件/跑目标测试/搜索到相关代码）→ hit=True；如果结果未被使用或与任务无关 → hit=False
- **ai_messages**：不参与命中计算（agent 自己的输出）
- **summarized_history**：不参与命中计算（压缩内容无法逐条判定）

**hit_rate 计算**：
```
hit_rate = effective_tokens / (effective_tokens + wasted_tokens)
effective_tokens = hit=True 的 tool_result tokens + system_prompt + user_message
wasted_tokens = hit=False 的 tool_result tokens
```

**采集实现**：

```python
# evals/shared/context_analyzer.py（新建）
class ContextAnalyzer:
    """分析 agent 上下文窗口的命中率。"""

    def __init__(self, task_description: str):
        self.task_description = task_description
        self.turns_data = []

    def record_turn(self, messages: list, tool_results: list):
        """每个 model call 后记录上下文内容。"""
        breakdown = self._classify_messages(messages)
        tool_breakdown = self._classify_tool_results(tool_results)
        effective = sum(b["tokens"] for b in breakdown if b.get("hit") is True)
        wasted = sum(b["tokens"] for b in tool_breakdown if b.get("hit") is False)
        hit_rate = effective / (effective + wasted) if (effective + wasted) > 0 else 1.0
        self.turns_data.append({
            "breakdown": breakdown + tool_breakdown,
            "effective_tokens": effective,
            "wasted_tokens": wasted,
            "hit_rate": hit_rate,
        })

    def _classify_tool_results(self, tool_results: list) -> list:
        """判定每个 tool result 是否命中任务。"""
        results = []
        for tr in tool_results:
            hit = self._is_relevant(tr["tool"], tr["content"], tr.get("args"))
            results.append({
                "tool": tr["tool"],
                "tokens": tr["tokens"],
                "hit": hit,
                "note": tr.get("note", ""),
            })
        return results

    def _is_relevant(self, tool_name: str, content: str, args: dict | None) -> bool:
        """启发式判定工具结果是否与任务相关。

        判定规则：
        - read_file：读的文件路径与任务涉及的文件相关 → True
        - search_files：搜索结果包含任务关键词 → True
        - terminal：命令与任务相关（跑测试/编译/查看相关文件）→ True；无关命令 → False
        - web_search/web_fetch：搜索内容与任务关键词相关 → True
        - write_file/patch_file：写的文件与任务相关 → True
        - 其他工具：默认 True（保守，避免低估命中率）
        """
        if not args:
            return True
        task_keywords = self._extract_keywords(self.task_description)
        args_str = json.dumps(args, ensure_ascii=False).lower()
        content_lower = content.lower()[:500]  # 只看前 500 字符

        if tool_name == "read_file":
            # 读的文件路径是否与任务相关
            file_path = args.get("file_path", "").lower()
            return any(kw in file_path for kw in task_keywords) or True  # 保守：默认 True
        elif tool_name == "terminal":
            # 命令是否与任务相关
            command = args.get("commands", "").lower()
            if any(kw in command for kw in ["test", "build", "compile", "lint", "check"]):
                return True  # 跑测试/编译/检查 = 与任务相关
            if any(kw in command for kw in task_keywords):
                return True
            # 跑了无关命令（如 curl 非任务 URL / pip install 非任务依赖）
            return False
        elif tool_name == "search_files":
            return True  # 搜索结果通常与任务相关
        else:
            return True  # 保守：默认 True

    def _extract_keywords(self, text: str) -> list[str]:
        """从任务描述中提取关键词。"""
        # 简单分词 + 去停用词
        words = text.lower().split()
        stop_words = {"the", "a", "an", "is", "are", "in", "on", "at", "to", "for", "of", "and", "or"}
        return [w for w in words if w not in stop_words and len(w) > 2]

    def summarize(self) -> dict:
        """汇总所有 turn 的命中率。"""
        if not self.turns_data:
            return {"avg_hit_rate": 1.0, "total_effective_tokens": 0, "total_wasted_tokens": 0}
        total_effective = sum(t["effective_tokens"] for t in self.turns_data)
        total_wasted = sum(t["wasted_tokens"] for t in self.turns_data)
        return {
            "avg_hit_rate": total_effective / (total_effective + total_wasted),
            "total_effective_tokens": total_effective,
            "total_wasted_tokens": total_wasted,
        }
```

### 7.4 Code-intel 使用追踪

**现状**：code-intel 工具（tree-sitter 符号索引 / ast-grep / LSP / semantic search）**不在主 agent 工具集里**——它们只注入给 `CODE_INTEL_ROLES`（researcher/librarian/executor/general）的子 agent。eval harness 不禁用也不强制启用 code-intel。如果 agent spawn 了 researcher/executor 子 agent 且 host 有 LSP/ast-grep 二进制，code-intel 才可用。

**容器限制**：LSP / ast-grep / tree-sitter 索引器都跑在 **host 进程**上（操作 host 侧 bind-mount 的仓库），不在容器内。只有 terminal 被 DockerBridge 桥接到 `docker exec`。semantic search 跑在进程内（ONNX runtime），fail-open。

**计划**：在代码类题库（DevBench/SWE-bench/Multi-SWE-bench/Terminal-Bench）eval 中启用 code-intel 并追踪使用情况。

#### 启用 code-intel

```bash

SHERRY_CODE_INTEL_ROOT=/eval/workspace/<task_repo>  # tree-sitter 索引根

npm install -g typescript-language-server  # TS LSP
```
