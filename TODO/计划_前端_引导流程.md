## 0. 背景（已核实）

### 0.1 sherry 现状：无 onboarding

`index.vue` 的 `onMounted`（`:520-532`）只做 `loadBackground` / `notifications.subscribe` / `webSearchStore.subscribe` / `useWs`，**无首次启动检测**。grep `onboarding/guide/引导/firstRun` 零命中（命中的"任务意图引导"是预设 name 字符串无关）。首次启动直接进对话页，新用户面对工具栏九宫格 + 右栏 tab 迷茫。

已有"一次性提示"先例：`SIDEBAR_FILES_HINT_KEY`（`index.vue:405-428`）用 `localStorage` 实现"每浏览器仅提示一次"——引导可复用此模式，但用 Dexie 更稳（跨设备清缓存可控）。

### 0.2 创建会话的复用障碍与解法

`NewSessionPresetDialog.confirm()`（`:110-160`）是 `<script setup>` 局部闭包，**无 `defineExpose`**，外部不能调。confirm 内部编排：
```
loadCatalog → loadPresetPayload → applyPresetPayload → cacheSessionPreset
→ ensureSessionCharacter → cacheSessionMeta → emit('session:created') → router.push
```

底层函数 `loadPresetPayload`（`persona-catalog.ts:453`）+ `applyPresetPayload`（`:492`）**已导出**。解法：把 confirm 的编排步骤抽成共享函数 `createSessionFromPreset(entry, opts)`，NewSessionPresetDialog 和引导都调它。这样：
- 引导步骤 4 用选中预设**自动创建会话**（不让用户再点 NewSessionPresetDialog）。
- NewSessionPresetDialog 的 confirm 改为调 `createSessionFromPreset`（消除重复）。
- 跳过引导 → `useNewSessionStore().openDialog()`（现有行为，用户手动选预设）。

### 0.3 预设体系（已就绪）

`BUILTIN_PRESETS`（`persona-catalog.ts:60-85`）4 个：pure/coding/companion/sherry。`DEFAULT_PRESET_ID='sherry'`（`:88`）。`catalogEntries(userPresets)`（`:102`）列出内置+用户预设。引导步骤 2 直接复用 `catalogEntries` 渲染预设卡片。

## 2. 抽取共享创建函数

### 2.1 目标

把 `NewSessionPresetDialog.confirm()` 的编排逻辑抽成 `createSessionFromPreset`，消除重复，让引导能程序化创建会话。

### 2.2 改动清单

- [ ] **2.2.1** `client/app/composables/persona-catalog.ts` 新增导出 `createSessionFromPreset`（从 `NewSessionPresetDialog.confirm()` `:110-160` 抽取）：
  ```typescript
  import { emit } from '~/composables/mitt';
  import { cacheSessionPreset } from '~/composables/bridge/session';  // 确认实际 import 路径
  import { cacheSessionMeta } from '~/composables/messages';          // 确认实际 import 路径

  export interface CreateSessionOpts {
    locale: string;
    t: (key: string) => string;
    facts: CatalogFacts;
    router: { push: (to: string) => Promise<unknown> };
    localePath: (path: string) => string;
  }

  /** 从预设创建会话的完整编排（抽自 NewSessionPresetDialog.confirm）。
   * 引导流程和 NewSessionPresetDialog 共用，消除重复。 */
  export async function createSessionFromPreset(
    entry: PresetEntry,
    opts: CreateSessionOpts,
  ): Promise<string> {
    const payload = await loadPresetPayload(entry, opts.locale, opts.t, opts.facts);
    const sessionId = crypto.randomUUID();
    await applyPresetPayload(payload, sessionId);
    await cacheSessionPreset({ session_id: sessionId, preset_id: entry.id, preset_name: opts.t(entry.nameKey ?? '') });
    await ensureSessionCharacter(sessionId);  // 锁定 character 快照
    const meta = { id: sessionId, title: '', createTime: Date.now(), updatedAt: Date.now() };
    void cacheSessionMeta(meta);  // 本地占位
    emit('session:created', meta);  // mitt 广播，SessionSidebar 接管
    await opts.router.push(opts.localePath(`/home/${sessionId}`));  // 必须用 localePath
    return sessionId;
  }
  ```
  - `ensureSessionCharacter` / `cacheSessionPreset` / `cacheSessionMeta` 的实际 import 路径需对照 `NewSessionPresetDialog.vue` 的 import 确认（confirm 里用的那些）。
  - `agentStore.loadCatalog()`（confirm `:117`）由调用方在调 `createSessionFromPreset` 前确保（或在此函数内调）。

- [ ] **2.2.2** `NewSessionPresetDialog.vue:110-160` 的 `confirm()` 改为调 `createSessionFromPreset`：
  ```typescript
  const confirm = async () => {

    } catch (e) { toastError(e); } finally { creating.value = false; }

  ```
  - 行为不变（F1）：同样的编排步骤，只是抽成函数。

    async function getFlag<T>(key: string): Promise<T | undefined> {
      const row = await db.appFlags.get(key);
      return row?.value as T | undefined;
    }
    async function setFlag(key: string, value: unknown): Promise<void> {
