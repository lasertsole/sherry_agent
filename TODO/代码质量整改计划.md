## 二、P0 — 关键缺陷（立即修复）

> 涉及正确性 bug、安全漏洞、资源泄漏，必须在下一次发布前修复。

### P0-1. `get_pending_interrupt` 逻辑 bug：misplaced break 导致 HITL 中断丢失

- **文件**: `server/service/messages.py:562-585`
- **问题**: `break` 语句在 `for task in state.tasks` 循环内无条件执行，导致只检查第一个 task。如果第一个 task 没有 interrupt，后续 task 的 HITL 中断被遗漏，用户审批请求不会弹出。
- **修复**: 删除 `break`，让循环继续检查后续 task；或如果图保证只有一个 task，删除循环直接取 `state.tasks[0]`。

### P0-2. `_run_semantic_search` 使用 `asyncio.run()` 导致网关模式死锁

- **文件**: `agent/tools/message_search.py:679`
- **问题**: 调用 `asyncio.run(semantic_search(...))` 而非项目约定的 `run_async()`。同文件 302-308 行注释明确说明 `asyncio.run()` 在线程上下文中创建一次性事件循环，与缓存的 AsyncOpenAI/httpx 客户端冲突，导致网关模式死锁。此处重新引入了这个 bug。
- **修复**: 将 `asyncio.run(semantic_search(...))` 改为 `run_async(semantic_search(...))`。

### P0-3. 远程模型 API 的 TLS 验证被全局禁用

- **文件**: `models/embed_model/core.py:51,128`、`models/reranker_model/core.py:128-129,583,633,688`
- **问题**: `requests.post(..., verify=False)` 禁用证书验证，且 `embed_model/core.py` 模块级调用 `urllib3.disable_warnings(InsecureRequestWarning)` 全局抑制警告。API key 在 Authorization 头中发送，暴露于 MITM 攻击。
- **修复**: 默认 `verify=True`；仅在显式环境变量 `SHERRY_TLS_VERIFY=false` 时禁用，且将 `disable_warnings` 限制在该分支内。

### P0-4. 上传端点无认证、无内容验证

- **文件**: `server/trigger/http/audio.py`、`image.py`、`video.py`
- **问题**: `/audio/upload`、`/images/upload`、`/video/upload` 接受任意字节写入磁盘，无认证、无速率限制、无内容类型验证。配合静态目录服务，构成开放文件存储。
- **修复**: 添加 token 认证；用 magic bytes 验证实际内容类型与声明扩展名一致；添加上传速率限制。

### P0-5. SQLite 连接泄漏：`ContextEpoch.prepare` 未关闭连接

- **文件**: `runtime/session/state_register.py:299-306`
- **问题**: `sqlite3.connect(self._db.db_path).execute(...)` 无 context manager、无 `close()`。每次调用 `prepare()` 泄漏一个连接。同类的 `initialize`/`replace`/`advance` 方法都正确使用了 `with sqlite3.connect(...)`。
- **修复**: 改为 `with sqlite3.connect(self._db.db_path) as conn: conn.execute(...).fetchone()`。

### P0-6. 心跳处理中同步 `agent.invoke` 阻塞事件循环

- **文件**: `server/service/heartbeat.py:112`
- **问题**: `result = agent.invoke(...)` 在 `async def process_heartbeat_task` 中同步调用，阻塞整个事件循环数秒，所有其他 async 任务被挂起。
- **修复**: 改为 `await agent.ainvoke(...)` 或 `await asyncio.to_thread(agent.invoke, ...)`。

### P0-7. 子 Agent spawn 附件回滚使用 None 值导致文件泄漏

- **文件**: `agent/tools/subagent/spawn/core.py:300-318`
- **问题**: `materialize_subagent_attachments` 返回 error 时，`_rollback_spawn` 被调用，但传入的 `attachments_dir=None` 和 `attachments_root_dir=None`（局部变量尚未赋值）。实际已部分写入磁盘的附件文件不会被清理。
- **修复**: 将 `mat_result.abs_dir` 和 `mat_result.root_dir` 传给 `_rollback_spawn`，而非尚未赋值的局部变量。

### P0-8. 附件验证失败时部分写入文件未清理

- **文件**: `agent/tools/subagent/spawn/attachments.py:134-184`
- **问题**: 物质化循环逐个写文件。如果后续附件验证失败（重复名、超限、写入失败），函数直接返回 error，不清理前面已写入的文件。
- **修复**: 在返回 error 前清理 `abs_dir`；或将写入延后到所有验证通过后。

## 三、P1 — 高优先级（本轮迭代修复）

> 涉及并发隐患、重复代码消除、核心模块拆分。

- [ ] 集成 `basedpyright --strict` 检查 `Any` 使用和缺失类型标注

### 7.2 Code Review 阶段

- [ ] 新增 sync/async 方法对时必须检查副作用一致性
- [ ] 新增 HTTP 端点必须使用 `read_body()` helper 和 `bad_request()` 响应
- [ ] 新增工具返回错误时必须用 `json.dumps({"success": False, "error": ...})` 格式
- [ ] 新增中间件必须继承 `BeforeAgentHooksMixin` 而非手动实现 delegation
- [ ] 新增文件锁/原子写入必须使用 `pub_base` 共享工具

### 7.3 架构规范

- [ ] 中间件 sync/async 重复：超过 30 行的方法对必须提取共享 helper
- [ ] 重复代码：相同逻辑出现 3 次以上必须提取
- [ ] 配置访问：不允许多进程 mutation-and-restore 全局单例，必须显式传参
- [ ] SQLite 访问：必须使用 `with sqlite3.connect(...)` context manager
- [ ] HTTP 请求：禁止 `verify=False`，除非显式环境变量 opt-in
- [ ] 配置定义：同一逻辑设置只能有一个配置源，禁止跨系统重复定义
- [ ] 截断/提取 helper：必须使用 `pub/func/message` 中的共享工具函数，禁止局部重新实现
- [ ] 调试脚本：禁止提交 `check_*.py` 到仓库根目录，必须放在 `scripts/`（gitignored）
