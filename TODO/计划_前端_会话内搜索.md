## 0. 背景（已核实）

### 0.1 sherry 现状

会话内无全文搜索。侧边栏有标题/日期过滤（`SessionSidebar.vue:343-395`），对话区 turn 折叠后内容多（`useChatTurnFold` 把工具/推理行折叠成摘要），缺 Ctrl+F 体验。

### 0.2 虚拟列表关键结构（搜索跳转的基础）

- **渲染单元**：turn group（`buildChatVirtualRows` :51），每个 virtual row 有 `key`（group 首消息 id）。
- **虚拟窗口**：`virtualRows` computed（:164），只有 visible + overscan(6) 行在 DOM。
- **内存上限**：`MAX_LOADED_ROWS=400`（:63），最老行释放（`headRowsToReleaseMessageIds` :213-227）。
- **分页**：`onScroll` 顶部触发 `onReachTop`（:242-245, `TOP_TRIGGER_PX=120`）→ ChatBox emit `reach-top` → `loadOlder()`（:78-103）。
- **head 释放后**：`resetExhausted()`（:109）重新启用分页。
- **跳转先例**：`scrollToMessage(messageId)`（:624-638）——展开工具卡 + `scrollToRow` + `focusedMessageId` 高亮环。

### 0.3 turn 折叠（搜索协调基础）

`use-chat-turn-fold.ts` 的 `TurnFoldView`：每个 assistant work group 有 `history`（折叠时隐藏的行：tool 卡、中间 AI 文本、reasoning）+ `finalMessage`（始终可见的最终 AI 行）。折叠是 per-group 的（`eligible` 为 true 才可折叠）。搜索遍历 `chatMessages` 内存数组能找到折叠行的匹配（它们不在 DOM 但在数组），但跳转到折叠行的 `history` 时需先展开该 group。

## 2. 搜索逻辑

### 2.1 use-conversation-find.ts

- [ ] **2.1.1** 新建 `client/app/composables/use-conversation-find.ts`：
  ```typescript
  export interface FindMatch {
    messageId: number;     // MessageItem.id
    charIndex: number;     // 匹配在 content 里的起始位置
    length: number;        // 匹配长度（= query.length）
  }

  export interface FindState {
    query: string;
    matches: FindMatch[];
    currentIndex: number;  // 当前高亮的 match 索引（-1 = 无）
  }

  export function useConversationFind(chatMessages: Ref<MessageItem[]>) {
    const findState = ref<FindState>({ query: '', matches: [], currentIndex: -1 });
    const findBarVisible = ref(false);

    function search(query: string): void {
      findState.value.query = query;
      if (!query.trim()) {
        findState.value = { query, matches: [], currentIndex: -1 };
        return;
      }
      const q = query.toLowerCase();
      const matches: FindMatch[] = [];
      for (const msg of chatMessages.value) {
        const content = (msg.content || '');
        if (!content) continue;
        const lower = content.toLowerCase();
        let idx = lower.indexOf(q);
        while (idx >= 0) {
          matches.push({ messageId: msg.id, charIndex: idx, length: q.length });
          idx = lower.indexOf(q, idx + q.length);
        }
      }
      findState.value = { query, matches, currentIndex: matches.length > 0 ? 0 : -1 };
    }

    function next(): void {
      if (findState.value.matches.length === 0) return;
      findState.value.currentIndex =
        (findState.value.currentIndex + 1) % findState.value.matches.length;
    }
    function prev(): void {
      if (findState.value.matches.length === 0) return;
      findState.value.currentIndex =
        (findState.value.currentIndex - 1 + findState.value.matches.length) % findState.value.matches.length;
    }
    function clear(): void {
      findState.value = { query: '', matches: [], currentIndex: -1 };
    }
    function open(): void { findBarVisible.value = true; }
    function close(): void { findBarVisible.value = false; clear(); }

    const currentMatch = computed(() =>
      findState.value.currentIndex >= 0 ? findState.value.matches[findState.value.currentIndex] : null
    );

    return { findState, findBarVisible, search, next, prev, clear, open, close, currentMatch };
  }
  ```
  - **性能**：O(N) 遍历 `chatMessages` 内存数组（非 DOM），400 行可接受。输入 debounce 300ms（在 ConversationFindBar 的 `@input` 上加 `v-debounce`）。
  - **搜索范围**：`msg.content` 文本（含折叠的 hidden 行——它们在 `chatMessages` 数组里）。不搜 tool args/result（第一版只搜 message content）。

### 2.2 高亮策略（MVP vs 进阶）

- [ ] **2.2.1** **MVP：当前匹配用 `focusedMessageId` 高亮环**。`jumpToMatch` 设置 `focusedMessageId = match.messageId`，复用 `ChatBox` 现有的 `focusedMessageId` 高亮环（`:612-634` 的环模式，scrollToMessage 先例）。不渲染全文 `<mark>`——当前匹配靠高亮环 + 滚动到视野标识。
- [ ] **2.2.2** **进阶：全文 `<mark>` 高亮**。在 ChatBox 渲染 message content 后，遍历 DOM 文本节点，匹配位置包 `<mark class="find-highlight">`，当前匹配加 `find-current` class。参考 ZCode 的 `conversationFindHighlightDom.ts`。复杂度高（markdown 渲染后的 HTML 结构与原文不同，需在 DOM 文本节点层面操作），留进阶。
  - **流式期间不高亮**（同代码高亮的 F2 约束）：`message.streaming` 为 true 时跳过高亮。

**验收**：F2 + F4。

## 4. 与虚拟列表协调（核心）

### 4.1 jumpToMatch

- [ ] **4.1.1** `use-conversation-find.ts` 的 `jumpToMatch`（next/prev 触发）：
  ```typescript
  function jumpToMatch(
    match: FindMatch,
    deps: {
      scrollToRow: (index: number) => void;
      findRowIndexForMessage: (messageId: number) => number;
      isRowLoaded: (index: number) => boolean;
      resetExhausted: () => void;
      loadOlder: (onDone?: () => void) => void;
      focusedMessageId: Ref<number | null>;
      expandGroupForMessage: (messageId: number) => void;  // 折叠协调
    }
  ): void {
    // 1. 折叠协调：若匹配所在 turn group 折叠了，先展开
    deps.expandGroupForMessage(match.messageId);

    // 2. 找 virtual row index
    const rowIndex = deps.findRowIndexForMessage(match.messageId);
    if (rowIndex < 0) return;

    // 3. 行已释放（head dropped）→ 加载后重试
    if (!deps.isRowLoaded(rowIndex)) {
      deps.resetExhausted();
      deps.loadOlder(() => nextTick(() => jumpToMatch(match, deps)));
      return;
    }

    // 4. 滚动 + 高亮（复用 scrollToMessage 先例）
    deps.scrollToRow(rowIndex);
    deps.focusedMessageId.value = match.messageId;
  }
  ```
  - `findRowIndexForMessage`：遍历 `virtualRows`（或 `buildChatVirtualRows` 的输出）找包含该 message 的 group row。参考 `scrollToMessage`（:624-638）的 row 定位逻辑。
  - `isRowLoaded`：检查 rowIndex 是否在 `MAX_LOADED_ROWS` 范围内（未被释放）。
  - **递归重试**：`loadOlder` 加载后 `nextTick` 重试 jumpToMatch（加载后 row 可能已 in range）。

### 4.2 折叠协调

- [ ] **4.2.1** `expandGroupForMessage(messageId)`：找到 message 所属的 turn group，若该 group 折叠了则展开：
  ```typescript
  function expandGroupForMessage(messageId: number): void {
    // use-chat-turn-fold 维护的展开状态集合（如 expandedGroups: Set<number>）
    // 找 messageId 所属 group 的 key，若该 group 在折叠状态（不在 expandedGroups），加入
    const groupKey = findGroupKeyForMessage(messageId);
    if (groupKey != null && !expandedGroups.value.has(groupKey)) {
      expandedGroups.value.add(groupKey);
    }
  }
  ```
  - **不自动恢复折叠**：搜索展开的 group 搜索完不自动重新折叠（用户手动折回）。避免展开/折叠闪烁。
  - **只展开跳转目标的 group**，不展开所有（性能 + 不打扰其他 group 的折叠状态）。

### 4.3 风险与约束

- **F1 虚拟列表**：jumpToMatch 只组合现有 API（`scrollToRow` + `loadOlder` + `resetExhausted`），不新增虚拟列表逻辑。
- **大列表性能**：搜索 O(N) 遍历内存数组（400 行），debounce 300ms，可接受。进阶可加索引（Dexie 全文索引），但 MVP 不需要。
- **释放行加载的边界**：`loadOlder` 加载更老的页，但如果匹配行在**已加载范围之外的未来方向**（不太可能——虚拟列表通常向上释放老行），需确认 `loadOlder` 方向。sherry 的分页是向上加载老历史（`onReachTop`），所以释放的是老行（head），jumpToMatch 的 `loadOlder` + `resetExhausted` 对应这个方向。

**验收**：F1 + F3 + F4。

## 7. 不做的事

| 项 | 不做的原因 |
|---|---|
| 跨会话搜索 | 只搜当前会话；跨会话搜索是后端能力 |
| 正则搜索 | 第一版只做纯文本匹配（大小写不敏感子串） |
| 搜索 tool args/result | 第一版只搜 message content 文本 |
| 全文 `<mark>` 高亮（MVP） | markdown 渲染后 DOM 文本节点遍历复杂，MVP 用 focusedMessageId 环；进阶加 |
| 搜索展开所有 group | 只展开跳转目标的 group，不打扰其他 group 折叠状态 |
| 自动重新折叠 | 搜索展开的 group 不自动折回（避免闪烁） |
