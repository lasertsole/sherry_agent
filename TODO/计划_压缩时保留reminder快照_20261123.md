# 计划：压缩时保留 system-reminder 快照

- 日期：2026-11-23
- 状态：**待评审**
- 来源：超长 turn 中途压缩会清掉 cutoff 窗口内的 reminder，模型在剩余 turn 内看不到 todo/taskflow 状态，越执行越偏
- 风险等级：**低** — 压缩代码里加一步捕获+去重+插入，不改注入逻辑、不改守卫、不改 DynamicReminderMiddleware
- 依赖：无
- 可独立执行：✅

---

## 0. 问题

超长 turn 中途压缩时，cutoff 窗口内的消息（含 system-reminder）被整段替换成 summary pair。模型在剩余 turn 内看不到 todo/taskflow 状态，没有锚点校准方向。

---

## 1. 设计

### 1.1 核心思路

压缩替换 cutoff 窗口时，从 `messages_to_summarize` 中**捕获每个非 transient source 的最后一条 reminder**，在截断步骤**之后**插入到 summary pair 和 preserved tail 之间：

```
改前: [summary_HM, summary_AI, ...preserved..., tool_result]
改后: [summary_HM, summary_AI, 快照reminder_block, ...preserved..., tool_result]
```

快照是**压缩时刻的版本**，不是最新 live state。

**插入时机**：在 `_aggressive_truncate` 和 `_truncate_summary_messages` **之后**插入快照（和 `_inject_recovery_context` 同位置），确保快照不被硬截断砍掉。快照很小（每个 source 上限 1500-2000 字符，全部 source 加起来可能 10-15K 字符 ≈ 3K token），截断后插入不会把结果推过红线。

### 1.2 为什么用快照而不是 live state

**串起历史线路**：模型看到一条完整的状态演进线：

```
[摘要: "我们做了X、Y、Z"]
→ [快照: "压缩时 todo 是 A完成、B进行中、C待做"]   ← 摘要的上下文
→ [preserved 里的 reminder: "B完成、C进行中"]       ← 更新的状态（更靠近尾部，注意力更强）
→ [tool_result]                                     ← 当前要处理的
```

- 快照提供历史上下文：帮助模型理解摘要做了什么、当时计划是什么
- preserved 里的 reminder 提供更近的状态：压缩点之后的，位置更靠后，注意力更强
- 两者代表不同时间点，不是重复，是一条时间线

### 1.3 去重：快照与 preserved 最旧 reminder 内容完全相同时不注入

同一 source 的快照和 preserved 里可能内容完全一样（压缩点之后该 source 没有变化）。这时两份完全相同的 reminder 是纯冗余。

preserved 里最旧（最靠前、最靠近摘要）的那条 reminder 是模型在 preserved 段遇到的**第一条**——它本身就是摘要之后的第一个状态锚点。如果快照和它完全一样，说明压缩点到第一条 preserved reminder 之间状态没变，快照是纯冗余，最旧的那条已经当了桥。

去重规则：对每个 source，如果快照内容和 preserved 里该 source**最旧**的一条 reminder 的内容**完全相同**（byte-identical），则该 source 的快照不注入。只保留 preserved 里的那份。

内容不同的（状态变了）→ 两份都留，串起时间线。

**为什么比最旧不比最新**：如果状态变了又变回来（快照 = 最新但 ≠ 最旧），比最新会误删快照，丢失压缩时刻的状态。比最旧只在"压缩点到第一条 preserved 之间没变化"时跳过——这时快照确实没有额外信息。

### 1.4 为什么不改 DynamicReminderMiddleware

- 不需要 flag 机制
- 不需要绕过 `last_human is not final` 守卫
- 不需要选择性剥旧
- 全部在 compression.py 里完成，DynamicReminderMiddleware 完全不动

### 1.5 为什么不删 preserved tail 里的旧 reminder

- preserved tail 里的 reminder 是压缩点**之后**注入的，比快照更新
- 它们位置更靠尾部，注意力更强
- 快照是压缩点**之前**的最后一份，两者代表不同时间点
- 不删 = 保留完整时间线，删了 = 断线

## 3. 改动细节

### 3.1 捕获函数（dynamic.py）

```python
def capture_reminder_snapshot(messages: list[Any], preserved: list[Any]) -> list[Any]:
    """从 cutoff 窗口的消息中捕获每个非 transient source 的最后一条 reminder。

    扫描 messages（即 messages_to_summarize），对每个非 transient 的
    system-reminder source（按 metadata.origin 区分），保留最后出现的那一条。
    transient reminder（current_time / lsp_diagnostics / project_instructions）
    不捕获——它们是瞬时状态，快照无意义。

    去重：如果某个 source 的快照内容和 preserved 中该 source 最旧的一条
    reminder 完全相同（byte-identical），则该 source 的快照不注入——
    preserved 里最旧的那条已经当了摘要后的第一个状态锚点，快照是纯冗余。

    返回按原始顺序排列的 reminder 消息列表，供压缩代码插入到 summary pair
    和 preserved tail 之间。
    """
    from .core import transient_source_ids

    transient_ids = transient_source_ids()

    # 1. 从 cutoff 窗口捕获每个 source 的最后一条 reminder
    latest_by_origin: dict[str, Any] = {}
    for msg in messages:
        if not is_system_reminder(msg):
            continue
        meta = getattr(msg, "metadata", None) or {}
        origin = meta.get("origin")
        if origin is None or origin in transient_ids:
            continue
        latest_by_origin[origin] = msg

    if not latest_by_origin:
        return []

    # 2. 从 preserved 中找每个 source 最旧的一条（第一次出现的那条）
    oldest_preserved_by_origin: dict[str, Any] = {}
    for msg in preserved:
        if not is_system_reminder(msg):
            continue
        meta = getattr(msg, "metadata", None) or {}
        origin = meta.get("origin")
        if origin is None or origin in transient_ids:
            continue
        if origin not in oldest_preserved_by_origin:
            oldest_preserved_by_origin[origin] = msg

    # 3. 去重：快照内容与 preserved 最旧的那条完全相同 → 跳过
    def _content(msg) -> str:
        return getattr(msg, "content", "") or ""

    skipped_origins: set[str] = set()
    for origin, snapshot_msg in latest_by_origin.items():
        oldest_preserved = oldest_preserved_by_origin.get(origin)
        if oldest_preserved is not None and _content(snapshot_msg) == _content(oldest_preserved):
            skipped_origins.add(origin)

    # 4. 按原始消息顺序返回（保持注入时的优先级顺序），跳过去重的
    seen = set()
    result = []
    for msg in messages:
        if not is_system_reminder(msg):
            continue
        meta = getattr(msg, "metadata", None) or {}
        origin = meta.get("origin")
        if origin is None or origin in seen or origin in skipped_origins:
            continue
        if origin in latest_by_origin and latest_by_origin[origin] is msg:
            result.append(msg)
            seen.add(origin)
    return result
```

## 4. 执行时序

### 正常 turn（无压缩）— 行为不变

```
abefore_model: 正常注入 reminder
wrap_model_call: 不压缩
（无快照插入）
```

### 压缩发生在 turn 中途 — 新行为

```
Turn N:
  ① 首次模型调用：abefore_model 正常注入 reminder
  ② 工具循环
  ③ 压缩：
     cutoff 窗口 = messages[:cutoff]（含 ① 注入的 reminder）
     preserved = messages[cutoff:]（可能含后续注入的更新 reminder）
     → 生成 summary
     → final_messages = [*summary_pair, *preserved]
     → _aggressive_truncate（如果超 budget×2）
     → _truncate_summary_messages
     → capture_reminder_snapshot(messages_to_summarize, preserved)
       → 从 cutoff 窗口捕获每个 source 最后一条 reminder
       → 与 preserved 最旧 reminder 去重
     → 插入快照：final_messages = [*summary_pair, *snapshot, *preserved]
     → cutoff 窗口的消息（含旧 reminder）被替换掉，但快照保留了最后的版本
  ④ 模型看到：
     [summary, 快照(压缩时状态), preserved(更新状态), tool_result]
     → 历史线路完整，模型有锚点
  ⑤ 下一个 turn：abefore_model 正常注入最新 live state（行为不变）
```

### 多次压缩 — 每次都保留快照

```
第 3 次模型调用: 压缩 → 捕获快照 → 插入
  [summary_1, snapshot_1, preserved_1, tool_result]

第 7 次模型调用: 又压缩 → 从当前 cutoff 窗口（含 summary_1 + snapshot_1 + 部分 preserved_1）
  捕获快照 → 插入
  [summary_2, snapshot_2(含source最新版), preserved_2, tool_result]
```

每次压缩时，`capture_reminder_snapshot` 从 cutoff 窗口（含上一次的快照）中取每个 source 的最后一条。上一次的快照如果落在 cutoff 窗口里，它的 reminder 会被捕获为这次快照的一部分（如果它比 cutoff 窗口里其他同 source 的 reminder 更新）。链式保留。

## 5. 不改的东西

| 项 | 理由 |
|----|------|
| DynamicReminderMiddleware | 完全不动，正常 turn 的注入/守卫/cooldown 行为不变 |
| abefore_model 守卫 | 不需要 flag、不需要绕过 `last_human is not final` |
| 选择性剥旧 | 不需要——preserved tail 不动，快照和 preserved 里的 reminder 代表不同时间点 |
| compress_exclude 标志 | 仍由 Summarization 读取控制 summary 输入，不变 |
| transient 剥离 | 仍每轮由 DynamicReminderMiddleware 剥离，不变。capture 函数也不捕获 transient |
| 前缀缓存 | 正常 turn 不受影响（无压缩 = 无快照插入）；压缩时缓存已碎，插入零成本 |
| `_reset_reminders_after_compact` / `reset_session` | 仍正常调用（当 need_update_system_prompt=True），清 throttle 供下一 turn 重注入 |

## 6. 快照内容

捕获范围：cutoff 窗口中所有**非 transient** 的 system-reminder，按 source 取最后一条。

| source | 是否捕获 | 理由 |
|--------|:--------:|------|
| todo_block | ✅ | 压缩时的 todo 状态快照，帮助模型理解摘要做了什么 |
| taskflow_status | ✅ | 压缩时的 TaskFlow board 状态 |
| plan_mode_block | ✅ | 压缩时的 plan mode 状态 |
| boulder_status | ✅ | 压缩时的 boulder 状态 |
| project_dir_notice | ✅ | 压缩时的项目目录信息 |
| memory_recall | ✅ | 压缩时的记忆召回内容 |
| continuity_context | ✅ | 压缩时的连续性上下文（compress_exclude=False 但仍捕获——它提供额外上下文） |
| project_instructions | ❌ | transient，每轮重新派生，快照无意义 |
| lsp_diagnostics | ❌ | transient，每轮重新派生 |
| current_time | ❌ | transient，时间快照会误导（显示旧时间） |

## 8. 风险

| 风险 | 缓解 |
|------|------|
| 快照不是最新 live state | preserved tail 里有更近的 reminder（压缩点之后的）；下一个 turn 正常注入刷新到最新 |
| 快照占额外 token | 每个 source 最多一条（捕获时已按 source 去重），总量受 reminder budget 上限约束（30K chars ≈ 3K token） |
| 快照被 `_aggressive_truncate` 砍掉 | 快照在截断**之后**插入（和 `_inject_recovery_context` 同位置），不受截断影响 |
| preserved 里没有更新 reminder 时快照过旧 | 比完全没有强（原问题是完全丢失）；下一个 turn 刷新 |
| capture 函数失败阻塞压缩 | try/except fail-open，失败时不插入快照，压缩正常完成 |
| 快照干扰下一 turn 的注入 | `_already_injected_this_turn` 扫描时，preserved 里通常有 AIMessage → 返回 False → 正常注入。快照在 summary AIMessage 后面，不影响扫描 |

### Kill criteria

- 若快照占 token 过多影响上下文效率，限制只捕获最高优先级的 source（todo_block + taskflow_status）
- 若快照干扰下一 turn 注入（`_already_injected_this_turn` 误判），给快照消息加特殊标记让扫描跳过

## 9. 验收

- 压缩时 cutoff 窗口含 reminder → final_messages 中 summary pair 后面有快照
- 快照只含非 transient source，每个 source 最多一条（最后一条）
- 快照在 `_aggressive_truncate` 和 `_truncate_summary_messages` 之后插入，不被截断砍掉
- cutoff 窗口无 reminder → final_messages 不含快照（行为同改前）
- preserved tail 不受影响（不删不改）
- 快照在 summary AIMessage 之后、preserved 第一条之前
- capture 失败时不阻塞压缩（fail-open）
- 正常 turn（无压缩）行为完全不变
- 下一个 turn 的 abefore_model 正常注入（不受快照干扰）
- 所有新增测试 + 现有测试通过
