# 计划_question升级结构化多选项_20261104

将 Sherry 的 `question` 工具从**单问题多选项**升级为**多问题批量结构化提问**，对齐 ZCode 的 AskUserQuestion 能力。

---

## 现状分析

`question` 工具**已具备**基本的结构化多选项能力，并非纯文本提问：

| 现有能力 | 位置 | 说明 |
|---|---|---|
| 结构化选项 | `agent/tools/question.py:32-36` | `QuestionOption{label, description}`，2-6 个 |
| 多选标志 | `question.py:53-56` | `multiple: bool`，前端支持切换选择 |
| HITL 中断 | `question.py:92-111` | 构建 `HITLRequest` → `interrupt()` 挂起图 |
| Headless 自动拒绝 | `question.py:112-118` | `no_operator_in_scope()` → 返回 `_HEADLESS_DECLINE_MESSAGE` |
| 答案返回 | `question.py:128-131` | `decisions[0]["message"]` → 扁平字符串 `User answered: "..."` |
| 前端渲染 | `[sid].vue:271-318` | 单选点击即提交 / 多选切换+Submit / 自定义输入兜底 |
| 侧会话渲染 | `SideChatPanel.vue:32-78` | 紧凑版同逻辑 |
| 答案提交 | `use-hitl-approval.ts:101-146` | `handleHitlDecision('approve', answer)` → WS `hitl_response` |
| Resume 契约 | `server/service/messages.py:619-643` | `Command(resume={"decisions":[{"type","message"}]})` |
| 中断读取 | `agent/state_port.py:116-134` | 字段无关，透传 `ActionRequest.args` 全部字段 |

---

## 与 ZCode AskUserQuestion 的差距

| 能力 | ZCode AskUserQuestion | Sherry question（现状） | 差距等级 |
|---|---|---|---|
| **多问题批量** | 1-4 个问题一次调用 | 单问题 | **重大** |
| **选项预览** | `preview` 字段（代码/mockup 并排对比） | 无 | **中等** |
| **结构化答案** | `{answers, annotations}` 结构化返回 | 扁平字符串 `User answered: "..."` | **中等** |
| **并排布局** | preview 存在时左右并排 | 纵向按钮 | 中等 |
| 选项数量 | 2-4 | 2-6 | 轻微（Sherry 更宽，保留） |
| header 长度 | max 12 字符 | max 30 字符 | 轻微（保留 30） |
| annotations | 每问题用户备注 | 无 | **必做** — 用户表达"选项之外的做法"的唯一通道 |
| "Other" 兜底 | 自动提供 | 已有自定义输入 | **对齐** |
| Recommended 标记 | "(Recommended)" | 同约定 | **对齐** |
| 多选 | `multiSelect: bool` | `multiple: bool` | **对齐**（语义相同） |

---

## 设计方案

### 核心思路

**新增 `questions` 数组字段，保留旧扁平字段为弃用回退。** 这使得：
- 新调用使用 `questions` 数组（多问题批量）
- 已有 checkpoint 中的 pending interrupt（旧扁平 args）仍正常渲染和 resume
- `read_interrupt` 字段无关，无需改动
- Server resume 契约不变（`message` 携带 JSON 字符串）

### 答案序列化策略

多问题模式下，前端将所有问题的选择序列化为 **JSON 字符串**存入 resume 的 `message` 字段：

```json
{"answers": [
  {"question": "用哪个框架？", "header": "前端框架", "selection": ["Vue"], "annotation": "如果 SSR 需要 Nitro 而非自定义"},
  {"question": "需要 SSR 吗？", "header": "SSR", "selection": ["是"], "annotation": ""}
]}
```

工具 `_ask` 反序列化此 JSON，返回结构化文本给模型（每问题一行，annotation 非空时附加）：

```
User answered:
• 前端框架 → Vue (备注: 如果 SSR 需要 Nitro 而非自定义)
• SSR → 是
```

单问题旧模式保持 `User answered: "..."` 不变。

### 第 2 步：工具实现重构 — `question.py` `_ask` 方法

**新 `_ask` 逻辑**（替换 line 84-131）：

```python
def _ask(self, **kwargs) -> str:
    questions = kwargs.get("questions") or []
    session_id = kwargs.get("session_id", "")

    # 弃用回退：questions 为空 → 从扁平字段构造单条
    if not questions:
        flat_q = kwargs.get("question", "")
        if not flat_q:
            return "Error: no question provided."
        questions = [QuestionSpec(
            question=flat_q,
            header=kwargs.get("header", ""),
            options=kwargs.get("options", []),
            multiple=kwargs.get("multiple", False),
        )]

    # 校验每条问题的 options >= 2
    for q in questions:
        if len(q.options) < 2:
            return f'Error: question "{q.header}" needs at least 2 options.'

    is_multi = len(questions) > 1

    hitl_request = HITLRequest(
        action_requests=[ActionRequest(
            name=self.name,
            args={
                "questions": [q.model_dump() for q in questions],
                # 也保留扁平字段的首条，供旧前端回退渲染
                "question": questions[0].question,
                "header": questions[0].header,
                "options": [o.model_dump() for o in questions[0].options],
                "multiple": questions[0].multiple,
                "_multi": is_multi,
            },
            description=questions[0].question,
        )],
        review_configs=[ReviewConfig(
            action_name=self.name,
            allowed_decisions=["approve", "reject"],
        )],
    )

    # Headless deny（不变）
    from agent.middlewares.humanInTheLoop.approval_scope import no_operator_in_scope
    if no_operator_in_scope():
        logger.info("[QuestionTool] headless turn — declining")
        return _HEADLESS_DECLINE_MESSAGE

    logger.debug("[QuestionTool] suspending for {} question(s)", len(questions))
    response = interrupt(hitl_request)

    decisions = response.get("decisions", [])
    decision_type = decisions[0].get("type") if decisions else ""
    if decision_type == "yolo" and session_id:
        from agent.middlewares.humanInTheLoop.approval import set_session_yolo
        set_session_yolo(session_id)
    if decision_type in ("approve", "yolo"):
        message = decisions[0].get("message", "")
        return _format_answer(message, questions, is_multi)
    return _DECLINE_MESSAGE
```

**新增 `_format_answer` 辅助函数**：

```python
def _format_answer(message: str, questions: list[QuestionSpec], is_multi: bool) -> str:
    """Parse the user's answer (plain string or JSON) and format for the model."""
    if not is_multi:
        return f'User answered: "{message}". You can now continue.'
    # 多问题模式：message 是 JSON
    try:
        data = json.loads(message)
        answers = data.get("answers", [])
    except (json.JSONDecodeError, TypeError):
        # 回退：非 JSON，当作单条答案
        return f'User answered: "{message}". You can now continue.'
    lines = ["User answered:"]
    for ans, q in zip(answers, questions):
        sel = ans.get("selection", [])
        annotation = ans.get("annotation", "")
        parts = sel
        val = ", ".join(parts) if parts else "(no selection)"
        # annotation 非空时附加到行尾 — 这是用户表达选项之外想法的通道
        if annotation.strip():
            val += f" (备注: {annotation.strip()})"
        lines.append(f"• {q.header} → {val}")
    return "\n".join(lines) + "\nYou can now continue."
```

**`_run` / `_arun` 签名更新**（line 133-155）— 改为接收 `questions` 等新参数：

```python
def _run(self, questions: list | None = None, question: str = "",
         header: str = "", options: list | None = None,
         multiple: bool = False, session_id: str = "", **kwargs) -> str:
    qs = [QuestionSpec(**q) if isinstance(q, dict) else q
          for q in (questions or [])]
    opts = [QuestionOption(**o) if isinstance(o, dict) else o
            for o in (options or [])]
    return self._ask(questions=qs, question=question, header=header,
                     options=opts, multiple=multiple, session_id=session_id)
```

**`[sid].vue` script**（line 746-807 区域新增）：

```typescript
const isMultiQuestion = computed(() => hitlRequest.value?.tool_args?._multi === true)
const questionList = computed(() => {
  const qs = hitlRequest.value?.tool_args?.questions
  if (!Array.isArray(qs)) return []
  return qs.map((q: any) => ({
    question: q.question || '',
    header: q.header || '',
    options: (q.options || []).filter((o: any) => o.label),
    multiple: q.multiple === true,
  }))
})
const multiSelections = ref<Record<number, string[]>>({})
const customAnswers = ref<Record<number, string>>({})
const annotations = ref<Record<number, string>>({})

function selectMulti(qi: number, label: string) {
  const q = questionList.value[qi]
  if (!q.multiple) {
    multiSelections.value[qi] = [label]
  } else {
    const cur = multiSelections.value[qi] || []
    multiSelections.value[qi] = cur.includes(label)
      ? cur.filter(l => l !== label) : [...cur, label]
  }
}
function isOptionSelected(qi: number, label: string) {
  return (multiSelections.value[qi] || []).includes(label)
}
function submitMultiQuestions() {
  const answers = questionList.value.map((q, qi) => ({
    question: q.question,
    header: q.header,
    selection: multiSelections.value[qi] || [],
    annotation: annotations.value[qi] || '',
  }))
  handleHitlDecision('approve', JSON.stringify({ answers }))
  multiSelections.value = {}
  customAnswers.value = {}
  annotations.value = {}
}
function rejectQuestions() {
  handleHitlDecision('reject')
}
```

## 风险与缓解

| 风险 | 缓解 |
|---|---|
| 旧 checkpoint pending interrupt 的 args 无 `questions` 字段 | 前端 `isMultiQuestion` 默认 false → 走旧单问题渲染路径 |
| 模型仍用旧扁平字段调用 | 工具描述引导用 `questions`，旧字段标注 deprecated 但仍可用 |
| JSON 序列化 message 过长 | 4 问题 × 6 选项，label 各 5 词 → JSON 约 500 字符，远低于 message 无上限 |
| 多问题卡片高度溢出 | 每问题卡片 `max-h-48 overflow-y-auto`，Submit 固定底部 |
| preview 内容含 HTML/代码 | `<pre>` 纯文本渲染，不做 v-html，安全 |

---

## 验收标准

1. 模型调用 `question(questions=[...])` 一次性提出多个结构化问题
2. 前端渲染多问题卡片，每问题独立选项 + Other 输入 + annotation 备注框
3. 选项含 `preview` 时显示代码/mockup 预览
4. 用户可在每问题的 annotation 框填写选项之外的想法，提交后 agent 能看到
5. 用户提交后，工具返回结构化答案文本（每问题一行，annotation 非空时附加备注）
6. 旧单问题调用（扁平字段）行为完全不变
7. 已有 pending interrupt（旧 args）刷新页面后仍正常渲染
8. Headless turn（cron/auto-turn）多问题模式仍自动拒绝
