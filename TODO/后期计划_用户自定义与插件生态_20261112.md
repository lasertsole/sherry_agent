# 后期计划：用户自定义与插件生态/市场

- 日期：2026-11-12
- 状态：**后期计划**（插件市场部分不在当前排期；Step 1 已完成，前置 A/B 可提前单独做）
- 合并来源：`计划_用户自定义功能.md` + `计划组_插件市场与沙箱GenUI.md` + `计划_Python版三通道插件体系_20261111.md`（三者已删除）
- 目标：用户能自定义命令/角色/MCP；第三方能按统一包格式发布插件；市场能发现/安装/更新；插件可带 MCP 工具、skills、commands、hooks、agent 角色、沙箱 UI、Gen-UI
- 非目标：Native in-process 插件、EventBus、插件付费/分成、多用户市场后端、竞品导入、自动更新、签名体系（v1）
- 启动门槛：**有真实的外部集成需求**（至少 3 个来自外部、不是内部工具），且有可持续的分发入口（社区/文档/精选列表）。没有需求就不启动插件市场部分。

> 市场判断：通用工具市场已被 MCP 商品化，低价值；楔子是**精选 MCP + 人格/技能/场景包**。
> 市场用静态 registry（GitHub/CDN JSON），不做 SaaS、不做支付；先验证供给和需求，再谈商业化。

## 0. 已核实的技术事实与决策

| 事实 | 影响 |
|---|---|
| `_MAIN_TOOLS_BUILDERS` 有 **25 个**工具 | 插件是追加，不改内置 |
| `build_main_tools()` 有 **6 个调用点** + `context_usage_service` 两处 | 插件工具必须模块级缓存、幂等 |
| `MultiServerMCPClient.get_tools()` **每次工具调用新建 session** | v1 按次连接；常驻会话后置 |
| `models/daemon/base.py` 已有 DaemonSpec/spawn/kill/IdleWatchdog | 不新建 daemon 骨架 |
| 子 agent 链**没有 HITL 中间件** | 插件工具默认只给主 agent |
| Native 的 venv **不是 import 隔离** | 不做 Native；代码插件一律 Process/MCP |
| `runtime/hooks.py` 是单槽 last-writer-wins | 不向插件暴露 hook 注册 |
| 自定义命令、skills、hooks、MCP、子代理角色都已有 loader | 插件注册直接复用，不造第二套 |

**决策**：

1. **MCP-first**：不发明插件工具协议；`plugin.json` 是 MCP + skills/commands/hooks/agents 的打包层。
2. **Process-only**：第三方代码只跑子进程；Native 与 EventBus 不做。
3. **静态 schema**：manifest 声明工具，不连接就能给 LLM 工具列表；调用时才连接。
4. **按次连接**：v1 接受冷启动延迟；只有实测不可接受才做常驻会话。
5. **市场是精选层**：不做通用市场、支付、多租户；先做官方/社区精选 JSON + 一键安装。
6. **沙箱 UI 是红线**：插件返回的 HTML 只能在 iframe sandbox 内渲染；没有沙箱就不发布 UI 市场。
7. **不再做自定义工具协议**：原“manifest `tools[]` + stdin/stdout”方案取消，插件工具统一走 MCP。

## 5. 统一插件包格式

```text
<plugin>/
  plugin.json
  server.py | server.js | ...      # MCP server 入口（可选）
  skills/...                        # SKILL.md 目录（可选）
  commands/...                      # 自定义命令（可选）
  agents/...                        # 自定义角色（可选）
  ui/...                            # MCP Apps HTML（Stage 3，可选）
```

`plugin.json`：

```json
{
  "name": "code-reviewer",
  "version": "1.0.0",
  "description": "Code review assistant",
  "author": "example",
  "license": "MIT",
  "min_sherry_version": "0.2.0",
  "components": {
    "mcp": {
      "server": {
        "transport": "stdio",
        "command": ["python", "$here/server.py"],
        "env": {}
      },
      "tools": [
        {
          "name": "review",
          "description": "Review a file",
          "inputSchema": {
            "type": "object",
            "properties": {"path": {"type": "string"}},
            "required": ["path"]
          }
        }
      ]
    },
    "skills": ["skills/review"],
    "commands": ["commands/review.md"],
    "agents": ["agents/security-reviewer.md"],
    "hooks": {
      "PostToolUse": [{"command": "python $here/hook.py", "matcher": "patch_file"}]
    }
  },
  "permissions": {
    "paths": ["read:./**", "write:./output/**"],
    "requires_hitl": []
  }
}
```

`marketplace.json`：

```json
{
  "name": "sherry-official",
  "description": "Curated Sherry plugins",
  "plugins": [
    {"name": "code-reviewer", "version": "1.0.0", "path": "./code-reviewer", "sha256": "..."}
  ]
}
```

规则：

- `name`：`^[a-z0-9][a-z0-9-]*$`；`version`：semver；`min_sherry_version` 不满足则拒绝安装。
- `$here` 解析为插件目录；不允许 `..` 逃逸。
- `components` 至少一个；`native` 明确拒绝（日志 + 面板报错）。
- **没有 `tools[]` 顶层自定义执行协议**；工具只能声明在 `components.mcp.tools`，由 MCP server 执行。
- `permissions` 是参数护栏，不是沙箱；面板必须写明。
- 工具可见名：`mcp__<plugin>__<tool>`；冲突时后者跳过并报诊断。
- 包大小上限：插件 50 MB，UI HTML 16 MB，Gen-UI HTML 5 MB。

## 6. Stage 1：统一插件运行时（5–9 天）

### 目标

把插件目录变成可安装、可注册、可调用的工具来源；先支持本地目录和 git，不做市场 UI。

### 后端步骤

- [ ] **1.1 Manifest**：`agent/tools/plugins/manifest.py`
  - Pydantic `PluginManifest` / `McpComponent` / `ToolSchema` / `Permissions`；校验 name/version/路径/大小。
  - `marketplace.json` 的 `MarketplaceManifest` 同文件或 `marketplace.py`。
- [ ] **1.2 扫描与缓存**：`agent/tools/plugins/registry.py`
  - 双源：`PLUGINS_PATH/plugins`（只读内置）+ `APP_HOME/plugins/installed`（可写）。
  - `scan_plugins()` 只读 manifest，不连接；坏 manifest 跳过并记录。
  - `get_plugins()` / `get_plugin_tools()` 进程级缓存。
- [ ] **1.3 工具包装**：`agent/tools/plugins/mcp_tool.py`
  - `PluginMcpTool(BaseTool)`：`name=mcp__<plugin>__<tool>`，`args_schema` 由 `inputSchema` 生成。
  - `_arun`：`MultiServerMCPClient({server: spec}).get_tools(server_name=...)` → 找同名工具 → `ainvoke`；失败返回 error string。
  - 连接超时 10 s；工具调用沿用现有工具预算；`_run` 明确 `NotImplementedError`。
- [ ] **1.4 组装**：`agent/tools/__init__.py`
  - `build_main_tools(*, include_plugins=True)`；插件工具缓存；`enabled=false` 时跳过扫描。
  - 子 agent 的 4 个调用点（`child_agent_factory`、`spawn/core`、`ptc_prefill`、`steer`）传 `include_plugins=False`。
  - `context_usage_service` 保持含插件。
- [ ] **1.5 安装/注册**：`server/service/plugin_service.py`
  - `install_from_dir(path, scope)` / `install_from_git(url, scope)`：临时目录 → 校验 → 原子复制到 `APP_HOME/plugins/installed/<name>` 或 `<project>/.sherry/plugins/<name>`。
  - 组件注册：
    - MCP → 写 `APP_HOME/mcp_servers/<name>.json`；
    - skills → `APP_HOME/skills/auto/<name>/`；
    - commands → `APP_HOME/commands/<plugin>/`；
    - agents → `APP_HOME/agents/<plugin>/`；
    - hooks → 合并进 `sherry.jsonc`（需用户确认）。
  - 卸载：按注册逆序删除；更新：原子替换 + 重新注册。
  - 安装/卸载需要重启后端（进程级缓存），返回 `restart_required: true`。
- [ ] **1.6 权限护栏**
  - 插件工具默认仅主 agent（1.4 已保证）。
  - `permissions.paths`：对字符串参数做路径识别 + 前缀检查；越界拒绝并记录。
  - `requires_hitl`：字段保留，v1 **不执行**；文档写明。
- [ ] **1.7 最小 UI**：ExtendPanel 的插件列表增加“安装本地目录 / git URL”入口、启用状态、重启提示；不做市场源管理。
- [ ] **1.8 测试**
  - `tests/agent/tools/plugins/test_manifest.py`（校验/坏包/冲突）
  - `tests/agent/tools/plugins/test_mcp_tool.py`（mock `get_tools`、fail-open、名称映射）
  - `tests/agent/tools/test_build_main_tools_plugins.py`（缓存/子 agent 不可见/25 工具回归）
  - `tests/server/service/test_plugin_service.py`（安装/卸载/更新/注册）
  - 真实 echo MCP server 的集成测试。

### 验收

本地 MCP 插件安装后，主 agent 看到 `mcp__<plugin>__<tool>`；未调用时没有子进程；调用返回结果；卸载后工具消失；子 agent 看不到；内置 25 工具回归不变；插件 commands/skills/agents 可被发现。

## 8. Stage 3：沙箱化插件 UI（12–16 天）

### 目标

MCP 工具返回自定义 HTML，在 iframe 沙箱中隔离渲染；通过 JSON-RPC over `postMessage` 与宿主通信。

### 协议

- 工具结果 `_meta.display.ui`：
  ```json
  {"resourceUri":"ui://plugin/tool","mimeType":"text/html;profile=mcp-app",
   "visibility":"inline|sidebar","csp":"..."}
  ```
- 宿主 → iframe：`ui/initialize`、`ui/theme-changed`、`ui/teardown`。
- iframe → 宿主（白名单）：`sherry/callTool`、`sherry/readResource`、`sherry/listResources`、`sherry/sendFollowUpMessage`、`sherry/openExternal`、`sherry/downloadFile`、`sherry/notifyIntrinsicHeight`、`sherry/setWidgetState`。
- CSP：`default-src 'none'`；`script-src 'self'`；`style-src 'self' 'unsafe-inline'`；`img-src 'self' data:`；`frame-ancestors 'self'`；`form-action 'none'`；`object-src 'none'`。`unsafe-eval` 仅在声明时放开。

### 实现

- [ ] **3.1 后端**：校验 `display.ui` 大小（HTML ≤16 MB）、CSP 声明；不执行 HTML。
- [ ] **3.2** `client/app/composables/use-plugin-sandbox.ts`：iframe sandbox + srcdoc + alias 注入 + postMessage JSON-RPC + handshake 15 s；容量 16，LRU；失败退化文本。
- [ ] **3.3** `client/app/utils/plugin-alias.ts`：`window.sherry` 只读状态 + 8 个方法；所有调用经宿主校验。
- [ ] **3.4** 宿主 handler：method 白名单、限频（`sendFollowUpMessage` 每会话 4 次）、camera/mic/geo 经宿主确认、下载/外链校验。
- [ ] **3.5** `PluginUiCard.vue`（inline，高度 80–1200）+ `PluginUiSidePane.vue`（右栏 fullscreen）。
- [ ] **3.6** `ChatToolCard.vue` 检测 `display.ui` → 渲染卡片；否则走现有文本/diff。
- [ ] **3.7** 主题投射（`--color-*` CSS 变量）；暗/亮切换同步。
- [ ] **3.8 测试**：沙箱内无法访问宿主 DOM/Pinia/WS；CSP 生效；handshake 失败退化；alias 白名单。

### 验收

工具返回 HTML → 卡片渲染；alias API 可用；暗/亮跟随；恶意 iframe 无法读宿主；失败退化纯文本。

## 9. Stage 4：Gen-UI（10–14 天）

### 协议

- LLM 输出：`::visualize{path="chart.html" title="趋势" mode="inline|wide"}`；行首锚定；一条回复可多个；路径 `^[a-z0-9]+(?:-[a-z0-9]+)*\.html$`；HTML ≤5 MB。
- HTML 由 `write_file` 写入 `<project>/.sherry/gen-ui/<path>`；宿主 `GET /gen-ui/:path`（复用 `resolve_within` 边界）。
- 解析失败/文件不存在 → 降级纯文本 `[Gen-UI Error: <reason>]`。

### 实现

- [ ] **4.1** 解析器 + `GET /gen-ui/:path` + 文件 watcher（或轮询）。
- [ ] **4.2** `use-gen-ui.ts`：复用 Stage 3 沙箱；handshake；tweak 定义；主题。
- [ ] **4.3** `GenUiCard.vue`：inline / wide（Dialog 原子移动不 remount）；高度自适应。
- [ ] **4.4** `TweakPanel.vue`：slider/color/toggle/select；实时调参（无模型 round-trip）；预览/原始切换；Reset；Submit。
- [ ] **4.5** Submit：tweak JSON → follow-up → LLM 重写 HTML → 文件变更 → reload → 清空 widgetState。
- [ ] **4.6** widgetState：≤16 KiB，注入下一轮为 `<untrusted_gen_ui_state>`；用户消息里 strip 伪标记。
- [ ] **4.7** `ChatBox.vue` 在 `done` 后扫描标记分段；流式时不解析。
- [ ] **4.8 测试**：解析器边界、非法路径、超限、tweak 流程、untrusted 注入/strip。

### 验收

LLM 输出标记 → 交互卡片；TweakPanel 实时调参；Submit 重写并可 reload；widgetState 回到模型且标记 untrusted。

## 12. 风险与边界

| 风险 | 缓解 |
|---|---|
| 第三方代码是任意代码 | Process 隔离 + 权限说明 + 精选审核；**不宣称沙箱** |
| 沙箱 UI 逃逸 | iframe `sandbox` + CSP + 白名单 + 容量上限；没有沙箱不发布 Stage 3 |
| manifest/schema 漂移 | 安装时 + 调用时双重校验；诊断不崩主流程 |
| 按次连接慢（0.5–3 s） | v1 接受并标注；实测不可接受再做常驻会话 |
| 6 个 `build_main_tools` 调用点 | 模块级缓存 + 幂等测试；子 agent 强制 `False` |
| 市场供给不足 | 先做精选 10–20 个，不做开放市场；没有需求不启动 |
| 审核/法律责任 | 精选制 + 许可证/权限声明；不接受任意上架 |
| 付费/分成 | 不在本计划 |
| Gen-UI 注入 | widgetState 标记 untrusted + 用户消息 strip；HTML 沙箱 |
| 插件 UI 跨平台 | Web/Tauri 都用 iframe；CSP 两端测试 |
| 自定义角色与专家团重叠 | 前置 B 只做文件式最小版；专家团持久 session/host UX 另立计划，不同时推进 |

## 13. 验收与 Kill criteria

### 总验收

- [ ] 自定义命令、MCP CRUD、自定义角色可用（前置 A/B）。
- [ ] 第三方插件（本地/git/marketplace）可安装、启用、更新、卸载。
- [ ] LLM 看到静态工具 schema，未调用时不启动子进程；调用失败 fail-open。
- [ ] 插件工具不出现在子 agent；内置 25 工具回归。
- [ ] 市场可添加/删除源、浏览、安装、诊断；workspace/user scope 正确。
- [ ] 插件 HTML 在 iframe 沙箱渲染；无法触达宿主；失败退化文本。
- [ ] Gen-UI 标记、TweakPanel、widgetState 全链路可用。
- [ ] 四语言文档、发布校验脚本、精选列表。

### Kill criteria

- **需求门槛未达到**：没有 3 个真实外部集成需求 → 停在 Stage 0/前置项，不做市场。
- **沙箱不达标**：Stage 3 无法通过隔离验收 → 不发布 UI 市场，只保留文本工具。
- **按次连接不可接受**：真实调用冷启动 >5 s 且热调用 >2 s → 先做常驻会话，否则停止扩展。
- **供给/审核不可持续**：没有稳定的精选供给或审核能力 → 退回“官方精选 MCP 列表 + 手动安装”。
- **必须做支付/多租户才能继续**：超出本计划，另立商业计划。
- **Native/EventBus 需求**：拒绝，不重启这两个方向。

## 14. 与其它计划的关系

- **专家团模式**：前置 B 是文件式自定义角色；专家团是持久专家 session + host UX + 派工协议，另立计划。两者不同时推进。
- **宿主能力授权**：Stage 3/5 的权限与密钥边界复用该计划；插件不持有模型密钥。
- **扩展能力引入**：本计划接管其“插件通道”部分；其余移动端/语音/记忆仍按原计划独立评估。
- **Hook Step 2/3**：插件 hooks 只复用 `load_sherry_hooks`；阻塞/改写 hooks 的 Step 2/3 仍是独立计划。
- **CLI / Ollama**：不属于本计划；Ollama 已删除，CLI 独立计划未保留。
