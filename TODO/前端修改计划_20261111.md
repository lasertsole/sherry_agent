## 1. 深色主题背景色变红 — 恢复纯黑

### 1.1 问题分析

**现象**：切换深色主题后，窗口背景色为红色而非深黑色。

**根因**：PrimeVue 升级（`primevue: "^4.5.5"` / `@primevue/themes: "^4.5.4"`）后，Aura 预设的深色 surface 色阶从中性黑变为暖灰（带红色调）。`NoirPreset`（`nuxt.config.ts:7-23`）只覆盖了 `primary` 色阶（slate），未覆盖深色 `surface` 色阶。`html.dark`（`main.css:72-75`）只设了 `--theme-text` 没设 `background-color`，背景完全依赖 Aura 注入的 CSS 变量，升级后变量值变了 → 红色。

**深色背景来源链**：
```
html.dark (main.css:72-75) → 仅设 --theme-text，未设 background-color
  → html / body 无显式深色背景
  → 背景色完全依赖 PrimeVue Aura 预设的 CSS 变量
    (--p-content-background / --p-surface-0 等)
  → Aura 4.5.x dark surface 含暖灰/红色调 → 深色模式背景变红
```

### 1.2 修改方案

**方案 A（兜底）**：`main.css` 的 `html.dark` 加显式背景色。

**文件：`client/app/assets/css/main.css:72-75`**

```css
/* 修改前 */
html.dark {
  --theme-text: #ffffff;
}

/* 修改后 */
html.dark {
  --theme-text: #ffffff;
  background-color: #0a0a0a;
}
```

`#0a0a0a` 接近纯黑但留出一点层次感（纯 `#000` 让阴影/边框消失）。

**方案 B（全覆盖）**：`NoirPreset` 覆盖深色 surface 色阶为中性灰。

**文件：`client/nuxt.config.ts:7-23`**

```ts
const NoirPreset = definePreset(Aura, {
  semantic: {
    primary: {
      50: '{slate.50}', 100: '{slate.100}', 200: '{slate.200}',
      300: '{slate.300}', 400: '{slate.400}', 500: '{slate.500}',
      600: '{slate.600}', 700: '{slate.700}', 800: '{slate.800}',
      900: '{slate.900}', 950: '{slate.950}'
    },
    colorScheme: {
      dark: {
        surface: {
          0: '#0a0a0a',
          50: '{zinc.50}', 100: '{zinc.100}', 200: '{zinc.200}',
          300: '{zinc.300}', 400: '{zinc.400}', 500: '{zinc.500}',
          600: '{zinc.600}', 700: '{zinc.700}', 800: '{zinc.800}',
          900: '{zinc.900}', 950: '{zinc.950}'
        }
      }
    }
  }
});
```

用 Tailwind `zinc` 色阶（中性灰，无红色调）替代 Aura 默认深色 surface。`surface.0` 显式设为 `#0a0a0a`。

**两个方案都做**：A 兜底 html 背景，B 覆盖所有 PrimeVue 组件（含 teleport 到 body 的 Dialog/Menu/Popover）的 surface 变量。

### 1.3 文件清单

| 操作 | 文件 | 改动 |
|------|------|------|
| 修改 | `client/app/assets/css/main.css:72-75` | `html.dark` 新增 `background-color: #0a0a0a` |
| 修改 | `client/nuxt.config.ts:7-23` | `NoirPreset` 新增 `colorScheme.dark.surface` 覆盖为 zinc 色阶 |

### 1.4 测试

- 切换深色主题 → 窗口背景为深黑色（`#0a0a0a`），无红色调。
- PrimeVue Dialog/Menu/Popover/Tooltip（teleport 到 body）背景也为中性深灰/黑色。
- 亮色主题不受影响。
- 背景图片功能不受影响。

## 2. 标题栏最大化/还原图标对齐 Windows 系统

### 2.1 问题分析

**文件：`client/app/components/TitleBar.vue:168-174`**

```ts
const maximize: TitlebarButton = {
  action: 'toggleMaximize',
  icon: isMaximized.value ? 'pi pi-window-minimize' : 'pi pi-window-maximize',
  ...
};
```

当前用 PrimeIcons 的 `pi-window-maximize` / `pi-window-minimize`：

| 状态 | 当前图标 | Windows 系统图标 | 差异 |
|------|----------|-----------------|------|
| 窗口态（可最大化） | `pi-window-maximize`：带箭头的窗口外框 | `□` 单方框轮廓 | PrimeIcons 是带箭头的窗口图形，不是简洁方框 |
| 最大化态（可还原） | `pi-window-minimize`：带向下箭头的窗口外框 | `❐` 两个重叠方框 | PrimeIcons 是缩小箭头，不是重叠方框 |
| 最小化 | `pi pi-minus`：横线 `—` | `—` | ✓ 已匹配 |
| 关闭 | `pi pi-times`：叉 `✕` | `✕` | ✓ 已匹配 |

最小化和关闭已匹配 Windows 系统，只有**最大化/还原**两个图标不一致。

### 2.2 修改方案

用内联 SVG 绘制 Windows 系统风格的方框图标，替代 PrimeIcons。

**Windows 10/11 系统标题栏图标规范**：
- 最大化（窗口态）：单个方框轮廓，10×10px，1px 描边
- 还原（最大化态）：两个错位重叠的方框轮廓，前小后大，1px 描边

#### 2.2.1 修改 TitleBar.vue — 用 SVG 替代 PrimeIcons

**文件：`client/app/components/TitleBar.vue`**

模板部分，将 `<i :class="btn.icon" />` 改为条件渲染 SVG：

```html
<button
  v-for="btn in controlButtons"
  :key="btn.action"
  type="button"
  class="titlebar-btn"
  :class="{ 'titlebar-btn--close': btn.action === 'close' }"
  :title="btn.title"
  :aria-label="btn.title"
  :data-test="btn.testId"
  @pointerdown.stop
  @click="btn.handler">
  <!-- 最小化：横线 -->
  <svg v-if="btn.action === 'minimize'" width="10" height="10" viewBox="0 0 10 10" fill="none">
    <line x1="0" y1="5" x2="10" y2="5" stroke="currentColor" stroke-width="1" />
  </svg>
  <!-- 最大化（窗口态）：单个方框 -->
  <svg v-else-if="btn.action === 'toggleMaximize' && !isMaximized" width="10" height="10" viewBox="0 0 10 10" fill="none">
    <rect x="0.5" y="0.5" width="9" height="9" stroke="currentColor" stroke-width="1" fill="none" />
  </svg>
  <!-- 还原（最大化态）：两个重叠方框 -->
  <svg v-else-if="btn.action === 'toggleMaximize' && isMaximized" width="10" height="10" viewBox="0 0 10 10" fill="none">
    <!-- 后方方框（右上） -->
    <rect x="2.5" y="0.5" width="7" height="7" stroke="currentColor" stroke-width="1" fill="none" />
    <!-- 前方方框（左下） -->
    <rect x="0.5" y="2.5" width="7" height="7" stroke="currentColor" stroke-width="1" fill="none" />
    <!-- 遮盖前方方框的右上角，形成重叠效果 -->
    <rect x="2.5" y="2.5" width="5" height="5" fill="currentColor" opacity="0" />
  </svg>
  <!-- 关闭：叉 -->
  <svg v-else-if="btn.action === 'close'" width="10" height="10" viewBox="0 0 10 10" fill="none">
    <line x1="0" y1="0" x2="10" y2="10" stroke="currentColor" stroke-width="1" />
    <line x1="10" y1="0" x2="0" y2="10" stroke="currentColor" stroke-width="1" />
  </svg>
  <!-- fallback -->
  <i v-else :class="btn.icon" />
</button>
```

#### 2.2.2 调整 controlButtons — icon 字段保留作 fallback

`icon` 字段保留（用于 macOS 或 fallback），但 Windows 路径下由 SVG 渲染：

## 4. 新建会话后历史列表为空时不显示骨架屏

### 4.1 问题分析

**文件：`client/app/pages/home/index/[sid].vue:14` + `client/app/composables/use-session-activation.ts:121,150`**

当前逻辑：

```ts
// use-session-activation.ts:130-154
const doLoadFor = (sid: string) => {
  deps.chatMessages.value = [];
  // ...
  isHistoryLoading.value = true;   // ← 设为 true
  void Promise.resolve(deps.syncHistory(sid)).finally(() => {
    if (seq === historyLoadSeq) isHistoryLoading.value = false;
  });
};
```

```html
<!-- [sid].vue:14 -->
<div v-if="isHistoryLoading && chatMessages.length === 0" ...>
  <!-- 骨架屏（3 条模拟消息） -->
</div>
```

**问题**：新建会话时 `doLoadFor` 清空 `chatMessages = []` 并设 `isHistoryLoading = true`，骨架屏立即显示。但新建会话**本来就没有历史消息**——`syncHistory` 返回的也是空列表。骨架屏闪现一下然后消失，给用户"正在加载历史"的错误预期，实际是空会话。

应该区分两种场景：
- **有历史的会话切换**：`syncHistory` 正在加载，列表暂时为空 → 显示骨架屏（合理）。
- **新建会话**：本来就无历史，`syncHistory` 返回空 → **不应显示骨架屏**。

### 4.2 修改方案

在 `doLoadFor` 中区分"新建会话"和"切换已有会话"——新建会话不设 `isHistoryLoading = true`。

**文件：`client/app/composables/use-session-activation.ts`**

```ts
// 修改 doLoadFor，新增 isNewSession 参数判断
const doLoadFor = (sid: string, isNewSession = false) => {
  deps.chatMessages.value = [];
  deps.isSending.value = false;
  // ...
  const seq = ++historyLoadSeq;
  // 新建会话本来就没有历史，不显示骨架屏；只有切换已有会话时才显示
  isHistoryLoading.value = !isNewSession;
  void Promise.resolve(deps.syncHistory(sid)).finally(() => {
    if (seq === historyLoadSeq) isHistoryLoading.value = false;
  });
  // ...
};
```

**调用方需传入 `isNewSession`**——找到所有 `doLoadFor` 的调用点，确认哪些是新建会话路径：

```
grep -n "doLoadFor" use-session-activation.ts
```

新建会话的调用点传入 `isNewSession = true`，会话切换的调用点保持默认 `false`。

如果 `doLoadFor` 的调用方无法直接区分新旧会话，另一个方案是**在骨架屏条件中加一个"会话有历史"的预判**——但这需要额外状态。更简洁的替代方案：

**替代方案（推荐）：不传参，而是检查会话是否刚创建**

在 `use-session-activation.ts` 中用一个 ref 标记当前会话是否是新建的：

```ts
const isNewSession = ref(false);

// doLoadFor 中
const doLoadFor = (sid: string) => {
  deps.chatMessages.value = [];
  // ...
  const seq = ++historyLoadSeq;
  isHistoryLoading.value = !isNewSession.value;  // 新建会话不显示骨架屏
  void Promise.resolve(deps.syncHistory(sid)).finally(() => {
    if (seq === historyLoadSeq) isHistoryLoading.value = false;
    isNewSession.value = false;  // 加载完成后重置
  });
};
```

`isNewSession` 由新建会话的入口（`createSessionFromPreset` / onboarding `finish`）设为 `true`。

**最简方案（无侵入）：直接在 `syncHistory` 的 finally 中判断——如果加载完成后 `chatMessages` 仍为空，说明本就无历史，骨架屏应在请求返回后立即消失（当前已如此）。问题只是"骨架屏闪了一下"——可以通过延迟显示骨架屏来避免：**

```ts
// 用 setTimeout 延迟 200ms 才显示骨架屏，新建会话（syncHistory 极快返回空）不会触发
const seq = ++historyLoadSeq;
let skeletonTimer: ReturnType<typeof setTimeout> | null = null;
skeletonTimer = setTimeout(() => {
  if (seq === historyLoadSeq) isHistoryLoading.value = true;
}, 200);  // 200ms 内返回的不显示骨架屏
void Promise.resolve(deps.syncHistory(sid)).finally(() => {
  if (skeletonTimer) clearTimeout(skeletonTimer);
  if (seq === historyLoadSeq) isHistoryLoading.value = false;
});
```

新建会话的 `syncHistory` 返回极快（空列表，无网络延迟），200ms 内完成 → 骨架屏不触发。切换已有会话的 `syncHistory` 需要网络请求 > 200ms → 骨架屏正常显示。

**推荐用延迟方案**——零侵入，无需改动调用方，且对所有"快速返回空"的场景都生效。

### 4.3 文件清单

| 操作 | 文件 | 改动 |
|------|------|------|
| 修改 | `client/app/composables/use-session-activation.ts:149-154` | `isHistoryLoading` 设为 true 前加 200ms 延迟，快速返回的不触发骨架屏 |

### 4.4 测试

- 新建会话 → 历史列表为空，无骨架屏闪现。
- 切换到已有会话（有历史）→ 骨架屏正常显示 → 历史加载完成消失。
- 切换到已有会话（历史为空，如刚创建后切走再切回）→ 无骨架屏（syncHistory 快速返回空）。
- 网络慢时切换会话 → 骨架屏 200ms 后出现。

## 7. 菜单-技能面板窄宽度时出现两个滚动条

### 7.1 问题分析

**文件：`client/app/pages/home/components/SkillsPanel.vue`**

两个滚动源叠加：

```html
<!-- 根容器：overflow-auto（同时纵向+横向滚动），min-w-[520px] 触发横向滚动 -->
<div class="flex flex-col h-full min-h-0 overflow-auto p-4 min-w-[520px]">
  <div class="flex min-w-[520px] flex-col gap-3">
    ...
    <!-- 技能列表：自己的 overflow-auto + max-height: 72vh -->
    <div class="overflow-auto flex flex-col gap-1 pr-1" style="max-height: 72vh">
    <!-- 技能详情：自己的 overflow-hidden + max-height: 72vh -->
    <div class="flex-1 flex flex-col overflow-hidden ..." style="max-height: 72vh">
      <!-- 详情内左列：overflow-auto + max-height: 72vh -->
      <div class="w-64 shrink-0 overflow-auto ..." style="max-height: 72vh">
      <!-- 详情内容：overflow-auto + max-height: 72vh -->
      <div class="... overflow-auto flex-1" style="max-height: 72vh">
  </div>
</div>
```

**两个滚动条来源**：
1. **根容器** `overflow-auto`（第 189 行）：纵向滚动整个面板内容。
2. **内层技能列表/详情** `overflow-auto` + `max-height: 72vh`（第 368/468/502 行）：各自纵向滚动。

当面板高度 < `72vh + 其他内容高度` 时，内层 `72vh` 容器超出面板可用高度 → 根容器也出现纵向滚动条 → 两个滚动条叠加。

`max-height: 72vh` 是视口相对值，不随面板实际高度变化——面板矮时 `72vh` 比面板还高，根容器被迫滚动。

### 7.2 修改方案

根容器只管横向滚动（`min-w-[520px]`），内层容器用 `flex-1 min-h-0` 替代 `max-height: 72vh`——填充剩余高度而非固定视口比例，只产生一个纵向滚动条。

**文件：`client/app/pages/home/components/SkillsPanel.vue`**

#### 7.2.1 根容器：overflow-auto → overflow-x-auto

```html
<!-- 修改前 -->
<div class="flex flex-col h-full min-h-0 overflow-auto p-4 min-w-[520px]">

<!-- 修改后 -->
<div class="flex flex-col h-full min-h-0 overflow-x-auto overflow-y-hidden p-4 min-w-[520px]">
```

根容器只处理横向滚动（`min-w-[520px]` 宽度溢出时），纵向不滚动（`overflow-y-hidden`），把纵向滚动交给内层。

#### 7.2.2 内层容器：max-height: 72vh → flex-1 min-h-0

**左右分栏容器**（第 207 行附近，`flex gap-3` + `min-height: 60vh`）：

```html
<!-- 修改前 -->
<div class="flex gap-3" style="min-height: 60vh">

<!-- 修改后：用 flex-1 min-h-0 填充根容器的剩余高度 -->
<div class="flex gap-3 flex-1 min-h-0">
```

**技能列表**（第 368 行）：

```html
<!-- 修改前 -->
<div class="overflow-auto flex flex-col gap-1 pr-1" style="max-height: 72vh">

<!-- 修改后 -->
<div class="overflow-y-auto flex flex-col gap-1 pr-1 flex-1 min-h-0">
```

**技能详情外层**（第 437 行）：

```html
<!-- 修改前 -->
<div class="flex-1 flex flex-col overflow-hidden rounded-lg bg-gray-50 dark:bg-gray-800/50" style="max-height: 72vh">

<!-- 修改后 -->
<div class="flex-1 flex flex-col overflow-hidden rounded-lg bg-gray-50 dark:bg-gray-800/50 min-h-0">
```

**详情内左列**（第 468 行）和**详情内容**（第 502 行）：同样移除 `max-height: 72vh`，改为 `flex-1 min-h-0`。

#### 7.2.3 所有 max-height: 72vh 移除

全文搜索 `max-height: 72vh`（第 369/437/469/503 行），全部移除或替换为 `min-h-0`。这些固定视口高度是双滚动条的根因。

### 7.3 注意事项

| 事项 | 说明 |
|------|------|
| flex 链完整性 | 根 `h-full min-h-0` → 内容 wrapper `flex-1 min-h-0` → 分栏 `flex-1 min-h-0` → 各列 `flex-1 min-h-0 overflow-y-auto`，整条 flex 链必须不断 `min-h-0`，否则 flex 子项的 `min-height: auto` 会阻止收缩 |
| 横向滚动 | 根 `overflow-x-auto` 保留 `min-w-[520px]` 的横向滚动，不受影响 |
| 分类按钮行 | 分栏上方的分类按钮 + curator 按钮行 `shrink-0`，不参与纵向滚动 |
| 技能列表 vs 详情 | 左列（技能列表）和右列（详情）各自 `overflow-y-auto`，只产生各自的滚动条——用户滚动技能列表不会滚动详情，反之亦然——但根容器不再滚动，不再叠加 |

| 操作 | 文件 | 改动 |
|------|------|------|
| 修改 | `client/app/pages/home/components/SkillsPanel.vue:189` | `overflow-auto` → `overflow-x-auto overflow-y-hidden` |

| 修改 | `client/app/pages/home/components/SkillsPanel.vue:368,437,468,502` | 移除所有 `max-height: 72vh`，改为 `flex-1 min-h-0` |

**更安全的做法**：

```python
class _WorkplaceFileStore(FileStore):
    def __init__(self) -> None:
        self.file_names = list(COMMUNITY_SYSTEM_FILE_NAMES)  # 只可写社区文件
        ...

def read_system_prompt_file() -> dict[str, str]:
    """Read ALL system prompt files (including AGENTS.md for template loading)."""
    # 读全部文件，不受 EDITABLE 限制
    ensure_workspace_system_files()
    result = {}
    for name in ALL_SYSTEM_FILE_NAMES:
        path = WORKSPACE_DIR / name
        if path.exists():
            result[name] = path.read_text(encoding="utf-8")
    return result
```
