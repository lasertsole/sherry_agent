## 0. 背景（已核实）

### 0.1 现有 @keydown 全貌

全仓约 20 处 `@keydown` 修饰符，分两类：
- **composer 类**（inputBox.vue:19-22）：Enter 发送 / Shift+Enter 换行 / ↑↓ 浏览历史 / Esc —— 绑在 contenteditable div 上，是用户最常重绑的。
- **组件局部 UI 类**（HistoryItem/ExtendPanel/SkillsPanel/SideChatPanel/Overlay 等的 Enter/Space/Esc）：列表项激活、重命名提交、overlay 关闭等 —— 是组件内部交互，非用户可重绑的快捷键。**MVP 不迁移这些**。

唯一 document-level keydown 是 `ToolbarPopover.vue:103-121`（Escape 关闭 popover，`watch(open)` 挂/卸 + `onBeforeUnmount` 兜底）。shell `index.vue` 与 `app.vue` 均无全局 keydown。

### 0.2 迁移策略：composer 类改运行时匹配，global 类走 plugin

inputBox 的 `@keydown.enter.stop.prevent` 是 Vue 编译时修饰符，固定绑死。要支持重绑，改为统一 handler + 运行时 `matchesBinding` 判断：

```vue
<!-- 原 :19-22 -->
@keydown.enter.stop.prevent="handleKeyEnter($event)"
@keydown.up.stop.prevent="handleKeyArrowUp"
@keydown.down.stop.prevent="handleKeyArrowDown"
@keydown.escape.stop.prevent="handleKeyEscape"

<!-- 改为 -->
@keydown.stop.prevent="onComposerKeydown"
```

`onComposerKeydown` 内用 `matchesBinding(event, id)` 判断按的是哪个快捷键（key 来源 = `resolveBinding(id)`，自定义 > 默认），再调原 handler。**defaultKeys 与原修饰符一致** → 不重绑时行为 byte-identical（F1）。

  - **Shift+Enter 换行**不注册为快捷键：contenteditable 的 Shift+Enter 默认换行是浏览器原生行为，`@keydown.stop.prevent` 改为统一 handler 后，不匹配任何快捷键的按键放行（不 preventDefault），Shift+Enter 自然换行。

  API：
  ```typescript
  export function useShortcuts() {
    const customBindings = ref<Record<string, KeyCombo>>({});  // id → 自定义 keys

    async function loadCustomBindings(): Promise<void> {
      // 从 Dexie shortcuts 表读
      customBindings.value = {};
      for (const row of await db.shortcuts.toArray()) customBindings.value[row.id] = JSON.parse(row.keys);
    }
    async function saveBinding(id: string, keys: KeyCombo): Promise<void> {
      await db.shortcuts.put({ id, keys: JSON.stringify(keys) });
      customBindings.value[id] = keys;
    }
    async function resetBinding(id: string): Promise<void> {
      await db.shortcuts.delete(id);
      delete customBindings.value[id];
    }
    function effectiveKeys(binding: ShortcutBinding): KeyCombo {
      return customBindings.value[binding.id] ?? binding.defaultKeys;
    }
    function resolveBinding(id: string): KeyCombo {
      const binding = DEFAULT_BINDINGS.find(b => b.id === id);
      return binding ? effectiveKeys(binding) : { ctrl:false,shift:false,alt:false,meta:false,key:'' };
    }
    return { DEFAULT_BINDINGS, customBindings, loadCustomBindings, saveBinding, resetBinding, effectiveKeys, resolveBinding };
  }
  ```

- [ ] **2.1.2** 匹配 + 冲突检测函数（模块级，纯函数）：
  ```typescript
  function comboFromEvent(e: KeyboardEvent): KeyCombo {
    return { ctrl:e.ctrlKey, shift:e.shiftKey, alt:e.altKey, meta:e.metaKey, key:e.key.toLowerCase() };
  }
  function combosEqual(a: KeyCombo, b: KeyCombo): boolean {
    return a.ctrl===b.ctrl && a.shift===b.shift && a.alt===b.alt && a.meta===b.meta && a.key===b.key;
  }
  // 供 inputBox 的 onComposerKeydown 用
  export function matchesBinding(e: KeyboardEvent, id: string): boolean {
    const { resolveBinding } = useShortcuts();
    return combosEqual(comboFromEvent(e), resolveBinding(id));
  }
  // 供设置面板用
  export function detectConflict(keys: KeyCombo, excludeId?: string): ShortcutBinding | null {
    const { effectiveKeys } = useShortcuts();
    return DEFAULT_BINDINGS.find(b => b.id !== excludeId && combosEqual(keys, effectiveKeys(b))) ?? null;
  }
  ```

### 2.2 全局监听 plugin

- [ ] **2.2.1** 新建 `client/app/plugins/shortcuts.ts`（仿 `error-handler.ts` 极简模式 + `directives.ts` 的 defineNuxtPlugin）：
  ```typescript
  export default defineNuxtPlugin(() => {
    if (typeof window === 'undefined') return;  // SSR 守卫
    const { DEFAULT_BINDINGS, effectiveKeys } = useShortcuts();
    void useShortcuts().loadCustomBindings();  // 启动时加载自定义绑定

    function isComposerFocused(): boolean {
      const el = document.activeElement;
      if (!el) return false;
      const tag = el.tagName;
      return tag === 'INPUT' || tag === 'TEXTAREA' || el.isContentEditable;
    }

    // global 类快捷键的 handler 注册表（各功能模块注册）
    const globalHandlers: Record<string, () => void> = {};
    // 由命令面板/搜索/侧栏等模块注册：
    //   registerGlobalHandler('command-palette', () => commandPaletteOpen.value = true)

    document.addEventListener('keydown', (e: KeyboardEvent) => {
      const combo = comboFromEvent(e);
      for (const binding of DEFAULT_BINDINGS) {
        if (binding.scope !== 'global') continue;  // composer 类不在这里处理
        if (!combosEqual(combo, effectiveKeys(binding))) continue;
        const handler = globalHandlers[binding.id];
        if (handler) { e.preventDefault(); handler(); return; }
      }
    });
  });
  ```
  - **composer 类不在 plugin 处理**：它们仍在 inputBox 的 `onComposerKeydown` 里（因为要访问 composer 内部状态——draft/history）。
  - **global handler 注册**：提供 `registerGlobalHandler(id, handler)` 给命令面板（Ctrl+K）、会话内搜索（Ctrl+Shift+F）、新建会话（Ctrl+N）、切换侧栏（Ctrl+B）注册。各模块在 onMounted 调，onBeforeUnmount 注销。

### 3.1 改动

- [ ] **3.1.1** `client/app/components/chat/inputBox.vue:19-22` template 改为统一 handler：
  ```vue
  <!-- 原 4 个 @keydown.修饰符 -->
  ```

  script 新增：
  ```typescript
  import { matchesBinding } from '~/composables/use-shortcuts';

  function onComposerKeydown(e: KeyboardEvent): void {
    // 匹配顺序：send-message（Enter 无 Shift）→ history-prev/next（↑↓）→ cancel-input（Esc）
    // 不匹配的按键放行（contenteditable 自然处理，如 Shift+Enter 换行、文字输入）
    if (matchesBinding(e, 'send-message')) { handleKeyEnter(e); return; }
    if (matchesBinding(e, 'history-prev')) { handleKeyArrowUp(); return; }
    if (matchesBinding(e, 'history-next')) { handleKeyArrowDown(); return; }
    if (matchesBinding(e, 'cancel-input')) { handleKeyEscape(); return; }
    // 未匹配：不 preventDefault（@keydown.stop.prevent 已 stop propagation + prevent default，
    //   所以需改为 @keydown.stop 只 stop 不 prevent，让未匹配按键放行）
  }
  ```
  - **关键调整**：`@keydown.stop.prevent` 会 prevent 所有按键（包括文字输入）。改为 `@keydown.stop`（只 stop propagation，不 prevent default），在 `onComposerKeydown` 里匹配的才手动 prevent。未匹配的按键（文字输入、Shift+Enter 换行）放行。
  - `handleKeyEnter` / `handleKeyArrowUp` / `handleKeyArrowDown` / `handleKeyEscape` 内部已 prevent（原修饰符的 .prevent 移到 handler 内或保留在 matchesBinding 分支）。
