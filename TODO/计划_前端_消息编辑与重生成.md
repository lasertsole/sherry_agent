## 0. 背景（已核实）

### 0.1 sherry 现状：append-only，无编辑/重跑

`handleSend`（`use-chat-stream.ts:933`）每次创建新 `msg_id` + 新 `turn_num`（本地 max+1），乐观追加 `userMsg` + 空 `aiMsg`（`:945,958,968`）。`edit_queued`（`agent-socket.ts:260` → `ws/messages.py:269-284`）只能编辑**还在队列里、尚未执行**的 QUEUED 行，不能改已落库的已发送消息。

### 0.2 checkpoint 截断的硬约束（关键修正）

原计划假设可以"回退到 turn N 之前的历史 checkpoint"。**探索发现这条路不通**：

- `on_turn_finished`（`turn_runner.py:264`）每个 turn 结束（非 HITL pending）调 `prune_session_checkpoints`（`turn_runner.py:288-290`）→ `aclean_thread_checkpoints`（`thread_safe_checkpointer.py:324-390`），**只保留最新 1 个 top-level checkpoint，删掉其余所有**。
- 所以 `aget_state_history` 在正常完成的 turn 后只返回 1 条记录，**无法回到 turn N 之前**。

**但 RemoveMessage 可行**：`add_messages` reducer 支持 `RemoveMessage(id=...)` 做 id-based 删除——`reminder_catalog/dynamic.py:131` 已用 `RemoveMessage(id=REMOVE_ALL_MESSAGES)` 做整表重写。所以可以从**当前唯一的 checkpoint live state** 读消息列表，按 turn 边界构造 `RemoveMessage` 列表，用 `aupdate_state` 提交删除。

### 0.3 MesMemory 截断：缺硬删 API

- `mark_messages_compacted(from_turn=N)`（`core.py:710-726`）：软删（`compacted=1`），行保留，默认 history 读不出。**但 `get_max_turn_num` 仍算软删行**——影响重跑的 turn_num 分配。不适用。
- `delete_messages_by_session`（`core.py:909-929`）：删整 session。粒度太粗。
- **缺 `delete_messages_from_turn`（硬删 turn_num >= N）**——需新增。
- `session_leafs` 表（`db.py:279-283`）+ `fork_from_message`（`core.py:373-376`）：消息树设计已存在，硬删后需重置 leaf 指向 turn N-1。

### 0.4 重跑入口可复用

截断后 session 处于 idle（无 CLAIMED 行、无 HITL），`submit_user_input(session_id, edited_text, "user")`（`input_queue_service.py:372`）走 STARTED 分支直接派发 `WsTurnExecutor` → `async_generate_multi`。**注意用新 `msg_id`**（dedup 拒绝重复 id，`input_queue_service.py:411-425`）。

### 0.5 turn_num 边界定位

checkpoint 消息无 turn_num 标签，但 **HumanMessage 计数 = turn_seq**（`state_port.py:168` 的 marker id 计算已用此事实）。第 N 条用户 HumanMessage 之后到第 N+1 条之前 = turn N。**需校准**：计数时跳过 `metadata.internal=True` 的 HumanMessage（workspace notice），与前端 turn_num（只算用户真实消息）对齐——与会话分支计划的 `_history_up_to_turn` 同一校准点。

- [ ] **2.2.1** `agent/state_port.py` 新增 `truncate_messages_after_turn`，加入 `__all__`（`:27-33`）：
  ```python
  async def truncate_messages_after_turn(
      session_id: str, turn_num: int, graph: CompiledStateGraph | None = None
  ) -> int:
      """Delete turn N and all later messages from the current checkpoint state.

      Uses RemoveMessage (add_messages reducer supports id-based deletion —
      verified by reminder_catalog/dynamic.py:131). The checkpoint history is
      pruned to latest-only after each turn (on_turn_finished → prune_session_
      checkpoints), so aget_state_history rewind is NOT available: this reads
      the ONE live checkpoint and removes messages by id.

      Returns the count of removed messages, or -1 if turn N is not in the
      checkpoint (compacted away → caller refuses the edit, F6).
      """
      from langchain_core.messages import RemoveMessage
      from pub.func import build_agent_config

      resolved, leased = await _resolve_graph(graph)
      try:
          messages = await read_messages(session_id, resolved)
          # Locate turn N's start: the Nth USER HumanMessage (skip internal
          # notices — metadata.internal=True — so the count matches the
          # frontend's turn_num which only counts real user messages).
          human_count = 0
          cut_index = None
          for i, msg in enumerate(messages):
              if msg.type != "human":
                  continue
              meta = getattr(msg, "metadata", None) or {}
              if meta.get("internal"):
                  continue  # workspace notice / steering — not a user turn
              human_count += 1
              if human_count == turn_num:
                  cut_index = i
                  break
          if cut_index is None:
              return -1  # turn N compacted away (F6)
          to_remove = [
              RemoveMessage(id=m.id)
              for m in messages[cut_index:]
              if getattr(m, "id", None)
          ]
          if not to_remove:
              return 0
          config = build_agent_config(session_id)
          await resolved.aupdate_state(config, {"messages": to_remove}, as_node="model")
          return len(to_remove)
      finally:
          if leased:
              from agent import core as agent_core
              agent_core.release_agent(resolved)
  ```

### 2.3 风险与约束

- **compaction 限制（F6）**：编辑的 turn N 必须仍在 checkpoint live state。若已被压缩成 summary（不在 `read_messages` 返回里），`truncate_messages_after_turn` 返回 -1，前端提示"该消息已超出可编辑范围（历史已被压缩）"。**前端判断**：可对照当前 turn 总数与压缩阈值估算，或直接后端拒绝。
- **turn_num 校准**：checkpoint 的 HumanMessage 计数需跳过 internal notice（workspace notice / steering），与前端 turn_num 对齐。这是 `truncate_messages_after_turn` 的 `metadata.internal` 跳过逻辑（与会话分支 `_history_up_to_turn` 同一校准点）。
- **busy 拒绝**：session 有在跑的 turn 或 HITL pending 时拒绝编辑（避免截断与正在跑的 turn 冲突）。
- **RemoveMessage 的 id 来源**：checkpoint 消息的 `id` 是 LangGraph 生成的（不是 MesMemory 行 id）。`read_messages` 返回的 `BaseMessage` 带 `id` 属性，直接用。无 id 的消息（极少）跳过。
- **session_leafs 树链**：硬删后 leaf 重置到 turn N-1。若用户后续从 turn N-1 fork（会话分支），树链一致。`fork_from_message`（`core.py:373-376`）的树设计兼容这个重置。
