# 计划：前端消息编辑 + 重新生成

- 建档日期：2026-10-23
- 状态：**待评审**
- **文档范围**：让用户能编辑已发送的用户消息并重新生成 AI 回答，消除 sherry append-only 模型下无法回退/重跑的短板。分两阶段：阶段一基础编辑重跑，阶段二工作区文件回退（复用 shadow-git）。
- **硬约束**：message store schema 不变（截断是逻辑标记 `superseded`）；现有 WS 协议向后兼容（新 frame 追加）；编辑仅限用户消息；不依赖 LLM 改输出格式。

## 0. 背景（已核实）

### 0.1 sherry 现状

sherry 是 append-only 模型：`use-chat-stream.ts:861` 的 `handleSend` 每次创建新 `msg_id`（`messages.ts:408`），乐观追加 `userMsg` + `aiMsg` 到 `chatMessages`（`use-chat-stream.ts:908`），调 `postAgentStream` 发送。**没有编辑已发送消息或重新生成的路径**。`agent-socket.ts` 的 `edit_queued`（`:260`）只能编辑**排队中**的消息，不能编辑**已发送**的。

### 0.2 turn 标识

客户端有两个 turn 标识：服务端 `turn_id`（string）和客户端 `turn_num`（正整数）。`turnIdToTurnNum` Map（`use-chat-stream.ts:170`）是桥接——`turn_started` 时设（`:434`），`done` 时删（`:507`）。每条 `MessageItem` 携带 `turn_num`，AI 行还携带 `turn_id`。

### 0.3 ZCode 做法

ZCode 的 `SingleUserInputRowView` 点击编辑展开完整编辑器（带附件/上下文 chip），提交 `editUserQuery`。进阶版有**编辑即回退工作区文件**（`ConversationFileRewindDialog.tsx`，带冲突预览 + "仅会话回退"兜底）。

## 1. ⚠️ 硬约束

| 约束 | 含义 | 验收方式 |
|---|---|---|
| **F1**：message store schema 不变 | 截断是逻辑标记（`superseded`），不物理删除行 | messages 表 schema 不变 |
| **F2**：WS 协议向后兼容 | 新 `edit_message` frame 是追加，老前端不崩 | 老前端收不到新 frame 走旧行为 |
| **F3**：编辑仅限用户消息 | 不能编辑 AI 回答（AI 回答通过重生成覆盖） | AI 消息无编辑按钮 |
| **F4**：不依赖 LLM 配合 | 编辑是前端+协议层做的 | 无需 LLM 改输出 |
| **F5**：fail-open | 编辑失败时保留原消息，提示错误 | 后端拒绝编辑时前端不崩 |

## 2. 任务一：阶段一——基础编辑重跑（必做）

### 2.1 目标

用户点击编辑某条历史用户消息 → 修改文本 → 提交 → 截断该消息之后的所有 messages → 用新文本重新跑一轮。

### 2.2 改动清单

#### 后端

- [ ] **2.2.1** 新增 WS frame `edit_message`（outbound）：
  - payload：`{type: 'edit_message', session_id, turn_id, new_text, msg_id}`
  - `agent-socket.ts` 增 `sendEditMessage(turnId, newText, msgId)` 方法

- [ ] **2.2.2** 后端 `server/service/turn_runner.py` 增 edit 入口：
  - 收到 `edit_message` → 调 `agent/state_port.py` 截断 message store 到该 `turn_id`（不含）→ 标记被截断行为 `superseded` → 用 `new_text` 作为新 HumanMessage 重跑一轮
  - **截断是逻辑标记**：`messages` 表增 `superseded` 列（`INTEGER DEFAULT 0`，ADDITIVE，不改 schema 结构）——或用 `additional_kwargs` 携带标记（零 schema 改动，**首选**）

- [ ] **2.2.3** 后端响应：编辑成功后走正常 `turn_started` → `chunk` → `done` 流程（复用现有 turn 执行器）

#### 前端

- [ ] **2.2.4** `ChatBox.vue:148-197` 用户消息行增编辑按钮：
  - hover/focus 显示铅笔图标（复用 `HistoryItem.vue` 的编辑图标风格）
  - 点击进入编辑模式：将用户消息 bubble 替换为 `inputBox` 编辑器（复用现有 composer + chip 体系）
  - 编辑器预填原消息文本 + 原有 file mention chips

- [ ] **2.2.5** `ChatBox.vue` 编辑提交逻辑：
  - 调 `agentSocket.sendEditMessage(turnId, newText, msgId)`
  - 前端截断 `chatMessages`：删除该 turn 之后的所有 messages（或标记 `superseded`，UI 上隐藏）
  - 新增用户消息 + AI 占位（复用 `handleSend` 的乐观追加逻辑）

- [ ] **2.2.6** `use-chat-stream.ts` 增 `handleEdit(turnId, newText, msgId)`：
  - 复用 `handleSend` 的 turn_num/streamingTurn/socket 装配
  - 找到该 turn 对应的 `turn_num`（从 `turnIdToTurnNum` 或 `chatMessages` 查）
  - 截断 + 重跑

- [ ] **2.2.7** 编辑取消：Esc 退出编辑模式，恢复原消息显示

### 2.3 风险与约束

- **F1 schema**：首选用 `additional_kwargs.superseded = true` 标记，零 schema 改动
- **F2 向后兼容**：`edit_message` 是新 frame，老前端收不到不崩
- **turn_id 来源**：用户消息行需携带 `turn_id`（当前 `MessageItem` 已有 `turn_num`，AI 行有 `turn_id`——用户行也需关联 `turn_id`）
- **HITL 冲突**：编辑时如果有 pending HITL，需先拒绝/忽略 HITL 再编辑

**验收**：F1 + F2 + F3 + F5。新建 `tests/server/test_edit_message.py` + 前端集成测试。

## 3. 任务二：阶段二——工作区文件回退（可选）

### 3.1 目标

编辑时可选"回退工作区文件到该 turn"，用 shadow-git 快照回退，带冲突预览。

### 3.2 改动清单

- [ ] **3.2.1** 后端：`edit_message` frame 增 `rewind_files: bool` 字段
- [ ] **3.2.2** 后端：用 `workspace/.sherry/shadow-git/` per-project write snapshots 回退到该 turn 的文件状态
  - shadow-git 在每次写文件时做快照（AGENTS.md 已记录）——需确认是否有 per-turn 快照粒度
- [ ] **3.2.3** 前端：新建 `client/app/components/chat/FileRewindDialog.vue`：
  - 冲突预览（difflib 对比当前文件 vs 快照）
  - "仅会话回退"兜底按钮（不回退文件，只重跑对话）
- [ ] **3.2.4** 编辑提交流程：弹出 `FileRewindDialog` → 用户选择是否回退文件 → 提交

### 3.3 风险与约束

- 依赖 shadow-git 的 per-turn 快照粒度——如果当前只有 per-write 快照，需从 turn 的最后一个 write 快照回退
- 文件冲突预览需要读快照内容（可能较大）

**验收**：阶段一全部通过 + 工作区回退可选且带冲突预览。

## 6. 不做的事

| 项 | 不做的原因 |
|---|---|
| 编辑 AI 回答 | AI 回答通过重生成覆盖，不需要编辑 |
| 物理删除被截断消息 | 保留 `superseded` 标记可恢复 |
| 会话分支 Fork | 另见 `计划_前端_会话分支.md` |
| 流式期间编辑 | 编辑仅限已 settle 的消息（非当前流式 turn） |
