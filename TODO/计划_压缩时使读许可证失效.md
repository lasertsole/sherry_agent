# 计划：压缩时使 read_state 许可证失效

## 问题

`write_file` 的读前写许可证（`read_state.py`）记录"这个 session 读过这个文件"，
但**不跟踪模型上下文窗口里是否还看得到文件内容**。当 SummarizationMiddleware
压缩历史消息时，`read_file` 的 `ToolMessage` 被丢弃，替换成结构化摘要（只有文件
路径，没有内容）。许可证仍然有效，`write_file` 的 CAS 也通过（文件没被别人改过），
于是模型基于压缩后的残缺记忆做**全量覆写**——500 行文件可能被写成 50 行，
**静默数据丢失，不触发任何错误**。

`patch_file` 不受此问题影响——它不查许可证，靠 `old_string` 匹配，记不准就匹配
不上，匹配不上就报错，自然迫使重读。

## 根因

`_LICENSES` 注册表（`read_state.py:67`）只在三种情况失效：
1. 进程重启（不持久化）
2. LRU 超过 4096 条被驱逐
3. `forget_session` / `forget_all`——**生产代码零调用**

Summarization 压缩 `ToolMessage` 时不清许可证。ContextEviction 切片时也不清。
许可证记录的是"发生过读取"这个历史事实，不是"模型现在还能看到内容"这个当前状态。

## 目标

SummarizationMiddleware 压缩掉 `read_file` 的 `ToolMessage` 时，同步使对应的
`read_state` 许可证失效。这样 `write_file` 会被拒绝（`UnreadFileError`），迫使
模型重读后再写。`patch_file` 不受影响（不查许可证）。

## 设计

### 扫描范围：双向扫描 + 差集失效

Summarization 在 `compression.py` 确定 cutoff 后，`messages_to_summarize =
current_messages[:cutoff]`（line 131）是要被丢弃的消息，`preserved =
current_messages[cutoff:]` 是保留的消息。**两个范围都要扫**。

`note_read` 每次调用都覆盖许可证（`_LICENSES[key] = FileLicense(...)`），所以
许可证始终对应**最近一次 read_file**。消息按时间排序（to-summarize 在前，
preserved 在后），所以 preserved 里的 read_file 一定比 to-summarize 里的更新。

**失效规则**：
1. 扫 to-summarize：收集 read_file 的路径 → 集合 A
2. 扫 preserved：收集 read_file 的路径 → 集合 B
3. 只对 **A − B**（在 to-summarize 里读过、但 preserved 里没有更新的读取）
   清许可证
4. **A ∩ B**（两边都读过）不清——preserved 里的那次更新，许可证和模型内容匹配

**为什么 A ∩ B 不清**：许可证 = 最近一次 `note_read` 的 revision。如果最近一次
read_file 在 preserved 范围，许可证就是那次的 revision，模型也有那次的完整内容
（ToolMessage 还在上下文里）。许可证和模型内容一致，CAS 会正确校验，不需要失效。

**为什么 A − B 清**：最近一次 read_file 在 to-summarize 范围，许可证是那次的
revision，但那次的内容已经被压缩掉，模型看不到。许可证声称"读过"但模型实际
已经不记得内容了——write_file 基于残缺记忆覆写 = 静默数据丢失。

### 多次读取同一文件的场景

```
Turn 1: read_file("utils.py") → 许可证 = R1
Turn 3: read_file("utils.py") → 许可证 = R2（覆盖）
Turn 5: read_file("utils.py") → 许可证 = R3（覆盖）
         cutoff 落在 Turn 3 和 Turn 4 之间

to-summarize = {Turn 1, Turn 3}  →  A = {"utils.py"}
preserved    = {Turn 5}          →  B = {"utils.py"}
A − B = {} → 不清 → 许可证 = R3（来自 Turn 5）→ 模型有 R3 内容 → 正确
```

```
Turn 1: read_file("utils.py") → 许可证 = R1
Turn 3: read_file("utils.py") → 许可证 = R2（覆盖）
         cutoff 落在 Turn 3 和 Turn 4 之间

to-summarize = {Turn 1, Turn 3}  →  A = {"utils.py"}
preserved    = {}                →  B = {}
A − B = {"utils.py"} → 清 → 许可证失效 → write_file 拒绝 → 迫使重读 → 正确
```

### 路径解析

`read_file` 的 `file_path` 参数可能是相对路径。许可证存储的是**解析后的绝对路径**
（经 `resolve_workspace_path`）。所以扫描时需要用当前 session 的 project dir 解析
路径，再按解析后的路径清许可证。

**边界情况**：如果 session 在 read 和 summarization 之间切换了 project dir，解析
结果可能不匹配旧许可证。此时 `forget_license` 找不到对应条目，许可证残留（=
当前行为，无回归）。这是罕见场景，fail-open 可接受。

### fail-open

扫描和清许可证的整个过程包在 `try/except` 里，**永不中断压缩**。路径解析失败、
tool call 格式异常、任何意外——许可证残留（= 当前行为），不 crash。

## 改动清单

### 1. 修改 `agent/tools/pub_base/read_state.py`

新增 `forget_license` 函数：

```python
def forget_license(session_id: str, path: Path) -> None:
    """Drop one file's license for a session.

    Called when the read_file ToolMessage that granted this license is
    compressed away by the summarization middleware — the model no longer
    has the file content in its context window, so an overwrite based on
    a stale memory would be a silent data loss.
    """
    key = _key(session_id, path)
    with _LOCK:
        _LICENSES.pop(key, None)
```

更新 `__all__` 和 `pub_base/__init__.py` 导出。

### 2. 修改 `agent/middlewares/summarization/compression.py`

在 `_apply_compression`（sync）和 `_aapply_compression`（async）中，
**在确定 `messages_to_summarize` 之后、构建摘要之前**，调用新函数：

```python
messages_to_summarize = current_messages[:cutoff]
preserved = current_messages[cutoff:]

# A read_file result being compressed away means the model no longer has
# the file content — invalidate the write license so a later write_file is
# refused (forces re-read) instead of silently overwriting with stale memory.
_invalidate_compressed_read_licenses(messages_to_summarize, session_id)
```

新增辅助函数（同文件或单独模块）：

```python
def _invalidate_compressed_read_licenses(
    messages_to_summarize: list, preserved: list, session_id: str
) -> None:
    """Drop read_state licenses for read_file results being compressed away.

    A license is invalidated only when the file's MOST RECENT read_file is in
    the to-summarize range (compressed away). If a later read of the same file
    is in the preserved range, the license stays — the model still has that
    content and the license matches it (note_read overwrites, so the license
    always reflects the latest read).

    Fail-open: never raises — a missed invalidation is the current behavior.
    """
    try:
        from agent.tools.pub_base import forget_license
        from agent.tools.pub_base.path_utils import resolve_workspace_path
        from runtime.session.project_dir import current_project_dir

        root = current_project_dir(session_id)

        def _read_paths(msgs: list) -> set[str]:
            """Extract resolved read_file paths from a message range."""
            paths: set[str] = set()
            for msg in msgs:
                tool_calls = getattr(msg, "tool_calls", None)
                if not tool_calls:
                    continue
                for tc in tool_calls:
                    if tc.get("name") != "read_file":
                        continue
                    file_path = tc.get("args", {}).get("file_path")
                    if not file_path:
                        continue
                    try:
                        resolved = resolve_workspace_path(file_path, root)
                        paths.add(str(resolved))
                    except Exception:
                        pass  # path resolution failure: skip this path
            return paths

        summarized_paths = _read_paths(messages_to_summarize)
        preserved_paths = _read_paths(preserved)
        # Only invalidate paths whose LATEST read is in to-summarize (not in preserved)
        for path_str in summarized_paths - preserved_paths:
            forget_license(session_id, Path(path_str))
    except Exception:
        pass  # never break summarization
```

## 权衡

- **只堵 write_file，不堵 patch_file**——patch_file 的 `old_string` 匹配失败是天然
  防线，不需要许可证。write_file 是全量覆写，没有天然防线，必须靠许可证拦截。
- **只处理 Summarization，不处理 ContextEviction**——ContextEviction 切片时模型
  仍有 4000 字符，且重读也会被切片，清许可证无收益。Summarization 是内容**完全
  消失**的场景，才是真正的盲区。
- **双向扫描避免误杀**——只清 A − B（to-summarize 里有、preserved 里没有的路径），
  不清 A ∩ B（两边都有）。这样同一文件读过多次、最新一次在 preserved 时，许可证
  保持有效，不会迫使不必要的重读。
- **路径解析可能不匹配**——session 切换 project dir 后，旧许可证的路径和新解析
  的路径不一致，清不掉。这是罕见场景，fail-open（许可证残留 = 当前行为，无回归）。
- **成本极低**——两次集合扫描（遍历 to-summarize + preserved 消息，提取 read_file
  路径），一次差集，若干次 dict pop。对压缩性能无可测量影响。
