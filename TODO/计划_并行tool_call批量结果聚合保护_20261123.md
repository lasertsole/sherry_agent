# 计划：并行 tool call 批量结果聚合大小保护

- 日期：2026-11-23
- 状态：**待评审**
- 来源：一个 AIMessage 生成大量并行 tool call，每个 ToolMessage 刚好卡在 ContextEviction 的 20K 字符阈值下，合计远超 context window。ContextEviction 逐个检查不看合计，压缩砍不动，session 卡死。
- 风险等级：**中** — 在 SafeToolNode 的批量结果收集点加聚合检查，改动核心路径但 fail-open
- 依赖：无
- 可独立执行：✅

---

## 0. 问题

```
模型生成 AIMessage(100 tool_calls)
  → SafeToolNode 并行执行 100 个工具，每个返回 ~19K 字符
  → ContextEviction.awrap_tool_call 逐个检查：19K < 20K → 不 evict
  → 100 个 ToolMessage 进入 state，合计 1.9M 字符 ≈ 475K token
  → 压缩砍不动 → 模型 API "context too long" → session 卡死
```

根因：`awrap_tool_call` 是 per-call 的（在 `ToolNode._arun_one` 内触发），100 个并行调用各自只看到自己的结果，没有聚合视角。中间件协议没有 post-batch 回调。唯一能看到全部结果的是 `SafeToolNode._afunc`/`_func` 在 `asyncio.gather` 返回后、`_combine_tool_outputs` 调用前。

---

## 1. 设计

在 `SafeToolNode._afunc`/`_func` 的 4 个 outputs 组装点（enforce/non-enforce × sync/async），插入聚合检查：

1. 计算所有 ToolMessage 的合计字符数
2. 合计 > `batch_result_threshold_chars`（默认 100K）时，从最大的开始逐个 evict
3. evict 复用现有的 `evict_tool_result(msg, session_id)`（`pub/func/message/eviction.py:399`）——offload 到磁盘 + head/tail 预览
4. `evict_tool_result` 返回 None（offload 失败/预览不更小）时，fallback 到 `hard_clip_tool_result(msg)`（内存 head/tail 截断，不写磁盘）
5. 已 evict 的（内容以 `[evicted to: ` 开头）跳过不重复处理
6. Command 包装的 ToolMessage 用 `_rewrite_tool_messages` 遍历

```python
def _extract_tool_message(output: Any) -> ToolMessage | None:
    """从 outputs 元素中提取裸 ToolMessage（可能是 ToolMessage 或 Command 包装的）。"""
    if isinstance(output, ToolMessage):
        return output
    # Command 包装：update["messages"] 里找 ToolMessage
    update = getattr(output, "update", None)
    if isinstance(update, dict):
        for m in update.get("messages", []):
            if isinstance(m, ToolMessage):
                return m
    return None


def _msg_content_size(output: Any) -> int:
    """outputs 元素的文本内容字符数（ToolMessage 或 Command 包装的）。"""
    msg = _extract_tool_message(output)
    if msg is None:
        return 0
    content = msg.content
    if isinstance(content, str):
        return len(content)
    if isinstance(content, list):
        # 多模态：累加 text block
        return sum(len(b.get("text", "")) for b in content if isinstance(b, dict) and b.get("type") == "text")
    return 0


def _is_already_evicted(output: Any) -> bool:
    """该结果是否已被 evict（内容以 '[evicted to: ' 开头）。"""
    msg = _extract_tool_message(output)
    if msg is None:
        return False
    content = msg.content
    return isinstance(content, str) and content.startswith(EVICTION_PREFIX)


def _evict_one(output: Any, session_id: str) -> Any:
    """对一个 outputs 元素做 eviction，返回替换后的元素。

    聚合场景用 force=True 跳过单个 20K 阈值检查——evict 的决策依据是
    合计大小（_enforce_batch_size_limit 已判断合计超阈值），不是单个大小。
    单个 19K 的结果在逐个检查时不 evict（< 20K），但 100 个 19K 合计 1.9M
    时必须 evict。

    复用 evict_tool_result（offload 到磁盘 + head/tail 预览，force=True）；
    返回 None 时 fallback 到 hard_clip_tool_result（内存截断，force=True）；
    都失败时返回原元素（fail-open）。
    处理 Command 包装：用 _rewrite_tool_messages 遍历。
    """
    def rewrite(msg: ToolMessage) -> ToolMessage:
        try:
            replacement = evict_tool_result(msg, session_id, force=True)
            if replacement is not None:
                return replacement
        except Exception:
            logger.debug("batch evict_tool_result failed for {}", getattr(msg, "tool_call_id", "?"))
        try:
            clipped = hard_clip_tool_result(msg, force=True)
            if clipped is not None:
                return clipped
        except Exception:
            logger.debug("batch hard_clip_tool_result failed for {}", getattr(msg, "tool_call_id", "?"))
        return msg  # fail-open：都失败时保留原结果

    return _rewrite_tool_messages(output, rewrite)


def _enforce_batch_size_limit(outputs: list[Any], session_id: str) -> list[Any]:
    """如果批量 ToolMessage 合计字符数超阈值，从最大的开始逐个 evict。

    已 evict 的跳过。evict 失败 fail-open 保留原结果。
    """
    threshold = TOOL_PARALLEL.get("batch_result_threshold_chars", 0)
    if threshold <= 0 or len(outputs) <= 1:
        return outputs

    total = sum(_msg_content_size(o) for o in outputs)
    if total <= threshold:
        return outputs

    logger.info(
        "SafeToolNode: batch result size {} chars exceeds threshold {}, evicting largest first ({} outputs)",
        total, threshold, len(outputs),
    )

    # 按内容大小降序，从最大的开始 evict
    indices_by_size = sorted(
        range(len(outputs)),
        key=lambda i: _msg_content_size(outputs[i]),
        reverse=True,
    )

    result = list(outputs)
    for i in indices_by_size:
        if total <= threshold:
            break
        if _is_already_evicted(result[i]):
            continue
        size_before = _msg_content_size(result[i])
        if size_before <= 0:
            continue
        result[i] = _evict_one(result[i], session_id)
        size_after = _msg_content_size(result[i])
        total -= max(0, size_before - size_after)

    return result
```

### 3.7 完整的 _afunc 改后代码

```python
async def _afunc(self, input: Any, config: RunnableConfig, runtime: Runtime) -> Any:
    tool_calls, input_type = self._parse_input(input)
    if not tool_calls:
        return self._combine_tool_outputs([], input_type)
    config_list = get_config_list(config, len(tool_calls))
    runtimes = self._build_runtimes(tool_calls, config_list, input, runtime)
    session_id = str(
        (config.get("configurable") or {}).get("thread_id")
        or (runtime.context or {}).get("session_id")
        or ""
    )
    plan = plan_batch(
        [dict(call) for call in tool_calls],
        dict(self.tools_by_name),
        runtimes[0].state if runtimes else None,
    )
    _log_plan(plan, list(tool_calls))

    async def run_one(index: int) -> tuple[int, Any]:
        return index, await self._arun_one(tool_calls[index], input_type, runtimes[index])

    if not TOOL_PARALLEL["enforce"]:
        outputs = await asyncio.gather(*(run_one(i) for i in range(len(tool_calls))))
        flat = [out for _, out in outputs]
        if session_id:
            flat = await asyncio.to_thread(_enforce_batch_size_limit, flat, session_id)
        return self._combine_tool_outputs(flat, input_type)

    async def run_group(indices: tuple[int, ...], concurrent: bool) -> list[tuple[int, Any]]:
        if concurrent and len(indices) > 1:
            return list(await asyncio.gather(*(run_one(i) for i in indices)))
        return [await run_one(i) for i in indices]

    group_results = await asyncio.gather(
        *(run_group(group.indices, group.concurrent) for group in plan.groups)
    )
    by_index: dict[int, Any] = {}
    for group in group_results:
        for index, output in group:
            by_index[index] = output
    outputs = [by_index[i] for i in range(len(tool_calls))]
    if session_id:
        outputs = await asyncio.to_thread(_enforce_batch_size_limit, outputs, session_id)
    return self._combine_tool_outputs(outputs, input_type)
```

## 5. 执行效果

### 19K × 100 场景（单个 < 20K 阈值，合计 1.9M）

```
100 个 ToolMessage × 19K = 1.9M 字符
  → 聚合检查：1.9M > 100K 阈值
  → 按大小降序（都 19K，任选）
  → 逐个调 evict_tool_result(msg, sid, force=True)：
     force=True 跳过 19K < 20K 的单个阈值检查
     → offload 到磁盘，替换成 ~500 字符预览
  → evict 到第 96 个时：4 × 19K + 96 × ~500 ≈ 76K + 48K ≈ 124K，还超
  → 再 evict 2 个：2 × 19K + 98 × ~500 ≈ 38K + 49K ≈ 87K < 100K ✓
  → state：2 个完整结果 + 98 个预览 ≈ 87K 字符 ≈ 22K token
  → 在 context window 内，压缩正常工作
```

**关键**：没有 `force=True` 时，`evict_tool_result` 对 19K 结果返回 None（19K < 20K 单个阈值），一个都 evict 不掉。`force=True` 让聚合检查绕过单个阈值，按合计大小做 evict 决策。

### 正常场景（2-5 个并行 tool call）

```
2-5 个 ToolMessage，合计通常 < 100K
  → 聚合检查不触发（total <= threshold）
  → 行为完全不变
```

## 6. 不改的东西

| 项 | 理由 |
|----|------|
| ContextEviction 的逐个检查 | 保留——它处理单个大结果（> 20K），聚合检查处理"多个中等结果的合计" |
| ContextEviction 的阈值（20K） | 不改——`force` 默认 False，现有逐个调用不传 → 行为不变 |
| `evict_tool_result` / `hard_clip_tool_result` 的核心逻辑 | 不改——只加 `force` 参数跳过阈值检查，offload/preview/clip 逻辑不变 |
| OrphanPairRepairer | 不改——它防 tool pair 拆分，是独立问题 |
| `_aggressive_truncate` | 不改——它是压缩后的兜底，聚合检查是压缩前的预防 |
| `plan_batch` 批次调度 | 不改——文件感知分组不变，聚合检查在分组执行后 |
| 防线 A（并行数量上限） | 不做——防线 B 单独就够，防线 A 的分批逻辑复杂且实际场景极少超过 20 个并行调用 |

## 8. 风险

| 风险 | 缓解 |
|------|------|
| 聚合 evict 丢关键信息 | 只 evict 最大的（通常是文件读取/搜索，head/tail 预览已足够）；小结果不 evict |
| evict 逻辑与 ContextEviction 不一致 | 直接复用 `evict_tool_result` + `hard_clip_tool_result`，不重写 |
| Command 包装遗漏 | 用 `_rewrite_tool_messages` 遍历（和 ContextEviction 同逻辑） |
| 同步 I/O 阻塞 event loop | async 路径用 `asyncio.to_thread` 包装（和 ContextEviction.awrap_tool_call 同做法） |
| 阈值设太低误 evict | 默认 100K 字符（≈ 25K token），正常 2-5 个并行结果不会触发 |
| session_id 为空 | 跳过聚合检查（无法 offload 到磁盘），fail-open |
| SafeToolNode 改动影响核心路径 | 四处插入点都在 `_combine_tool_outputs` 调用前，纯加法，不改现有执行逻辑；fail-open 包裹 |

### Kill criteria

- 若聚合 evict 导致模型丢失关键信息，提高阈值到 200K 或加白名单（只 evict name 在指定集合里的工具结果）
- 若 100K 阈值仍让 session 卡死（极端 case），加并行数量上限防线 A
- 若 `asyncio.to_thread` 在高并发下性能差，改为在 `_arun_one` 层面做 per-call 聚合计数

## 9. 验收

- 2-5 个正常并行结果，合计 < 100K → 不触发聚合 evict，outputs 原样返回
- 100 个 19K 结果 → 合计 > 100K → 从最大的开始 evict，最终合计 < 100K
