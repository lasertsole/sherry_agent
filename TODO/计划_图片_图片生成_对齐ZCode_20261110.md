## 0. ZCode 做法（核实）

ZCode 图片**留工具卡，不挪最终气泡**：
- 工具结果带 `media`/`images` 字段（`{mimeType, data, artifactUri}`）
- 专用渲染器把图片渲染成缩略图网格（`NodeReplImageGrid` for node-repl、`CuaScreenshotSection` for cua）+ 点击 lightbox（`ImagePreviewDialog`）
- 图片在 turn 中途的工具卡位置，不移动到最终 AI 气泡
- ZCode 源码无 `image_generation` 专用渲染器（`image_generation` 是 OpenAI Responses API 内置工具，OpenAI 侧运行）；真正有专用图片渲染的是 node-repl/cua 工具结果

## 2. 设计（skill 路线 + 工具卡渲染）

### 2.1 修 skill 脚本（核心：artifact store + print URI + 格式守卫）

`skills/builtin/text_to_image/scripts/core.py` 改造：

```python
@validate_call
def generate_image(prompt: str, *, size: str = "1024x1024", quality: str = "standard",
                   n: int = 1, model: str | None = None) -> str:
    """生成图片，写入 artifact store，返回 sherry-artifact:// URI。"""
    # 1. 读 TTI_* env（url/api_name/api_key）
    # 2. 解析 model（参数 > env TTI_API_NAME）
    # 3. 格式守卫（§2.3）：新模型省略 response_format，旧模型强制 b64_json
    # 4. POST 图片 API
    # 5. 解码 b64_json → bytes（处理 data: 前缀）
    # 6. 写 artifact store（需 session_id，见下）
    # 7. print(sherry-artifact:// URI) 到 stdout  ← 让 terminal 工具结果捕获
    # 8. return URI
```

**关键改动**：
- `STATIC_DIR` → artifact store（`agent/tools/pub_base/artifact_store.py`）
- 返回 `None` → 返回/print `sherry-artifact://<sid>/<name>` URI
- 硬编码 `response_format: b64_json` → 格式守卫
- 硬编码 size/seed → 可配参数

**session_id 获取（需解决）**：artifact store 的 URI 是 session 作用域（`sherry-artifact://<session_id>/<name>`）。脚本经 terminal 运行，需拿到 session_id。两个方案：
- A：terminal 工具执行命令时注入 `SHERRY_SESSION_ID` 环境变量（需改 terminal 工具，设 env）
- B：SKILL.md 调用时把 session_id 作为参数传给脚本（`generate_image(prompt, session_id=...)`）——但 SKILL.md 的脚本模板得知道怎么拿 session_id

**建议方案 A**（terminal 注入 env），因为它是通用增强（任何经 terminal 的 skill 脚本都能拿 session_id），不只服务图片。需核实 terminal 工具当前是否设了这个 env，没有则加。

### 2.2 ChatToolCard 图片渲染分支（核心前端改动）

`client/app/components/chat/ChatToolCard.vue` 现在所有工具结果走 `<pre>` 纯文本（`message.toolResult`）。新增**图片渲染分支**：

```vue
<!-- 现有：纯文本 <pre> -->
<!-- 新增：检测 toolResult 含 sherry-artifact:// URI → 渲染缩略图 -->
<template v-if="hasArtifactImages(message.toolResult)">
  <ImageThumbnailGallery>
    <img v-for="uri in extractArtifactUris(message.toolResult)"
         :src="resolveArtifactUriToHttp(uri)" @click="openLightbox(uri)" />
  </ImageThumbnailGallery>
</template>
<pre v-else>{{ message.toolResult }}</pre>
```

- `hasArtifactImages`：检测 toolResult 文本含 `sherry-artifact://` 正则匹配
- `extractArtifactUris`：提取所有 URI
- `resolveArtifactUriToHttp`：复用 `media-resolver.ts::artifactUriToHttp`
- lightbox：复用 `useImagePreview`（`openGallery(items, startIndex)`）
- **通用分支**：任何工具结果（terminal 跑 skill / 未来专用工具）含 `sherry-artifact://` URI 都渲染，不绑定工具名

参照 ZCode 的 `NodeReplImageGrid`（缩略图网格 + `ImagePreviewDialog` lightbox）。

**图片默认可见（关键 UX，否则图片藏在折叠工具卡里看不到）**：

Sherry 工具卡默认折叠（`expandedToolCards` Set 默认空），且整个 turn 工作历史还折叠在最终答案后面（`use-chat-turn-fold.ts`）。图片只在工具卡里 → 默认不可见。两层保证可见：

1. **自动展开含图工具卡**（选项 1）：工具结果含 `sherry-artifact://` URI 时，该工具卡**自动展开**（加入 `expandedToolCards` 默认集合，不走点击展开）。改 `useChatCardExpansion`（或渲染时检测 URI → 强制 expanded）。这样图片在 turn 中途的工具卡里直接可见，不需用户点击。

2. **turn 折叠头部露缩略图**（选项 3）：当 turn 历史折叠时（`ChatTurnHistoryStatus` 折叠按钮），扫描该 turn 工具结果里的 `sherry-artifact://` URI，在折叠按钮旁显示**小缩略图预览**（一张或几张缩略图 peeks）。用户一眼看到"这里有图"→ 点击展开 turn 历史 → 看到完整图（自动展开的工具卡里）。

两层配合：turn 折叠时头部露缩略图（选项 3 提示有图）→ 展开后工具卡自动展开（选项 1 直接显示图）→ 工具卡内点击图进 lightbox（§2.2 渲染分支）。全程不需模型在气泡复述、不动中间件。
