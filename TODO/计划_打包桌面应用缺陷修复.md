# 计划_打包桌面应用缺陷修复

打包版桌面应用（`D:\selfProj\EMA AI Agent`，`APP_HOME = %APPDATA%\com.ema-ai.agent`）首次启动遇到的 6 个问题。按根因归为 4 类：

1. 首次启动 / 预设选择器创建会话失败 `([object Object])` —— workspace 目录缺失 + 错误对象渲染退化
2. 关闭时不询问最小化到托盘 —— 关闭按钮无拦截
3. 模型配置 / 应用配置加载失败、切语言保存报 `/sherry-config (HTTP 500)` —— `--sherry-home` CLI 与 `SHERRY_HOME` env 解析不一致
4. 记忆配置面板空白 —— `memory_read`/`memory_write` Tauri 命令未注册

---

## 一、创建会话失败 `([object Object])`（Onboarding + 预设选择器）

### 现象

- **入口 A（Onboarding）**：首次启动完成引导到“一切就绪，开始对话吧”，点击创建会话提示：
  `创建会话失败 ([object Object])`
- **入口 B（预设选择器）**：创建新会话弹出预设窗口，点任一项提示：
  `预设应用失败，请检查后端连接后重试 ([object Object])`

每个预设都复现。两条文案分别是 `onboarding.createFailed` 与 `personaPreset.applyFailed` i18n key。

### 根因（两个缺陷叠加）

两入口共用同一链：`createSessionFromPreset`（`client/app/composables/persona-catalog.ts:466`）→ `applyPresetPayload`（`:551`）→ `writeSystemPrompt`（`:552`）→ Tauri `invoke('system_prompt_write')` → Rust 代理 `PUT /system_prompt`（`client/src-tauri/src/commands/system_prompt.rs:146`）→ 后端 `FileStore._write_one`（`server/service/file_store.py:69`）。

**缺陷 A（后端，决定失败本身）**：打包版首次启动 `%APPDATA%\com.ema-ai.agent\workspace\` 目录从未被创建（实机确认缺失，同级 `src/` 已建）。`_write_one` 里 `open(workspace/AGENTS.md, "w")` 不自动建父目录，抛 `FileNotFoundError`。写路径 `write_files`（`file_store.py:78`）不触发读路径的 `ensure_workspace_system_files()`（`workspace/file_sync.py:62`），且该函数本身也不 `mkdir` workspace 根目录。后端 200K token 门对桌面版未配置模型放行（`server/__main__.py:149` 的 `--sherry-desktop` 分支），所以**后端在线、能服务，只是写 persona 时崩**——不是模型/启动门问题。

实机错误日志佐证（重复 6 次对应 6 次重试）：
`C:\Users\swx1456303\AppData\Roaming\com.ema-ai.agent\logs\output\error\error_2026-11-05_38704.log`
```
FileNotFoundError: [Errno 2] No such file or directory:
'C:\...\com.ema-ai.agent\workspace\AGENTS.md'
```

**缺陷 B（前端，决定信息不可读）**：Tauri 把 `Err(FrontendError)`（`client/src-tauri/src/utils/error.rs:152`，结构体 `{code, message}`）序列化成 JS 端**普通对象**，不是 `Error` 实例。两处 catch 用同一写法，`String(普通对象)` = `"[object Object]"`：
- `client/app/components/OnboardingDialog.vue:239-242`
- `client/app/pages/home/components/NewSessionPresetDialog.vue:128-131`

```ts
const detail = e instanceof Error ? e.message : String(e);  // → "[object Object]"
```

`requestApi.ts` 的 `fetchApi` 吞 HTTP 错误返回 `null` 不抛，throw 必然来自 Tauri IPC 路径，与浏览器 HTTP 抓包无关。

### 解决方案

**修缺陷 A（必做，真正解决）**——写路径补目录创建：

```python
# workspace/file_sync.py ensure_workspace_system_files 起始
WORKSPACE_DIR.mkdir(parents=True, exist_ok=True)
```

```python
# server/service/file_store.py write_files，复用现有 _before_read
def write_files(self, files):
    self._before_read()  # 复用：确保目录+模板就绪（确认幂等：目标缺失才 copy）
    return [self._write_one(name, content) for name, content in files]
```

若 `_before_read` 的 copy 对已写内容有覆盖副作用，改为仅在目录缺失时 mkdir、不触发文件 copy。

**修缺陷 B（建议，改善可诊断性）**——抽公共函数，两处替换：

```ts
function describeError(e: unknown): string {
  if (e instanceof Error) return e.message;
  if (e && typeof e === 'object') {
    const msg = (e as any).message;
    const code = (e as any).code;
    if (typeof msg === 'string' && msg) return code ? `${code}: ${msg}` : msg;
    try { return JSON.stringify(e); } catch { /* fallthrough */ }
  }
  return String(e);
}
```

放 `client/app/utils/`，`OnboardingDialog.vue:241` 与 `NewSessionPresetDialog.vue:130` 都替换掉 `e instanceof Error ? e.message : String(e)`。

**顺带**：把 `personaPreset.applyFailed` 文案“请检查后端连接后重试”改为“请查看日志后重试”，避免误导（后端实际在线）。

### 验证

1. 删除 `%APPDATA%\com.ema-ai.agent\workspace` 重启 → 重走 Onboarding 创建会话成功；主界面新建会话选任一预设成功。
2. 故意触发后端 500 → 前端提示显示真实 `BACKEND_ERROR: HTTP 500: ...` 而非 `[object Object]`。
3. 补一条首次写、目录不存在的后端测试用例。

## 二、关闭时不询问最小化到托盘

### 现象

点窗口关闭按钮（×）直接退出进程，不弹“是否最小化到托盘”询问框，也没有“不再询问”选框；且即便最小化到托盘，**托盘区也不显示图标**（无可视入口，用户无法点回窗口）。

### 现状（已核实）

- **托盘对象已创建但无图标**：`client/src-tauri/src/lib.rs:93-116` 的 `TrayIconBuilder::new()` 只设了 `.menu()`、`.tooltip("EMA AI Agent")`、`.on_menu_event(...)`，**从未调用 `.icon(...)`**——托盘条目创建了（右键菜单 `show`/`hide`/`quit` 逻辑齐全），但通知区没有可见图标，用户既看不到、也无从右键。`tauri.conf.json` 的 `icon` 数组（`icons/32x32.png` 等）只作用于窗口/可执行文件图标，**不自动赋给托盘**——托盘图标必须显式 `.icon(Image)` 设置。打包目录 `D:\selfProj\EMA AI Agent` 下也不带 `icons/` 文件夹（图标已嵌入 exe，非独立资源）。
- **关闭按钮无拦截**：全 `client/src-tauri/src/` 无 `on_window_event`/`CloseRequested`/`prevent_close`。`tauri::Builder`（`lib.rs:33`）链式注册插件、`invoke_handler`、`setup`，但从未 `.on_window_event(...)`。关闭走默认行为——销毁窗口、退出进程。
- **前端无关闭处理**：`client/app/` 未导入 `@tauri-apps/api/window`、无 `onCloseRequested`。唯一关闭相关是 `client/app/app.vue:65-77` 的 `beforeunload`，只清理 WebSocket 单例，不阻止关闭。
- **无托盘偏好**：`minimizeToTray`/`closeToTray`/`closeAction` 全仓无匹配。但已有现成落点——Dexie `appFlags` 表（`client/app/composables/db.ts:427`，schema v6，泛型 key/value，已存 onboarding seen 位）+ `use-app-flags.ts` 的 `getAppFlag`/`setAppFlag`（Dexie + localStorage 双写）。无需 schema 迁移。
- **`tauri.conf.json`/capabilities 无需改**：托盘已在 Rust 构建，自定义命令在 `core:default` 下可调用。

### 解决方案

**0. Rust：给托盘设置图标（修复“无托盘图标”）**

`lib.rs:93` 的 `TrayIconBuilder::new()` 缺 `.icon(...)`，导致通知区无可视图标。复用 `tauri.conf.json` 已配置的窗口图标最省事（编译期嵌入，不依赖运行时资源路径，打包版也成立）：

```rust
let mut tray_builder = TrayIconBuilder::new()
    .menu(&tray_menu)
    .tooltip("EMA AI Agent");
// 复用 app 默认窗口图标（来自 tauri.conf.json 的 icon 数组，已嵌入二进制）
if let Some(icon) = app.default_window_icon() {
    tray_builder = tray_builder.icon(icon.clone());
}
let _tray = tray_builder.on_menu_event(| ... | { ... }).build(app)?;
```

> 备选：`.icon(tauri::image::Image::from_bytes(include_bytes!("../icons/32x32.png")))` 编译期嵌入指定图。不要用运行时路径读图标——打包目录不带 `icons/` 文件夹。

**1. Rust：拦截关闭事件转前端决策**

`client/src-tauri/src/lib.rs` 的 `tauri::Builder` 链加 `.on_window_event`：

```rust
.on_window_event(|window, event| {
    if let tauri::WindowEvent::CloseRequested { api, .. } = event {
        api.prevent_close();  // 无条件阻止默认退出，让前端 onCloseRequested 决策
        // 前端未注册监听（webview 未就绪）时加超时兜底 window.hide()
    }
})
```

**2. 前端：关闭询问对话框 + “不再询问”选框**

- 新建 `CloseToTrayDialog.vue`（复用 PrimeVue `Dialog`），三语 i18n（`closeTray.*`）：标题“关闭应用”、正文“关闭后是否最小化到托盘？”、选框“不再询问”、按钮 最小化到托盘 / 直接退出。
- `app.vue` 或 shell 层监听：

```ts
import { getCurrentWindow } from '@tauri-apps/api/window';
const win = getCurrentWindow();
await win.onCloseRequested(async (event) => {
  const pref = await getAppFlag('closeAction'); // undefined | 'tray' | 'exit'
  if (pref === 'tray') { event.preventDefault(); await win.hide(); return; }
  if (pref === 'exit') { return; }  // 放行退出
  const choice = await askCloseToTray();        // 'tray'|'exit'
  if (remember.checked) await setAppFlag('closeAction', choice);
  if (choice === 'tray') { event.preventDefault(); await win.hide(); }
});
```

**3. 设置面板露出选项**

`client/app/pages/home/components/ConfigPanel.vue` 加“关闭行为”下拉（最小化到托盘 / 直接退出 / 每次询问），读写同一 `closeAction` flag。

**4. 兜底**：托盘“退出”仍走 `app.exit(0)`（`lib.rs:109`）不受影响；最小化到托盘后托盘“显示”恢复（`lib.rs:98`）。

2. 首次点 × → 弹框，勾“不再询问”+“最小化到托盘” → 窗口隐藏、托盘图标仍在、进程不退。

4. 设置面板改“直接退出” → 点 × 进程退出。
5. 改“每次询问” → 恢复弹框。
6. 重启后偏好仍生效（Dexie + localStorage 双写）。

## 三、模型配置/应用配置加载失败 + 切语言报 `/sherry-config (HTTP 500)`

### 现象

- 菜单 → 系统配置 → **模型配置** tab 显示“模型配置加载失败，请检查后端服务是否已启动。”
- 菜单 → 系统配置 → **应用配置** tab 显示“应用配置加载失败，请检查后端服务是否已启动。”
- 在应用配置里切语言（改 `WORKSPACE_TEMPLATE_LANG`）保存时报 `/sherry-config (HTTP 500)`。

后端实际在线（能服务、其他面板正常），提示文案误导。

### 根因（同根因，读/写两种表现）

**`--sherry-home` CLI 参数 与 `SHERRY_HOME` 环境变量解析不一致**：Tauri shell 只把可写 home 作为 `--sherry-home` CLI 参数传给后端，**故意不设 `SHERRY_HOME` 环境变量**（`client/src-tauri/src/services/python_process.rs:206-215`，注释 `:190-192`）。但三个拆分配置模块只读环境变量、不扫 CLI 参数，于是它们算出的 `APP_HOME` 与 `config/path.py` 不一致——指向只读的打包树 `_CODE_ROOT`，配置文件静默 seeding 失败。

- `config/sherry_settings.py:29-30`、`config/models_settings.py:46-50`、`config/network_settings.py:46-51`：`_APP_HOME_RAW = os.environ.get("SHERRY_HOME","")` → 空 → `APP_HOME = _CODE_ROOT`。
- `config/path.py:33-54`：扫 `sys.argv` 的 `--sherry-home` → `APP_HOME` = app-data（正确，所以 `.env` 正常生成）。

**实机确认** `%APPDATA%\com.ema-ai.agent\`：`.env` 存在；`.models` / `.network` / `sherry.jsonc` **全部缺失**（seeding 块 `if APP_HOME != _CODE_ROOT` 被跳过，或模板路径不匹配 / 只读 `OSError` 被 `except: pass` 吞掉）。

#### 失败链（读——加载失败）

1. 前端打开模型配置 → `loadEnvConfig()`（`ConfigPanel.vue:607`）`Promise.all([readModelsConfig(), readNetworkConfig(), readEnvConfig()])`。
2. `GET /models-config` → `read_models_config()`（`server/service/models_config.py:125`）`if not MODELS_CONFIG_PATH.exists(): raise FileNotFoundError`（`:135`）→ handler（`server/trigger/http/models_config.py:13`）无 try/except → **HTTP 500** → `Promise.all` reject → `envLoadError = "模型配置加载失败…"`（`ConfigPanel.vue:637`）。
3. `GET /sherry-config` → `read_sherry_config()`（`server/service/sherry_config.py:84`）同样 `FileNotFoundError`（`:95`）→ handler（`sherry_config.py:11-18`）无 try/except → 500 → `sherryLoadError = "应用配置加载失败…"`（`ConfigPanel.vue:776`）。
4. `/env` 本身可能成功（`ENV_PATH` 走 path.py 的 app-data 路径），但模型配置 tab 的 `Promise.all` 因 `readModelsConfig()`/`readNetworkConfig()` 抛错而整体失败。

#### 失败链（写——切语言保存失败）

1. 用户改 `WORKSPACE_TEMPLATE_LANG`（App Config tab，`ConfigPanel.vue:721`）后点保存 → `persistSherryChanges()`（`:785`）→ `writeSherryConfig(changes)`（`:791`）。
2. `PUT /sherry-config` → handler（`sherry_config.py:21-39`）`write_sherry_config(changes)`，只 `except ValueError`，**不 catch FileNotFoundError**。
3. Service（`sherry_config.py:151-152`）：`if not SHERRY_CONFIG_PATH.exists(): raise FileNotFoundError`——**写路径只拒绝、从不创建文件**。
4. 未捕获 → 全局 `handle_exception`（`server/trigger/core.py:88-120`）返回 **HTTP 500**（`:104-105`）→ 前端 toast `/sherry-config (HTTP 500)`。

**补充**：UI 界面语言切换器（`I18nPanel.vue:33` → `use-locale-switch.ts:42-47`）本身只 `setLocale` + 写 cookie，**不 PUT config**。触发 PUT 的是 App Config tab 里 `WORKSPACE_TEMPLATE_LANG`（工作区模板语言）的保存——两者都属“语言设置”，但写 config 的是后者。

### 解决方案

**核心修复**：让三个配置模块的 `APP_HOME` 解析与 `config/path.py` 一致——优先扫 `sys.argv` 的 `--sherry-home`，再 fallback 到 `SHERRY_HOME` env。

更彻底：把 home 解析收敛为单一来源——抽到 `config/_home.py`，`path.py` 与三个 settings 模块都从它 import，避免循环依赖（`path.py` 已 import `sherry_settings` 的 `get_sherry_setting`，`sherry_settings` 不能反向 import `path`）。

```python
# config/_home.py
import os, sys
from pathlib import Path

def resolve_app_home() -> Path:
    for i, a in enumerate(sys.argv[:-1]):
        if a == "--sherry-home" and sys.argv[i+1].strip():
            return Path(sys.argv[i+1].strip()).resolve()
    env_home = os.environ.get("SHERRY_HOME", "").strip()
    if env_home:
        return Path(env_home).resolve()
    return Path(__file__).resolve().parents[1]

APP_HOME = resolve_app_home()
```

三个模块把 `_APP_HOME_RAW`/`APP_HOME` 计算替换为 `from config._home import APP_HOME`。

**辅助修复**：
- `server/service/sherry_config.py` 的 `write_sherry_config` 写路径在 `SHERRY_CONFIG_PATH` 缺失时先 `ensure_sherry_config_file()`（seeding）再写，而非直接 `raise FileNotFoundError`——与读路径的 `_before_read` 思路一致（参照问题一的 `FileStore` 写路径）。
- `server/trigger/http/` 四个 handler（`models_config.py:13`、`network_config.py:15`、`env.py:13`、`sherry_config.py:11-18` 与 `21-39`）加 `except FileNotFoundError`，返回结构化 404/503 + “配置文件未初始化”提示，而非裸 500。
- seeding 的 `except OSError: pass`（三处）改为至少 `logger.warning`，避免静默失败难诊断。
- 修正 `python_process.rs:87` 过时注释（“value exported as `SHERRY_HOME`”是错的，shell 实际不导出）。
- 核对 `I18nPanel` 的 UI 语言切换与 App Config 的 `WORKSPACE_TEMPLATE_LANG` 文案是否易混淆，必要时区分标签。

### 验证

1. 删除 `%APPDATA%\com.ema-ai.agent` 下 `.models`/`.network`/`sherry.jsonc`（保留 `.env`）重启。
2. 打开模型配置 tab：正常加载；确认 `.models`/`.network`/`sherry.jsonc` 已在 app-data 生成。
3. 打开应用配置 tab：正常加载；改 `WORKSPACE_TEMPLATE_LANG` 保存 → 不再 500。
4. UI 语言切换器（`I18nPanel`）切语言只写 cookie、不触发 `/sherry-config`，无报错。
5. 重启后 `WORKSPACE_TEMPLATE_LANG` 持久化生效。
6. 补单测：模拟 `sys.argv` 含 `--sherry-home <tmp>` 且 `SHERRY_HOME` 未设，断言三个模块的 `*_CONFIG_PATH` 指向该 tmp 目录。

## 四、记忆配置面板空白

### 现象

打开记忆面板（右侧栏“记忆”tab，对应 `workspace/memory/MEMORY.md` / `USER.md` 编辑器）后**不显示任何内容**——无条目、无 loading、无错误提示，一片空白。

### 根因

**`memory_read` / `memory_write` 两个 Tauri IPC 命令从未在 Rust shell 里实现/注册**，且 `invokeNative` 的 null-fallback 契约在“命令缺失”时被打破（抛异常而非返回 null），导致 `readMemory` 既走不通原生路径、也来不及回退 HTTP。

#### 失败链

1. `MemoryPanel.loadContent()`（`client/app/pages/home/components/MemoryPanel.vue:221`）→ `readMemory()`（`client/app/composables/bridge/memory.ts:17`）。
2. `readMemory` 先 `await invokeNative('memory_read')`（`bridge/memory.ts:18` / `transport.ts:40-45`）：
   ```ts
   export async function invokeNative<T>(command, args?): Promise<NativeInvokeResult<T>> {
     if (!isTauri()) return null;          // 浏览器模式才返回 null
     const invoke = await getInvoke();
     return { kind: 'native', value: await invoke<T>(command, args) };  // 无 try/catch
   }
   ```
3. 打包版 `isTauri()` 为 true → `invoke('memory_read')`。但 `memory_read` **未注册**在 `invoke_handler`（`client/src-tauri/src/lib.rs:62-79`，只有 agent/session/system_prompt/system/cuda），`commands/mod.rs` 命令表也无 memory 模块（`core/memory/mod.rs` 是 agent-core 记忆，与此无关）→ Tauri **reject**。
4. `invokeNative` 无 try/catch → rejection 直接传播 → `readMemory` 的 `await invokeNative(...)` **在 `if (native !== null)` HTTP 回退之前就抛出**。
5. `MemoryPanel.loadContent` 的 catch（`MemoryPanel.vue:233-234`）只 `logUtil.e` 静默吞错 → `finally` `loading=false` → 面板空白。

`writeMemory`（`bridge/memory.ts:32-41`）同样 `invokeNative('memory_write')` → 缺失命令 → 抛异常 → 不回退 HTTP，保存也失败。

**这是独立根因**：`system_prompt_read/write` 有注册（所以问题一的写能到达后端），memory 命令从未注册。`invokeNative` 的“原生不可用则返回 null 回退 HTTP”契约在“命令缺失”这一情况被打破。

### 解决方案

**方案 A（推荐，与现有架构一致）：注册 `memory_read` / `memory_write` Rust 命令**

仿 `system_prompt.rs` 的 `system_prompt_read/write`（`client/src-tauri/src/commands/system_prompt.rs`），新建 `client/src-tauri/src/commands/memory.rs`，代理 `GET/PUT /memory`。在 `commands/mod.rs` 加 `pub mod memory;`，在 `lib.rs:62` 的 `generate_handler!` 注册。返回结构对齐前端 `PromptFileResponse`（`{ value: { file_to_content } }`）。

**方案 B（防御性，补契约）：让 `invokeNative` 在命令缺失时返回 null 而非抛异常**
