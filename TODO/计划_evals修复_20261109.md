### ② 修 ToolGuardrails 测试读取边界（run 222819 的失败链）

**问题。** run 222819（16820，默认 180）的失败链是：补丁语义不全 → agent 想继续读测试文件定位剩余 5 个 P2P 断言失败 → `ToolGuardrails` 阻止继续读 → agent 主动停止。guardrail 为阻止无效 terminal 探测而设计，但在这里切断了“读测试 → 修剩余断言”的合法路径。

**根因。** `agent/middlewares/tool_guardrails/core.py` 的 read-streak 计数把测试文件读取和无效探查一视同仁；`clears_guardrail_blocks` 只解锁工具 block，不放宽测试读取计数。

**改法（二选一，倾向第一个）。**
1. **测试文件读取豁免**：把 `tests/` 路径下的 `read_file` 从 read-streak 计数里豁免（类似浏览器调试工具的豁免机制）。需要 `ToolGuardrails` 识别目标路径——可以复用 `PathGuard` 的根 + 路径解析。
2. **patch 成功后临时放宽**：扩展 `clears_guardrail_blocks` 语义，让 `patch_file` 成功后不仅解锁工具 block，还临时给 N 次（如 5 次）测试文件读取额度。

**验证。** 重跑 16820：期望从 1/2 提升到 2/2，且 17051 的 4/4 不回归。

- [x] 实现豁免：`read_file` 的测试路径不参与 signature/no-progress/pair/signature-block
- [x] 单测：test-path read 豁免、source read 仍计数、只有 read_file 享受豁免

### ④ 【可选增强】plan 完成后 spawn reviewer subagent 复查工作产物

**现状（prompt 级复查收尾已存在，但不是 subagent 复查）。** `workspace/template/en/AGENTS.md:53-58`（四语言都有）的 **Completion Contract (Sisyphus)** 段就是从 opencode 抄来的复查收尾契约：

- **DoneClaim**：认为任务做完时先 CLAIM，但**不**立即标 completed
- **AdversarialVerify**：跑验收标准，探查 stale state / dirty worktree / leftover resources
- **FullyDone**：验证通过后才标 completed；失败则 re-dispatch 或 fix
- Anti-Patterns 段把 “Marking completed without verification” 标为 SISYPHUS VIOLATION

这是 **prompt 级、主代理自己 verify**，对应 opencode `beast.txt` 的 “verified that everything is working correctly”。它**不是**代码级自动插入复查 todo（`agent/tools/todolist/service.py` 没有这种逻辑），也**没有**让 main_agent spawn reviewer subagent 来复查工作产物 —— AdversarialVerify 的措辞是 “Run the acceptance criteria”，主代理自己跑。

现有两条**代码级** background-review 路径都不是复查工作：
- `_COMPRESSION_TODO_PROMPT`：压缩后对齐 todo 列表与实际进度（不是 review 代码）
- `_SKILL_REVIEW_PROMPT`：plan 完成后辅助模型 review **skill 文件**（不是 review 这次的工作产物）

todolist 的 transition barrier（`service.py:163`）是“绑了 subagent/TaskFlow 的 todo 必须等子任务返回才能标 completed”，是**完成门**，不是复查。

**增强（与已有 AdversarialVerify 的关系）。** 当前 AdversarialVerify 让主代理自己 verify，但 16820 run 222819 暴露的问题是：主代理跑完 `migrations` 全量测试发现 5 个 P2P 失败后**列出了剩余工作却停手** —— prompt 的 “If verification fails, re-dispatch or fix” 没被遵守。可选增强：plan 完成时 `sessions_spawn(functional_role="reviewer")` 让**独立只读视角**复查 diff + 跑目标测试 + 报告剩余断言失败，主代理接报告后继续修。这是给 AdversarialVerify 加一个**外部执行体**（subagent 而非主代理自检），降低“自己列了剩余工作就停”的概率。与 ③ 共存：③ 强化 prompt 让主代理自跑测试自修，④ 给一个独立复查兜底。

**增强。** plan 完成时（所有 todo `completed`/`cancelled`），可选 `sessions_spawn(functional_role="reviewer")` 让只读角色复查 diff + 跑目标测试 + 报告剩余断言失败，主代理接报告后继续修。与 ③ 共存：③ 管“自己跑测试自己修”，reviewer subagent 管“独立视角复查”。

**注意。** 这是新功能，不是修 bug。先做 ②③，若 16820 仍卡 1/2 再考虑 ④。

## 四、不做的事

- **不加 hard “tests-must-pass-before-finish” gate**。wiki 明说没有这个 gate 是有意的 —— 它会把“测试不可见”的 SWE-bench-faithful 实例变成不可解，且 agent 会学会绕过（hack 测试）。收敛靠 guardrail + prompt（②③），不靠硬门。
