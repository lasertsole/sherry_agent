## 0. 现状

### 0.1 LangGraph ToolNode 已并发执行

Sherry 用 LangGraph 的 ToolNode 执行工具。ToolNode 对模型返回的**并行 tool call 已经并发执行**（`asyncio.gather` over async tools）。`ToolGuardrails` 中间件已用 session 级 `threading.Lock` 保护自己的计数器状态（`tool_guardrails/core.py:123`：*"ToolNode executes a step's parallel tool calls concurrently"*）。

**问题**：没有**调度前的并行安全判定**——模型可以返回两个写文件的工具调用，它们会并发执行，可能产生竞态。Sherry 不知道哪些工具可以安全并行，只能靠 LLM 自觉串行调用。

### 0.2 现有工具 metadata

工具用 `metadata: dict` 声明属性（已有的字段）：

| 字段 | 类型 | 含义 | 示例 |
|---|---|---|---|
| `idempotent` | `bool` | 幂等性（重复调用无副作用） | `read_file: True`, `terminal: False` |
| `scope` | `str` | 可见范围 | `"main_only"` / `"researcher_only"` |
| `nudge` | `bool` | 是否触发 memory nudge | `memory: True` |
| `skip_heartbeat` | `bool` | 跳过心跳检查 | `question: True` |

**缺的**：`destructive` / `concurrent_safe` / `side_effect_scope`——并行安全判定三要素。

### 0.3 ZCode 做法

ZCode 的 `canRunInParallel(tool)` 逻辑（`scheduler.ts:85`）：

```
destructive == true                    → 阻止
concurrentSafe == true                 → 允许
readOnly 或 sideEffectScope == "none"  → 允许
否则                                   → 阻止
```

`READ_ONLY_TOOLS`（`:233`）显式列出 9 个默认只读工具。调度：拓扑排序 → `groupByParallel` → 按 `maxConcurrency`（默认 10）切分并行组 → 顺序遍历各组并行执行；任一组返回 `stopTurnAfterResult` → 剩余组全部标 `ToolCancelled`。

## 1. 设计：静态标注字段

### 1.1 新增三个 metadata 字段

```python
# 在 BaseTool 的 metadata dict 中新增三个字段

class ToolSafetyMeta(TypedDict, total=False):
    """并行安全静态标注，声明式，不执行任何用户代码。"""
    destructive: bool          # True = 有破坏性，永远不并行（如删除文件、终止进程）
    concurrent_safe: bool      # True = 显式声明可安全并行（即使有副作用）
    side_effect_scope: str     # "none" | "workspace" | "git" | "network" | "system" | "session" | "user_interaction"
```

**判定逻辑**（对标 ZCode `canRunInParallel`）：

```python
def can_run_in_parallel(tool_metadata: dict) -> bool:
    """调度前的并行安全判定。"""
    if tool_metadata.get("destructive", False):
        return False
    if tool_metadata.get("concurrent_safe", False):
        return True
    scope = tool_metadata.get("side_effect_scope", "workspace")  # 默认有副作用
    if scope == "none":
        return True
    # idempotent 且 scope == "session" 的工具也可并行（如 read_file）
    if tool_metadata.get("idempotent", False) and scope == "none":
        return True
    return False
```

## 3. 并行安全检查

### 3.1 设计

不改 ToolNode、不加分组调度器——LangGraph ToolNode 已并发执行同批 tool calls，而 `write_file` / `patch_file` 已有 `file_write_lock`（per-path `threading.Lock` → 跨进程 `flock`）+ 两层 CAS 保护并发写。真正的价值是**可观测性**：知道哪些工具被并发调用了、是否安全。

在 ToolGuardrails 的 `wrap_tool_call` / `awrap_tool_call` 的 **precheck** 阶段（`_wrap_tool_call_precheck`，`tool_guardrails/core.py:520`）加并行安全 warning。如果检测到不安全并行组合，记 warning 但**不阻断**——file_write_lock + CAS 已保护文件操作，terminal / python_repl 的并发风险靠 prompt 引导（Phase 3）而非强制串行。

**不做方案 B（自定义 ToolExecutor 替换 ToolNode）**：file_write_lock + CAS 已覆盖并发写竞态，替换 ToolNode 是重架构改动，边际收益不匹配成本。如果 Phase 1 的 warning 日志在实测中确实发现了真实的并发竞态（不是假阳性），再评估是否需要强制串行。

### 3.2 配置

**新文件**：`config/features/agent_side/tool_parallel.py`

```python
class ToolParallelConfig(TypedDict):
    log_unsafe_parallel: bool      # 记录不安全并行组合的 warning 日志

TOOL_PARALLEL: ToolParallelConfig = {
    "log_unsafe_parallel": True,
}
```

## 6. 风险

| 风险 | 对策 |
|---|---|
| 标注错误导致 warning 误报 | warning 不阻断执行，假阳性只是日志噪声；`catalog.py` 加测试确保所有工具名在 `TOOL_GROUPS` 或 `READ_ONLY_TOOLS` 中有记录 |
| `side_effect_scope` 值不规范 | 用 `Literal["none", "workspace", "git", "network", "system", "session", "user_interaction"]` 约束 |
| 子 agent 工具集不同 | `can_run_in_parallel` 按 metadata 判定，子 agent 的 `inherited_tool_policy.py` 已过滤可见工具，标注随工具走 |
