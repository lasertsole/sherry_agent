## 0. 结论先行

这份计划管的是**单个 agent 在同一次模型回复里返回的一批 tool calls**，不是多 agent 调度。

v1 只做静态标注 + warning，不阻断。v2 改为一个真正的批次级执行器：

- 批次全部安全 → 保持 `asyncio.gather` / `executor.map` 并发。
- 批次里有任何不安全工具 → 整批按模型给出的调用顺序串行执行。
- `enforce=False` 时只分类并记录 warning，行为与现在完全一致，用于观察误报。
- 多 agent 的并发仍由 `runtime/lane`、spawn admission、`file_write_lock`/CAS 负责，不在本计划范围内。

不直接合并 `xp_graph` 的 `SmartToolNode`：它现在的实现对当前 LangGraph 1.3.9 不兼容，且只按 `idempotent` 判定。保留的是它的**批次级分类思路**，代码按当前版本重写。

## 1. 参考实现评估

### 1.1 它做对了什么

`origin/xp_graph:agent/smart_tool_node.py` 的核心很小：

```python
def _should_parallelize(tool_calls, tools_by_name) -> bool:
    if len(tool_calls) <= 1:
        return False
    return all(tool.metadata.get("idempotent", False) for ...)
```

`SmartToolNode` 覆写 `_afunc` / `_func`：

- `_should_parallelize` 为真 → `asyncio.gather` / `executor.map`。
- 否则 → 按 `tool_calls` 列表顺序逐个 `await self._arun_one` / `self._run_one`。

这正是需要的批次级语义：**全安全才并发，否则整批顺序执行**。批次上下文和 `tools_by_name` 都在 ToolNode 里，不需要从 middleware 猜兄弟调用。

### 1.2 不能直接用的原因

| 问题 | 说明 |
|---|---|
| 未启用 | `origin/xp_graph:agent/core.py:12-16` 只 import 了 `patch_tool_node`，调用被注释掉，当前没有任何效果。 |
| 只认 `idempotent` | `memory` 当前是 `idempotent=True`（`agent/tools/memory.py:767`），但它会写 MesMemory；计划要求它不可并行。`sessions_spawn` 是 `idempotent=False`，但计划要求它可并行。单靠幂等会同时产生漏放和误串行。 |
| 当前版本不兼容 | 分支用的 `_get_config_list()` / `_build_tool_runtimes()` 在 LangGraph 1.3.9 的 `ToolNode` 上不存在；现在这两个步骤在 `_afunc` / `_func` 内联完成。直接复制会在运行时 `AttributeError`。 |
| 无测试 | 分支没有 `smart_tool_node` 的测试，无法防止升级漂移。 |
| 全局 monkeypatch | 分支直接改 `langchain.agents.factory.ToolNode`；这是 `create_agent` 唯一能注入自定义 ToolNode 的位置（`create_agent` 没有 `tool_node` 参数），可以保留，但必须做成显式安装 + 可关闭 + 兼容性测试。 |

## 2. 最终设计

### 2.1 静态标注字段

在工具 metadata 中新增三个字段（`agent/tools/parallel_safety.py` 定义 `TypedDict`）：

```python
class ToolSafetyMeta(TypedDict, total=False):
    destructive: bool          # True = 永远不并行
    concurrent_safe: bool      # True = 显式声明可并行（即使有副作用）
    side_effect_scope: Literal[
        "none", "workspace", "git", "network", "system", "session", "user_interaction"
    ]
```

判定顺序：

```python
def tool_is_parallel_safe(name: str, tool: BaseTool | None) -> bool:
    if name in READ_ONLY_TOOLS:
        return True
    meta = getattr(tool, "metadata", None)
    if not isinstance(meta, dict):
        return False
    if meta.get("destructive"):
        return False
    if meta.get("concurrent_safe"):
        return True
    return meta.get("side_effect_scope") == "none"
```

规则：

- 显式 `destructive` 优先，任何声明都不能翻案。
- 未知工具、缺 metadata、缺 `idempotent` 都按**不安全**处理。
- **不再用 `idempotent` 推导并行安全**。`idempotent` 只服务 ToolGuardrails 的重复调用检测；并行安全是独立语义。
- `READ_ONLY_TOOLS` 是名单兜底，不要求每个只读工具都改 metadata。

### 2.2 批次分类

```python
def batch_parallel_safe(tool_calls, tools_by_name) -> bool:
    return all(
        tool_is_parallel_safe(call["name"], tools_by_name.get(call["name"]))
        for call in tool_calls
    )
```

单调用批次分类为安全也无害（没有并发对象）；空批次直接走并发路径。

### 2.3 `SafeToolNode`（对标 SmartToolNode，适配当前版本）

新增 `agent/safe_tool_node.py`：

- `class SafeToolNode(ToolNode)`：只覆写 `_afunc` / `_func`，其余行为继承。
- `_should_parallelize(tool_calls, tools_by_name)` 调用 `batch_parallel_safe`。
- 并发分支保持当前 1.3.9 的实现：`get_config_list(config, n)` + 每个 call 构建 `ToolRuntime` + `asyncio.gather` / `executor.map`。
- 串行分支按 `tool_calls` 原顺序逐个执行，保证 `write A → patch A` 这种同批调用仍按模型给出的顺序运行。
- 结果统一交给 `_combine_tool_outputs(outputs, input_type)`，`Command` / `return_direct` 等行为不变。
- 分类/日志放在 `_should_parallelize` 内，每个批次只执行一次，天然不会为每个 tool call 重复打日志。

关键点：**不要**从分支复制 `_get_config_list` / `_build_tool_runtimes`；它们不存在。按当前 `ToolNode._afunc` / `_func` 的内联写法重写，并在兼容性测试里 pin 住所依赖的私有方法。

### 2.4 安装方式

`create_agent` 不暴露 `tool_node` 参数；`langchain.agents.factory` 在构造时读取模块级 `ToolNode`。因此：

```python
def install_safe_tool_node() -> None:
    import langchain.agents.factory as factory
    factory.ToolNode = SafeToolNode
```

调用位置：`agent/core.py` 模块导入时、`built_agent()` 之前执行一次（子代理的 `create_agent` 也走同一个 factory 全局，自动生效）。分支里被注释掉的 `patch_tool_node()` 改为受配置控制：

- `TOOL_PARALLEL["enabled"] = False` → 不 patch，行为与今天完全一致。
- `TOOL_PARALLEL["enabled"] = True` → patch 一次；进程内所有 `create_agent`（main / child / auxiliary）都用 `SafeToolNode`。
- `TOOL_PARALLEL["enforce"] = False` → `SafeToolNode` 仍走原生并发，只记录不安全批次，用于观察误报。
- `TOOL_PARALLEL["enforce"] = True` → 不安全批次整批串行。

保留全局 patch 的理由：这是唯一能在不改 `create_agent` 源码的情况下拿到完整批次的位置。风险由“pin LangGraph 版本 + 兼容性测试”兜底；上游若改私有方法，测试会先红。

### 2.5 配置

新增 `config/features/agent_side/tool_parallel.py`：

```python
class ToolParallelConfig(TypedDict):
    enabled: bool              # install SafeToolNode
    enforce: bool              # False = observe only
    log_unsafe_batches: bool   # one warning per unsafe batch

TOOL_PARALLEL: ToolParallelConfig = {
    "enabled": True,
    "enforce": True,
    "log_unsafe_batches": True,
}
```

下面是**收尾后的默认值**；Phase 1 先设 `enforce=False` 观察日志，Phase 2 再切到 `True`。`enabled=False` 是总开关；`enforce=False` 是灰度观察；`log_unsafe_batches` 只影响日志，不改变执行。

### 2.6 与现有多 agent 机制的关系

- 本计划只约束**一个 agent 的一次 ToolNode 批次**。
- 每个子 agent 在自己的图中执行，`SafeToolNode` 也会作用于它的批次（因为全局 patch），但父/子之间没有共享锁。
- 两个 agent 同时写同一个文件仍由 `file_write_lock` + `patch_file` 的 CAS 保护。
- 同一子代理的并发数量、排队与超时仍由 `runtime/lane` 的 SUBAGENT lane 和 spawn admission 控制。
- 不做跨 session 的全局锁；那会把不同会话的写操作无谓串行化，而且会把“单 agent 批次安全”升级成另一个问题。

## 3. 工具标注清单

### 3.1 READ_ONLY_TOOLS

放在 `agent/tools/parallel_safety.py`，按真实工具名：

```python
READ_ONLY_TOOLS = frozenset({
    # 文件读取 / 搜索
    "read_file", "search_files", "search_scan",
    # 代码智能（只读）
    "ast_grep", "lsp",
    # 网络读取
    "web_search", "web_fetch",
    # 历史 / 列表
    "message_search", "todolist_list", "taskflow_list", "taskflow_progress",
    "terminal_bg_list", "terminal_bg_output",
    "skill_list", "skill_view",
    "agents_list", "subagents_list", "sessions_messages",
    # 交互
    "question",
})
```

`code_intel_*` 的只读查询也加入；如果该组工具是动态注册的，在工厂里按实际名字补。

### 3.2 显式 `concurrent_safe`

| 工具 | 标注 | 理由 |
|---|---|---|
| `sessions_spawn` | `concurrent_safe: True` | spawn 本身是登记新 child，不共享可变状态；真正的并发由 SUBAGENT lane 控制 |
| 其他 | 不标 | 默认不安全 |

### 3.3 必须标 `side_effect_scope` 的写工具

| 工具 | scope | 说明 |
|---|---|---|
| `write_file`, `patch_file` | `workspace` | 同文件竞态已有 file_write_lock / CAS，但并行语义仍标不安全 |
| `terminal`, `python_repl`, `execute_code`, `ptc` | `system` | 可能写文件 / 改环境 |
| `memory` | `session` | 写 MesMemory；**即使 idempotent=True 也不可并行** |
| `todolist_write` | `session` | 写 SQLite todo |
| `taskflow_*` 的写操作 | `session` | 写 SQLite / dispatch |
| `skill_manage`, `enter_plan_mode`, `exit_plan_mode` | `session` | 改技能 / state register |
| `sessions_send`, `sessions_steer`, `sessions_kill`, `sessions_yield` | `session` | 改子代理状态 / 等待 |
| `browser_*` | `network` | 浏览器操作有副作用 |
| `cron_*` | `session` | 写 cron_jobs.json |

不要求给所有工具都加 scope；没有 scope 且不在 READ_ONLY_TOOLS 的工具默认不安全，行为是保守的。测试要保证 `TOOL_GROUPS` 里的每个名字要么在 READ_ONLY_TOOLS，要么在测试的“已知不安全”名单里，防止新增工具漏标。

## 4. 实施顺序

### Phase 0：分类基础设施（不改行为）

1. 新增 `agent/tools/parallel_safety.py`：`ToolSafetyMeta`、`READ_ONLY_TOOLS`、`tool_is_parallel_safe`、`batch_parallel_safe`。
2. 新增 `config/features/agent_side/tool_parallel.py` + 导出。
3. 单测：`read_file` / `memory` / `write_file` / `sessions_spawn` / 未知工具。

### Phase 1：SafeToolNode + 安装

1. 新增 `agent/safe_tool_node.py`，按 1.3.9 的 `ToolNode._afunc` / `_func` 重写（不要复制分支的缺失 helper）。
2. `agent/core.py` 导入时按 `TOOL_PARALLEL["enabled"]` 调用 `install_safe_tool_node()`。
3. 先跑 `enforce=False`（观察模式），确认日志里的不安全批次符合预期。
4. 兼容性测试：`ToolNode` 上仍存在 `_parse_input` / `_extract_state` / `_arun_one` / `_run_one` / `_combine_tool_outputs` / `tools_by_name`；不存在时测试失败并提示升级适配。
5. 子代理集成测试：父子 agent 的 `create_agent` 都使用 `SafeToolNode`（可断言 factory 已被替换）。

### Phase 2：标注 + 强制

1. 给 `sessions_spawn` 加 `concurrent_safe`；给写工具加 `side_effect_scope`；给 `memory` 明确不可并行。
2. 把 `enforce` 切到 `True`。
3. 全量测试门 + 文档同步（AGENTS 的 middleware / tools 说明）。

### Phase 3：观察与收尾

1. 用真实会话观察 `unsafe batch` 日志，确认没有把只读/独立工具误判为不安全；发现漏标就补 metadata 或 READ_ONLY_TOOLS。
2. 如果日志显示 `terminal` / `python_repl` 的并发风险不在本计划能覆盖的范围（跨 agent），再单独评估 scope 锁，不塞进本计划。

## 5. 测试

新增 `tests/agent/tools/test_parallel_safety.py`：

- `read_file` + `web_search` → safe。
- `memory` → unsafe（即使 `idempotent=True`）。
- `write_file` / `patch_file` / `terminal` → unsafe。
- `sessions_spawn` → safe。
- 未知工具 / 缺 metadata → unsafe。
- `destructive=True` 覆盖 `concurrent_safe=True`。

新增 `tests/agent/test_safe_tool_node.py`：

- 两个 safe 工具并发：用 `asyncio.Event` / `barrier` 证明重叠。
- 一个 safe + 一个 unsafe：整批不重叠，且顺序与 `tool_calls` 顺序一致。
- 两个 unsafe：顺序执行。
- `enforce=False`：仍并发，但记录一次 warning。
- `enabled=False`：factory 未被 patch。
- 结果顺序与 `tool_calls` 对齐；`Command` / `return_direct` 输出不被破坏。
- 同步 `_func` 与异步 `_afunc` 各覆盖一次。

兼容性测试：

- `SafeToolNode` 依赖的 `ToolNode` 私有方法存在；LangGraph 升级后先在这里失败。
- 使用真实 `create_agent` 构建一个两工具 agent，确认 `factory.ToolNode is SafeToolNode`。

回归：

- `tests/agent/middlewares/` 全量；ToolGuardrails、HITL、MessagePersistence 的 tool-call 包装链不因替换 ToolNode 改变。
- 全量 split gate（A/B/C）。

## 6. 风险与非目标

| 风险 | 对策 |
|---|---|
| LangGraph 私有方法漂移 | pin 版本 + 兼容性测试；升级时按 `ToolNode._afunc` / `_func` 重新对齐。 |
| 全局 patch 影响所有 `create_agent` | `TOOL_PARALLEL["enabled"]` 总开关；`enforce=False` 可先观察；测试断言 patch 生效与关闭。 |
| 标注错误导致过度串行 | 默认不安全只是性能损失；观察日志 + 补 READ_ONLY / `concurrent_safe`，不阻断正确性。 |
| 串行批次中的长工具阻塞同批其它调用 | 这是安全语义，不是缺陷；依赖顺序或长任务的调用本来就不应该放在同一批。 |
| 多 agent 同时写同一文件 | 不在本计划范围；`file_write_lock` + CAS 继续负责。 |
| 子代理不同工具集 | 分类按 `tools_by_name` 的 metadata 走；每个 child 的 `SafeToolNode` 独立分类。 |

非目标：

- 不做跨 session / 跨 agent 的全局工具锁。
- 不做工具依赖 DAG 或按参数细分的动态判定。
- 不把 `idempotent` 当作并行安全的唯一依据。
- 不把 `smart_tool_node.py` 原样合入 `dev`。
