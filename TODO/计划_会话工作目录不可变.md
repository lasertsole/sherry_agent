- 建档日期：2026-10-22
- 状态：**计划（未开工）**

## 0. 背景：当前可变设计及其代价

### 0.1 当前机制

会话的工作目录是**运行时可变**的——用户可以在会话中途通过 `PUT /sessions/project` 切换目录。为了支持中途切换，sherry 维护了一套复杂的 park/promote 机制：

```
用户切换目录（turn 运行中）
  ↓ apply_project_choice_async 检测到 turn active
  ↓ park_project_choice 写入 PROJECT_DIR_PENDING
  ↓ turn 结束 → on_turn_finished → promote_pending_project_dir
  ↓ write_project_dir(pending=False) 正式生效
  ↓ 下一轮 WorkspaceNoticeMiddleware 检测到 PROJECT_DIR_ANNOUNCED ≠ current
  ↓ 注入 HumanMessage 通知 agent "目录从 X 切换到 Y"
```

涉及 **3 个 StateKey**（`PROJECT_DIR` / `PROJECT_DIR_PENDING` / `PROJECT_DIR_ANNOUNCED`）、**1 个完整 service**（`session_project_service.py`）、**1 个中间件**（`WorkspaceNoticeMiddleware` 的目录检测路径）、**turn runner 的 promote 逻辑**、以及客户端的切换 UI（`ProjectDirectoryChip` + `ProjectDirectoryPicker` + `project-directory` store 的 `select` 方法）。

### 0.2 为什么废除

1. **复杂度**：park/promote/announce 三态机制 + 中间件检测 + turn boundary promote 是为了一个低频操作（用户很少中途切目录）维护的高复杂度管道
2. **语义安全**：中途切目录会导致工具的相对路径解析突变——`read_file("src/main.py")` 在目录 A 和目录 B 指向不同文件；`.sherry/` 的 per-project 状态（codeintel 索引、FACTS.md）需要跟着重载
3. **`.sherry/` 的前提**：per-project FACTS.md 和 codeintel 索引假设目录不变——中途切目录会让 per-project 快照失效，需要复杂的 invalidate 逻辑。目录不可变让 per-project 状态自然稳定
4. **所有同类项目都不支持中途切**：ZCode 的 workspace 绑定在 session 创建时；codex 的 cwd 在启动时固定；claudeCode 的 worktree fingerprint 在创建时确定

## 2. 硬约束

| 约束 | 含义 |
|---|---|
| **C1**：`current_project_dir` / `session_workspace_root` 签名不变 | 所有读侧消费者零改动 |
| **C2**：git HEAD 检测保留 | `WorkspaceNoticeMiddleware` 保留 git 分支/HEAD 变更通知（agent 用 terminal commit 后分支变了，下一轮通知 agent） |
| **C3**：子代理继承保留 | 子代理在 spawn 时从父会话继承目录，一次性写入子会话——不变 |
| **C4**：cron/heartbeat 不受影响 | 这些会话无 project_dir 绑定，走 `resolve_default_project_dir()` fallback——不变 |
| **C5**：外部路径 HITL 保留 | `resolve_external_path` 的"在 session 项目目录内"检查不变 |
| **C6**：重启后绑定恢复 | `PROJECT_DIR` 仍在 SQLite 镜像里，`prime_mem_from_store` 预热 PROJECT_DIR（去掉 ANNOUNCED） |
| **C7**：旧无绑定会话兼容 | 已有的无绑定会话仍走 `resolve_default_project_dir()` fallback——不崩 |
| **C8**：不能绑定 sherry 自身目录 | `validate_project_dir` 拒绝 `ROOT_DIR`（sherry 代码树）和 `APP_HOME`（sherry 可写状态目录）——agent 不能在自己的源码或状态目录里工作 |

- [ ] **3.1.1a** `validate_project_dir` 加 ROOT_DIR / APP_HOME 拒绝检查

`config/path.py:370` 的 `validate_project_dir` 追加：

```python
def validate_project_dir(value: str | os.PathLike[str]) -> Path:
    """...（现有 docstring）..."""
    # ... 现有验证（空 / 相对 / 不可解析 / 非目录）...

    # 拒绝 sherry 自身目录——agent 不能在自己的源码或状态目录里工作
    _ROOT = ROOT_DIR.resolve()
    _HOME = APP_HOME.resolve()
    if resolved == _ROOT:
        raise ValueError(
            f"project directory must not be the sherry repository itself ({resolved}); "
            "select the project you want the agent to work on, not sherry's own source tree"
        )
    if resolved == _HOME:
        raise ValueError(
            f"project directory must not be sherry's data home ({resolved}); "
            "select the project you want the agent to work on, not sherry's state directory"
        )

    return resolved
```

**检查范围**：只拒绝**等于** `ROOT_DIR` 或 `APP_HOME` 的路径——不拒绝父目录或子目录。如果用户选 `/home/user/projects/`（sherry 是其子目录），允许——agent 的工具解析相对路径到项目目录内，PathGuard 限制写操作在项目目录内，sherry 源码作为子目录里的只读文件不影响安全。如果用户选 `ROOT_DIR/tests/`（sherry 的子目录），也允许——那是一个正常的测试目录。

**为什么只查 `==` 不查 `is_relative_to`**：`ROOT_DIR.is_relative_to(resolved)` 会拒绝所有包含 sherry 的父目录（如用户 home 目录），过于严格。agent 在包含 sherry 的目录里工作不等于 agent 在 sherry 目录里工作——前者是"sherry 是子目录"的正常场景，后者是"agent 在自己源码里工作"的危险场景。

**`resolve_default_project_dir` 不改**：进程默认目录可能 fallback 到 `ROOT_DIR`（未配置时）——这是向后兼容行为，不经过 `validate_project_dir`。只有用户显式选择的目录走 `validate_project_dir` 检查。

## 4. 影响面分析

### 4.1 `.sherry/` 创建时机联动

`计划_统一项目隐藏目录到sherry.md` §5 的创建时机条件需要更新：

| 条件 | 原方案 | 不可变后 |
|---|---|---|
| ① 用户显式设置了项目目录 | `project_dir_source == "session"` | 不需要——创建时已绑定，始终 `"session"` |
| ② 目录与上次绑定的不同 | `current != last_announced` | **删除**——目录不变，无需比对 |
| ③ 目录中不存在 `.sherry/` | 不变 | 不变 |
| ④ 用户开始发对话 | 不变 | 不变 |

简化后只需两个条件：**`.sherry/` 不存在** + **首轮首次模型调用**（确认用户开始工作）。

### 4.2 `project_dir_notice` reminder 联动

`project_dir_notice`（priority=60，`only_if_changed=True`）在目录不可变后：
- 首轮：`_build_project_dir_block` 返回绑定目录文本 → hash 不存在 → 注入一次
- 后续轮：hash 匹配 → `only_if_changed` 跳过 → 零开销
- 上一轮的 reminder 在历史消息里，模型仍可见

行为正确，不需要改动。

### 4.3 FACTS.md per-project 联动

`计划_统一项目隐藏目录到sherry.md` §2.6 的 FACTS.md per-session 快照：
- 原方案需要处理项目切换时快照失效 + 重新加载
- 目录不可变后，快照只需在 session 首次构建系统提示时加载一次——**简化**

### 4.4 子代理不受影响

子代理在 spawn 时通过 `resolve_spawned_workspace_inheritance` 从父会话继承目录，调 `write_project_dir(child_session_key, cwd)` 一次性绑定到子会话——这个机制不变。子代理的目录也是不可变的（创建时绑定，不再变）。

### 4.5 cron/heartbeat 不受影响

这些会话无 `project_dir` 绑定，走 `resolve_default_project_dir()` fallback。`project_dir_source` 对它们返回 `"default"`。不在此 TODO 范围内。
