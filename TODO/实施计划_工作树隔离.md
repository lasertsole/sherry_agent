## 一、非 git 项目：自动 `git init`（三条实测约束）

### 实测约束（全部已验证，不可绕过）

1. **空仓库无法建 worktree**
   ```
   $ git init -q . && git worktree add --detach wt HEAD
   fatal: 无效引用：HEAD
   ```
   → auto-init **必须先造一个基线 commit**，这是 git 的硬性要求。

2. **秘密会进历史**
   新 `git init` 的项目通常没有 `.gitignore`，`git add -A` 会把 `.env`（实测含 `API_KEY=sk-real-secret`）**提交入库**。一旦入库即永久留存 —— 事后删文件不足以清除。
   → **deny-list 必须在 `git add` 阶段生效**，不能是 add 之后再删。

3. **`git stash create` 不含未跟踪文件**，且 `rsync --from0 --files-from=-` 在本环境**静默无效**（返回 0 但零文件落地）。
   → 物化一律用 Python `shutil.copy2` + `os.makedirs`。

### auto-init 契约

触发条件：**仅当请求隔离且目标目录不是 git 仓库**。非隔离的原地操作不触发，因此 sherry 不会在用户只是聊天时凭空建仓库。

```
1. git init -q <project>
2. 按 deny-list 过滤后 git add -A → git commit -m "sherry: isolation baseline"
   · deny-list 见下
   · 不加任何 remote，永不 push
3. 写标记文件 <project>/.sherry-isolation-repo（内容：创建时间 + sherry 版本 + 删除方法）
4. 走 P0 正常流程建 worktree
```

### 基线 commit 的 deny-list（必须实现）

在 `.gitignore` 之外**额外**排除，否则基线会巨大且带毒：

- 秘密：`.env` / `.env.*`（**保留 `.env.example`**）、`*.pem`、`*.key`、`id_rsa*`、`.npmrc`、`.pypirc`、`.aws/`、`.ssh/`、`*_rsa`、`*_ed25519`
- 体积：`**/node_modules/`、`.venv/`、`__pycache__/`、`*.pyc`、`target/`、`dist/`、`build/`、`.next/`、`.cache/`
- 状态：`.git/`、`.sherry-isolation-repo`

体积类被排除后，由 §二 的 `.worktreeinclude` 物化进 worktree（symlink），不丢可用性。

### 生命周期与用户可见性

- `.git/` **留在用户项目里**（基线 commit 必须存活，否则 worktree 无从建立）
- 用户可随时 `rm -rf <project>/.git <project>/.sherry-isolation-repo` 恢复原状；该操作会一并丢弃所有隔离树，**必须先确认无正在运行的子代理**
- 文档须写明：sherry 不会 `push`、不会加 remote、不会改写用户已有历史

## 二、被忽略路径的逐路径物化（`worktreeInclude` 机制）

`git worktree` 的 checkout 不materialize 被 `.gitignore` 忽略的文件。解决它的是**第三方工具族** `worktreeInclude`（已核实存在，非 git 内建）：

- `draxxris/git-worktree-include`（Go，binary `wti`）：读 `.gitignore` ∩ `.worktreeinclude`，post-checkout hook 内 hardlink / symlink / copy
- `amondnet/worktreeinclude`（Bun）：用 `git check-ignore --stdin -z` 过滤候选
- `satococoa/git-worktreeinclude`：`.worktreeinclude` 置源 worktree 根，gitignore 兼容语法

### 生态核实（不采用其交付方式，只采纳其策略模型）

| 生态 | 检索结果 |
| --- | --- |
| git 本体 | 仅 `worktree.guessRemote` / `core.worktree` / `extensions.worktreeConfig` / `gc.worktreePruneExpire` —— **无任何 include 机制** |
| opencode 二进制 | token `worktreeInclude` 命中 **0**；worktree API 面仅 `worktreeCreate` / `worktreeRemove` / `worktreeReset` |
| OMO 包 | 字段全集 `worktreeEnabled` / `worktreeBranches` / `worktreePath` / `worktreePlanPath` / `worktreeMemberEndpoint` …… —— **无 include/exclude** |
| Codex | 配置键仅 `git-worktree-root` / `worktree-auto-cleanup-enabled` / `worktree-keep-count`；`Feature::Worktrees` 受 `/experimental` 控制 |

### 采纳 / 拒绝

**采纳**（三个独立实现共同摸出的设计）：`.worktreeinclude` 声明式文件 + gitignore-glob 语法 + 逐路径 `# wti=symlink|copy` 指令 + 「必须同时命中 `.gitignore`」的交集规则。

**拒绝**：**post-checkout hook**（会写进用户 `.git/hooks`，用户手动 checkout 也触发，对 sherry 侵入）与 **Go / Bun 二进制依赖**（`isolation/tree.py:54` 已有排除逻辑，Python 实现约 120 行）。

### 逐路径策略表（数据全部实测）

| 路径 | 忽略来源 | 体积 | 策略 | 理由 |
| --- | --- | --- | --- | --- |
| `client/node_modules/` | ignored | 603M | **symlink** | 巨大、只替换不编辑 |
| `src/` | ignored | 265M | **symlink（整目录）** | 共享进程级状态；整目录 symlink 自动保持 `-wal` / `-shm` 一致 |
| `workspace/memory/`、`workspace/sessions/` | `.gitignore:49:/workspace/` | 16K | **symlink** | 记忆连续性；`flock` 跟随 symlink 至同一 inode，**跨树互斥反而正确** |
| `cron_jobs.json` | ignored | — | **symlink** | 全局共享注册表 |
| `skills/auto/` | ignored | — | **symlink** | 生成物，陈旧比共享更糟 |
| `.omo/` | ignored | 3.3M | **copy** | 活的可变任务状态；两个并发 worktree 共用一个 boulder 文件会损坏 |

**tracked persona（`SOUL.md` 等）无需额外处理** —— P0 第 ① 段的 `$DIRTY` tree 已等于工作区当前状态，提交与否都正确。

### 已实测验证的两条依赖

- **SQLite 经 symlink 目录**：读、写双向透传，`PRAGMA journal_mode` 保持 `wal`。`src/` 用整目录 symlink 即依赖此性质。
- **同 device 可硬链接**：`stat -c %d` 显示 `src` 与 `.` 同为 `65097`。本方案用 symlink（语义更清晰）；跨设备部署时硬链接是退路。

## 五、明确保留（与回退无关的承重结构）

删除回退**不触碰**以下三层，它们与「恢复到写前 revision」无关：

- `agent/tools/pub_base/read_state.py` —— read-before-write license 与 revision 来源
- `agent/tools/pub_base/file_lock.py` —— 线程锁 + 跨进程 `flock`
- `agent/tools/pub_base/atomic_write.py` —— `atomic_write_text_no_follow`（TOCTOU）
- `patch_file` 两层 CAS（fingerprint at read + `expected_revision` re-assert before `os.replace`）

已核实：删 `snapshot.py` 不会切断 CAS 链 —— CAS 的 revision 来自 `read_state`，不依赖 snapshot 行。

`agent/tools/subagent/isolation/` 移除 `backend` 分支与 `copy` 实现，只保留 worktree 路径。**保留**：

### 接线项（P1 必须处理）

symlink 指向 worktree 根之外。`resolve_external_path` / `_open_no_follow` 的判定是「在 `ROOT_DIR` 内**或**在 session project dir 内」：project dir 绑到 sherry 根时通过，但用户绑了别的项目目录时会被判为外部路径而触发 HITL 审批。需为物化出的 symlink 路径建立显式豁免，同时保持 `PathGuard` 既有的「外部路径需审批」策略不被削弱。

## 九、P4 — 自动 merge-back

「自动 merge 回当前分支」用 `merge.py:102` 的现成契约：

- per-root `flock` 下按路径合并
- 冲突按路径上报，父树不动
- worktree 侧对应一次 `merge --no-ff`（对齐 OMO `integrateMemberBranch` 的禁 squash / 禁 rebase 策略）

## 十、风险与已知代价

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| **auto-init 把秘密提交进历史** | 凭据永久留存 | §一 deny-list 在 `git add` 阶段生效；单测断言 `.env` / `*.pem` 不入库 |
| **auto-init 在用户目录留 `.git/`** | 用户目录被改动 | 仅隔离请求触发；写 `.sherry-isolation-repo` 标记；文档写明 `rm -rf` 恢复方法 |
| **失去单文件回退** | 改错一个文件须弃整树 | 明确接受；靠 `patch_file` 的 CAS + `read_state` 在**写入前**拒绝，而非事后回退 |
| symlink 指向树外触发 HITL | 每个跨树读都卡审批 | P1 接线项：显式豁免物化路径 |
| `.omo/` 用 copy，兄弟 worktree 看不到彼此进度 | 隔离树内进度面板不完整 | 预期语义；merge-back 时回写 |
| 物化遗漏新忽略路径 | agent 在 worktree 内失联 | `.worktreeinclude` 显式声明 + 与 `.gitignore` 求交集并有单测守护 |
| 并发 merge 竞争 `index.lock` | merge 失败 | per-root `flock` + 串行 merge + 基于原始 base SHA 的漂移检测 |
| 用户在隔离期间提交到当前分支 | worktree 基线失效 | manifest 记 `$DIRTY`，merge 前校验基线，失效报冲突而非静默覆盖 |
| 删除回退后 UI 空引用 | 前端编译失败 | 与 §四 同批删除 `ChatFileRevertDialog` 及其 Pinia 接线，跑 `pnpm test:unit` + `dpdm` |
