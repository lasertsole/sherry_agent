## 1. 后端依赖

专家注册库 API（来自专家团计划步骤 1-2）：

```
GET    /experts                    列出所有专家
GET    /experts/:name              获取单个专家配置
POST   /experts                    创建专家（body: ExpertConfig）
PUT    /experts/:name              更新专家配置
DELETE /experts/:name              删除专家
GET    /experts/:name/teams        列出引用该专家的团队
```

ExpertConfig schema：
```json
{
  "name": "frontend-expert",
  "description": "Frontend development specialist",
  "persona_prompt": "You are a frontend expert...",
  "model": "claude-3-5-sonnet",
  "thinking": "medium",
  "functional_role": "executor",
  "skills": ["code_wiki", "text_to_image"],
  "mcp_servers": [],
  "step_timeout_seconds": 1800
}
```

如果后端 API 尚未实现，S2 前端先用 mock 数据开发，后端就绪后切换。

## 2. 前端 store

**文件**：`client/app/stores/expert-registry.ts`（新建）

```typescript
interface ExpertConfig {
  name: string
  description: string
  persona_prompt: string
  model: string
  thinking: string
  functional_role: string
  skills: string[]
  mcp_servers: string[]
  step_timeout_seconds: number
}

interface ExpertWithUsage extends ExpertConfig {
  team_count: number  // 被多少团队引用
}

export const useExpertRegistryStore = defineStore('expert-registry', () => {
  const experts = ref<ExpertWithUsage[]>([])
  const loading = ref(false)
  const error = ref<string | null>(null)

  async function loadAll() {
    loading.value = true
    error.value = null
    try {
      const res = await $fetch('/api/experts')  // Ingress 反代到 cell
      experts.value = res.experts
    } catch (e) {
      error.value = String(e)
    } finally {
      loading.value = false
    }
  }

  async function create(config: ExpertConfig) {
    await $fetch('/api/experts', { method: 'POST', body: config })
    await loadAll()
  }

  async function update(name: string, config: Partial<ExpertConfig>) {
    await $fetch(`/api/experts/${name}`, { method: 'PUT', body: config })
    await loadAll()
  }

  async function remove(name: string) {
    await $fetch(`/api/experts/${name}`, { method: 'DELETE' })
    await loadAll()
  }

  return { experts, loading, error, loadAll, create, update, remove }
})
```

## 5. 验收标准

| # | 场景 | 预期 |
|---|------|------|
| 1 | 左栏导航行有 👥 图标 | 点击切换到专家库 |
| 2 | 专家列表加载 | 显示已注册专家卡片（name + model + skills 数 + team 引用数） |
| 3 | 搜索框输入关键词 | 卡片列表实时过滤 |
| 4 | 点 + 新建 | 右栏打开 ExpertEditPanel（空表单） |
| 5 | 填表 → 保存 | POST /experts → 列表刷新 → 新卡片出现 |
| 6 | 点已有专家卡片 | 右栏打开 ExpertEditPanel（预填配置） |
| 7 | 改配置 → 保存 | PUT /experts/:name → 列表刷新 |
| 8 | 删除专家 → 确认 | DELETE /experts/:name → 列表刷新 → 卡片消失 |
| 9 | 专家被团队引用 | 卡片显示 "N团" badge |
| 10 | 切到其他导航项再切回 | 专家列表状态保持（KeepAlive） |
| 11 | 后端 API 未就绪 | 前端用 mock 数据，不报错（loading + empty 状态） |
