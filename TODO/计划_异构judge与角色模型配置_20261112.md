# 计划：异构 Judge 与角色模型配置（UI 暴露 + per-role 继承）

- 日期：2026-11-12
- 状态：**待评审**
- 来源：TaskFlow 弱点补救核实——异构 judge 机制已有（三家族独立可配），零代码 config 即可激活；本计划把 StepJudge / CompletionJudge / 各角色 subagent 的模型配置暴露到 UI，并加 per-role 配置项 + 继承说明
- 风险等级：**低-中** —— 机制已有（build_family_llm 通用模式），主要是 config 暴露 + 前端表单 + per-role build 接入；不动中间件链、不动 TaskFlow 逻辑

---

## 0. 背景

### 0.1 异构 judge 机制已有（核实）

TaskFlow 的三个 LLM 家族**独立可配**：
- **StepJudge** 用 `build_taskflow_llm` → `TASKFLOW_LLM_*` 家族（`step_judge.py:170`，`build_family_llm("TASKFLOW_LLM")`）
- **CompletionJudge** 用 `build_auxiliary_llm` → `AUXILIARY_LLM_*` 家族（`completion_judge.py:161`）
- **executor / 子 agent** 用 `build_main_llm` → `MAIN_LLM_*` 家族（`child_agent_factory.py:341`）

`build_family_llm`（`models/LLMs/family_llm.py:65`）三态：`<PREFIX>_MODEL_LOCAL=true` 复用 aux 本地；设了 `<PREFIX>_PROVIDER`/`API_BASE` 走独立远程；都不设 fallback 到 `build_auxiliary_llm`。

**把 `TASKFLOW_LLM_PROVIDER` 配成和 `MAIN_LLM_PROVIDER` 不同家族 = 异构 judge，纯 config，零代码。**

### 0.2 当前 config 现状（`config/models_settings.py`）

| 家族 | config 键 | 已有？ | 用于 |
|---|---|---|---|
| MAIN_LLM_* | provider/name/base/key/max_token/max_output/thinking | ✅ 已有 | executor + 所有子 agent + 主 agent |
| AUXILIARY_LLM_* | provider/name/base/key | ✅ 已有 | CompletionJudge + safety moderation + consolidation |
| TASKFLOW_LLM_* | provider/name/base/key（空=follow AUX）| ✅ 已有 | StepJudge + taskflow_plan/replan/finish |
| per-role（executor/researcher/reviewer/librarian）| — | ❌ 没有 | 现在全部继承 MAIN |

### 0.3 executor 为啥继承 MAIN 而非 AUX（设计意图）

executor 干真活（写代码/改文件/调工具）——产出的主力，需最强模型。aux 为次要任务设计（判定/审核/moderation/整合）——更简单、能容忍更弱模型。分工是异构 judge 的正确形态：executor=强模型（main，干活）+ judge=不同/更便宜模型（aux/taskflow，查活），强模型产出、不同模型验证 → 错误去相关。

read-only 角色（researcher/librarian/reviewer）理论上能用更便宜模型，现在也继承 main 是为简单/质量。per-role 配置后用户可把 read-only 角色降档省成本（executor 保持 main）。

## 1. 设计

### 1.1 目标

在 **系统配置 → 模型配置** 面板暴露：
- StepJudge 模型（TASKFLOW_LLM_*）
- CompletionJudge 模型（AUXILIARY_LLM_*，标注"CJ 复用 aux，如需独立请配 CJ_LLM_*"）
- 各角色 subagent 模型（新增 EXECUTOR_LLM_* / RESEARCHER_LLM_* / REVIEWER_LLM_* / LIBRARIAN_LLM_*）

每个配置项带**继承说明**：不配置则继承对应默认模型。

### 1.2 继承链

```
StepJudge:        TASKFLOW_LLM（配了用）→ AUXILIARY_LLM（空时 fallback）→ MAIN（aux 也空时）
CompletionJudge:  CJ_LLM（新增，配了用）→ AUXILIARY_LLM（默认）
executor:         EXECUTOR_LLM（新增，配了用）→ MAIN_LLM（默认）
researcher:       RESEARCHER_LLM（新增，配了用）→ MAIN_LLM（默认）
reviewer:         REVIEWER_LLM（新增，配了用）→ MAIN_LLM（默认）
librarian:        LIBRARIAN_LLM（新增，配了用）→ MAIN_LLM（默认）
```

**继承规则**：`build_family_llm(prefix)` 已实现"prefix 空 → fallback aux"。per-role 扩展为"prefix 空 → fallback main"（read-only/write 角色都 fallback main，因为它们当前都用 main）。CJ 扩展为"CJ_LLM 空 → fallback aux"。

### 1.3 异构 judge 推荐配置（说明文案）

面板顶部加一段说明（非强制）：
> 异构 judge：让 judge 用和 executor 不同的模型家族可减少"同源盲点"（executor 和 judge 在同一种地方同时犯错）。推荐：executor 保持强模型（如 Claude/DeepSeek），StepJudge/CompletionJudge 配不同家族（如 DeepSeek↔Claude 互换）。不配则 judge 继承 aux/默认。

## 2. 配置项清单

| 配置项 | config 键前缀 | 默认继承 | 前端已有？ |
|---|---|---|---|
| 主模型（executor + 主 agent） | MAIN_LLM_* | —（根） | ✅ 已有 |
| 辅助模型（CJ + moderation + 整合） | AUXILIARY_LLM_* | —（根） | ✅ 已有 |
| StepJudge 模型 | TASKFLOW_LLM_* | 空→AUXILIARY | ✅ 已有（LlmModelManager 管理，带"follows auxiliary"空配置徽章） |
| 压缩模型（参照） | COMPRESSION_LLM_* | 空→AUXILIARY | ✅ 已有（内部家族模式参照） |
| executor 模型 | EXECUTOR_LLM_*（新增） | 空→MAIN | ❌ 新增 |
| researcher 模型 | RESEARCHER_LLM_*（新增） | 空→MAIN | ❌ 新增 |
| reviewer 模型 | REVIEWER_LLM_*（新增） | 空→MAIN | ❌ 新增 |
| librarian 模型 | LIBRARIAN_LLM_*（新增） | 空→MAIN | ❌ 新增 |
| CompletionJudge 模型 | 复用 AUXILIARY_LLM | — | ✅ 已有（CJ_LLM 独立可选新增） |

**前端现状核实**：`LlmModelManager.vue` 已管理 MAIN/AUXILIARY/TASKFLOW/COMPRESSION/ITTT/VTTT/TTI/RERANKER/EMBEDDING/STT 十组。`INTERNAL_FAMILIES = ['TASKFLOW_LLM', 'COMPRESSION_LLM']` 已实现"内部家族空配置→跟随 aux"徽章逻辑。per-role 四个新家族走同样模式，扩展为"空配置→跟随 main"（加 `followsMain` 逻辑）。StepJudge 无需新增前端面板，已有。

**CJ_LLM_* 是否新增**：CompletionJudge 当前直接用 `build_auxiliary_llm`。如果想让 CJ 独立于 aux（比如 aux 给 moderation、CJ 给 judge，两个不同家族），需新增 CJ_LLM_* + 改 `completion_judge.py` 读 `build_family_llm("CJ_LLM")`。如果不需 CJ 和 aux 分开，CJ 就复用 aux 配置项（标"CJ 复用辅助模型"），不新增。

**建议**：首版 CJ 复用 aux（不新增 CJ_LLM_*），StepJudge 已有前端，per-role 四个新增前端面板。CJ_LLM_* 看是否需要 CJ≠aux 再加。

## 3. 后端

### 3.1 config schema（`config/models_settings.py`）

新增 per-role 家族键（参照 TASKFLOW_LLM_* 结构）：
```python
# Per-role subagent models (empty = follow MAIN_LLM)
"EXECUTOR_LLM_PROVIDER": "",
"EXECUTOR_LLM_API_NAME": "",
"EXECUTOR_LLM_API_BASE": "",
"EXECUTOR_LLM_API_KEY": "",
"RESEARCHER_LLM_PROVIDER": "", ...   # 同结构
"REVIEWER_LLM_PROVIDER": "", ...
"LIBRARIAN_LLM_PROVIDER": "", ...
# （可选）CJ_LLM_* 若 CJ 需独立于 aux
```

### 3.2 build 接入（`models/LLMs/`）

- 新增 `build_executor_llm` / `build_researcher_llm` / `build_reviewer_llm` / `build_librarian_llm`，调 `build_family_llm("<PREFIX>")` + fallback 到 `build_main_llm`（而非默认的 aux）
- `family_llm.py::build_family_llm` 加一个 fallback 参数：`build_family_llm(prefix, fallback="auxiliary"|"main")`，per-role 用 `fallback="main"`
- `child_agent_factory.py:341` 按角色调对应 builder（executor→`build_executor_llm`，researcher→`build_researcher_llm`，...）而非统一 `build_main_llm`
- StepJudge / CompletionJudge 不改（已用 taskflow / aux）

### 3.3 API（`server/trigger/http/`）

- 现有模型配置 API（`/sherry-config` 或模型 config 端点）扩展支持新增的 per-role 键
- `GET /sherry-config/model-roles`（新增）返回各角色当前 effective 模型 + 继承来源（用于 UI 显示"继承自 MAIN"）

### 3.4 角色模型解析日志

spawn 时记录该子 agent 实际用的模型 + 来源（继承自哪）到 trajectory，便于调试配置生效与否。

## 4. 前端（系统配置 → 模型配置面板）

### 4.1 新增配置区（per-role 四个；StepJudge 已有无需新增）

StepJudge（TASKFLOW_LLM）**前端已有**（LlmModelManager 已管理，带"follows auxiliary"徽章）。新增 per-role 四个面板，走 `INTERNAL_FAMILIES` 同样模式但"follows main"：

```
角色 subagent 模型（不配则继承主模型）

executor 模型     [provider][name][base][key]   继承：空→主模型
researcher 模型   [provider][name][base][key]   继承：空→主模型
reviewer 模型     [provider][name][base][key]   继承：空→主模型
librarian 模型    [provider][name][base][key]   继承：空→主模型
```

- `LlmModelManager.vue` 的 `INTERNAL_FAMILIES` 扩展加入四个 per-role 家族
- `followsAuxiliary` 逻辑扩展为 `followsMain`（空配置时显示"跟随主模型"徽章，与 TASKFLOW 的"跟随辅助"对称）
- `GROUP_HELP_KEYS` 加四个 per-role 的 help 文案
- `TESTABLE_GROUPS` 加四个（可测连接）

### 4.2 继承说明

每行配置项旁标继承来源（从 `GET /sherry-config/model-roles` 读 effective model + source）。空配置时显示"继承 [来源家族]：[实际模型名]"，配了显示"[已配置]：[模型名]"。

### 4.3 异构 judge 说明文案

区顶部一段说明（§1.3 的文字）。

### 4.4 高级：CJ_LLM（可选折叠）

如新增 CJ_LLM_*，在"高级"折叠区加 CJ 独立配置项 + 说明"CJ 独立于辅助模型时配此项"。

## 6. 验收

- 系统配置 → 模型配置 面板有"角色与判定模型"区，含 StepJudge + per-role 四项 + 继承说明
- 空配置时：executor/researcher/reviewer/librarian 继承 MAIN；StepJudge 继承 AUX（经 TASKFLOW fallback）
- 配置 StepJudge 成不同家族 → StepJudge 实际用该家族（trajectory 日志验证）
- 配置 executor 成不同家族 → executor 子 agent 用该家族
- 配置 researcher 成便宜模型 → researcher 子 agent 降档（省成本）
- 异构配置（executor=family A，StepJudge=family B）→ 两者实际用不同家族
- 继承来源正确显示（UI 标"继承自 MAIN：[模型名]"）
- 回归：现有 MAIN/AUX/TASKFLOW 行为不变（空配置等价原行为）
- `uv run pytest tests/agent/tools/subagent tests/agent/tools/taskflow -q` 全过

## 7. 备注

- 异构 judge 的核心（三家族独立可配）**机制已有**，本计划主要是 UI 暴露 + per-role 扩展 + 继承说明
- 零代码激活异构 judge：即便不做 UI，直接配 `TASKFLOW_LLM_PROVIDER` env 即可。UI 是让用户不用改 env 就能配
- per-role 配置的额外价值：read-only 角色（researcher/librarian/reviewer）可降档便宜模型省成本，executor 保持强模型
- CJ_LLM_*（CJ 独立于 aux）是可选项，首版可不做（CJ 复用 aux）
- 角色模型解析日志到 trajectory 便于调试配置生效（避免"配了但没生效"的困惑）
