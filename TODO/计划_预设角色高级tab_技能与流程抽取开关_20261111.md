# 计划：预设角色"高级"Tab — 技能抽取 / 流程抽取开关（会话继承全局）

- 日期：2026-11-11
- 状态：**待评审**
- 来源：用户需求——在 菜单-当前会话/全局-预设角色 的预设角色设置里加"高级"tab，控制技能抽取与流程抽取（PTC+LDW）开关，会话级默认继承全局级
- 风险等级：**低-中** —— 新增配置字段 + UI tab + 后端 gate 读取；不改首次执行、不加门；关闭抽取只是不生成产物（skill 定义/replay 脚本），不影响 agent 正常运行

---

## 0. 背景

Sherry 现有三个"抽取"机制当前基本 always-on：
- **技能抽取（skill review）**：计划完成时 `_run_skill_review` 让辅助 LLM 更新 `skills/auto/<skill>` 的 skill 定义。目前计划完成就跑
- **PTC 编译**：成功的 TaskFlow step 编译成 `ptc__<plan>__<step>.py`。`ptc_prefill_enabled` 默认 False（观察态）
- **LDW 编译**：成功 plan 编译成 `ldw__<plan_key>.py`。`LDW.enabled` 默认 True，`min_replays` 默认 3

用户要的是**面向用户的统一开关**，分两级（全局/会话），让用户控制这些抽取是否发生。尤其"流程抽取"把 PTC + LDW 合并为一个用户可懂的总开关。

## 1. 配置 Schema（四字段，分 scope）

新增 `config/features/agent_side/extraction.py`（或并入现有 preset config）：

```python
class ExtractionConfig(TypedDict):
    skill_extraction_enabled: bool       # 经验学习（skill review），会话可 override，默认 True
    flow_extraction_enabled: bool        # 流程复用编译（PTC+LDW），全局只读会话不可改，默认 True
    iteration_budget_main: int           # 主智能体迭代上限，会话可 override，默认 = 现有 IterationBudget main 值
    iteration_budget_sub: int            # 子智能体迭代上限，会话可 override，默认 = 现有 subagent 值
```

**字段 scope（r2 修订）**：

| 字段 | 用户面名称 | 全局可改？ | 会话可改？ | 默认 |
|---|---|---|---|---|
| `skill_extraction_enabled` | 经验学习 | ✅ | ✅（override） | True |
| `flow_extraction_enabled` | 流程复用编译 | ✅ | ❌（只读继承全局） | True |
| `iteration_budget_main` | 主智能体迭代上限 | ✅ | ✅（override） | 现有值 |
| `iteration_budget_sub` | 子智能体迭代上限 | ✅ | ✅（override） | 现有值 |

> **r2 关键变化**：`flow_extraction_enabled` 会话级**不可修改**（用户要求）——会话只读继承全局值。UI 会话入口对该开关显示只读 + "由全局配置控制"提示。理由：流程编译是基础设施级决策（是否生成 replay 脚本），不宜会话级临时关。

**技能与流程的父子约束**（不变）：
- `skill_extraction_enabled=False` → `flow_extraction_enabled` 强制视为 False（父关子必关）
- `skill=True, flow=True`：完整管线
- `skill=True, flow=False`：skill review 跑但不编译 PTC/LDW
- `skill=False`：全关（flow 无论全局值都视为 False）

**IterationBudget 字段**（r2 新增）：
- `iteration_budget_main`：主智能体每轮工具调用迭代上限，超出触发摘要压缩
- `iteration_budget_sub`：子智能体每轮上限（低于 main 以控成本）
- 这两个字段喂给 `IterationBudget` 中间件（现 position 5 main / 1 child，`_BOTH` 必需集），替代/扩展现有硬编码阈值
- 默认值取现有 IterationBudget 配置（`config/features/agent_side/` 当前值，待核实）

**与现有底层 gate 关系**（不变）：`flow_extraction_enabled` 是用户面总开关同时控 PTC+LDW；底层 `ptc_prefill_enabled`/`LDW.enabled`/`LDW.min_replays` 保留细粒度不暴露。

## 2. 两级存储 + 继承

### 2.1 两级

| 级别 | 存储位置 | 作用域 |
|---|---|---|
| **全局-预设角色级** | 每个预设角色的配置（preset 定义 / `sherry.jsonc` 的 presets 段 / preset 配置文件） | 该预设角色被任何会话使用时的默认 |
| **当前会话级** | session state register（StateKey）+ parked twin（同 thinking/model 控制的 park/promote 模式） | 仅本会话覆盖 |

### 2.2 继承规则（r2 修订：flow 全局只读）

```
读取 effective 配置（用于 gate 判定）：
  skill_extraction_enabled:
    1. session 有显式 override？→ 用 session 值
    2. 否则 → 全局 preset 值
    3. 都没有 → 默认 True
  flow_extraction_enabled:
    1. 全局 preset 值（会话不可 override）
    2. 没有 → 默认 True
    ※ 会话级只读继承，UI 不允许修改
  iteration_budget_main / sub:
    1. session 有显式 override？→ 用 session 值
    2. 否则 → 全局 preset 值
    3. 都没有 → 现有默认值
```

- `skill_extraction` / `iteration_budget_*`：会话可 override（默认继承全局）
- `flow_extraction`：会话**只读继承**全局（用户要求）——会话 UI 显示全局值 + 不可编辑
- 会话创建时未 override 的字段**默认继承**全局 preset 配置
- 会话内改可 override 字段 → 写 state register（parked，turn 边界 promote）
- 全局改 → 影响所有未 override 该字段的会话（flow 改影响所有会话，因会话不可 override）

### 2.3 parked/promote（会话级）

复用 thinking 控制的 park/promote 机制（`runtime/session/` 已有）：
- 会话运行中改"高级"配置 → 写 `StateKey.EXTRACTION_PENDING`（parked）
- `turn_runner.on_turn_finished` 在 turn 边界 promote 到 `StateKey.EXTRACTION`（避免 turn 中途切换导致不一致）
- HITL-pending 会话延后 promote（同 thinking）

## 4. 后端消费（gate 读取）

五个消费点读 effective 配置：

| 消费点 | 读哪个字段 | 行为 |
|---|---|---|
| `_run_skill_review`（计划完成时） | `skill_extraction_enabled` | False → skip skill review |
| PTC 编译器 `compiler.py` | `flow_extraction_enabled`（且 skill 开） | False → 不生成 PTC 脚本 |
| LDW 编译 `compile_plan_to_workflow` | `flow_extraction_enabled`（且 skill 开） | False → 不生成 LDW 脚本 |
| `IterationBudget` 中间件（main，position 5） | `iteration_budget_main` | 替代现有硬编码阈值；超限触发摘要压缩 |
| `IterationBudget` 中间件（child，position 1） | `iteration_budget_sub` | 同上，子代阈值 |

**读取入口**：统一 helper `get_effective_extraction_config(session_id) -> ExtractionConfig`，封装继承逻辑（skill/budget：session override → 全局 → 默认；flow：全局 → 默认，会话不可 override）。五个消费点调它。

**IterationBudget 改造**：中间件当前读硬编码/现有 config 阈值；改为读 `get_effective_extraction_config` 的 `iteration_budget_main`/`sub`。main agent 构建时（`agent/core.py`）传 main 值；child agent 构建（`child_agent_factory.py`）传 sub 值。`_BOTH` 必需集不变（仍都装 IterationBudget），只是阈值来源换成 effective config。

**fail-open**：读取失败 → 默认值（skill=True, flow=True, budget=现有值），不阻塞。

**与防重放计划的关系**：`flow_extraction_enabled=False` 时根本不编译（含 non_idempotent 的也不编译，无冲突）；`True` 时防重放计划的 non_idempotent 拒编生效。

### 5.3 交互

- **不显示字段名**——全部用四语言易懂名称（§3）+ 说明文字
- 经验学习关 → 流程复用编译禁用（灰显 + tooltip i18n："需先开启经验学习"）

## 7. Kill criteria

- 若继承逻辑在 preset 切换场景取错值 → 显式 fallback 日志 + 默认值兜底（fail-open）
- 若 IterationBudget 改造后 main/child 阈值与现有行为不一致 → 先保留现有值为默认，改造仅换来源不改数值
- 若 flow 全局只读导致会话无法临时关流程编译 → 设计如此（用户要求）；用户需到全局关，接受影响所有会话
- 若 sub > main 输入未校验导致子代比主代能迭代更多 → 前端校验 sub ≤ main；后端 clamp sub = min(sub, main)

## 8. 验收

### 8.1 配置 + 继承
- 全局设 经验学习=False → 新会话继承 False（skill review 不跑）
- 会话 override 经验学习=True → 该会话跑（覆盖全局）
- 会话"重置为全局默认" → 清除 override 回继承
- **流程复用编译**：全局设值 → 所有会话只读继承；会话 UI 不可改；会话 API 拒绝 flow 字段
- 迭代上限同 skill（会话可 override）

### 8.2 gate 生效
- 经验学习=False → skill review skip
- 经验学习=True, 流程复用=False → skill review 跑但不编译 PTC/LDW
- 经验学习=True, 流程复用=True → 完整管线
- 经验学习=False → 流程复用强制视为 False（父关子必关）
- 迭代上限：main agent 超限触发摘要压缩；child 同理（阈值独立）

### 8.3 IterationBudget
- main agent 构建用 `iteration_budget_main`
- child agent 构建用 `iteration_budget_sub`
- 默认值 = 现有值（行为不变）
- sub > main 时 clamp

### 8.4 park/promote
- 会话运行中改可 override 字段 → parked，turn 边界 promote
- HITL-pending 会话延后 promote

### 8.5 UI（四语言）
- 预设角色设置含"高级"tab
- 四项用四语言易懂名称（§3），不显示字段名
- 经验学习开关 + 流程复用编译开关（会话只读 + 锁图标 + "由全局配置控制"）+ 主/子迭代上限输入
- 经验学习关时流程复用禁用灰显
- 当前会话级：可改字段 override + 重置按钮；全局级：四项全可改
- 四语言切换正常（en/zh/ja/ko）

- 与"非幂等防重放"计划互补：本计划是用户面抽取总开关（要不要编译），防重放计划是编译时安全门控（拒编高危工具）。`flow_extraction_enabled=False` 直接不编译；`True` 时防重放 non_idempotent 拒编生效
- 与"内存优化"计划正交
- IterationBudget 改造与本计划绑定（阈值来源换 effective config），不单独成计划
