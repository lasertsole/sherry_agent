# 计划：Session 运行报告——Token/上下文命中率/code-intel 使用

- 日期：2026-11-23
- 状态：**待评审**
- 来源：eval 有三个 post-task 分析器（token_tracker / context_analyzer / code_intel_tracker），产品侧没有。用户看不到"这次跑了多少 token""上下文有多少浪费了""agent 在用 LSP 还是 grep"。
- 风险等级：**低** — 纯 post-task 分析，不改热路径
- 依赖：无
- 可独立执行：✅

---

## 0. 现状

eval 侧有三个分析器（`evals/shared/`）：

| 分析器 | 作用 | eval 位置 |
|--------|------|-----------|
| `token_tracker.py` | 主 agent + 每个子 agent 的 token 分解，可选 USD 成本 | `evals/shared/token_tracker.py` |
| `context_analyzer.py` | 每次工具调用 HIT/WASTED 判定，计算上下文命中率 | `evals/shared/context_analyzer.py` |
| `code_intel_tracker.py` | LSP/explore 精确检索 vs grep/read_file 粗暴检索比率，检测 fail-open 降级 | `evals/shared/code_intel_tracker.py` |

三者都是 **post-task 分析**——从会话 transcript 读取，不在热路径插桩（`context_analyzer.py:5` 明确说 "works POST-TASK ... no instrumentation in the hot path"）。

产品侧有 token 计费（`TokenBudgetMiddleware`），但不暴露 per-session/per-role/per-tool-class 分解；没有上下文命中率；没有 code-intel 使用比率。

## 1. 设计

把三个分析器提取到 `pub/func/`（产品侧共享），在 session 结束时（或用户手动触发时）生成运行报告，UI 展示。

### 1.1 提取分析器到产品侧

| eval 文件 | 产品侧目标 | 改动 |
|-----------|-----------|------|
| `evals/shared/token_tracker.py` | `pub/func/session_report/token_tracker.py` | 去掉 eval-specific 依赖，通用化 |
| `evals/shared/context_analyzer.py` | `pub/func/session_report/context_analyzer.py` | 同上 |
| `evals/shared/code_intel_tracker.py` | `pub/func/session_report/code_intel_tracker.py` | 同上 |
| `evals/shared/score_reporter.py` | `server/service/session_report_service.py` | 聚合三个分析器，生成报告 |

### 1.2 触发时机

- **自动**：session 的最后一个 turn 结束后（agent 产出最终回复，无 continuation），异步生成报告
- **手动**：API `GET /sessions/{session_id}/report`，用户随时可查

### 1.3 报告内容

```json
{
  "session_id": "...",
  "duration_seconds": 1234,
  "tokens": {
    "main": {"input": 50000, "output": 8000, "total": 58000},
    "children": [
      {"role": "executor", "input": 20000, "output": 3000, "total": 23000},
      {"role": "reviewer", "input": 10000, "output": 1000, "total": 11000}
    ],
    "grand_total": 92000,
    "estimated_cost_usd": 0.15
  },
  "context_hit_rate": {
    "total_tool_calls": 45,
    "effective": 32,
    "wasted": 13,
    "hit_rate": 0.71,
    "wasted_by_tool": {"search_files": 8, "read_file": 5}
  },
  "code_intel": {
    "precise_calls": 10,
    "greedy_calls": 20,
    "lsp_vs_grep_ratio": 0.33,
    "degraded_calls": [
      {"tool": "lsp_diagnostics", "reason": "binary not found"}
    ]
  }
}
```

### 1.4 UI 展示

在 session 结束后（或用户点"运行报告"按钮时）展示一个折叠面板：

- **Token 概览**：总量 + per-role 分解 + 可选成本
- **上下文命中率**：百分比 + 浪费最多的工具
- **code-intel 比率**：LSP vs grep 比率 + 降级告警

### 1.5 成本估算（可选）

token_tracker 支持 USD 成本估算，需要价格表（`SHERRY_EVAL_TOKEN_PRICES` 或产品侧 config）。不设价格表时跳过成本字段。

## 3. 验收

- session 结束后自动生成报告
- `GET /sessions/{session_id}/report` 返回 JSON
- token 分解包含 main + 每个 child role
- 上下文命中率 = effective / (effective + wasted)
- code-intel 比率包含降级检测
- 不设价格表时跳过成本字段
- UI 展示折叠面板
