## 0. 问题

### 0.1 sherry 多 agent 架构下 stop 不传播

sherry 有 4 条并发 lane，用户按 stop 时：

| lane | stop 后行为 | 问题 |
|---|---|---|
| MAIN（主 turn） | `asyncio.Task.cancel()` ✓ | 没问题 |
| SUBAGENT（最多 8 个子代理） | **不 cancel**——子代理在独立 session 独立 task | **继续跑，烧 token，用户已经不想要了** |
| NUDGE（memory review） | 不 cancel | 可能还在跑 LLM call |
| NESTED（sessions_send 回复） | 不 cancel | 可能还在跑 |

`_cancel_session`（`ws/messages.py:144-163`）只 cancel `_active_tasks[main_session_id]`——子代理的 task 在独立 session 上，不在主 session 的 `_active_tasks` 里。

### 0.2 hermes 怎么做——`child.interrupt()` 显式传播

hermes 的 `AIAgent.interrupt()`（`run_agent.py:2692-2770`）做五件事：

```python
def interrupt(self, message):
    self._interrupt_requested = True              # ① 主 agent flag
    self._active_request_abort("interrupt_abort") # ② 关 LLM socket
    _set_interrupt(True, self._execution_thread_id)  # ③ per-thread flag
    for _wtid in _worker_tids:
        _set_interrupt(True, _wtid)               # ④ fan out 到 tool worker threads
    for child in children_copy:
        child.interrupt(message)                  # ⑤ ★ 传播到子代理
```

子代理的 conversation loop（`conversation_loop.py:647-653`）检查 flag：

```python
if agent._interrupt_requested:
    interrupted = True
    _turn_exit_reason = "interrupted_by_user"
    break
```

### 0.3 为什么 hermes 模式比 codex 模式适合 sherry

| 维度 | codex `CancellationToken` | hermes `_interrupt_requested` + `child.interrupt()` | sherry 适合谁 |
|---|---|---|---|
| 传播范围 | 单 turn 内的 async stream loop | **跨 session 子代理**——遍历 children 逐个 set flag | **hermes**——sherry 子代理在独立 session 上，需要跨 session 传播 |
| 检查时机 | `.or_cancel()` 在 stream event 边界 | `if flag: break` 在 loop 顶部 + tool 边界 | **hermes**——sherry 的 middleware 在 `before_model`/`wrap_tool_call` 检查 flag 最自然（跟 `HeartbeatStaleness` 同 pattern） |
| 机制复杂度 | `CancellationToken` + 100ms grace + `TurnAborted` 事件 + `handle.abort()` | flag + 遍历 children + 安全点检查 | **hermes**——更简单，sherry 已有 `state_register` 做 per-session flag |
| 主 turn cancel | `CancellationToken` 替代 `task.cancel()` | `task.cancel()` 保留 + flag 给子代理 | **hermes**——sherry 的 `task.cancel()` 对主 turn 已够用，gap 是子代理传播 |

**codex 的 `CancellationToken` 是单 turn 内的**——它 cancel 一个 turn 的 stream loop，不跨 session 传播。sherry 的 gap 是**子代理不传播**，不是主 turn cancel 方式不够好。hermes 的 `child.interrupt()` 直接解决传播问题。

### 1.2 `interrupt_children`——子代理中断传播

**文件**：`agent/tools/subagent/registry/`（现有 registry 已跟踪 running 子代理）

```python
# agent/tools/subagent/registry/interrupt.py（新）
"""子代理中断传播——借鉴 hermes child.interrupt(message)（run_agent.py:2764）。

sherry 的子代理在独立 session 独立 asyncio task 上——不在主 session 的
_active_tasks 里。本函数遍历 subagent registry 的 running 子代理，
逐个 set INTERRUPT_REQUESTED flag + cancel child task。
"""

from runtime.session.state_register import state_register_mem
from runtime.session.state_keys import StateKey

async def interrupt_children(parent_session_id: str, reason: str = "user_stop") -> int:
    """遍历 parent 的 running 子代理，逐个中断。

    借鉴 hermes run_agent.py:2764: for child in children_copy: child.interrupt(message)

    返回被中断的子代理数量。
    """
    from agent.tools.subagent.registry import get_running_children
    children = get_running_children(parent_session_id)
    count = 0
    for child in children:
        child_session_key = child.child_session_key
        # ① set INTERRUPT_REQUESTED flag（子代理 middleware 检查它）
        state_register_mem.set_state(child_session_key, StateKey.INTERRUPT_REQUESTED, True)
        # ② cancel child 的 asyncio task（如果注册在 _active_tasks 里）
        from server.trigger.ws.messages import _active_tasks
        child_task = _active_tasks.get(child_session_key)
        if child_task is not None and not child_task.done():
            child_task.cancel()
            count += 1
        # ③ 也 set 在 db tier（重启不丢——子代理崩溃恢复时看到 flag）
        state_register_db.set_state(child_session_key, StateKey.INTERRUPT_REQUESTED, True)
    if count:
        logger.info(
            "[interrupt] propagated to {} child agents of session {}",
            count, parent_session_id,
        )
    return count
```

**跟 hermes 的差异**：
- hermes：`child.interrupt(message)` 直接调 child agent 对象的方法 → set child 的 `_interrupt_requested`
- sherry：子代理是独立 session，没有直接的 agent 对象引用 → set `state_register` 的 flag + cancel child 的 asyncio task

**cancel child task 用 `task.cancel()` 还是 flag？** 两者都做：
- `task.cancel()` 立即中断 child 的当前 await（LLM stream / tool call）——hard cancel
- `INTERRUPT_REQUESTED` flag 让 child 的 middleware 在 `before_model`/`wrap_tool_call` 检查——如果 child 在 cancel 后恢复（HITL resume / auto-turn），flag 阻止它继续跑

### 1.3 `_cancel_session` 加传播

**文件**：`server/trigger/ws/messages.py::_cancel_session`

```python
async def _cancel_session(session_id, reason="interrupted"):
    # 现有：cancel 主 turn task
    task = _active_tasks.get(session_id)
    if task is not None and not task.done():
        task.cancel()
        try:
            await asyncio.wait_for(task, timeout=5.0)
        except (asyncio.TimeoutError, asyncio.CancelledError):
            pass
    else:
        state_register_mem.set_state(session_id, StateKey.ANSWERING, False)

    # ★ 新增：传播到子代理（借鉴 hermes child.interrupt）
    from agent.tools.subagent.registry.interrupt import interrupt_children
    await interrupt_children(session_id, reason)

    # ★ 也 set 主 session 的 flag（防止 stop 后 auto-turn 重触发）
    state_register_mem.set_state(session_id, StateKey.INTERRUPT_REQUESTED, True)
    # flag 在 turn 结束时清（见 §1.6）
```

### 1.4 `InterruptCheckMiddleware`——子代理在安全点检查 flag

**文件**：`agent/middlewares/interrupt_check/`（新）

借鉴 hermes `conversation_loop.py:647-653` 的 `if agent._interrupt_requested: break`——在 middleware 层检查 flag：

```python
# agent/middlewares/interrupt_check/core.py（新）
"""子代理中断检查——借鉴 hermes conversation_loop.py:647 的 flag 检查。

在 model call / tool call 边界检查 INTERRUPT_REQUESTED flag。
flag = True 时：model call → raise CancelledError；tool call → 合成 error ToolMessage。
子代理的 agent loop 在安全点退出，不继续跑。
"""

class InterruptCheckMiddleware(AgentMiddleware):
    """在 model/tool 边界检查 INTERRUPT_REQUESTED flag。

    注册在主链 + 子代理链（scaffolding._MAIN_REQUIRED + _SUBAGENT_REQUIRED）。
    主 agent 的 flag 由 _cancel_session set；子代理的 flag 由 interrupt_children set。
    """

    async def abefore_model(self, state: AgentState, runtime: Runtime | None = None) -> None:
        session_id = self._resolve_session_id(state)
        if session_id and state_register_mem.get_state(session_id, StateKey.INTERRUPT_REQUESTED, False):
            raise asyncio.CancelledError("Interrupt requested")

    async def awrap_tool_call(self, request, handler):
        session_id = self._resolve_session_id_from_request(request)
        if session_id and state_register_mem.get_state(session_id, StateKey.INTERRUPT_REQUESTED, False):
            # 借鉴 ZCode stream_recovery_interrupted_tool（streaming-tool-synthetic-result.ts:13-52）：
            # 未执行的 tool 合成 error result——不只是 "Interrupted"，
            # 还告诉模型 "不要盲目重试" + "副作用可能未知"
            return ToolMessage(
                content=(
                    "[Interrupted] Parent agent was stopped by user. "
                    "This tool was not executed. "
                    "Do not retry blindly — side effects may be unknown. "
                    "Inspect current state before retrying."
                ),
                tool_call_id=request.tool_call_id,
            )
        return await handler(request)
```

**注册**：
- `agent/middlewares/catalog.py::MIDDLEWARE_ORDER` 加 `InterruptCheck`（在 `HeartbeatStaleness` 之后——先查心跳再查中断）
- `agent/middlewares/scaffolding.py::_MAIN_REQUIRED` + `_SUBAGENT_REQUIRED` 都加——主 agent 和子代理都检查

**为什么 `awrap_model_call` 不做而 `abefore_model` 做**：`abefore_model` 在 model call 之前跑——如果 flag 已 set，直接 raise `CancelledError`，不调 model。`awrap_tool_call` 在 tool 执行前检查——flag set 时合成 error ToolMessage 不调 handler。两个检查点覆盖了 agent loop 的两个关键边界。

### 1.5 `<turn_aborted>` marker——告诉模型中断原因

**文件**：`server/service/interrupt_marker.py`

# interrupt_marker.py::write_interrupted_marker 改造
async def write_interrupted_marker(session_id, ai_text, reason="interrupted", *, heal=True):

### 1.6 flag 清理——turn 结束时清 INTERRUPT_REQUESTED

**文件**：`server/service/turn_runner.py`

flag 不能永久留着——否则子代理恢复（HITL resume / auto-turn）时会立刻被 flag 挡住。在 turn 结束时清：

```python
# turn_runner.py::on_turn_finished 加
def on_turn_finished(session_id, result):
    # 现有逻辑...
    # ★ 清 INTERRUPT_REQUESTED flag（主 session + 子代理都清）
    state_register_mem.set_state(session_id, StateKey.INTERRUPT_REQUESTED, False)
    state_register_db.set_state(session_id, StateKey.INTERRUPT_REQUESTED, False)
    # 子代理的 flag 在子代理 task 结束时自行清（见下）
```

子代理的 flag 清理：子代理被 cancel 后，它的 turn 结束流程（`StreamTurn._run_frames` 的 `finally` / `on_finish`）也会调 `on_turn_finished(child_session_key, ...)` → 清 flag。

**但如果子代理 task 被 cancel 没有 `on_finish`？** `interrupt_children` 里 `child_task.cancel()` 后 child 的 `StreamTurn._run_frames` 的 `except CancelledError` 分支会跑 `_on_cancelled` → `on_finish` → 清 flag。如果 child task 已经 done（不在 `_active_tasks` 里），flag 由 `interrupt_children` set 但没有 task 来清——下次该 session 的 turn 启动时 `abefore_model` 检查 flag → raise → turn 立刻结束 → `on_turn_finished` 清 flag。自愈。

### 1.8 中断通知——告诉模型"用户停的，不要自行恢复"

**文件**：`server/service/interrupt_marker.py` + `agent/tools/subagent/announce/`

**借鉴 ZCode**（`background-stop-dynamic-workflow.ts:54-56`）：后台 run 被 user stop 后，通知模型时带 `stopInitiator === "user"` + "这是用户的决定，不要自行恢复"。

sherry 的子代理被中断后，completion notice 通过 `SteeringQueue` 回到主 agent。现有 notice 是"子代理完成了"——没有"子代理被用户中断了"的区分。改成带中断原因：

```python
# agent/tools/subagent/announce/delivery.py::_build_completion_message
# 现有：子代理完成时发 notice
# 改后：子代理被中断时发不同的 notice

def _build_completion_message(run, *, interrupted: bool = False, interrupt_reason: str = ""):
    if interrupted:
        metadata = {
            "internal": True,
            "provenance": "subagent_completion",
            "run_id": run.run_id,
            "status": "interrupted",           # ★ 新增：区分"完成" vs "中断"
            "interrupt_reason": interrupt_reason,  # "user_stop"
        }
        content = (
            f"[Subagent interrupted] {run.label} was stopped because the parent "
            f"agent was interrupted by the user. This was the user's decision — "
            f"do not auto-resume. Partial work may have been completed."
        )
    else:
        metadata = {  # 现有的完成 notice
            "internal": True,
            "provenance": "subagent_completion",
            "run_id": run.run_id,
            "status": run.status,
        }
        content = f"[Subagent completed] {run.label}: {run.result_summary}"
    ...
```

主 agent 的 `SubagentCompletionDrainMiddleware` 在 `before_model` drain 这些 notice——模型看到 `[Subagent interrupted] ... was stopped because the parent agent was interrupted by the user. Do not auto-resume.`，知道：
- 子代理没正常完成，是被用户中断的
- 不要自动恢复子代理
- 可能有部分工作已完成

**跟 ZCode 的差异**：ZCode 的通知是异步的（后台 run stop 后通过 notification system 通知）；sherry 的通知通过 `SteeringQueue` 在 `before_model` drain——如果主 agent 也被 stop 了，notice 在 queue 里等下一轮 drain。

### 1.9 后台子代理脱钩——借鉴 ZCode `detachParent()`

**文件**：`agent/tools/subagent/registry/interrupt.py`

**借鉴 ZCode**（`subagent/runner.ts:640` `detachParent()`）：子代理转后台时从 parent 的 abort signal 脱钩——parent stop 不传播到后台子代理。

sherry 的子代理目前没有"前台/后台"区分——所有 running 子代理都会被 `interrupt_children` 传播。如果要支持"后台子代理不被 parent stop 影响"（比如长跑研究子代理），加一个 `background` flag：

```python
# interrupt.py::interrupt_children 改造
async def interrupt_children(parent_session_id: str, reason: str = "user_stop") -> int:
    children = get_running_children(parent_session_id)
    count = 0
    for child in children:
        # ★ 借鉴 ZCode detachParent()：后台子代理不被 parent stop 传播
        if getattr(child, "is_background", False):
            logger.debug("[interrupt] skipping background child {}", child.child_session_key)
            continue
        # 前台子代理：set flag + cancel task
        state_register_mem.set_state(child.child_session_key, StateKey.INTERRUPT_REQUESTED, True)
        ...
```

**本计划 P0 不做后台脱钩**——sherry 当前所有子代理都是前台。后台脱钩是 P2 扩展（如果未来加"后台子代理"概念）。但设计预留了 `is_background` flag 的接入点。

## 6. 回归风险与缓解

| 风险 | 缓解 |
|---|---|
| `interrupt_children` cancel child task 导致 child 的 partial 输出丢失 | child 的 `StreamTurn._run_frames` 的 `except CancelledError` 分支跑 `_on_cancelled` → `write_interrupted_marker` → 双写持久化。sherry 已有这套机制——不改 |
| `INTERRUPT_REQUESTED` flag 残留导致子代理恢复后被挡 | §1.6 `on_turn_finished` 清 flag + §1.6 自愈（残留 flag → 下次 turn `abefore_model` raise → turn 结束 → 清 flag） |
| `InterruptCheckMiddleware` 增加中间件链长度 | sherry 已有 24 个中间件——加 1 个极轻（只检查一个 bool flag）影响极小 |
| `_cancel_session` 改造影响 HITL resume | HITL resume 也调 `_cancel_session`——现在会传播到子代理。但 HITL resume 是模型主动 `interrupt()` 暂停等用户回答——此时子代理可能也在跑。传播中断给子代理是正确行为（用户回答 HITL 时不需要子代理继续跑） |
| `interrupt_children` 跟 SUBAGENT lane 释放冲突 | child task cancel → lane permit 归还 → `LaneManager` 自动释放 slot。不冲突 |
| terminal 不杀后台进程导致僵尸 | marker 告知模型"进程可能还在跑"——模型下一轮可查/kill。下次 `clear_session` 会清 |

## 7. 已知不在本计划范围内

- **hermes 打字中断**：用户在 busy 时打字自动中断 + 重排队——sherry 的 input queue 已把 busy 消息入队等下一 turn。打字中断是另一个计划。
- **codex `CancellationToken` + 100ms grace**：不引入——hermes flag 模式更适合 sherry 的跨 session 传播需求。主 turn 的 `task.cancel()` 保留。
- **codex `TurnAborted` 正式事件**：不引入——`<turn_aborted>` marker + `stopped` frame 够。trajectory 库加 `turn_aborted` kind 是可选 P2。
- **NUDGE / NESTED lane 传播**：本计划只传播 SUBAGENT lane 的子代理。NUDGE（memory review）和 NESTED（sessions_send）的 task 也在独立 session——如果需要传播，`interrupt_children` 的 `get_running_children` 可以扩展查这两个 lane。P2 扩展。
- **hermes per-thread flag**：不引入——sherry 是 asyncio 不是 thread。`state_register` 的 per-session flag 是 asyncio 等价物。

## 8. 数据流

```
用户按 stop：
  WS frame {"type":"stop"} → _handle_stop → _cancel_session(session_id, "interrupted")
    │
    ├─ 现有：cancel 主 turn task（asyncio.Task.cancel）
    │   → StreamTurn._run_frames except CancelledError
    │   → _on_cancelled → write_interrupted_marker(<turn_aborted reason="interrupted">)
    │   → heal_trailing_tool_calls + MesMemory 双写 + VOIDED CLAIMED row
    │   → yield "Request cancelled" + stopped frame
    │
    ├─ ★ 新增：interrupt_children(session_id)
    │   │  遍历 subagent registry 的 running 子代理
    │   │
    │   ├─ child 1: set INTERRUPT_REQUESTED=True + cancel child_task
    │   │   → child StreamTurn._run_frames except CancelledError
    │   │   → child _on_cancelled → write_interrupted_marker
    │   │   → child on_finish → 清 child flag + 释放 SUBAGENT lane slot
    │   │
    │   ├─ child 2: 同上
    │   └─ child N: 同上
    │
    ├─ set 主 session INTERRUPT_REQUESTED=True（防 auto-turn 重触发）
    │
    └─ on_turn_finished → 清主 session flag

子代理安全点检查（正常运行时）：
  child agent loop
    ├─ abefore_model: 检查 INTERRUPT_REQUESTED → True? raise CancelledError
    ├─ awrap_tool_call: 检查 INTERRUPT_REQUESTED → True? 合成 error ToolMessage
    └─ 正常运行时 flag=False → 不影响
```

## 9. 一句话

借鉴 hermes `child.interrupt()`（`run_agent.py:2764`）+ codex `<turn_aborted>` marker（`turn_aborted.rs:10`）+ ZCode `throwIfTurnAborted`（`turn-errors.ts:83`）+ 未执行工具合成 error（`streaming-tool-synthetic-result.ts:13`）+ `stopInitiator` 通知（`background-stop-dynamic-workflow.ts:54`）+ openclaw durable kill intent（`SubagentKillIntent`，用 `state_register_db` 简化覆盖）。用户 stop 后 `_cancel_session` 不仅 cancel 主 turn task，还调 `interrupt_children` 遍历 subagent registry 的 running 子代理逐个 set `INTERRUPT_REQUESTED` flag（mem + db 双写，借鉴 openclaw durable kill）+ cancel child task。子代理的 `InterruptCheckMiddleware`（注册在主链 + 子代理链）在 `abefore_model`/`awrap_tool_call` 检查 flag（借鉴 ZCode `throwIfTurnAborted`）——flag=True 时 model call raise CancelledError、tool call 合成 error ToolMessage 含 "do not retry blindly"（借鉴 ZCode `stream_recovery_interrupted_tool`）。子代理在安全点退出后走 `write_interrupted_marker`（`<turn_aborted reason="interrupted">` 告诉模型"用户故意中断的，子代理可能还在收尾"——借鉴 codex）+ heal trailing tool calls（sherry 独有）+ 双写持久化（sherry 独有）。中断的 completion notice 带 `status:"interrupted"` + "用户停的，不要自行恢复"（借鉴 ZCode `stopInitiator`）。flag 在 `on_turn_finished` 清（+ 自愈）。terminal 后台进程不杀（借鉴 codex unified-exec）。保留 sherry 独有优势：trailing tool call healing + 双写持久化 + 主 turn `task.cancel()`。
