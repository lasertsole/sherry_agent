## 0. 背景：sherry 是唯一不从项目目录读指令的

### 0.1 六项目对比

| 项目 | 读 AGENTS.md | 读 CLAUDE.md | 从项目目录读 | 注入位置 |
|---|---|---|---|---|
| codex | ✅ 主力（git root→cwd 全拼接） | ❌ | 项目 cwd | 系统提示 |
| hermes | ✅ 优先级 2 | ✅ 优先级 3 | cwd + 上溯到 git root | 系统提示（prompt injection 扫描后） |
| openclaw | ✅ 主力 | ❌ | `process.cwd()` | 系统提示 |
| claudeCode | ❌ | ✅ 主力（`/init` 生成） | 项目 cwd | 系统提示 |
| ZCode | ❌（读 `.zcode/config.json`） | ❌ | 项目 cwd | 系统提示 |
| **sherry** | **❌** | **❌** | **不从项目目录读** | **无** |

sherry 的 persona 文件（`AGENTS.md`/`SOUL.md`/`USER.md` 等）全在 `WORKSPACE_DIR`（`SHERRY_HOME/workspace/`），是 agent 自己的全局配置——与用户的项目无关。系统提示里唯一的"项目目录"信息是 `_build_project_dir_block` 输出的路径标签（不读文件内容）。

### 0.2 sherry 系统提示组装流程（不改动的部分）

`build_system_prompt(session_id)` 组装的稳定块（三层缓存，冻结快照）：

```
1. AGENTS.md     (persona — WORKSPACE_DIR)
2. SOUL.md       (persona — WORKSPACE_DIR)
3. USER.md       (persona — WORKSPACE_DIR)
4. ROLE.md       (persona — WORKSPACE_DIR)
5. MEMORY.md     (memory 快照 — WORKSPACE_DIR/memory)
6. USER.md       (memory 快照 — WORKSPACE_DIR/memory)
7. FACTS.md      (memory 快照 — WORKSPACE_DIR/memory)
8. Skills index  (skills 文本)
9. FILE_REFERENCE_BLOCK (常量)
```

DynamicReminderMiddleware 每轮注入的 live 块（per-turn，不入缓存）：

```
plan_mode(85) → todo(80) → taskflow(75) → boulder(70) → continuity(65) → project_dir_notice(60) → knowledge_index(50)
```

### 0.3 为什么放 reminder 而不是系统提示

sherry 的架构原则（`core.py` docstring）：

> "The prompt now holds only stable content (persona + memory + skills index). Live views go to reminders."

项目目录是 **live session state**——`PROJECT_DIR_PENDING` 在 turn boundary 被 `turn_runner.on_turn_finished` promote，用户可以在会话中途切换项目目录。如果把 `AGENTS.md` 读进系统提示：

1. 需要在每次 `PROJECT_DIR_PENDING` promote 时 invalidate `StateKey.SYSTEM_PROMPT` + `"workspace"` 快照——新且脆弱的 plumbing
2. 大指令文件（repo AGENTS.md 可以几 KB）会改变系统提示前缀，invalidate provider prefix cache
3. 跨越 `WORKSPACE_DIR` 边界——`build_system_prompt` 目前只读 sherry 自己的 workspace 文件，从项目目录读是新的 I/O 路径

reminder source 天然解决这些问题：
- `only_if_changed=True` + SHA-256 hash → 项目目录和文件不变时跳过（steady-state 免费）
- 项目切换 → hash 变 → 下一轮自动 re-inject，无需额外 wiring
- 不影响系统提示缓存

## 1. 设计：最合适的组合

### 1.1 方案选择

| 维度 | 选 | 理由 |
|---|---|---|
| 文件名 | `AGENTS.md` 优先，`CLAUDE.md` 回退 | AGENTS.md 是 codex/hermes/openclaw 的 de-facto 标准；CLAUDE.md 回退兼容 claudeCode 项目 |
| 注入位置 | reminder source（per-turn live） | 项目目录是 live state，符合"live views go to reminders"原则 |
| 不做的事 | 不创建 `.sherry/` 目录、不改 `.gitignore` | sherry 设计哲学是"项目目录干净"；一个 `.md` 文件是最小污染 |
| 不做的事 | 不嵌套遍历（git root→cwd） | 第一版从项目根读一个文件；codex 的嵌套遍历留给 Phase 2 |

### 1.2 新 reminder source

```python
register(
    ReminderSource(
        source_id="project_instructions",
        channel=ReminderChannel.CURRENT_TURN,
        builder=_as_builder(_build_project_instructions_block),
        budget_chars=8000,      # 真实 AGENTS.md 可能 2-5K，留余量
        priority=62,            # 在 continuity(65) 和 project_dir_notice(60) 之间
        only_if_changed=True,   # 项目目录/文件不变时跳过——steady-state 免费
        # cooldown_turns=0      # 默认值，always eligible，only_if_changed 做去重
    )
)
```

**优先级 62 的理由**：在 `continuity_context`(65) 和 `project_dir_notice`(60) 之间——连续性上下文是跨 session 的，优先级最高；项目指令是当前 session 的核心约定，优先于路径标签（路径标签只是"你在哪个目录"，指令是"在这个目录里怎么干活"）。

**budget 8000 的理由**：reminder 总预算 30,000 字符，七个现有 source 占约 9,000（实际全部注入时），8000 占 27%——对于一个可能包含技术栈/测试命令/工作规范的真实 AGENTS.md 是够的。如果 AGENTS.md 超过 8000 字符，会被 `core.py:158-159` 的 per-source cap 截断 + 省略号。

### 1.3 builder 函数

```python
def _build_project_instructions_block(session_id: str) -> str:
    """Read project-level instructions (AGENTS.md or CLAUDE.md) from the
    session's project directory.

    Returns "" when the project dir has no instruction file (most sessions
    won't). The content is wrapped in a <system-reminder> by the reminder
    layer's wrap_reminder, so nested tags are escaped and the model can tell
    it from user content.
    """
    try:
        from runtime.session.project_dir import current_project_dir

        root = current_project_dir(session_id)
        if not root:
            return ""

        root_path = Path(root)

        # AGENTS.md first (de-facto standard), CLAUDE.md fallback
        for filename in ("AGENTS.md", "CLAUDE.md"):
            candidates = [root_path / filename, root_path / "AGENTS.md"]
            # 第一版只读项目根；不遍历子目录
            file_path = root_path / filename
            if file_path.is_file():
                content = file_path.read_text(encoding="utf-8", errors="replace")
                content = content.strip()
                if content:
                    return content
        return ""
    except Exception:
        logger.debug("project instructions read failed", exc_info=True)
        return ""
```

### 1.4 注入后的消息列表（reverse 后）

```
[...历史消息...,
 用户消息,
 knowledge_index(50),       ← 低优先级在前
 project_dir_notice(60),    ← 路径标签
 project_instructions(62),  ← 新增：项目指令内容
 continuity_context(65),
 boulder_status(70),
 taskflow_status(75),
 todo_block(80),
 plan_mode_block(85)]       ← 高优先级在尾
```

路径标签（project_dir_notice）告诉模型"你在哪个目录"；项目指令（project_instructions）紧随其后告诉模型"在这个目录里遵守什么规矩"——自然衔接。

### 1.5 安全性

不需要额外的 prompt injection 扫描（hermes 做了 `_scan_context_content`），因为：

1. `wrap_reminder(source_id, content)` 把内容包在 `<system-reminder source="project_instructions">...</system-reminder>` 里，模型知道这是注入的上下文而非用户输入
2. `wrap_reminder` 转义嵌套的 `<system-reminder>` 和 `</system-reminder>` 标签（`pub/func/message/system_reminder.py:88-89`），防止 AGENTS.md 内容里的标签提前关闭 reminder 块
3. `metadata.provenance = "reminder_catalog"` + `metadata.internal = True`——所有消费者（summarizer、turn splitter、HITL）跳过此消息

## 5. 完整流程（改动后）

```
用户打开项目 /app/myproject（有 AGENTS.md）
  ↓ 绑定 project_dir = /app/myproject
  ↓ 首轮首次模型调用
  ↓ DynamicReminderMiddleware.abefore_model
  ↓ resolve_injections(session_id, state, current_turn=1)
  ↓ project_instructions source:
  ↓   _build_project_instructions_block(session_id)
  ↓   current_project_dir(session_id) → /app/myproject
  ↓   Path("/app/myproject/AGENTS.md").is_file() → True
  ↓   read_text() → "## 项目约定\n技术栈：Python 3.13 + uv\n测试：uv run pytest\n..."
  ↓   only_if_changed: hash 不存在 → 注入
  ↓ wrap_reminder("project_instructions", content)
  ↓ HumanMessage 追加到消息列表（reverse 后在 project_dir_notice 之后）
  ↓ 模型看到：
  ↓   <system-reminder source="project_dir_notice">## Current Working Directory: /app/myproject</system-reminder>
  ↓   <system-reminder source="project_instructions">## 项目约定\n技术栈：Python 3.13 + uv\n...</system-reminder>
  ↓ 模型知道项目目录 + 项目约定
  ↓
第二轮（项目目录和 AGENTS.md 都没变）
  ↓ resolve_injections → project_instructions source
  ↓   _build_project_instructions_block → 同样的内容
  ↓   only_if_changed: hash 匹配 → 跳过（不注入）
  ↓ 上一轮的 reminder 在历史消息里，模型仍可见
  ↓ 零开销（只有一次 is_file() stat）

用户切换项目目录到 /app/other-project
  ↓ PROJECT_DIR_PENDING → turn boundary promote
  ↓ 下一轮 resolve_injections → project_instructions source
  ↓   current_project_dir → /app/other-project
  ↓   Path("/app/other-project/AGENTS.md").is_file() → True (不同内容)
  ↓   only_if_changed: hash 不匹配 → 注入新项目的指令
  ↓ 模型看到新项目的 AGENTS.md 内容
```

## 6. 不做的事（边界）

| 项 | 不做的原因 |
|---|---|
| 嵌套遍历（git root → cwd 全拼接） | codex 的方式，适合 monorepo 但复杂度高；第一版从项目根读一个文件够用 |
| 创建 `.sherry/` 目录 | sherry 设计哲学是"项目目录干净"；一个 `.md` 文件是用户自己写的，不是 sherry 创建的 |
| 生成 AGENTS.md 的 `/init` 命令 | claudeCode 的做法，需要检测技术栈/测试命令/仓库结构——是另一个 TODO 的范围 |
| prompt injection 扫描 | `wrap_reminder` 已转义嵌套标签 + `internal:True` 标记；hermes 的 `_scan_context_content` 是其自己注入系统提示的安全需求，reminder 层不需要 |
| 读 `.cursorrules` | hermes 的兼容项，sherry 第一版只做 AGENTS.md + CLAUDE.md |
| 把 AGENTS.md 写进系统提示 | 项目目录是 live state，违反"系统提示只放稳定内容"原则 |
| 项目级 skills/commands（`.sherry/skills/`） | ZCode 的 `.zcode/skills/` 模式，是更大的 feature，另起 TODO |
| 改 .gitignore | sherry 从不碰项目的 .gitignore（六个项目中只有 claudeCode 这么做） |
| per-project 状态存储（workspace hash 分组） | ZCode 按 workspace hash 分组 sessions/memory，sherry 当前是扁平存储（`SESSIONS_DIR/<session_id>/` + 全局 `MEMORY.md`）；改成 per-project 分组是 ~500+ 行的架构变更（影响存储布局 + API + 前端 + 工具作用域），另起 TODO |
